五、反思/分析/建议

  1. 需求对齐先行：用户要求"先计划对齐再动手"，本次通过多轮分批 question 把布局拓扑/滚动方向/交互/筛选全部确认后才实施，避免了返工。结论：信息架构类改动必须大幅对齐后动手。
  2. z-index 堆叠上下文陷阱：.node-tip 初版 z-index 30 看似高，但作为 .node 子元素，受父节点堆叠上下文限制（P3=4/hover=8/9），浮层仍被邻接节点盖住。教训：子元素 z-index 受父堆叠上下文约束，置顶需同时提高父元素 z-index。最终 .node:hover z-index 100 + .node-tip 200 解决。
  3. grid 转置 vs width 溢出：grid 列宽 minmax(150px) 但节点固定 150px+padding 会溢出列，改 width:100% 自适应后才不溢出。教训：grid/border-box 布局中，元素宽度应自适应容器而非写死，否则溢出。
  4. f-string 嵌入 JS 花括号：Python f-string 中嵌入含单大括号的 JS（如注释 {lane:true}、对象字面量）会触发 ValueError，需全部转义为 {{}} 或拆分。教训：大段 JS 注入 f-string 时，所有非格式化花括号必须双写。
  5. 改进建议：①可加泳道悬浮时整行高亮、时间轴缩放聚焦近期；②关系线可加方向箭头/类型标签；③悬停概要可扩展显示四维背景档案（当时主流/痛点/为何胜出/后续影响）。
