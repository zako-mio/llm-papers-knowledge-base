## 摘要

本文解读阿里 Qwen 团队 2026 年 4 月发布的开源权重模型 **Qwen3.6-35B-A3B**——Qwen3.6 系列的首个开源权重变体，以 Apache 2.0 许可释出。其核心论断可以用一个不等式概括：**3B 的激活参数预算，可以撬动 35B 的总容量，并在 agentic coding 主战场上击败激活规模数倍于己的 dense 对手**（对标并部分超越 dense 27B 的 Qwen3.5-27B，比肩 Gemma4-31B）。支撑这一论断的是一条完整的技术栈：40 层按「10 组 ×（3 层 Gated DeltaNet 线性注意力 + 1 层 Gated Attention 全注意力）」循环堆叠的混合架构；256 选 8 + 1 共享专家、专家中间维仅 512 的极窄激活 MoE；预训练即带多步 MTP 头、配合 vLLM/SGLang 投机解码的推理加速；原生 262,144 tokens 上下文可扩展至 1,010,000；外加 thinking/non-thinking 双模式与新特性 Thinking Preservation。证据侧，模型在 Terminal-Bench 2.0 拿下对比五模型最高的 **51.5**，QwenWebBench 以 **1397 Elo** 领先次优 200 分，MCPMark **37.0** 约为 Gemma4-31B 的两倍；视觉语言侧多数基准持平 Claude Sonnet 4.5，空间智能（RefCOCO 92.0 / ODInW13 50.8）显著反超。但成绩单同样留有清晰的暗面：SWE-bench Verified 73.4 仍低于自家上代 dense 旗舰的 75.0，HLE 21.4 落后 2.9 分，General Agent 组三项均非第一，且训练数据/算力/后训练配方完全未披露、三个内部基准无第三方复现。本报告按「问题定位—概念内核—方法拆解—证据链—批判性分析—启示与影响」六层结构逐层拆解。

## 一、问题定位：开源生态缺一枚「编程钢炮」

### 1.1 该节点要解决的问题

这份文档不是论文，而是一份「权重卡 + 博客」形态的产品级技术发布。它要解决的问题因此不在学术前沿，而在**开源生态的结构性空位**上：

1. **能力空位**：2026 年上半年的 agentic coding 场景（SWE-bench 系列、Terminal-Bench、仓库级重构、MCP 工具编排）已成为模型竞争力的主战场，但开源权重池里缺少一个「能在本地/低成本环境跑起来、又具备旗舰级 agent 能力」的中等规格选项——要么是大激活的 dense 模型（跑不动），要么是能力不足的小模型（不好用）。
2. **成本空位**：dense 27B 级模型的推理成本随序列长度线性膨胀，而 agent 工作负载的特征恰恰是**长上下文 + 多轮工具调用 + 大量重复前缀**。没有稀疏化与线性注意力的加持，开源社区拿不到经济可用的 agent 底座。
3. **生态空位**：Qwen3.6-Plus 已先行发布（闭源 API），开源社区等待的是同代的权重版本——这个节点回答的是「Plus 的能力何时、以何种规格开源」的问题。

### 1.2 在产品谱系与竞争格局中的定位

从命名即可读出定位逻辑：「35B-A3B」= 35B 总参数 / 3B 激活参数。它同时向两个方向宣战：

- **向上打 dense**：官方明确主张以 3B 激活参数在多项关键编码基准上超过 dense 27B 的 Qwen3.5-27B、比肩 Gemma4-31B——这是「稀疏 MoE 可达成卓越 agentic coding」这一全文中心论点的直接表达；
- **向后压旧代**：全面超越直系前代 Qwen3.5-35B-A3B（同为 35B 总参/3B 激活的稀疏架构），提升在 agentic coding 与推理任务上尤为显著——说明同一规格下的迭代收益主要被投进了 agent 能力。

对比池的选择也暴露了定位意图：四个基线（Qwen3.5-27B、Gemma4-31B、Qwen3.5-35BA3B、Gemma4-26BA4B）**全部是开源同级模型**，没有任何闭源旗舰入场。「rivaling much larger dense models」的说法严格限定于开源同级池内。

> **一句话小结**：这个节点解决的不是学术问题，而是「开源社区需要一个跑得动、用得起、agent 能力对标 dense 大模型的中杯钢炮」的生态问题；其全部叙事都围绕「3B 激活 ≥ 数十 B 激活的 dense」这一效率命题展开。

## 二、概念内核：六个核心概念逐一定义

### 2.1 稀疏 MoE 与「总参—激活」分离

**术语定义**：模型总参数 35B，每个 token 仅激活 3B。MoE 层配置为 **256 个专家，每 token 激活 8 个 routed 专家 + 1 个共享专家**，专家中间维仅 512，hidden dimension 2048。

**拆解**：这是「35B-A3B」命名的字面来源，也是全文效率命题的物理基础。「总参—激活」分离的本质是把**知识容量**（存进 256 个专家）与**每 token 计算量**（只走 9 个专家）解耦：模型"知道多少"由 35B 决定，模型"想一个问题花多少钱"由 3B 决定。极窄的激活宽度（9/256 ≈ 3.5% 的专家利用率）意味着路由质量成为生死线——好在 agent 编码场景的任务模式相对收敛（读写文件、跑命令、改前端），路由模式的可预测性较高。（推断）这也解释了为何该架构在 agent 场景的性价比优势比在开放域对话上更容易兑现。

### 2.2 混合注意力布局：3:1 线性/全注意力

**术语定义**：40 层按 10 组循环堆叠，每组 = 3 ×（Gated DeltaNet → MoE）+ 1 ×（Gated Attention → MoE）。Gated DeltaNet 为线性注意力（32 个 V 头 / 16 个 QK 头，head dim 128）；Gated Attention 为带 GQA 的全注意力（16 个 Q 头 / 2 个 KV 头，head dim 256，RoPE dim 64）。

**拆解**：这是继承自 Qwen3.Next 路线的核心架构决策，其分工逻辑非常清晰：**75% 的层走线性注意力**——KV cache 成本不随序列长度增长，承担长上下文的「廉价记忆」；**25% 的层走全注意力**——保留精确检索能力，负责「关键时刻回头查原文」。agent 工作负载恰好是这种混合的理想客户：数万 token 的工具调用历史适合线性注意力维持状态，而「第 37 步修改过的那个文件内容」需要全注意力精确召回。GQA 把 KV 头压缩到 2 个，进一步压低全注意力层的显存占用。两种注意力的头规格差异（DeltaNet head dim 128 vs Attention head dim 256）暗示设计者把表达预算集中投给了少数全注意力层。（推断）

### 2.3 多步 MTP 与投机解码

**术语定义**：MTP（Multi-Token Prediction）以 multi-steps 形式参与预训练；部署侧官方直接给出 vLLM `qwen3_next_mtp` 与 SGLang NEXTN 投机解码配置（num_speculative_tokens=2 / steps 3）。

**拆解**：MTP 让模型在训练时就学会「一次猜后续多个 token」，推理时作为草稿模型供目标模型验证——命中则一步吐出多个 token，未命中则回退。它与稀疏 MoE 是天然互补的两项优化：MoE 降低每次前向的计算成本，MTP 减少生成固定文本所需的前向次数。对 agent 场景尤其实用——编码产出中大量结构化、高确定性的内容（代码骨架、命令、JSON）正是投机解码命中率最高的文本类型。（推断）

### 2.4 双模式输出与 Thinking Preservation

**术语定义**：thinking 模式默认开启，思维过程包裹于 `<think>...</think>` 标签；可切换 non-thinking 直接作答。新特性 **Thinking Preservation** 允许保留历史消息中的 reasoning context 用于迭代开发，减少重复推理开销。

**拆解**：双模式是对「推理深度 vs 响应成本」的显式开关——官方甚至给出分场景采样参数：通用 thinking 用 temp=1.0/top_p=0.95/top_k=20/presence_penalty=1.5，精确编码与 WebDev thinking 用 temp=0.6/top_p=0.95/presence_penalty=0.0，non-thinking 用 temp=0.7/top_p=0.80。Thinking Preservation 则是更精细的一刀：传统多轮 agent 流程中每一轮都要重算或复述思考过程，该特性让历史思考上下文得以延续，直接削减迭代开发的 token 开销。注意其机制（裁剪还是压缩策略）未公开，属后训练/API 行为层特性而非架构改动。

### 2.5 原生多模态

**术语定义**：单模型内置 Vision Encoder（pipeline tag: image-text-to-text），预训练与后训练全部完成；纯文本部署可用 `--language-model-only` 跳过视觉编码器，省显存换 KV cache。

**拆解**：多模态不是外挂而是原生属性——VL 基准成绩（第四章）证明这不是「能看个大概」的装饰品。而 `--language-model-only` 开关的设计体现了对两类用户群的诚实：需要视觉的用户拿到完整能力，不需要的用户不必为视觉编码器支付常驻显存。这种「全能力默认 + 按需裁剪」的交付方式，是小显存部署场景的务实解法。

### 2.6 Agentic 生态兼容矩阵

**术语定义**：官方推荐四条接入路径——Qwen-Agent（推荐框架，支持 MCP 配置）、OpenClaw（前称 Moltbot/Clawdbot）、Claude Code 兼容、Qwen Code（深度优化 Qwen 系列的终端开源 agent）。

**拆解**：兼容 Claude Code 是其中信号最强的一条——它意味着模型的行为接口对齐了事实上的 agent 工具标准，用户可以零迁移成本把现有工作流的后端换成这枚开源钢炮。加上 Thinking Preservation 这类专为迭代开发设计的特性，整份发布的靶心始终锁定在「开发者把它当生产力工具」的场景上。

> **一句话小结**：六个概念构成一条自洽的效率链——MoE 解耦容量与计算（2.1），混合注意力解耦记忆与检索（2.2），MTP 再砍一刀解码成本（2.3），双模式与 Thinking Preservation 管理推理开销（2.4），原生多模态扩大适用面而不强制付费（2.5），生态兼容矩阵保证能力可触达（2.6）。

## 三、方法拆解：一条「架构—加速—行为—部署」的完整技术体系

### 3.1 架构侧逐参数还原：35B 与 3B 各自从哪来

完整架构参数表（[HF] Model Overview）：hidden dimension 2048，词表 248,320（padded），40 层，混合布局如 §2.2，MoE 256 专家/激活 8+1/专家中间维 512，上下文 262,144（可扩展至 1,010,000）。

**总量守恒的粗略核算（推断）**：单个专家为标准 SwiGLU FFN，参数 ≈ 3 × 2048 × 512 ≈ 3.15M；256 个专家 × 3.15M ≈ 806M/层，40 层合计 ≈ 32.2B——这就是「总参 35B」的主体。每 token 实际走的 9 个专家 ≈ 28.3M/层 × 40 ≈ 1.13B，加上全注意力 10 层投影（约 190M）、DeltaNet 30 层投影（约 600M–750M）、嵌入与输出层（约 0.5–1B），合计落在 3B 附近——「激活 3B」的账目大致闭合。换言之：**约 92% 的参数沉睡在未激活专家里充当知识库，每个 token 只唤醒不到 4%**。（推断，官方未给分解）

这套参数还有两个值得注意的细节：其一，词表 248,320 明显大于常见规模，服务多语言与代码 token 的细粒度切分；其二，RoPE dim 只占 head dim 256 的 64 维，剩余维度可能承载其他位置编码方案或留给扩展上下文的外推机制——后者官方未说明（是否 YaRN 类方法未披露）。

### 3.2 加速侧：长上下文 + 投机解码的双引擎

- **长上下文**：原生 262,144 tokens 直接覆盖绝大多数仓库级任务（评测协议中 SWE-bench 即用 200K 上下文运行），标称可扩展至 **1,010,000** tokens——逼近百万级。实现方式未披露，但「原生即 256K」意味着无需外推技巧即可获得生产级长文本能力。
- **投机解码**：MTP 头预训练自带（非事后补训），vLLM/SGLang 的官方 Quickstart 直接给出可用配置。对部署者而言这是零成本的吞吐红利：同样的硬件，同样的模型权重，解码速度因配置而异。

两者的合力指向同一个 KPI：**单位时间内的有效 token 吞吐**。agent 工作流动辄数十轮调用，每轮数千 token，吞吐直接决定任务完成时长与 API 成本。

### 3.3 行为侧：三种采样档位与思考管理

官方推荐采样参数构成一张「场景—参数」映射表：

| 场景 | temperature | top_p | top_k | presence_penalty |
|---|---|---|---|---|
| 通用 thinking | 1.0 | 0.95 | 20 | 1.5 |
| 精确编码/WebDev thinking | 0.6 | 0.95 | — | 0.0 |
| non-thinking | 0.7 | 0.80 | — | — |

（推断）这张表本身就是行为层方法论的一部分：通用场景的高温度 + 强 presence_penalty 鼓励探索防止复读；编码场景降温度求确定性；non-thinking 档进一步收紧分布。Thinking Preservation 补足多轮场景——思考上下文跨轮保留，避免每轮重新推理相同前提。

### 3.4 部署侧：一套权重三种形态

同一份 Apache 2.0 权重对应三条消费路径：① 开放权重下载（HF + ModelScope），自托管全控制；② Qwen Studio 在线体验，零门槛试用；③ Model Studio API（模型名 `qwen3.6-flash`，发布时标注 coming soon），按量付费。加上 `--language-model-only` 的显存裁剪开关，从个人显卡到云端集群都有对应的落点。这种「一份训练投入、多形态回收」的分发策略，是开源权重商业化的标准打法，Qwen 在此执行得相当完整。

> **一句话小结**：方法体系没有单点黑科技，而是一组互相放大的工程决策——稀疏 MoE 定成本基线，混合注意力定长上下文基线，MTP 定吞吐上限，行为层参数定使用体验，分发形态定触达面；全部选择一致地服务于「agentic coding 钢炮」这一个定位。

## 四、证据链：两张基准表的逐组解读与协议审计

### 4.1 Coding Agent 组（10 项）：主战场近乎全胜，唯余一处暗点

| 基准 | Qwen3.5-27B | Gemma4-31B | 旧 35BA3B | Gemma4-26BA4B | **本模型** |
|---|---|---|---|---|---|
| SWE-bench Verified | **75.0** | 52.0 | 70.0 | 17.4 | 73.4 |
| SWE-bench Multilingual | **69.3** | 51.7 | 60.3 | 17.3 | 67.2 |
| SWE-bench Pro | **51.2** | 35.7 | 44.6 | 13.8 | 49.5 |
| Terminal-Bench 2.0 | 41.6 | 42.9 | 40.5 | 34.2 | **51.5** |
| Claw-Eval Avg | 64.3 | 48.5 | 65.4 | 58.8 | **68.7** |
| Claw-Eval Pass^3 | 46.2 | 25.0 | **51.0** | 28.0 | 50.0 |
| SkillsBench Avg5 | 27.2 | 23.6 | 4.4 | 12.3 | **28.7** |
| QwenClawBench | 52.2 | 41.7 | 47.7 | 38.7 | **52.6** |
| NL2Repo | 27.3 | 15.5 | 20.5 | 11.6 | **29.4** |
| QwenWebBench (BT/Elo) | 1068 | 1197 | 978 | 1178 | **1397** |

逐行解读：

1. **SWE-bench 三连是唯一没有拿下第一的编码子组**：Verified 73.4 vs 自家 dense 27B 的 75.0（差 1.6），Multilingual 67.2 vs 69.3，Pro 49.5 vs 51.2。三线皆负但差距都在 2 分以内——官方叙事对此的处理是强调「超过旧代 35BA3B」（+3.4/+6.9/+4.9），回避与 dense 旗舰的正面对比。这是全文最诚实也最微妙的数据区。
2. **Terminal-Bench 2.0 的 51.5 是全场最大领先**：超出第二名 Gemma4-31B（42.9）达 **8.6 分**。终端任务是纯 agentic 能力试金石（多轮命令执行、环境交互、错误恢复），此处的断层式领先是「agentic coding 升级」主张的最硬证据。且该评测协议相当克制（3 小时超时、32 CPU/48GB 资源上限、5 次运行取平均）。
3. **SkillsBench 28.7 vs 旧代 4.4 的六倍跳变**：旧代在此几乎失效（4.4），新代跃居第一。78 个自包含任务经 OpenCode 评测、5 次平均，协议透明。这一项最能说明「同一规格、两代模型」的能力代差。
4. **QwenWebBench 1397 Elo 领先次优 200 分**：内部前端代码生成基准，覆盖 Web Design/Web Apps/Games/SVG/数据可视化/动画/3D 七类，自动渲染 + 多模态裁判。领先幅度巨大，但它是内部基准且 BT/Elo 计分制与百分制不可比——说服力打折（见第五章）。

### 4.2 General Agent 组（7 项）：并非通吃

TAU3-Bench 67.2（旧代 68.9 更高）、VITA-Bench 35.6（Gemma4-31B 达 43.0）、Tool Decathlon 26.9（27B 达 31.5）三项均非第一；DeepPlanning 25.9、MCPMark 37.0、MCP-Atlas 62.8、WideSearch 60.1 四项第一。**7 项中 4 胜 3 负**，且输的项目集中在对通用对话式 agent 能力的考察上。这与「钢炮」定位自洽：资源向编码 agent 倾斜，通用 agent 能力做到强但不追求登顶。（推断）MCPMark 37.0 约为 Gemma4-31B 两倍的差距尤其值得注意——MCP 工具集成恰是 coding agent 与外部世界连接的管道，此项强势与主战场优势互相印证。

### 4.3 Knowledge & STEM 组（9 项）：知识持平，数学微胜

MMLU-Pro 85.2（vs 27B 的 86.1）、C-Eval 90.0（vs 90.5）微幅落后——知识面基本持平而非超越。SuperGPQA 64.7、MMLU-Redux 93.3 亦居次。但 GPQA **86.0** 与 AIME26 **92.7** 两项登顶（后者用完整 AIME 2026 I+II 口径，官方特意注明分数可能与 Qwen3.5 笔记不同口径），HMMT Feb 26 83.6 同样第一。LiveCodeBench v6 80.4 以 0.3 分之差居次（27B 为 80.7）。HLE 21.4 显著低于 27B 的 24.3——人类终极考试类的高难推理仍是 dense 旗舰的优势区。

整体判读：**知识与高难科学推理「够用但不封顶」，竞赛数学意外强势**。对一枚主打编码的钢炮而言，这个知识面配置是合理的取舍。

### 4.4 视觉语言表：平 Claude Sonnet 4.5，空间智能反超

六列对照中含 Claude-Sonnet-4.5 参比列。22 项 VL 基准的本模型值与要点：

- **与 Claude Sonnet 4.5 的正面对比多数占优或持平**：MMMU-Pro 75.3 vs 68.4（+6.9）、RealWorldQA 85.3 vs 70.3（+15.0）、CC-OCR 81.9 vs 68.1（+13.8）、OmniDocBench1.5 89.9 vs 85.8、MLVU 86.2 vs 72.8（+13.4）；MMMU 81.7 vs 79.6 微胜，HallusionBench 69.8 vs 59.9 大幅领先。
- **与自家上代 27B 相比互有胜负**：SimpleVQA 58.9 反超（56.0），ZEROBench_sub 34.4 微逊（36.2），CharXiv(RQ) 78.0（79.5）、LVBench 71.4（73.6）、RefSpatialBench 64.3（67.7）微降。
- **空间智能是最亮眼的反超区**：RefCOCO(avg) **92.0**（上代 90.9）、ODInW13 **50.8**（上代 41.1，**+8.2**）。官方将「多数 VL 基准持平 Claude Sonnet 4.5、空间智能反超」作为 VL 部分的总结论，数据支持这一表述。

（推断）ODInW13 的 +8.2 跳变幅度在成熟基准上并不常见，提示 3.6 代可能在视觉定位/检测类数据的配比上有针对性加强；而 RefSpatialBench 的回落说明「指代定位」与「空间关系推理」并非同步进步。

### 4.5 评测协议脚注审计：11 条脚注透露了什么

协议细节整体规范度较高，几处值得点名：

- **公平性加分项**：SWE-bench Pro 官方修正了公开集的部分问题任务，且**所有基线在修订版上重评**——避免了「自己用修正版、对手用原版」的经典不公平；Terminal-Bench 五次平均降低方差；SkillsBench 明确剔除依赖特定 API 的任务。
- **裁判依赖披露清晰**：VITA-Bench 裁判换用 claude-4-sonnet（原 claude-3.7-sonnet 不可用）、MCP-Atlas 用 gemini-2.5-pro 裁判、TAU3-Bench 用户模拟用 gpt-5.2（low reasoning effort）——裁判与用户模型全部来自竞品/第三方阵营，这一点诚实且降低了「自家裁判偏袒自家模型」的风险，但 LLM-as-judge 本身的系统性偏差仍在。
- **两处口径提醒**：NL2Repo 其余模型经 Claude Code harness 评测（max_turns=900）而本模型的 harness 未明说是否相同；AIME26 口径变化被显式声明。前者属潜在混淆变量。

### 4.6 独立侧写交叉参照

## 五、批判性分析：成绩单的另一面

### 5.1 官方表格内的相对短板（作者可见而不强调处）

1. **SWE-bench 三线皆负于自家上代 dense 27B**（差 1.6–2.1 分）：「以小胜大」的核心叙事在这条最权威的编码基准线上并未成立——成立的版本是「以小接近大、大幅超越同规格旧代」。对选型者而言，若 SWE-bench Verified 是唯一考量，dense 27B 仍略优。
2. **HLE 21.4 vs 24.3**：高难推理的天花板差距明显，且对比列中 Gemma4-26BA4B 低至 8.7，说明该项分化极大、模型间差异真实存在。
3. **General Agent 组 3 项失守**：TAU3/VITA/Tool Decathlon 分别落后旧代 35BA3B、Gemma4-31B、27B——「agentic 全面领先」应限定为「coding agent 领先」。
4. **Pass^3 口径下的稳定性隐忧**：Claw-Eval Pass^3 50.0 vs 单次均值 68.7，三次连续通过率掉近 19 分，说明任务成功率仍有相当的波动性（所有对比模型同样如此，46.2/25.0/51.0/28.0）。

### 5.2 未披露项清单及其含义

训练数据构成/token 量/算力成本、后训练配方（RL 算法、奖励设计、数据规模）、Vision Encoder 参数量与结构、百万上下文的实现机制、Thinking Preservation 内部策略、API 定价限速——**全部未披露**。这份发布是「能力结果展示」而非「技术报告」：读者知道模型做到了什么，无从知晓怎么做到。对工程使用者影响有限（权重在手可直接测），但对研究者而言无法从中提取可复现的训练方法论——这也是权重卡形态与论文形态的本质区别。

### 5.3 内部基准的可信度边界

QwenWebBench（1397 Elo，领先次优 200 分的最大亮点之一）、QwenClawBench、Claw-Eval 三项均为内部基准：无第三方复现，QwenClawBench 标注 "open-sourcing soon" 但截至提取日未见放出。它们贡献了官方叙事中最惊人的数字（Elo 断层、两倍 MCP 差距），却恰恰处在最不可独立验证的位置。（推断）合理的处理方式是把这三项视为「方向性强信号、绝对值存疑」，等开源后再校准预期。

### 5.4 基线选择的叙事策略

四个基线全是开源同级模型，无任何 2026 年闭源旗舰入场。这在营销上是安全的——「rivaling much larger dense models」在池内成立；但它回避了真正的问题：与 Claude/GPT 系列的 coding agent 能力差距是多少？VL 表拉来 Claude-Sonnet-4.5 作参比列的做法反而凸显了这个缺席——视觉侧敢比闭源旗舰，语言 agent 侧不敢，两相对照耐人寻味。（推断）

### 5.5 「3B 激活 rival dense 27B」的边界条件

这句 headline 的成立依赖三个未明说的条件：① 任务域限定——在编码 agent 上成立（Terminal-Bench/NL2Repo/MCPMark 等），在高难知识推理（HLE）与部分通用 agent 任务上不成立；② 对比口径限定——比较的是**总参不同的模型**（35B 稀疏 vs 27B dense），若按「等激活参数 dense」比较则无从谈起，若按「等总参」比较则稀疏方还多了 8B 容量；③ 部署场景限定——3B 激活的优势要在批量服务/显存受限场景才能兑现，单请求延迟上 dense 小模型未必吃亏。正确的读法是：**「同等 agent 编码能力下，推理成本低一个量级」**，而非「3B 模型打败 27B 模型」。

> **一句话小结**：批判火力应集中在四处——SWE-bench 主线未胜 dense 旗舰、内部基准无第三方验证、闭源基线缺席、以及「以小胜大」叙事的条件性；但这些都动摇不了一个扎实的事实内核：**同规格代际跃升真实存在，编码 agent 主战场的领先有协议较严谨的公共基准背书**。

## 六、启示与影响：对开源生态与工程实践的意义

### 6.1 五条可迁移启示

1. **「稀疏 + 混合注意力」是中杯 agent 模型的成熟答案**：3:1 线性/全注意力混合 + 极窄激活 MoE + 多步 MTP 的组合拳，在本节点拿到了完整的基准验证。对任何要造「长上下文 + 多轮工具调用」底座的团队，这是一套可以直接抄的架构配方——其本质是把三类成本（每 token 计算、每序列记忆、每输出 token 解码）分别交给 MoE、线性注意力、MTP 三种机制各管一项。
2. **agent 能力可以被「定向投放」**：同规格两代模型对比显示，SkillsBench 从 4.4 到 28.7、Terminal-Bench 从 40.5 到 51.5 的跃升说明 agent 能力是后训练与迭代的函数，而非纯粹由规模决定。（推断）这对资源有限的团队是好消息：与其堆参数，不如把迭代预算精准投向目标工作负载。
3. **Thinking Preservation 点出 agent 成本的隐藏大头**：多轮 agent 流程中重复推理的开销常被忽视，保留思考上下文是一个产品级创新点。类似思路可推广到任意 agent 框架的会话管理设计——缓存的不只是 KV，还有推理结论本身。
4. **评测协议的规范性值得效仿**：修正版 SWE-bench Pro 全基线重评、五次平均、裁判模型来自第三方阵营、口径变化显式声明——这些细节构成了「可信的自评报告」模板，任何发布基准数据的团队都可以对照检查。
5. **「权重开源 + API 待上 + 在线体验」三轨分发是开源商业化的标准解**：Apache 2.0 权重建立生态信任，coming soon 的 API 留出商业化接口，在线体验降低尝鲜门槛。三者共享一份训练投入。

### 6.2 观察点与局限走向

- **qwen3.6-flash API 的落地表现**：定价与限速公布后，「$0.25/M 级别的编码 agent 能力」若坐实，将对中小模型 API 市场形成直接冲击；
- **内部基准的开源兑现**：QwenClawBench 承诺的 open-sourcing 是否兑现、第三方能否复现 1397 Elo，是检验本发布可信度的试金石；
- **Vision Encoder 信息补全**：当前一手文档完全缺失视觉塔细节，后续技术报告若补齐，方能评估其多模态路线的独立性；
- **与闭源旗舰的真实差距**：待独立评测机构将其纳入与 Claude/GPT 系列的同台对比，方能给「开源 coding agent 天花板」一个准确定位。

## 总结

《Qwen3.6-35B-A3B》是一份目标极其清晰的发布：不做全能王，只做「开源世界里跑得动的最强编码 agent 底座」。它的技术体系——3:1 混合注意力、256 选 8+1 的极窄激活 MoE、多步 MTP、双模式与 Thinking Preservation——全部服务于同一个效率命题，并在主战场上交出了可验证的成绩：Terminal-Bench 2.0 五模型最高 51.5、NL2Repo 29.4、MCPMark 37.0、GPQA/AIME26 登顶、VL 面平 Claude Sonnet 4.5 且空间智能反超（RefCOCO 92.0 / ODInW13 50.8）。它的暗面同样清晰：SWE-bench 三线未胜自家 dense 旗舰、General Agent 组非通吃、HLE 有天花板差距、训练配方零披露、三个内部基准无第三方验证、基线池不含闭源旗舰。正确的打开方式是把它当作一个**条件成立的效率命题**——「在开源同级池内，3B 激活在编码 agent 上打平乃至超越数倍激活的 dense 模型，同时把推理成本压低一个量级」——这个命题成立且有数据支撑；而任何把它泛化为「3B 打败 27B」「开源追平闭源」的读法，都超出了证据所能支撑的范围。
