## §4 方法要点

1. **两阶段 RL 扩缩**：
   - **阶段一（数学 + 编码）**：从 cold-start checkpoint 出发，纯 outcome-based reward。数学用**准确率验证器**（accuracy verifier，只验最终答案正确性）；代码用**代码执行服务器**判定是否通过预定义测试用例。显式弃用传统神经 reward model，杜绝 reward hacking 的主要来源。随训练 episode 推进两域性能持续上升。
   - **阶段二（通用能力）**：少量步数的通用 RL，reward 来自通用 reward model + 若干规则验证器混合。效果：指令遵循、人类偏好对齐、agent 性能提升，且数学/编码无明显回退。
2. **基座假设**：RL 的收益以强预训练基座为前提（"robust foundation models pretrained on extensive world knowledge"）——小模型 + 强 RL ≠ 弱基座 + 强 RL。
3. **Agentic 推理融合**：将工具使用（tool use）纳入推理过程，模型"边思考边调用工具、依据环境反馈调整推理链"。
4. **推理形态**：长思维链生成（示例 max_new_tokens=32768），API 侧分离 `reasoning_content` 与最终 `content`。

## §5 评测结果要点

- **对标逻辑**：核心叙事是"32B ≈ 671B(37B active)"——AIME24 仅差 0.3 分（79.5 vs 79.8），LiveCodeBench 差 2.5 分，LiveBench 反超 1.5 分，IFEval 基本打平，BFCL 反超 6.1 分。
- **对 distilled 系碾压**：全面领先 R1-Distill-Qwen-32B（72.6 AIME24）与 R1-Distill-Llama-70B（70.0），说明自产 RL 路线优于"大模型蒸馏小模型"路线。
- **对 o1-mini 全面领先**：除 IFEval（83.9 vs 84.8）外全部占优。
- **弱项**：数学（AIME24）与代码（LiveCodeBench）仍略逊 R1 满血；IFEval 未超 o1-mini。
- **评测协议备注**：官方 eval README 建议 AIME24/25 采样 64 次、LiveCodeBench 8 次、IFEval 1 次（pass@1 口径下的重复采样均值）。
