## §4 方法细节
- **动机与对照**：BrowseComp 类基准靠人工整理、成本高规模小无法用于训练；已有开源训练数据要么规模不足要么过简。既有两条路线——graph-based（WebSailor/WebShaper 显式构图+子图选 QA）与 evolution-based（迭代注入新信息加长 query），前者节点扩展与选择启发式复杂，后者易产生不自然表述。
- **Model-Based Exploration**：不做显式图构建（对比 WebSailor/WebShaper 的 graph-based 方法），仅用 prompt 让强 LLM 以 ReAct 方式从种子实体（来自 Wikipedia）出发迭代 search+browse 自主构建信息空间，模型自行决定何时停止并合成需跨多网站的初始 QA。示例：种子 "Brazil National Team" 经 1950 世界杯→裁判 George Reader→Southampton→1976 FA Cup→Bobby Stokes 多跳串联成题。
- **Iterative Query Evolution（长到短）**：区别于以往"注入新信息变长"的 short-to-long 进化，反方向删减——(1) 移除显著线索 (2) 对日期/地点/专名做模糊化 (3) 用替代描述替换显式引用（如 Manchester United→First Division giant），答案不变；每轮进化继续补充探索信息空间（式 3）。合成 prompt 以 BrowseComp-en 的 3 条 exemplar 为范例。
- **SFT 冷启动**：用商业模型 rejection sampling 只保留正确轨迹；ReAct 格式，<think>/<tool_call>/<tool_response> 标签。
- **RL**：GRPO 直接用合成 QA（无需轨迹示范）；format 奖励保结构正确，accuracy 由 DeepSeek-V3 LLM-as-Judge 判定；训练中渐进放宽长度与轮数上限。
- **Scaffold**：两工具——search 返回 Google top-10（标题/URL/snippet）；browse 用 Jina 抽取网页全文 + Gemini 2.5 Flash 按 browse query 作答（Appendix C）。
- **ReAct 形式化**：轨迹 H_T = (τ0, α0, o0, ..., τ_T)，动作 α_t ∈ {search, browse}，α_t = (类型, 参数)；search 参数为 query 列表，browse 参数为 URL+抽取目标。

## §5 实验结果要点
- 8B 规模 SOTA：BC-en 15.7 / BC-zh 32.0，超过 72B 的 WebSailor（12.0/30.1）甚至更大体量 Kimi-K2（14.1/28.8）；<10B 内全榜单第一。
- WebWalkerQA 62.7 超 WebShaper-72B 达 10 个绝对点；FRAMES 75.7 为 <100B 开源最佳。
- 泛化性：训练数据全部为 Wikipedia 类知识型 QA，却在 STEM 为主的 HLE 上得 17.3%，超 ASearcher-Web-QwQ 与 WebThinker-32B（均 12.5/15.8 附近），验证难查询训练的迁移价值。
- RL 动力学发现：tool calls 数与 benchmark 分数同步增长（BC-en 7.9→15.7），类比单轮数学 RL 的 long CoT 涌现，说明长程 agentic search 能力可由 RL 持续扩展。

- 对比专有模型：OpenAI-o3 在统一 scaffold 下 BC-en 50.9 / GAIA 70.5，Claude-4-Sonnet BC-en 仅 12.2（与 WebExplorer-8B 相当），说明开源 8B 已逼近部分旗舰闭源水平。
- GAIA 采用 103 样本 text-only 验证子集（沿用 WebShaper 口径）；所有分数 Avg@4 + LLM-as-Judge。
- 进化前后分布对比：4 turns 内易解样本比例显著下降（Figure 4 左），Evolved QA 的 turns 分布已接近 BrowseComp-en。

## §6 局限
- Evolved QA 与 BrowseComp-en 的 tool calling turns 分布仍有差距（Figure 4 右），作者认为完全对齐 BrowseComp 难度对当前开源模型非必要。
- 训练语料限于知识型 QA（Wikipedia 种子），未覆盖 STEM/多模态检索场景。
- 基线可比性瑕疵：MiroThinker 使用 search/browse 之外的额外工具，scaffold 不完全对齐（§4.1）。
- 无独立 Limitations 章节；评测依赖 LLM-as-Judge（DeepSeek-V3）而非人工核验。
- 团队归属：HKUST（刘俊腾、何俊贤）与 MiniMax 合作，Wenhu Chen（Waterloo）参与；代码开源 github.com/hkust-nlp/WebExplorer，模型定位为低成本长程 web agent 的可行路径，全部评测于统一 search/browse scaffold 下完成。
