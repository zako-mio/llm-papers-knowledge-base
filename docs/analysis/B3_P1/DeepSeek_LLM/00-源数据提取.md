## §4 方法细节

### 4.1 数据管线（§2.1 p4）

- 三阶段：**去重（deduplication）→ 过滤（filtering）→ 重混（remixing）**。去重采用跨全部 91 个 CC dump 的激进策略；过滤结合语言学与语义双视角评估文档质量、提高信息密度；重混向上采样不足领域以平衡分布。
- Tokenizer：BBPE（Huggingface tokenizers 库），pre-tokenization 阻止换行/标点/CJK 跨类合并（仿 GPT-2）；数字逐位切分（仿 LLaMA）。词表 100000 常规 + 15 特殊 = 100015，训练配置 vocab_size=102400。

### 4.2 架构与训练规格（§2.2-2.4 p5-6）

- 微观沿用 LLaMA：Pre-Norm + RMSNorm、SwiGLU（中间维 8/3·d_model）、RoPE。宏观差异：7B 用 30 层（常见为 32）、67B 用 **95 层**（加深而非加宽 FFN），便于流水线切分并换取更好性能。
- 67B 采用 GQA（64 heads / 8 kv_heads）。7B：n_layers=30, d_model=4096, batch 2304, lr 4.2e-4；67B：n_layers=95, d_model=8192, batch 4608, lr 3.2e-4；均训 2T tokens、上下文 4096（Table 2 p5）。
- 优化器 AdamW（β1=0.9, β2=0.95, weight_decay=0.1），初始化 std 0.006，梯度裁剪 1.0。
- **Multi-step LR scheduler**：2000 步 warmup 至峰值 → 训练 80% tokens 后降至 31.6% → 90% 后降至 10%。最终性能与 cosine 基本一致（1.6B/100B tokens 对照实验，Fig.1a p6），但改训练规模时可复用第一阶段，利于 continual training；阶段比例 80%/10%/10% 为复用与性能折中（Fig.1b）。
- 基础设施：HAI-LLM 框架集成 DP/TP/SP/1F1B PP；FlashAttention；ZeRO-1 切分优化器状态；bf16 计算 + fp32 梯度累积；in-place cross-entropy（CUDA 核内 bf16 logits→fp32 即时转换再覆写）省显存；每 5 分钟异步存档；支持跨 3D 并行配置续训。评测用 vLLM（生成任务）。

### 4.3 Scaling Laws 方法论（§3 p7-12）

- **超参缩放律**：先在 1e17 FLOPs 网格搜索 batch/lr，发现泛化误差对二者均不敏感（宽平稳区）；再用 multi-step scheduler 复用第一阶段，在 1e17–2e19 多预算下重复实验，取误差≤最小+0.25% 的参数为"近优"，拟合出幂律式(1)。在 1e20 FLOPs 上验证拟合参数居最优区中心（Fig.2b）。
- **模型/数据缩放律**：以 M（含注意力开销、不含 vocab 开销的非嵌入 FLOPs/token）替代 N，C≈MD 消除近似误差；沿用 Chinchilla 的 IsoFLOP profile 法，8 个预算档 × 每档约 10 种配比，泛化误差用 100M token 同分布验证集 bits-per-byte 度量，得式(4) 并外推预测 7B/67B。
- **数据质量消融**：early in-house / current in-house / OpenWebText2 三套数据分别拟合，得到 C4 结论。

### 4.4 对齐流程（§4 p12-13）

- 指令数据约 150 万实例（中英）：helpful 120 万（通用语言 31.2% / 数学 46.6% / 代码 22.2%）+ 安全 30 万。
- SFT：7B 4 epochs（lr 1e-5），67B 仅 2 epochs（lr 5e-6）——67B 很快触顶且过拟合严重。监控指标除基准分外加入**重复率**（3868 条中英 prompt 中无法终止、无限复读的比例）。
- 7B 采用两阶段微调：stage1 全量数据 → stage2 剔除数学/代码只用对话数据；67B 只做一阶段。
- DPO：helpful/harmless 双线构造偏好数据，候选回复由自家 Chat 模型生成；1 epoch、lr 5e-6、batch 512、warmup+cosine。结论：提升开放式生成，标准基准几乎不变。

### 4.5 评测协议（§5.1 p13-14）

- 选择题用 perplexity 法（ARC/OpenBookQA 用无条件归一化，其余长度归一化）；TriviaQA/NQ/DROP/MATH/GSM8K/HumanEval/MBPP/BBH/AGIEval 等用贪心解码生成式评测；Pile-test 报 bits-per-byte。
- 开放评测：中文 AlignBench（8 大类 36 子类 683 题，GPT-4 判分；角色扮演/写作/开放问答温度 0.7，其余 0.1）；英文 MT-Bench；held-out 用 2023 年 7 月后的 LeetCode 周赛（Weekly 351-372 + BiWeekly 108-117，126 题）、匈牙利高中数学考试（33 题人工评分）、Google IFEval（25 类可验证指令约 500 prompt，loose 口径）。
- 安全：20 人专家团队建五类分类体系（歧视偏见/侵权/商业秘密与知产/违法违规/其他），诱导、角色扮演、多轮、预设立场等多样化提问方式（防"grandmother"漏洞），共 2400 测试题，safe+拒绝均计为安全。

### 4.6 Discussion 四项工程发现（§5.5 p21-22）

1. **Staged fine-tuning**：小模型需要更长数学/代码微调但伤对话能力 → 第二阶段纯对话数据修复（重复率降、IFEval 升、代码/数学分不动）。
2. **MC 数据**：+2000 万中文多选题使 MC 基准暴涨但对生成式评测无效 → 从预训练与微调中全部剔除，拒绝"刷榜"。
3. **预训练末期掺指令数据**（末 10% 掺 500 万指令，主要为 MC）：base 基准提升但与同数据放 SFT 阶段效果几乎相同 → 不采用。
4. **System prompt**：67B 显著受益（+0.23 MT-Bench），7B 反而受损——大模型才能理解 system prompt 的意图。

## §5 实验结果要点

- **Base 主表（Table 5 p15）**：英文理解类与 LLaMA2 打平或互有胜负（HellaSwag 84.0 平；RACE-High 50.7 vs 54.3 落后；TriviaQA 78.9 vs 79.5 接近）；优势集中在 MATH/GSM8K/HumanEval/MBPP/BBH/AGIEval 及全部中文任务。语言冲突对小模型的伤害更大：67B 对 70B 的领先幅度 > 7B 对 7B。LLaMA2 未训中文却在 CMath 达 53.9，说明基础数学能力可跨语言迁移；成语类 CHID 则必须靠中文预训练量（55.5 vs 92.1）。
- **Chat 对比（Table 6 p16）**：数学/代码大涨（GSM8K 63.4→84.1、MATH 18.7→32.6、HumanEval 42.7→73.8，0-shot 达到 base few-shot 水平）；知识类波动视为噪声；cloze/补全类（HellaSwag 84.0→75.7）一致性下降属预期；AGIEval 曾跌至 19.3 后经调整恢复。作者判断 SFT 学的是推理格式而非推理能力本身。
- **Scaling 涌现**：同一数据下 67B 的 GSM8K/BBH 远高于 7B，归因于大模型 few-shot 能力；但随着数学数据占比提高，大小模型差距会缩小。
- **AlignBench（Table 7 p17）**：67B-Chat-DPO 总分 6.69，中文语言总分 7.60 超过 gpt-4-0613 的 7.59；中文推理显著领先其他国产模型。
- **MT-Bench（Table 8 p18）**：67B Chat 8.35 → DPO 后 8.76，Reasoning 维度 8.00→9.05 提升最大。
- **Held-out（Table 9 p19）**：印证"总算力决定新题表现"；ChatGLM3 MBPP 52.4 接近 67B 但 LeetCode 仅 2.4。
- **消融（Appendix A.5 p32）**：DPO 阶段对标准基准影响很小，主要作用于开放域。

## §6 局限

- 论文自述（§6 p23）：① 预训练截止后知识无法更新；② 可能生成幻觉与非事实内容（如未经验证的建议）；③ 初版中文语料不够全面，部分中文话题表现欠佳；④ 语料以中英为主，其他语言能力脆弱。
- 方法层面（作者承认的 open questions）：超参缩放律尚未考虑 C 之外因素的影响（如模型/数据配比对最优参数区的扰动，§3.1 p9）；不同数据集上最优超参空间略有漂移，留待后续研究。
- 评测口径提示：Chat 模型在 MMLU/GSM8K/MATH/C-Eval/CMMLU 用 0-shot 而 base 用 few-shot，两表数字不可直接横比；AlignBench/Do-Not-Answer 中带 * 的分数为官方仓库自测，其余转引自原论文。
