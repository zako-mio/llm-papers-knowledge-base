## §4 方法细节

### 4.1 背景：标准实现与 FlashAttention 回顾（§2 p3-5）

- 标准实现将 S=QK^T、P=softmax(S) 物化到 HBM（O(N²) 内存），三步 GEMM-softmax-GEMM 受内存带宽限制；反向还需保存 P。
- FlashAttention：tiling 分块加载 HBM→SRAM + online softmax（逐块算局部 softmax 并重缩放：维护 m(j)=rowmax、ℓ(j)=rowsum(e^{S-m})，输出按 diag(ℓ)^{-1} 缩放合并）避免中间矩阵落 HBM；反向在 SRAM 内重算 S/P 免存储。前向 2 个 matmul、反向 5 个 matmul。

### 4.2 FlashAttention-2 算法改动：削减非 matmul FLOPs（§3.1 p5-7）

1. **延迟缩放**：不再每次迭代都对输出两项乘 diag(ℓ^{(j)})^{-1}，而是维护"未缩放"输出 Õ 并保留统计量，循环结束后一次性 O_i = diag(ℓ^{(Tc)})^{-1}·Õ_i；
2. **只存 logsumexp**：反向只需 L = m + log(ℓ)，替代同时保存 m 与 ℓ（Algorithm 2 中 P = exp(S − L)）。
- 复杂度不变：精确输出、O(N²d) FLOPs、O(N) 额外内存。

### 4.3 因果掩码优化（§3.1.1 p6）

- 块级跳过：列索引全大于行索引的块直接不计算（长序列时约省一半）；
- 对角块处理：行索引严格小于列索引的块无需 mask，每行只需对 1 个对角块应用 causal mask（方阵块假设）。

### 4.4 并行化改造（§3.2 p7-8）

- **前向**：外层循环改为按序列长度（行块）遍历——各 thread block 独立处理一个 Q 行块（embarrassingly parallel，无需通信），叠加 batch/head 维并行。长序列（小 batch·heads，总 thread block 数 <108 SM 时）占用率大幅提升。（交换内外循环+序列维并行的思路由 Phil Tillet 在 Triton 实现中首创，本文吸收进 CUDA 实现。）
- **反向**：唯一跨列块共享的计算是 dQ 更新，故按列块并行调度 thread block，dQ 用 atomic adds 跨块累加。

### 4.5 Warp 级工作划分（§3.3 p9）

- 前向：FA 用 split-K（K、V 按 warp 切分、Q 共享）→ 每个 warp 算出部分 QK^T 后须写共享内存、同步、求和；FA2 改为 Q 按 warp 切分、K/V 全 warp 共享 → 每 warp 直接得到自己的输出切片，零 warp 间通信。
- 反向：同样避开 split-K；因 Q/K/V/O/dO/dQ/dK/dV 依赖更复杂仍需少量同步。
- Block size：通常取 {64,128}×{64,128}，权衡共享内存读写量 vs 寄存器压力/spill；按 head dim 手工调优（仅 4 种组合），auto-tuning 留作 future work。

### 4.6 MQA / GQA 支持（§3.1.2 p7）

- 多查询/分组查询注意力下多个 query 头共享同一 KV 头；实现上不物理复制 KV 头，而是隐式操作头索引；反向对被隐式复制的头间求和 dK、dV。

### 4.7 基准口径（§4 p9-10）

- 硬件 A100 80GB SXM4（另含 H100 SXM5 图）；序列长 512–16k，固定总 token 数 16k 定 batch；hidden dim 2048，head dim 64（32 头）/128（16 头）。
- FLOPs 口径：前向 4·seqlen²·head_dim·num_heads（causal 除以 2）；反向 ×2.5（前向 2 matmul : 反向 5 matmul 含重计算）。端到端沿用 Megatron-LM 公式 6·seqlen·params + 12·layers·hidden·seqlen²（attention 项不折半，保持文献一致性）。
- 对比对象：PyTorch 标准实现、FlashAttention 原版、xformers/cutlass 版 FA、Triton 版 FA。

## §5 实验结果要点

1. **内核基准（Figure 4/5/6 p10-12）**：四个设置（±causal × head_dim 64/128）全面领先。代表性数字：
   - 无因果掩码 d=128 前向：FA2 223-227 TFLOPs/s（FA 仅 71-73，xformers 122，Triton 160-163）；
   - 有因果掩码 d=64 前向：FA2 171-183（FA 92-97）；
   - 反向 d=128 无掩码：FA2 193-196 vs FA 84-88；
   - PyTorch 标准实现在 16k 序列 OOM，FA2 全程无 OOM。
2. **H100 迁移测试（Figure 7 p13）**：不改代码即达 296-338 TFLOPs/s（fwd+bwd，无掩码），有掩码 d=128 达 308-328；验证算法可移植性，专用新指令优化留待后续。
3. **端到端训练（Table 1 p12）**：GPT3-1.3B 2k/8k：196/220 TFLOPs/s；GPT3-2.7B 2k/8k：205/225 TFLOPs/s；8k 场景相对 FA 提升最大（170→220、175→225），印证长序列受益更多。
4. **效率解读**：72% MFU 已接近"非 attention 部分"的理论上限区间；剩余差距主要来自 softmax/exp 等非 matmul 运算与访存。

## §6 局限

1. **block size 依赖手工调优（§3.3 p9 自述）**：仅 4 种组合但需按 head dimension 与设备共享内存人工选择；作者明确提出应引入 auto-tuning，留作 future work。
2. **H100 专属特性未利用（§4.1 p11 / §5 p12）**：当前版本未使用 TMA、第 4 代 Tensor Cores、FP8，H100 上还有 1.5-2× 预期提升空间（后续 FlashAttention-3 方向）。
3. **反向仍有同步开销**：虽然避开了 split-K，反向因梯度依赖关系复杂仍需一定 warp 间同步，反向峰值（63%）低于前向（73%）。
4. **评测范围有限**：基准限于 A100/H100 NVIDIA GPU、seq ≤16k、head_dim 64/128、GPT-style 语言模型训练；AMD GPU 支持列为计划而非实测；未报告推理/Prefill 场景与多模态形状。
5. **工程属性强、算法层面无变化**：输出与 FLOPs 复杂度与 FlashAttention 完全一致——收益依赖特定硬件代际的微架构细节（SM 数量、SRAM 容量、Tensor Core 吞吐比），跨硬件的可迁移性需要重新调参与验证。
