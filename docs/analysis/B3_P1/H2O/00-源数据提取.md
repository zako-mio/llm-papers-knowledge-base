## §4 方法细节

### 4.1 问题形式化（§2.1 p4）

- 定义带尺寸约束的生成过程：预算 k<n；每步维护下标集合 S_i ⊂[n]，|S_i|=k 且每步至多驱逐 1 条 KV（|S_i\S_{i-1}|≤1）；被驱逐 KV 置零并在 softmax 归一化中扣除（D_i 修正项）。目标：输出分布尽量逼近无限制 KV 的原始生成过程。
- 传统 Belady 算法对 KV cache 不适用——KV 驱逐具有顺序依赖性，误删关键 KV 会引发功能性崩塌（§3.2 p5）。

### 4.2 关键观察（§3 p4-5）

1. **稀疏性**：WikiText-103 验证集上对预训练 OPT 做零样本推理，按行最大值 1% 阈值统计，几乎全部层注意力稀疏度 >95%（Figure 2(a)）⇒ 每步只需 ~5% KV 即可解码出相同 token。
2. **重击者**：所有 token 累积注意力分数服从幂律（Figure 2(b)）；H2 与语料中词共现频次强相关；mask 掉 H2 精度断崖式下跌（Figure 2(c)）。
3. **贪心低代价**：每步仅汇总"当前 token 对之前 token"的局部注意力得分即可识别 H2，无需未来信息（Figure 2(d)）。
4. 理论衔接：若注意力方案满足 submodular，H2 即贪心算法解，具近优性（Lemma 3.1，informal；受 Han et al. [38] 启发）。

### 4.3 H2O 算法（§4 p5-6）

- **动态次模框架（Definition 4.1）**：F(Z,·) 关于 Z 为 submodular；把逐步的 S_i 序列代入即得实例。
- **H2O 驱逐策略（Definition 4.3 + Algorithm 1）**：S_i ← (S_{i-1} ∪ {i}) \ {u}，其中 u = argmax_v F_score(S_{i-1}∪{i}\{v})，F_score 取注意力得分行和；i≤k 时只增不删。
- **理论保证（Theorem 4.4，informal）**：温和假设下贪心 top-k 得到的 S̃_i 满足 f(S̃_i) ≥ (1−α)(1−1/e)·max_{|S|=k} f(S) − β（α,β>0），即经典次模最大化的 (1−1/e) 型保证加噪声项；完整证明在附录 D（含 Hessian 正定/Lipschitz、robust greedy 等 22 小节）。
- **系统实现（§4.2 p6 + Appendix A p20-21）**：
  - 基于 FlexGen 白盒改造 OPT 推理；KV cache 内存预分配，避免驱逐时的数据搬移，新 KV 直接覆写；
  - 缓存布局 = 前 K 条 heavy hitters + 末 K 条 recent tokens，recent 区用循环队列 O(1) 更新；
  - prefill 时 prompt 长度 ≥2K 则选 K 个 H2 + K 个 recent；不足则全保留；解码时每步淘汰 recent 区最旧 1 条 + 每 head 驱逐 1 条 H2，腾位给最新 token；
  - 与 FlexGen 的 offloading/量化优化正交可叠加。

### 4.4 实验设置（§5.1 p7 + Appendix A p20）

- 任务八选二框架：HELM（XSUM、CNN/Daily Mail，zero-shot，1000 测试样例）+ lm-eval-harness（COPA、MathQA、OpenBookQA、PiQA、RTE、Winogrande，默认 5-shot）；另在 AlpacaEval 与 MT-bench 上验证（附录）。
- 缓存预算扫描：4%/10%/20%/60%；基线：Full KV、Local（仅最近 KV）、Sparse Transformer（strided/fixed）、少样本全缓存（0/1-shot）对照。

## §5 实验结果要点

1. **端到端精度（Figure 4/Table 1 p7-8）**：20% 预算 H2O 全面碾压 Local（如 OPT-30B 类任务组 PiQA 79.22 vs 57.94、Winogrande 71.67 vs 51.30），达到或超过 Full；H2O 折算每输入仅需 ~1.2 样本开销，胜过 0/1-shot 全缓存基线。
2. **长文本生成（XSUM/CNN-DM）**：Local 策略在 60% 预算即崩溃，H2O 20% 预算仍匹配 Full（{LLaMA-13B,XSUM}、{LLaMA-7B,CNN/DM} 案例）。
3. **系统吞吐（Table 3/4 p8）**：T4 上 512+1024 场景 OPT-6.7B：H2O 52.1 tok/s（batch 4, G）vs FlexGen 16.9（batch 1, G）、DeepSpeed 10.1（需 CPU offload）、Accelerate 5.6（CPU offload）；30B 模型 H2O 13.82（264, C）vs FlexGen 7.1（48, C）；真实数据 XSUM 同趋势（6.7B：30.40 vs 10.80）。
4. **A100 长序列（Table 5 p9）**：7000+1024@30B 延迟 57.0s→50.4s；2048+2048@6.7B batch24 延迟 99.5s→53.5s（1.86×）、吞吐 494→919 tok/s；batch64 时 FlexGen OOM 而 H2O 达 1161 tok/s。
5. **流式无限长（Q1）**：4M token 输入可用，PPL 曲线全面低于 StreamingLLM（attention-sink 方法）。
6. **shot 鲁棒性（Q2）**：0–10 shot 内 H2O 与 Full 差距 <1%，Local 最差掉 37%。
7. **多样性红利（Q5，Appendix C.1 p23）**：同 prompt 下 H2O 生成重复更少、更有创意；Self-BLEU（越低越多样）LLaMA-7B/XSUM 100 例：Full 0.0057、H2O 0.0051、Local 0.0436（后者退化成重复标点符号）。
8. **组件拆解（Q4）与 Top-K 增强（C.5）**：H2O 还能增强"Top-K"类基线；MLP 块中也观察到 H2 现象（C.10），为后续工作埋线。

## §6 局限

1. **参数量仍是主瓶颈（Appendix B.2 p22 自述）**：吞吐提升后，LLM 推理的主要负担回到巨大权重参数本身；大部分参数在 MLP 块中——作者提出未来应基于"MLP 块中同样存在的 H2 现象"设计 offloading 策略以进一步提效。
2. **理论假设非平凡**：(1−1/e) 保证建立在注意力方案 submodular 的温和假设之上（informal Lemma 3.1/Theorem 4.4），α、β 未给出紧致界，实践中无法据此直接预测精度。
3. **量化联手的工程折扣**：与 4-bit 量化组合虽扩 batch ~20 倍，但因 FlexGen 量化核实现低效，实测吞吐提升 <2×（Appendix C.2 p24），收益兑现依赖更优 CUDA kernel。
4. **评测边界**：主要基于 OPT 系（FlexGen 白盒支持），LLaMA/GPT-NeoX 为精度验证；HELM 任务 zero-shot 而 lm-eval-harness 默认 5-shot，两套口径混排；吞吐测试用 padding 到等长的合成数据为主（另有 XSUM 补充）。
5. **驱逐不可逆**：被驱逐 KV 不再可见，一旦误判关键 token 会造成功能性崩塌——方法本质是启发式贪心 + 经验性 H2 统计，无在线纠错机制；早期 token 占 H2 显著比例的现象（p22）提示与 attention sink 相关的行为尚未完全解释。
