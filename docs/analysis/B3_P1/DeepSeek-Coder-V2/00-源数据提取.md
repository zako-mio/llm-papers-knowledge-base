## §4 方法细节
- **数据**：预训练配比 60% 代码 + 10% 数学 + 30% 自然语言（NL 直接采自 DeepSeek-V2）。GitHub（2023-11 前）按 DeepSeek-Coder 规则过滤去重得 821B 代码（338 语言）+185B 代码相关文本；Common Crawl 按 DeepSeekMath fastText 回流管线迭代 3 轮得 70B 代码相关 + 221B 数学网页 token；GitHub 同管线再收 94B，新代码语料合计 1,170B。
- **训练目标**：236B 仅 Next-Token-Prediction；16B Lite 另加 FIM（PSM 模式，rate 0.5）。
- **架构**：对齐 DeepSeek-V2（MLA + DeepSeekMoE），超参对应 V2-Lite/V2；训练中遇梯度尖峰，弃用指数归一化回退传统 normalization。优化器 AdamW（β1=0.9, β2=0.95, wd=0.1），cosine 衰减至初始 LR 的 10%，2000 warm-up steps。
- **长上下文**：YaRN（s=40, α=1, β=32）两阶段扩到 128K——32K/bs1152×1000 步 → 128K/bs288×1000 步，上采样长文本比例。
- **对齐**：SFT 用约 300M tokens 指令数据（2 万代码 + 3 万数学指令 + DeepSeek-V2 通用样本），cosine 调度、100 warm-up、初始 LR 5e-6，批大小 1M tokens 共训 1B tokens；RL 采用 GRPO（免 critic，成本低），约 4 万带测试用例 prompt；奖励用自训 reward model 替代编译器 0-1 信号（泛化更稳）。
- **评测协议**：代码生成统一 greedy search 并以相同脚本/环境重测全部基线；多语言评测将 HumanEval 扩展至 C++/Java/PHP/TypeScript/C#/Bash/JavaScript 等 13 种附加语言。

## §5 实验结果要点
- 代码生成（HumanEval 多语言，greedy、统一脚本重测基线）：DSC-V2 Instruct Python 90.2%，超过 GPT-4-Turbo-0409（88.2%），仅略低于 GPT4o-0513（91.0%）；Java/C++/C#/TS/JS/PHP/Bash 全线领先开源模型，多语言平均 75.3% 仅次于 GPT-4o 的 76.4%（§4.1）。
- 竞赛编程（表4）：LiveCodeBench（1201-0601 防污染子集）overall 43.4%，与 GPT-4o 并列第二、仅次于 GPT-4-Turbo-0409（45.7%）；USACO 12.1%。Lite 版 LiveCodeBench 24.3% 已超 DS-Coder-instruct-33B（22.5%）。
- 仓库级补全 RepoBench v1.1（只用 2023-12 数据防泄漏；2k–16k 五档上下文，cross-file-first/random + in-file 三设定，取首行非空非注释输出算 exact match）：Python 平均分 Codestral 46.1% > DS-Coder-33B 39.1%；Lite-Base（2.4B 激活）Python 能力 ≈ DS-Coder-Base-33B，Java ≈ DS-Coder-7B。
- FIM 单行补全（Python/Java/JavaScript 三语言）：DS-Coder-V2-Lite-Base 在对比模型中领先（三语言得分约 89.1%/87.2%/86.4%，表6）。
- 代码修复：Defects4J / SWE-bench / Aider（133 任务）测试；图1 中 SWE-Bench 12.7 仍落后闭源最佳（18.3）。
- 代码理解推理 CRUXEval（I/O 正反向预测）：开源模型中最优梯队（表8）。
- 数学推理：GSM8K 94.9 / MATH 75.7，另测 AIME 2024 与 Math Odyssey（表9），达闭源第一梯队水平。
- 通用自然语言（§4.6）：继承 DeepSeek-V2 能力，BBH/MMLU/ARC/TriviaQA/NQ/AGIEval 及中文 CLUEWSC/C-Eval/CMMLU 上与 V2 Chat 相当，推理类基准甚至反超。

## §6 局限
- **指令遵循短板**（作者明示）：与 GPT-4 Turbo 等仍有显著差距，导致 SWE-Bench 等复杂真实场景表现差（12.7 vs Claude/Gemini 更高值）；后续将重点提升指令遵循能力（§5 Conclusion）。
- **训练语料截止约束**：GitHub 代码取自 2023-11 前创建仓库，竞赛类评测需选防污染子集（LiveCodeBench 1201-0601、RepoBench 仅用 2023-12 数据），时效性受限。
- 236B 版禁用 FIM 目标，infilling 能力依赖 Lite 分支；FIM rate 固定 0.5 未做敏感性分析。
- RL 依赖 reward model 质量：编译器测试用例覆盖不足时直接 0-1 反馈噪声大，需额外训练 RM 缓解。
- 训练不稳定记录：指数归一化引发梯度尖峰，回退传统 normalization，暗示该技术在大规模 MoE 继续预训练中风险较高。
