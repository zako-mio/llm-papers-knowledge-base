## §4 方法细节

**三 prompt 循环（Algorithm 1, p3）：**
1. `y₀ = M(p_gen ∥ x)` —— 初始生成（few-shot 或 instruction）；
2. `fb_t = M(p_fb ∥ x ∥ y_t)` —— 同一模型对自身输出生成反馈；
   - 反馈要求 **actionable**（含具体改进动作）且 **specific**（指认输出中的具体片段），示例："This code is slow as it uses a for loop which is bruteforce. A better approach is to use the formula n(n+1)/2"；
3. 若 `stop(fb_t, t)` 不满足则 `y_{t+1} = M(p_refine ∥ x ∥ y₀ ∥ fb₀ ∥ … ∥ y_t ∥ fb_t)` —— 完整历史保留进 prompt（Eqn 4）；
4. 停止条件两类：固定轮数上限（实验设 **最多 4 轮**），或从反馈中抽取标量 stop score。

**实现要点：**
- 全部 FEEDBACK/REFINE 用 few-shot prompt 实现（即使 ChatGPT/GPT-4 这类指令模型也统一处理，保证跨模型一致）；
- 解码：greedy with temperature 0.7；
- 7 个任务：Dialogue Response（DailyDialog）、Code Optimization（效率优化）、Code Readability（变量命名改进）、Math Reasoning（GSM8K solve rate）、Sentiment Reversal（Yelp 差评转好评）、Acronym Generation（新任务）、Constrained Generation（commongen 加难版：20–30 关键词约束）；
- 指标三类：任务自动指标 / 盲评人类 A/B 偏好 / GPT-4 代理偏好。

## §5 实验结果要点

**主表 Table 1（Base → +SELF-REFINE）：**

| 任务 | GPT-3.5 | ChatGPT | GPT-4 |
|---|---|---|---|
| Sentiment Reversal | 8.8→30.4 | 11.4→43.2 | 3.8→36.2 |
| Dialogue Response | 36.4→63.6 | 40.1→59.9 | 25.4→74.6 |
| Code Optimization | 14.8→23.0 | 23.9→27.5 | 27.3→36.0 |
| Code Readability | 37.4→51.3 | 27.7→63.1 | 27.4→56.2 |
| Math Reasoning | 64.1→64.1 | 74.8→75.0 | 92.9→93.1 |
| Acronym Generation | 41.6→56.4 | 27.2→37.2 | 30.4→56.0 |
| Constrained Generation | 28.0→37.0 | 44.0→67.0 | 15.0→45.0 |

- 规律①：**基座越强收益越大**（GPT-4 版普遍优于 GPT-3.5/ChatGPT 版），作者解读为 SELF-REFINE 释放了强模型单次生成未表达的潜力；
- 规律②：**约束越多、解空间越大、可验证性越弱的任务收益越大**（Constrained/Dial/Acro/Senti）；**可精确判错的任务反而难获益**（Math Reasoning——错误细微且表面连贯的推理链会欺骗 LLM 判断）；
- 补充：数学任务若引入外部 oracle 判断答案正误，增益可放大到 5%+（App H.1）；
- Codex 上代码任务趋势一致（App F）；置信区间见 App J。

## §6 局限（论文自述 §6 Limitations and Discussion）

1. **依赖基座的 few-shot/instruction 能力**：Vicuna-13B 实证无法完成反馈格式化与按反馈改写（复读或幻觉），说明该方法有模型能力下限；
2. **闭源模型依赖**：实验全部基于 GPT-3.5/ChatGPT/GPT-4/CODEX，预训练语料、规模、偏差不透明且收费（已开源代码与输出缓解复现问题）;
3. **仅英语数据集**：其他语言未必有同等收益；
4. **安全边界**：prompting 技术可能被滥用于引导生成毒性文本，本文方法无显式防护；
5. （分析章节补充）数学推理等"难以自查"的任务上近乎无效，需外部验证源配合。
