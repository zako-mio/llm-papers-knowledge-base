## §4 方法细节

### 4.1 自动课程（Automatic Curriculum，§2.1 p3-4）

- 由 GPT-4 以"discover as many diverse things as possible"为总目标自底向上生成下一个任务（in-context 形式的 novelty search），依据 agent 当前状态与探索进度动态调整难度。
- 课程 prompt 五要素（Appendix A.3.1）：①鼓励多样性+可行性约束的指令；②agent 状态全量描述（背包、装备、32 格内方块/实体、已见箱子内容、biome、时间、生命/饥饿值上限 20、三维坐标）；③已完成与已失败任务列表；④附加上下文（GPT-3.5 基于 state 自问自答，问题挂 concept 用于从 MineDojo wiki 知识库检索相关文档）；⑤要求先推理再给任务的 chain-of-thought。
- Warm-up 调度（A.3.3）：训练初期逐步引入状态信息与附加上下文。
- 任务格式约束为单一短语："Mine [quantity] [block]" / "Craft ..." / "Smelt ..." / "Kill ..." / "Cook ..." / "Equip ..." 等。

### 4.2 技能库（Skill Library，§2.2 p4-5）

- 技能=可执行 JavaScript 程序（基于 Mineflayer API），表示时序扩展、可解释、可组合的动作。
- 存储：key=GPT-3.5 生成的程序描述文本的 embedding（text-embedding-ada-002），value=程序本体，存于向量数据库。
- 检索：新任务到来时先用 GPT-3.5 生成通用解题建议，与环境反馈拼接为查询，取 top-5 相关技能注入 GPT-4 的 prompt。
- 控制 primitiva API（Appendix A.4.1，作者封装+Mineflayer 原生两层）：`exploreUntil`、`mineBlock`、`craftItem`、`placeItem`、`smeltItem`、`killMob`、`getItemFromChest`、`depositItemIntoChest`、`bot.pathfinder.goto` 等。
- 代码生成 prompt 含：代码规范指令（"函数将被复用，须通用"）、控制原语+检索到的相关技能、上一轮代码/环境反馈/报错/critique、agent 状态、CoT 先推理后写码。

### 4.3 迭代提示机制（Iterative Prompting Mechanism，§2.3 p5-6）

三类反馈闭环：
1. **环境反馈**：程序执行中间进展（经 `bot.chat()` 注入），如"I cannot make an iron chestplate because I need: 7 more iron ingots"；
2. **执行错误**：代码解释器的异常栈（如 `No item named acacia_axe` → GPT-4 改为 wooden axe）；
3. **自验证**：另一个 GPT-4 实例充当 critic，输入当前状态+任务判断成败；失败时给出如何完成的 critique——比 Reflexion 的 self-reflection 更全面（既查成功又反思错误）。

循环执行直到自验证确认完成 → 程序入技能库 → 向课程请求下一目标；**4 轮代码生成仍卡住则放弃该任务回询课程**。探索实验最大迭代 160，零样本任务最大 50。

### 4.4 实验设置（§3.1-3.2 p6）

- 环境：MineDojo + Mineflayer JS API；bot 死亡后在最近地面复活且保留背包；工作台/熔炉用后回收。
- 温度：全部 0，唯自动课程 0.1 以保任务多样性。
- 基线适配：ReAct（环境反馈+状态作观测，1 轮生成+3 轮精修循环）、Reflexion（ReAct+self-reflection，接入作者的自验证模块）、AutoGPT 重实现（GPT-4 分解子目标，缺技能库/自验证/自动课程）。明确不与像素输入的低层控制方法（VPT/DreamerV3 等）做同台对比，定位差异见 Table A.2。

### 4.5 多模态人类反馈扩展（§3.5 p9）

- 当时 GPT-4 API 仅文本，无视觉感知；演示两种人类介入方式：human-as-critic（替代自验证，纠正 3D 结构空间细节）与 human-as-curriculum（分解复杂建造任务），成功建造 Nether Portal 与房屋。

## §5 实验结果要点

1. **探索（Figure 1 p1/p7）**：160 迭代 63 个独特物品（3.3×）；AutoGPT 明显落后，ReAct/Reflexion 因开放式目标缺乏合适课程几乎无进展。
2. **科技树（Table 1 p7）**：三级加速 15.3×/8.5×/6.4×；唯一解锁钻石级（102 迭代，3 次中 1 次成功）。消融中去掉技能库后钻石级也 0/3。
3. **地图覆盖（Figure 7 p7）**：2.3× 距离且跨越多样地形；基线困守局部区域。
4. **零样本泛化（Table 2/Figure 8 p8）**：新世界 4 任务全 3/3；技能库作为 plug-and-play 资产能直接提升 AutoGPT（部分任务从 0/3 → 1/3~2/3）。
5. **消融（Figure 9 p9，六变体定义见 B.3）**：随机课程 -93%、无自验证 -73%、无技能库后期停滞、GPT-3.5 写码 -5.7×；环境反馈与执行错误的移除亦有明显下降（右图）。
6. **人类反馈建造（Figure 10 p9）**：Nether Portal 与房屋的渐进式建造过程展示。

## §6 局限

1. **成本（§4 p10 自述）**：GPT-4 API 价格为 GPT-3.5 的 15 倍，而代码生成质量跃升又离不开 GPT-4，开源 LLM 当时无法替代（引用 [60]）。
2. **不精确/卡死（§4 p10）**：仍有生成不出正确技能的情形，靠课程稍后重试；自验证偶发误判（如未把 spider string 识别为击败蜘蛛的成功信号）。
3. **幻觉（§4 p10）**：课程会提出游戏内不存在任务（如 craft "copper sword"/"copper chestplate"）；代码生成中 GPT-4 会拿 cobblestone 当燃料、调用不存在的 API 导致执行报错。
4. **无视觉感知（§3.5 p9）**：受限于当时 GPT-4 API 文本-only，空间结构任务需人类视觉 critique 弥补；未来需接多模态感知模型。
5. **评测口径限制（§3.2 p6-7）**：基线均为 NLP agent 方法的 Minecraft 重适配而非原生设计；与像素级 RL/VPT 类方法不做 apples-to-apples 对比；科技树/零样本各任务仅 3 runs，方差大（如 AutoGPT ±103）且钻石级仅 1/3。
6. **部署边界（§7 Broader Impacts p11）**：迁移到物理机器人等真实域需额外安全约束与人工监督。
