## §4 方法细节

**任务构造（§2 p.2 + Appendix A.1.1 p.6）**：数据为二元运算表 a∘b=c 的等式，每个元素以无内部结构的离散符号表示——网络看不到十进制数字或置换的线记法，只能从符号间交互学习其性质（类比填数独）。序列 token 化为 ⟨x⟩⟨op⟩⟨y⟩⟨=⟩⟨x∘y⟩ 五个独立 token。

**运算清单（mod p=97 素数）**：
- x+y、x−y、x/y（0<y<p）、混合运算 [x/y if y odd else x−y]
- x²+y²、x²+xy+y²、x²+xy+y²+x、x³+xy、x³+xy²+y
- S₅ 置换群上的 x·y、x·y·x⁻¹、x·y·x

对每个运算随机选比例子作训练集，其余作验证集。损失与准确率只在答案 token 上计算。

**模型与训练（Appendix A.1.2）**：标准 decoder-only Transformer（Vaswani et al. 2017）+ causal masking。超参数以性能/简洁性平衡选定（例如未采用在某些情形更优的 lr 退火）。§3.3 消融变体包括：full-batch Adam、full-batch+高斯噪声更新方向、residual dropout 0.1、AdamW(wd=1)、朝初始化而非原点的 weight decay、不同 lr、权重高斯噪声 σ=0.01 等。

**关键分析工具**：
- 数据效率曲线：固定优化步数预算下，扫描训练集占比，观察泛化何时发生。
- t-SNE 嵌入可视化（§3.4, Fig.3）：输出层行向量投影。模加法网络呈现圆拓扑（"number line"，按 mod 8 余数着色）；S₅ 网络呈现置换聚类，每簇是子群 ⟨(0,3)(1,4),(1,2)(3,4)⟩ 或其共轭的一个 coset。
- Sharpness 近似 φ（A.5）：训练多个 seed 至约一半 grok，计算 sharpness 与验证准确率相关性。

## §5 实验结果要点

1. **Grokking 普遍性**（§3.1）：改进后的泛化跨越一系列模型、优化器与数据规模出现；在接近"预算内能泛化的最小数据规模"时最显著；数据量更大时 train/val 曲线趋于同步。
2. **学习时间曲线**（§3.1.1）：收敛性能在一段数据规模区间内恒定保持 100%，但所需优化时间随数据减少快速指数增长——一种用算力换数据量的途径。
3. **运算难度排序**（§3.2, Fig.2 right）：
   - 对称运算（x+y, x*y, x²+y², x²+xy+y²）比对应非对称版本（x−y, x/y, x²+xy+y²+x）需要更少数据泛化；作者认为部分源于架构（Transformer 易于通过忽略位置嵌入学对称函数）。
   - 代数等价性得到验证：素数域上 x+y (mod p−1) ≡ x*y (mod p)（原根表示），x−y 与 x/y 所需数据量确实相近。
   - x³+xy²+y (mod 97) 在任何 ≤95% 数据占比下都不泛化——网络只记忆，数据对其等效随机。
   - 混合运算 [x/y if y odd else x−y] 表明即使运算不能干净地用群/环结构解释，泛化也可能发生。
4. **消融**（§3.3）：weight decay 最有效（样本减半以上）；朝初始化的 weight decay 也有效但略逊于朝原点——"零权重先验"解释部分而非全部收益；minibatch 梯度噪声/权重噪声有益（与找到更平坦极小值的假说一致）。
5. **嵌入可视化**（§3.4）：grok 后的网络嵌入反映底层数学对象的可识别结构，weight decay 优化的网络结构更明显。
6. **噪声容忍**（A.4）：小量 outlier 不影响，说明网络容量远超记忆所需，泛化本身需要非平凡解释。
7. **与 double descent 的关系**（A.3）：本文观察到验证 loss 的第二次下降发生在训练 loss 首次变小之后很远（有时数万 epoch），且准确率无非单调行为——作者认为该现象不同于 Nakkiran/Belkin 的经典 double descent 设定。

## §6 局限

1. **机制未解**：论文只记录现象并给出猜想（SGD 噪声驱动至更平坦/更简单的解），sharpness 相关性仅为初步证据（单一任务、preliminary investigation），因果机制留待后续工作。
2. **任务范围窄**：全部结论基于小型算法生成的二元运算表；作者自己也提出需验证其他数据集是否呈现同样的"数据↓→优化时间指数↑"效应（§4 Discussion）。
3. **部分运算完全不 grok**：如 x³+xy²+y 在所有测试数据占比下均不泛化，边界条件不明。
4. **超参敏感**：泛化仅在约一个数量级宽的学习率窗口内发生，实际复现对调参敏感。
5. **架构依赖迹象**：对称运算的数据优势被作者怀疑部分是 Transformer 特有的（位置嵌入可忽略），现象并非完全 architecture-agnostic。
