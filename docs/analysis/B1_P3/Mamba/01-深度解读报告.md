## 摘要

本文解读 Gu 与 Dao 提出的《Mamba》。论文的核心论断是：序列模型的效率与质量之争，本质上是一场**状态压缩质量**的竞争——注意力机制不压缩上下文（KV cache 随序列线性膨胀）因而强大却昂贵，循环模型把上下文压进有限状态因而廉价却记不住该记的东西。作者在 S4 状态空间模型的基础上引入**选择机制**（Selection），让 SSM 的核心参数 (Δ, B, C) 成为输入的函数，打破僵化的线性时不变（LTI）约束，使模型第一次能够基于内容做"记住什么、遗忘什么"的动态决策；同时用 **selective scan** 硬件感知算法（kernel fusion + parallel scan + recomputation）保住递归模式的线性复杂度与并行训练能力，最终得到首个真正达到 Transformer 质量、且推理吞吐 **5×** 于同尺寸 Transformer 的线性时间序列架构 Mamba。语言建模上 Mamba-3B 匹配两倍尺寸的 Transformer；Induction Heads 合成任务上外推至百万级序列（4000×），而其他方法不超过 2×；DNA 与音频模态同样刷新纪录。本报告按"问题—概念—方法—证据—批判—启示"六层结构逐层拆解。

## 一、问题定位：效率与质量的两难，被误读为一个二选一

### 1.1 论文要解决的问题

论文针对的是深度序列建模的一个根本性张力：自 Transformer 兴起以来，主流叙事把它当作"质量天花板"，而 RNN 类结构被视为"效率备胎"。作者把这个叙事翻转成一个更精确的问题表述——**序列建模的核心是把历史上下文压缩进一个有限状态**。从这个视角看：

- **注意力不压缩**：KV cache 完整存储全部历史，训练与推理代价随序列长度二次/线性增长，换来的是"随时可查任意历史位置"的无损检索；
- **经典循环模型过度压缩**：固定维度的隐态被迫把所有历史挤在一起，压缩本身有损且不可控——模型无法决定"哪些 token 值得保留、哪些可以丢弃"。

于是问题的真正形态不是"选注意力还是选 RNN"，而是：**能否造出一个既拥有大状态容量、又能对状态进行内容感知管理的模型，同时保持线性时间的计算代价？**

### 1.2 问题谱系中的定位

论文将自身置于一条清晰的改进链上：

| 结构家族 | 代表 | 序列交互方式 | 核心缺陷 |
|---|---|---|---|
| 注意力 | Transformer | 全对全（不压缩） | 训练 O(L²)、推理 KV cache 线性增长 |
| 经典 RNN | LSTM 等 | 循环（强压缩） | 串行训练慢、容量有限 |
| 结构化 SSM | S4 | LTI 循环/全局卷积二象性 | 时不变参数无法内容选择 |
| 门控卷积 | H3、Hyena、RetNet | 卷积+门控 | 门控不在序列轴交互，仍非内容感知 |
| **本文** | **Mamba (S6)** | **选择性递归（time-varying）** | —— |

S4 家族此前最优雅的性质是"二象性"：同一套参数既能展开成线性递归（推理快），也能计算成全局卷积（训练并行）。但这套性质的代价恰恰是 **LTI（线性时不变）**——(Δ, A, B, C) 对所有时间步恒定，模型对所有输入一视同仁地滤波，永远学不会"看到这个 token 就把它刻进记忆"。论文的诊断非常明确：LTI 不是工程妥协的残留，而是**能力上限的直接根源**。

### 1.3 关键洞察：合成任务是诊断器，而非玩具

作者没有直接堆语言实验，而是设计了两个最小合成任务作为"显微镜"，精准暴露 LTI 的失败模式：

1. **Selective Copying（选择性复制）**：复制输入中的若干 token 但忽略中间的随机间距噪声。这要求**内容感知的记忆**——记住"是什么"而忘记"在哪里"。LTI 因时不变性只能均匀记忆位置，无法跳过噪声。
2. **Induction Heads（归纳头）**：序列中出现过的 bigram 在后续重现时需快速预测其延续，这是关联式记忆与大模型 ICL 能力的机制性代理。

这一方法论本身就是本文的重要贡献之一：（推断）它把"为什么循环模型输给注意力"从一句含糊的经验之谈，降解成了两个可复现、可归因的最小失败案例，后续大量 SSM/RNN 论文都沿用了这套诊断范式。

> **一句话小结**：本文重新定义了问题——不是"打败注意力"，而是"证明高效压缩（有限状态）与高质量（内容感知）可以在同一架构中共存"；两个合成任务就是这一论断的最小证据。

## 二、概念内核：五个核心概念逐一定义

### 2.1 状态空间模型（SSM）

**定义**：源自控制论的连续系统，Eq.(1)：h'(t) = Ah(t) + Bx(t)，y(t) = Ch(t)。输入 x 经隐态 h（维度 N）映射到输出 y，A 是状态转移矩阵，B 是输入投影，C 是读出投影。

**拆解**：SSM 的本质是 RNN 与 CNN 的结合体——离散化后既可按时间步递归计算（RNN 形态，推理 O(1) 每步），也可展开为全局卷积一次算完整个序列（CNN 形态，训练可并行）。隐态维度 N 是独立于模型维度 D 的旋钮：N 越大，状态容量越大，能记住的历史细节越多。（推断）这正是 Mamba 后来敢说"状态扩张几乎免费"的结构基础。

### 2.2 LTI（线性时不变）及其失败模式

**定义**：当 (Δ, A, B, C) 对所有时间步恒定时，系统是线性时不变的；此时递归与卷积两种计算模式严格等价（Eq.3），S4 的效率优势全部建立在此之上。

**拆解**：LTI 系统等价于一个**固定的线性滤波器**——无论输入内容是什么，它都以相同的方式加权历史。这在音频等平稳信号上是合理归纳偏置，但在语言这种高度非平稳、信息密度极不均匀的模态上是灾难：一个冠词和一个命名实体理应占据完全不同的记忆份额，而 LTI 给它们相同的待遇。这就是 §1.2 所述"压缩不可控"的形式化表达。

### 2.3 选择机制（Selection，S6）

**定义**：让参数 (Δ, B, C) 成为输入的函数——s_B(x)、s_C(x) 取 Linear(x) 或 Broadcast(Linear(x))，s_Δ 经 τ = softplus 激活——使系统变为 time-varying（参数带序列长度维 L），即 Algorithm 2 的 S6。

**拆解**：三个参数各司其职：（推断）Δ 控制当前输入写入状态的强度（大 Δ = 当前 token 重要、覆盖旧记忆；小 Δ = 忽略当前输入、保持记忆）；B 控制"写入什么"；C 控制"读出什么"。三者联合实现了对状态的内容感知管理。**代价是打破 LTI**：time-varying 参数不再存在等价的卷积形式，只能走递归路径——这正是必须发明 selective scan 的原因。注意 A 保持为输入无关的静态参数（推断）：转移动力学本身稳定，只有"输入如何进入状态、状态如何被读取"是动态的，这是一个刻意收窄的自由度设计。

### 2.4 Selective Scan（硬件感知状态扩张算法）

**定义**：§3.3 的核心算法，三项技术组合：kernel fusion（融合算子）、parallel scan（工作高效并行扫描）、recomputation（反向重算）。

**拆解**：naïve 递归实现需物化全部隐态 h(B,L,D,N)，FLOPs 为 O(BLDN)；卷积形态为 O(BLD log L)。selective scan 的做法是**从不物化状态**：把离散化与递归整体放进 SRAM 内核完成，只把最终输出 (B,L,D) 写回 HBM；序列轴的串行依赖用 work-efficient parallel scan 打破；反向传播不存中间态、现算现用。结果是内存占用与 FlashAttention 优化的 Transformer 持平，速度反而更快——比标准 PyTorch scan 快 **20–40×**，序列超过 2K 后比 FlashAttention-2 还快，在 A100 上相对先前 SSM 方法最高 **3×** 提速。（推断）这篇 §3.3 的工程叙述之所以重要，在于它确立了"算法-硬件协同设计"作为序列建模研究的标配范式，FlashAttention 的思路被完整移植到了递归一侧。

### 2.5 Mamba 架构（均质 block）

**定义**：把 H3 的类注意力 block 与 Transformer 的 MLP block 合并为单一均质 block（借鉴 GAU 思想），内部以 S6 层替代注意力层。

**拆解**：模型维 D 按扩展因子 E 扩展（实验固定 E=2）；大多数参数集中在线性投影（3ED² = 输入投影 2ED² + 输出 ED²），SSM 内部参数占比很小。两层 Mamba block 即匹配 Transformer "MHA+MLP" 的 12D² 参数量，保证公平对比。激活用 SiLU/Swish（Gated-MLP 对应 SwiGLU），LayerNorm 位置借鉴 RetNet。（推断）"均质化"看似平淡，实则是与 Transformer 生态兼容的战略决策——参数分布、block 数量、扩展规则都对齐后，"同尺寸换内核"的对比才无懈可击，社区迁移成本也降到最低。

> **一句话小结**：五个概念构成一条完整链条——SSM 提供状态骨架、LTI 暴露失败根源、Selection 注入内容感知、Selective Scan 保住硬件效率、均质 Mamba block 把这一切封装成 Transformer 的即插即用替代品。

## 三、方法拆解：从 S4 到 Mamba 的完整推导链

### 3.1 公式级还原：连续 → 离散 → 选择

**第一步（连续系统）**：h'(t) = Ah(t) + Bx(t)，y(t) = Ch(t)。这是控制论标准形，隐态 h 维度 N 决定状态容量。

**第二步（离散化）**：经 ZOH 规则（Eq.4）将连续参数 (Δ, A, B) 变换为离散参数 (Ā, B̄)，随后两条等价计算路径：线性递归逐步推进，或全局卷积（Eq.3）一次并行。**LTI 保证二者严格等价**——这是 S4 效率魔法的数学根基。

**第三步（注入选择）**：令 B:(B,L,N) ← s_B(x)、C:(B,L,N) ← s_C(x)、Δ:(B,L,D) ← τ(Parameter + s_Δ(x))，其中 s_· 是简单线性投影、τ = softplus（保证 Δ > 0）。参数获得长度维 L 后，卷积等价性失效，**只剩递归一条路**——Algorithm 2 明确注明"仅递归模式"。

这条推导链的精妙之处在于每一步的取舍都有明确的交换物：选择机制买来了内容感知，卖掉了卷积并行；selective scan 又用硬件工程把并行性赎了回来。**方法论的完整性正在于没有任何单点优化，而是三件套互相成就。**

### 3.2 动机的压缩视角：为什么选择机制是对的答案

论文 §3.1 用"压缩"统一了所有序列模型的理论框架：

| 模型 | 上下文处理 | 效率 | 效果瓶颈 |
|---|---|---|---|
| 注意力 | 不压缩（全存） | 差（随 L 增长） | 无（无损检索） |
| LTI SSM | 固定压缩 | 好（O(L)） | 压缩不可控 |
| 选择性 SSM | **受控压缩** | 好（O(L)） | —— |

架构门控（gating）路线（H3、RetNet、Hyena 配门控）为何不够？论文的回答一针见血：**门控作用在通道维而非序列轴，不构成跨时间步的交互**，因此无法实现"根据当前 token 决定对过去某段历史的取舍"。合成任务的实证支持了这一点：Selective Copying 上门控架构只部分改善，而 S4 → S6（仅加选择机制）即可轻易解决。

### 3.3 Selective Scan 的三个工程支柱

1. **Kernel Fusion**：离散化 + 递归 + 读出全部融进单个 GPU kernel，消除中间张量往返 HBM 的开销；
2. **Parallel Scan**：前缀和式的 work-efficient 并行扫描，把表面上串行的递归在 log L 深度内并行化，保住训练吞吐；
3. **Recomputation**：反向传播时不保存中间激活，从前序状态重算，用计算换显存——这是激活检查点思想的极致化。

三者合力达成的指标：内存需求与 FlashAttention 优化的 Transformer **持平**，而理论复杂度仍是线性的。（推断）这意味着 Mamba 不是"省内存但慢"或"快但吃显存"的偏科生，而是在效率四边形（训练速度/推理吞吐/显存/复杂度）上首次全面不弱于注意力基线的循环架构。

### 3.4 架构账本：与 Transformer 逐参数对齐

| 设计项 | Mamba | Transformer | 对齐意图 |
|---|---|---|---|
| Block 结构 | 单一均质 block（S6 + 门控 MLP 合并） | MHA + MLP 两段式 | 消除结构差异混淆 |
| 参数扩展 | E=2，主要在线性投影 3ED² | MHA+MLP 共 12D² | 两层 Mamba ≈ 一层 Transformer 参数 |
| 激活/归一化 | SiLU(SwiGLU 式) + 可选 LayerNorm(RetNet 位置) | GELU + LayerNorm | 工程惯例对齐 |

（推断）这张账本的潜台词是：Mamba 的对比实验里不存在"隐藏的参数优势"或"调包空间"，胜负手被干净地锁定在选择机制本身——这也让第四章消融实验（Table 6/7）的结论格外有力。

> **一句话小结**：方法体系是一条"三步推导 + 三项工程"的闭环——理论上用压缩视角论证选择机制的必然性，数学上用 time-varying 参数改写 SSM，工程上用 selective scan 让改写在真实硬件上成立，最后用逐项对齐的架构账本保证对比公平。

## 四、证据链：从合成到真实、从质量到效率的五重验证

### 4.1 合成任务：机制的直接验证

**Selective Copying**：S4 → S6 加选择机制后轻易解决；门控架构（H3、Mamba-with-Hyena 变体）只能部分改善。这直接证明了"内容感知"与"通道门控"的本质差异。

**Induction Heads**：2 层模型、训练序列长 256、vocab 16，测试外推至 2⁶=64 直至 2²⁰≈**1,048,576**。结果呈现数量级断层：Mamba 完美解决并外推 **4000×**，其他方法不超过 **2×**。值得注意的细节是 Mamba 仅用 D=64，其他基线用 D=128——在参数减半的情况下取得数量级优势。（推断）4000× 外推的意义远超合成任务本身：它证明选择机制学到的"关联记忆"算法是**长度无关的程序性知识**，而非对训练长度的过拟合，这是对"SSM 只会背短模式"质疑的有力回击。

### 4.2 语言建模：Table 3 的全线胜利

与 Pythia、RWKV 同 tokenizer、同 300B tokens 预训练对比（Mamba/Pythia 上下文 2048，RWKV 1024），六个下游基准（LAMBADA、HellaSwag、PIQA、ARC-E、ARC-C、WinoGrande）加 Pile perplexity 平均分：

| 尺寸 | Mamba avg | Pythia avg | RWKV avg | 判定 |
|---|---|---|---|---|
| ~3B | **63.3** (2.8B) | 59.1 (2.8B) | 59.6 (3B) | Mamba 领先 ≥3.7 点 |
| ~1.4B | **59.7** | 55.2 (1.4B) | —— | 领先 4.5 点 |
| ~370M | **50.0** | 51.9 (**1B**) | —— | 小尺寸逼近大一倍半的 Pythia |

核心结论成立：**每个尺寸 Mamba 全线最佳，Mamba-3B 匹配两倍尺寸 Transformer**。（推断）RWKV 的 1024 上下文劣势需要在解读时打折考虑，但 Pythia 同为 2048 且是事实上的开源标准基线，这一对比的说服力不受影响。

### 4.3 DNA 与音频：跨模态泛化

**DNA 建模**：HG38 单个人类基因组约 **4.5B tokens** 预训练；长序列分类任务优于 Hyena 与先前 SOTA，且性能随序列长度增长持续提升至百万级——这是"真实数据上序列长度可达 1M"主张的实证来源。

**音频生成（SC09）**：数字极为悬殊——Mamba 6.1M 参数即达 FID **0.94**（Transformer 为 **7.7**，差逾 8 倍）、mIS 88.54 vs 47.03；扩到 24.3M 后 FID **0.67**、mIS 144.9、AM 0.36，全面优于 SaShiMi（其 AM 为 0.74）与 Hyena，FID 较先前 SOTA 降超一半。（推断）有趣的是，这与论文自述的"无免费午餐"局限形成了微妙呼应——音频本是 LTI 最擅长的连续模态，Mamba 在此依然碾压，说明选择机制并未如作者担心的那样牺牲连续模态性能，至少在此任务规模上没有。

### 4.4 效率：Figure 8 的工程答卷

- 训练：selective scan 比标准 PyTorch scan 实现快 **20–40×**；序列超过 **2K** 后比 FlashAttention-2 更快；
- 推理吞吐：Mamba 达相似尺寸 Transformer 的 **4–5×**；Mamba-6.9B（prompt 2048，A100 80GB）吞吐约 **1814**，超过 5× 小于它的 Transformer-1.3B；Mamba-1.4B 约 1688/1445；
- 反观 Transformer：1.3B/6.7B 在更长序列或更大 batch 下 **OOM**——注意力的高效区间是有边界的，而 Mamba 的线性显存曲线尚未触及边界。

（推断）"6.9B 打赢 1.3B 的吞吐"是全文最具商业冲击力的单一数字：它意味着在同等硬件预算下，部署方可以选择更大容量的 Mamba 模型而不损失服务能力。

| 初始化（Table 8） | 实值对角初始化优于复值 | S4D-Real > S4D-Lin |
| 状态维 N（Table 10） | 状态扩张近乎免费 | N=16 带来 **>1.0** ppl 改进而仅 **+1%** 参数 |

Table 10 是全文核心动机的定量收官："更大的状态几乎不要钱"正是选择机制存在的意义——如果状态扩张昂贵，压缩质量的竞争就无从谈起。（推断）Table 7 中"单独 Δ 已拿到 10.93→9.81 的大部分收益"提示我们：若追求最小改动方案，仅给 Δ 加输入依赖可能是性价比最高的子集，这对后续简化复现工作（事实上催生了后来的 Mamba-2 简化路线）有直接的指导价值。

> **一句话小结**：证据体系呈金字塔形——底层两个合成任务证明机制有效，中层语言/DNA/音频证明跨模态泛化，顶层效率基准证明工程可用，而消融表把每一层收益精确归因到具体设计，几乎没有悬案。

## 五、批判审视：局限的深层含义与独立疑点

### 5.1 作者自述五项局限的深层含义

1. **Scaling 受限**：实验模型 ≤~350M 参数（Chinchilla 最优 tokens 配比），低于 Llama/RWKV/RetNet 等已验证的 7B 级。深层含义：**"Mamba-3B 匹配 2× Transformer"是在小模型域内的结论，向 7B+ 外推时缩放律形状可能改变**。事后来看（推断）这正是社区后续争论最激烈的战场。
2. **无免费午餐（连续-离散光谱）**：选择性增强文本/DNA 等离散模态，理论上可能削弱 LTI 擅长的音频/视频连续信号。这是全文最诚实的一条自我设限——作者主动承认自己的改进是**光谱上的移动而非帕累托改进**。SC09 的结果虽未显现代价，但（推断）任务规模较小，不足以排除大规模场景下的退化。
3. **下游 affordances 未验证**：微调、提示、ICL、RLHF、量化等 Transformer 生态能力均未检验。深层含义：架构的"质量分数"不止于困惑度——**一个架构能否继承五年积累的对齐与适配工具链，决定了它的实际命运**。
4. **复值→实值的取舍**：实值 SSM 主要节省推理硬件，效果差异小；超大规模 SSM 需额外工程调整，本文未讨论。
5. **长上下文优势依赖特定任务**：百万级上下文的实证来自合成/音频/基因组，通用语言的超长上下文未系统验证。（推断）这条常被宣传叙事忽略——"1M 上下文"是模态特化的成果，不能直接等同于"聊天窗口可塞一本书"。

### 5.2 独立观察到的四个疑点

**① "匹配 2 倍尺寸"的比较口径问题**：Mamba 与 Pythia 同为 300B tokens 训练，但 Transformer 家族在该 token 预算下处于严重欠训练区（Chinchilla 最优配比下 3B 模型应喂更多 tokens）。（推断）"Mamba-3B 匹配 6.9B Pythia"部分反映的是 Mamba 的参数效率，另一部分反映的是**双方都在远离各自最优点的训练制度下比较**；后来 Llama 式高 token 预算的训练制度普及后，这一差距的实际幅度需要重新校准。这不是否定结论，而是提醒结论的条件性。

**② Induction Heads 外推的评测深度**：4000× 外推是合成任务上的完美成绩，但测试 vocab 仅 16、任务仅 induction 一种模式。（推断）真实语言的 ICL 依赖多种叠加机制（位置敏感、语义聚类、格式遵循等），单一机制的完美外推是必要非充分条件，向真实 ICL 能力的推广链有一环缺失——而这恰与局限③（affordances 未验证）互为印证。

**③ 消融的完备性缺口**：Table 6/7/8/10 覆盖了 block 结构、选择性参数、初始化与状态维，但没有回答"选择机制的收益中有多少来自 softplus-Δ 的门控效应、多少来自真正的跨时间步内容路由"——毕竟批评者可以主张 S6 只是"更好的门控"。合成任务的对照（门控架构只部分改善）提供了间接反驳，但缺少在同一架构内"仅门控 vs 全选择"的直接单变量对照。（推断）这一缺口后来成为 Mamba-2 用 SSD 框架统一"SSM 即（退化的）注意力/门控"的理论动机之一。

**④ 效率对比的硬件锚定**：所有速度数字锚定于 A100 80GB 单卡与 prompt 2048 设定。FlashAttention-2 与 selective scan 在不同代际硬件（Hopper 的 TMA、更低精度单元）上的相对表现会随硬件特性漂移；（推断）">2K 后 scan 快于 FA-2"的交叉点是硬件相关的工程常数，不应被当作架构间的普适定律引用。

> **一句话小结**：本文的证据质量在同代架构论文中属第一梯队（消融细致、合成诊断精彩），但其全部头条结论共享同一个前提条件——"中小模型 + Chinchilla 制度 + A100 时代"；这些前提在 7B+ 规模、长 token 制度与新硬件下的稳定性，论文自己已经诚实地挂起了问号。

## 六、启示提炼：可迁移的经验与历史走向

### 6.1 五条可迁移启示

1. **把权衡翻译成压缩问题是最强的理论杠杆**：论文最漂亮的一步不是 S6 本身，而是"序列建模 = 上下文压缩进有限状态"这个视角转换——注意力与 RNN 从此不再是两个物种，而是压缩谱系的两个端点。（推断）任何"效率 vs 质量"之争都可以尝试此类统一框架，往往能把二选一的伪问题降解为可优化的真参数。
2. **合成任务是机制研究的一等公民**：Selective Copying 与 Induction Heads 以极低成本完成了真实基准做不到的机制归因。方法论可直接迁移：为怀疑的能力缺口设计最小失败案例，再验证修复——这比在真实榜单上盲试快得多。
3. **打破不变性要先修好工程账**：选择机制在数学上半页纸就能写完，但若没有 kernel fusion/parallel scan/recomputation 三件套，它在真实硬件上就是负资产。**理论自由度的每一次扩张都必须配套硬件感知的实现方案**，否则论文只会停留在玩具阶段。
4. **与在位者逐项对齐是挑战者的礼仪与策略**：均质 block、E=2 扩展、两层对齐 12D²、同 tokenizer 同 tokens——Mamba 把一切可能被指摘的混淆变量提前锁死，使其结论难以被"不公平比较"攻讦。挑战性工作的对比协议设计范本。
5. **状态扩张的成本曲线是架构设计的隐藏主轴**：N=16 仅 +1% 参数换来 >1.0 ppl 改进，暗示"加大状态、学会管理"可能普遍优于"加大参数、被动记忆"。（推断）这一原则后来在 KV cache 压缩、linear attention、混合专家记忆等方向上反复重现。

### 6.2 局限的走向与历史坐标

- **Scaling 之问（对应局限①）**：≤350M 的验证域注定被追问，后续社区在 7B+ 规模上的复现与混合架构（如 Jamba 式 attention+SSM 交替）成为自然延伸；（推断）"纯 SSM 是否够"逐渐让位于"SSM 占多大比例最优"。
- **生态之问（对应局限③）**：affordances 缺口指向微调/量化/推理栈适配的补课，这决定了学术架构能否变成产业基础设施。
- **光谱之问（对应局限②）**：连续-离散权衡暗示未来的多模态统一模型可能需要**模态自适应的选择强度**，甚至混合 LTI 与选择性分支。
- （推断）历史坐标：Mamba 与 FlashAttention 同出一门（Tri Dao），共同确立了"硬件感知算法 + 结构先验"的研究纲领；选择机制的思想随后辐射到视觉、基因组、推荐、语音等领域，并与线性注意力、RVQ 记忆等工作合流，构成后 Transformer 时代架构探索的主干道之一。

## 总结

《Mamba》是一次教科书级的架构研究：它先用压缩视角重构问题（注意力不压缩、循环不可控压缩），再用两个合成任务把 LTI 的失败钉死在最小案例上，然后用一行公式的选择机制（Δ, B, C 输入化）打开理论闸门，用 selective scan 三件套在硬件上兑现线性时间的承诺，最后以逐项对齐的实验协议交出全线证据——Mamba-3B 匹配 2× 尺寸 Transformer、推理吞吐 5×、Induction Heads 外推 4000×、SC09 FID 从 7.7 降至 0.94。其局限同样清晰：scaling 域 ≤350M、生态 affordances 未验、连续-离散光谱的自我设限，以及全部头条数字所共享的"A100 + Chinchilla 制度"前提。但无论后续缩放争议如何演化，本文确立的方法论遗产——压缩视角、合成诊断、硬件感知、对齐式对比——已经成为序列建模乃至整个深度学习架构研究的通用语法。
