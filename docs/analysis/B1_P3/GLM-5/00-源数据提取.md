## §4 方法细节

### 4.1 架构
- **MLA (Multi-Latent Attention)**：使用降维的 key-value 向量，在 Muon 优化器实验中，576 维 latent KV-cache 的 MLA 表现不及 GQA-8（8 个 query 组，2048 维 KV-cache）。两种变体：**MuonSplit**（将 up-projection 矩阵 W_U, W_Q, W_K, W_V 按 head 拆分并分别正交化），使 MLA 匹配 GQA-8；**MLA-256**（head 维度 192→256，头数减 1/3），保持训练计算与参数量不变，降低解码计算。
- **MTP (Multi-Token Prediction)**：训练时共享 3 个 MTP 层的参数，使 draft model 内存成本与 DeepSeek-V3 一致，同时提升 accept rate（GLM-5 2.76 vs DeepSeek-V3.2 2.55）。
- **DSA**：颠覆 dense O(L) attention，以动态细粒度 selection 机制代替固定 pattern（如 sliding window）；两阶段 dense-warm-up + sparse-training-adaptation 从 dense 模型过渡。

### 4.2 预训练数据与 mid-training
- **Web**：引入基于 sentence-embedding 的 DCLM 分类器 + World Knowledge 分类器（基于 Wikipedia + LLM 标签），从 medium-low quality 数据中提取长尾知识。
- **Code**：扩大语料，fuzzily dedup 唯一 token 增 28%；修复 Software Heritage metadata alignment；为低资源语言（Scala/Swift/Lua 等）训练专用分类器。
- **Math & Science**：用 LLM 打分候选文档；对长上下文档用 chunk-and-aggregate scoring；严格过滤合成/AI/模板数据。
- **Mid-training**：200K 阶段加入 MRCR-类数据；合成数据用 interleaved packing（NextLong/EntropyLong 启发）缓解 lost-in-the-middle。

### 4.3 训练基础设施
- 内存：灵活 MTP 布局（co-locate 输出层）、Pipeline ZeRO2 gradient sharding、Muon 零冗余通信、pipeline activation offloading（host memory）、sequence-chunked output projection。
- 并行：deferred weight gradient computation；长序列用 workload-aware reordering + 动态 redistribution + 分级 context-parallel groups + hierarchical all-to-all。
- INT4 QAT（SFT 阶段），且开发了训练+离线权重量化共用 kernel，保证 bitwise-identical 行为。

### 4.4 后训练
- **3.1 三种思考模式**：Interleaved Thinking（每次响应与 tool call 前思考）、Preserved Thinking（在 coding agent 场景跨多轮保留全部 thinking block）、Turn-level Thinking（逐轮控制，轻量请求关、复杂任务开）。
- **3.2 Reasoning RL**：基于 GRPO 并集成 IcePop 的 training-inference mismatch 策略；明确区分 train π 与 infer π；移除 KL 正则以加速；on-policy，β=2, ε_low=0.2, ε_high=0.28，group size 与 batch size 32。
- **3.4 General RL**：三维目标（foundational correctness / emotional intelligence / task-specific quality）；混合奖励系统（rule-based rewards + ORM + GRM）；引入高质量的 human-authored 响应作为风格锚点。
- **3.5 On-Policy Cross-Stage Distillation**：将前一阶段 checkpoint 作为 teacher，advantage 项替换为 gap 项（式2），group size=1，batch size=1024。
- **3.6 slime Framework**：高度可定制 rollout，HTTP API 服务器式 rollout，tail-latency 优化（no-queue serving、FP8 rollout、MTP、PD disaggregation），heartbeat-driven fault tolerance。

### 4.5 Agentic Engineering（§4）
- **4.1 异步 RL**：解耦训练/推理引擎到不同 GPU；轨迹达到阈值后批量送训练；每 K 次梯度更新同步权重；重置 optimizer 以应对 off-policy。
- **4.1.1**：server-based Multi-Task Rollout Orchestrator，统一 message-list 表示，轨迹标准化。
- **4.1.2 稳定性**：TITO 保持逐 action 对应；Direct Double-sided Importance Sampling 用 rollout log-prob 直接作 behavior proxy，避免维护历史 checkpoint 历史；对超长 off-policy 样本用版本差阈值 τ 丢弃；用 DP-aware routing + consistent hashing 保持 KV cache locality。

### 4.6 环境扩展（§4.2）
- SWE：RepoLaunch 框架构建可执行环境，提取 F2P/P2P 测试。
- Terminal：seed data 三阶段合成（draft 生成→concrete 实施→迭代优化），Harbor 格式；web-corpus 闭环自校验 pipeline。
- Search：WKG 构建（>2M pages）+ 高难 QA 过滤（排除 tool-free 可答、早期 agent 几步可答、验证 agent 双向校验）。
- Slide：HTML-based，多级奖励（Level-1 静态 markup、Level-2 运行时渲染属性、Level-3 视觉感知特征），自改进 pipeline + rejection sampling + masking 修正。

### 4.7 国产芯片适配（§5）
- Ascend Atlas 案例：W4A8 混合精度量化（Attention/MLP 用 W8A8/INT8，MoE experts 用 W4A8/INT4，msModelSlim 工具 + QuaRot 离群抑制 + Flex_AWQ_SSZ），融合 kernel（Lightning Indexer、Sparse FlashAttention、MLAPO），推理引擎优化（vLLM-Ascend/SGLang 异步调度、RadixCache/PrefixCache、DP+EP 混合、FlashComm、MTP）。
- 结论：单节点国产性能比肩双 GPU 国际集群，降低长序列部署成本 50%。

## §6 局限

- **静态基准 vs 真实能力差距**：作者强调"真实经验比 leaderboard 更重要"；CC-Bench-V2 移除人工标注，全程自动化（Claude Code + 单测 + Agent-as-a-Judge）。
- **ISR 落后 Claude Opus 4.5**：GLM-5 满足单个需求（CSR 高、BSR 98%），但完整端到端任务 ISR 仍落后（HTML 38.9 vs 52.2，React 34.6 vs 39.7），指出完成整任务的能力差距。
- **Chained Tasks 错误累积**：长程链式任务中单个任务的次优编辑会静默破坏后续测试，GLM-5 52.3 vs Claude Opus 4.5 61.6（Table8）；作者指明需推进 long-context consistency 与 long-horizon self-correction。
- **SWE-rebench 上落后**：相较于 Claude Opus 4.5 的 ResolvedRate 52.9%，GLM-5 42.1%；相较于 GPT-5.2(xhigh) 51.7%。
- **泛化与前沿差距**：作者承认 open-weights 与绝对静态前沿的差距正在缩小但"竞赛远未结束"；在演进型 SWE（SWE-rebench）上仍低于闭源前沿。
- **架构效率原因**：GLM-5 选择 DSA 而非 SWA/GDN/SimpleGDN 等线性注意力，因为这些方法在细粒度检索任务有不可避免的信息损失（RULER@128K 差至 5.69 点、RepoQA@128K 至 7.33 点）。
- **方法学透明性与主观局限**：作者在 §8 Easter Eggs 提到 PonyAlpha 匿名发布验证（25% 用户猜是 Claude Sonnet 5，20% DeepSeek，10% Grok），表明该报告相较于纯技术 paper 更偏叙事。
- **环境噪声**：Terminal-Bench 2.0 依赖 agent framework（Terminus-2 / Claude Code），不同框架结果波动（56.2 与 56.2/61.1），可能受框架配置影响而非模型纯能力。
