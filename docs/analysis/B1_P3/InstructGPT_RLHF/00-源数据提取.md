## §4 方法细节

### 4.1 三步法总览（§3.1，Fig.2）
1. **Step 1 — SFT**：标注者写"期望行为"演示，在 prompt 分布上用监督学习微调预训练 GPT-3。
2. **Step 2 — RM**：采集模型输出之间的比较数据（标注者指出哪个更受偏好），训练 reward model 预测人类偏好输出。
3. **Step 3 — PPO**：以 RM 输出为标量奖励，用 PPO 微调监督策略。Steps 2–3 可迭代。

### 4.2 训练细节（§3.5）

**SFT**：训练 16 epochs，cosine 学习率衰减，残差 dropout 0.2；最终模型按验证集 RM 分数选择。尽管 1 epoch 后验证 loss 就过拟合，多 epoch 训练确能提升 RM 分和人类偏好。

**RM**：从去掉最终 unembedding 层的 SFT 模型出发；仅使用 6B RM（省算力；175B RM 训练不稳定，不宜作 RL 价值函数）。让标注者对 K=4 到 K=9 个响应排序，每 prompt 产生 C(K,2) 个比较；用"整包 batch element"而非打散，避免过拟合。损失函数（Eq.1）：

loss(θ) = −1/C(K,2) · E_{(x,yw,yl)~D}[log(σ(rθ(x,yw) − rθ(x,yl)))]

RM 损失平移不变，故 RL 前用 bias 将标注者演示均值归一化为 0。

**RL（PPO）**：环境为 bandit——随机给客户 prompt、期望响应，RM 给奖励并结束回合。加 per-token KL penalty（从 SFT 模型，β 系数）抑制对 RM 的过度优化。价值函数由 RM 初始化。

**PPO-ptx 综合目标（Eq.2）**：

objective(φ) = E_{(x,y)~D_πRL}[ rθ(x,y) − β·log(πRL_φ(y|x)/πSFT(y|x)) ] + γ·E_{x~D_pretrain}[ log(πRL_φ(x)) ]

其中 γ=0 即 "PPO"；论文默认 InstructGPT 指 PPO-ptx。

### 4.3 数据采集（§3.2–3.4）
- prompt 主要来自 OpenAI API Playground（早期 InstructGPT 版本），按 user id 切分 train/val/test，保证测试集用户不进训练；过滤 PII。
- 约 40 名承包商（Upwork / ScaleAI），经 screening test 筛选，敏感性测试。
- 标注者写三种 prompt：Plain、Few-shot、User-based。数据集 >96% 为英文。
- 训练时优先 helpfulness；最终评估时优先 truthfulness 与 harmlessness。

## §5 实验结果要点

- **API 分布偏好（Fig.1, Fig.4）**：GPT-3 最差；逐步改进顺序 GPT-3(prompted) → SFT → PPO。InstructGPT 输出更符合客服助手语境、更常遵循显式约束（如"2 段内回答"）、更少完全漏跟指令、闭域更少幻觉。
- **TruefulQA（Fig.6）**：PPO 模型比 GPT-3 更真实（默认行为，无需专门提示）；例外是 1.3B PPO-ptx 比同尺寸 GPT-3 略差。加 "Instruction+QA" prompt（不知道时说"I have no comment"）时，PPO 倾向"真实但不详尽"而非自信地编造。
- **毒性（Fig.7）**：respectful prompt 下 InstructGPT 毒性低于 GPT-3（Perspective API + 人工双确认）；无 prompt 时优势消失；被明确要求生成有毒输出时 InstructGPT 比 GPT-3 更有毒。
- **偏置**：Winogender / CrowS-Pairs 上未比 GPT-3 更少偏置；被要求 respectful 时熵更低、偏置更高（模型对输出更确定）。
- **对齐税**：PPO-ptx 大幅缓解 SQuADv2/DROP/翻译的回归，HellaSwag 甚至反超；增大 KL 系数会导致验证奖励显著下降且无法完全恢复（Fig.33/34 对比）。
- **定性（Fig.8/Fig.9）**：泛化到非英语指令与代码问答；但会犯简单错误——被含假前提的指令"带偏"、过度 hedge（回避直接回答）、多约束指令性能下降。推测 hedge 源于标注者奖励"认知谦逊"，false-premise 因训练集缺乏此类样本。
- **对齐成本**：RLHF 效果超过"单纯变大 100×"，相比预培训成本很低（§5.1）。

## §6 局限

- **方法论**：行为部分由承包商反馈决定，受其身份/文化/看法的价值判断影响；团队仅约 40 人，主要是英语母语者，数据几乎全英文，不具代表性。多数比较仅由 1 名承包商标注（成本原因），难识别分歧并在分歧中加权少数群体偏好。
- **模型**：既非完全对齐也非完全安全——仍会生成有毒/偏置输出、编造事实、无提示生成色情暴力内容。最大局限是多数情况下仍会遵从用户指令，即使会导致现实伤害（如被要求最大偏置时比 GPT-3 更有毒）。
- **对齐对象**：对齐到的是特定群体（标注者、研究人员、API 客户）的偏好，而非更广泛的"人类价值"；OpenAI 客户来自 waitlist，初始种子为内部员工，具偏倚。
- **其他**：训练/评估标准冲突、公共 NLP 数据集不代表真实使用、泛化范围有限。
