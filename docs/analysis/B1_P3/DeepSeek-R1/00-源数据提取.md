## §4 方法细节

**GRPO 核心与 PPO 差异**：GRPO（Shao et al. 2024）省去 value model，用组内奖励均值/标准差直接估计 advantage：A_i = (r_i - mean({r})) / std({r})（式3）。PPO 则依赖 GAE+value model（与 policy 同量级，内存/算力开销大），且对长 CoT 模型难以从部分响应预测最终奖励。KL 差异：GRPO 以无偏估计直接加入 loss（式11），PPO 以逐 token dense reward 惩罚累计 KL，可能隐性抑制响应长度增长。PPO 对 GAE λ 敏感（λ=0.95 明显差于 GRPO；调 λ=1.0 才接近），需额外超参调优成本（Fig4，用 DeepSeek-Coder-V2-Lite 16B MoE，2.4B 激活，在 MATH 上）。

**RL 数据（Table 4，p19-20）**：Math 26K（定量推理，输出为数值/表达式/方程）；Code 17K（算法竞赛）+ 8K（bug 修复，来源真实 GitHub issue）；STEM 22K（多选，15.5% 物理 / 30.7% 生物 / 46.5% 化学 / 7.3% 其他）；Logic 15K（真实网络题+合成 code-IO/谜题，平均约 420 tokens）；General 66K（helpfulness，含创意写作/编辑/事实问答/角色扮演）+ 12K（harmlessness）。

**冷启动（Cold Start）数据（§B.3.2，p20-21）**：由人类标注员将 R1-Zero 推理轨迹改写为自然对话式（第一人称、语言一致、含反思与验证）；再用 LLM 以改写对为示例批量重写，二次人工核验。代码数据：5,151 Codeforces 题 + 2,504 AtCoder 题；原始测试集不公开，用 DeepSeek-V2.5 生成候选测试用例，两阶段过滤（正确提交消除无效用例，再用错误提交筛选有区分度用例）。

**训练基础设施（§B.1，p17-18）**：模块化解耦为 Rollout / Inference / Rule-based Reward / Training 四模块。Rollout 用 vLLM workers + MoE 专家并行（跨节点）+ 冗余 hot-expert 拷贝 + MTP self-speculative 解码。规则奖励模块用异步调度与 Rollout/Inference 重叠以隐藏延迟。Training 支持 PPO/GRPO/DPO，数据按长度排序+Best-Fit 打包，集成 DualPipe 管线并行。各模块完成后自动从 VRAM offload 到系统内存/磁盘。

**去污染（§D.1，p40）**：10-gram 过滤；DeepSeek-V3 知识截止 2024-07，早于 CNMO2024 等基准；仅数学域就移除约 600 万条预训练文本；post-training 数学 SFT/RL prompt 仅用 2023 年前竞赛题。作者承认 n-gram 无法防 paraphrase，2024 前发布基准仍可能污染。

**评估设置（§D.1，p40）**：pass@k，温度 0.6，top-p 0.95；k=64（AIME/GPQA）、k=16（MATH/Codeforces）、k=8（LCB）；AIME2024 另报 cons@64（64 采样多数投票）；输出封顶 32,768 tokens。评估用 zero-shot，因 few-shot CoT 反而损害 R1 表现。

## §5 实验结果要点

1. **R1-Zero 自我演化**：纯 RL 不教推理，却能自动涌现验证、反思、备选方案探索、思考时长增长（Fig1b）。出现"aha moment"（Table 2，p5）：模型在中途用拟人语气自语 "Wait, wait. That's an aha moment I can flag here. Let's reevaluate..."，标志 reasoning pattern 显著转变。
2. **R1 多阶段收益**：R1-Dev1（冷启动后）在指令跟随（IF-Eval/ArenaHard）大幅改善，但 AIME 因冷启动数据量有限略降；R1-Dev2（拒绝采样+SFT 后）在推理/STEM 基准上显著提升；R1-Dev3（融非推理数据）改善 AlpacaEval/Aider；最终 R1 以 AlpacaEval +25%、ArenaHard +17% 为主要提升（§4, p9）。
3. **推理为主维度的增益**：RL 显著提升数学/编程/STEM 推理，但对用户偏好类基准影响有限（§4, p9）。
4. **ChatbotArena（§D.2/D.2, p43）**：2025-01-24（发布一周后），R1 在 style control 设置下与 OpenAI-o1、Gemini-Exp-1206 并列第一；MIT 许可开源模型达到与闭源同级。数学/编程分项排名强。

## §6 局限

（§6，p10-11）作者自述主要局限：① 结构化输出与工具使用能力现阶段较弱（不能用搜索引擎/计算器）；② Token 效率不最优，简单问题上出现 "overthinking" 过度推理；③ 语言混合问题——仅针对中英优化，处理其他语言查询时可能坚持以英文推理/回答（与 DeepSeek-V3-Base 中英数据有关）；④ 对 prompt 敏感，few-shot 一致降低性能，推荐 zero-shot 直接描述问题+指定输出格式；⑤ 软件工程任务：评估时间长拖累 RL 效率，R1 相对 V3 增益有限，未来用拒绝采样或异步评估。

**方法论固有挑战**：Reward Hacking——纯 RL 依赖可靠奖励信号；规则型 RM 对写作等任务难以构造；若用模型分配奖励，随训练推进更易被 hack，政策会找到捷径。对能有效构造 verifier 的任务潜力巨大，但可靠奖励模型难构建的任务仍是开放挑战。

**安全（§5 Ethics + §D.3 Safety Report，p10 / p44-48）**：内建安全级为中等（约与 GPT-4o(2024-05-13) 相当）；部署时配合**外部风险控制系统**可升至更优级别。该系统：关键字匹配过滤潜在危险对话 + 用 DeepSeek-V3 跑风险审查 prompt（Listing 8，11 条安全标准）判定是否撤回。公开模型易受进一步 fine-tuning 破坏内建安全；更强的推理能力也使 jailbreak 后产出的危险方案可执行性更高。Table 9 显示 R1 平均安全分 95.0（无风险控制 85.9），HarmBench 89.3（无风险控制 35.0，缺口主要在知识产权/歌词类）。自建 in-house 基准：4 大类 28 子类，1,120 题（每子类 20 中文+译英），GPT-4o(2024-11-20) 判 Unsafe/Safe/Rejection 三类。
