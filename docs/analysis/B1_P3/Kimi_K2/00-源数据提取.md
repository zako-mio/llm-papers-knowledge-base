## §4 方法细节

**MuonClip（§2.1，Algorithm 1）**：Muon 优化更 token-efficient（同等 compute 与数据下明显优于 AdamW，见 Moonlight 工作）。但放大 Muon 训练引出 instability——attention logits 爆炸（mid-scale 9B 激活/53B 总参数模型在 vanilla Muon 下 max logit 迅速超 1000，导致 loss spike/divergence）。QK-Clip：对每个 attention head h，用 per-head max logit S^h_max = max_i,j (Q^h_i·K^h_j)/√d 判断；当 S^h_max > τ 时设 γ^h = min(1, τ/S^h_max)，按 α=0.5 均衡缩放 W_q^h、W_k^h。因仅少数 head 爆炸，采用 per-head，最小化对训练的干预。对 MLA 只 clip 未共享组件：q^c/k^c（head-specific）各乘 γ，q^R（rotary）乘 γ，k^R（shared rotary）不动以免跨 head 影响。对比现有方案：logits softcap 会先 cap 但点积仍已暴增；QK-Norm 不适用于 MLA（其 Key 矩阵推理期间未完整物化）。附录 D 证明 QK-Clip 不损模型质量；附录 E 解释 Muon 更易受 logit 爆炸：当 head 数量相对 layer 数量翻倍时，更多 head 各自累积高 logit。

**预训练数据重写（§2.2）**：提升 token utility（每 token 有效信号）。重写优于多轮重复（重复致过拟合）。两类重写：
- Knowledge data rephrasing（Synthetic 2.0）：style/perspective 多样 prompt（受 WRAP 启发）+ chunk-wise auto-regressive 生成（拼回完整段落保全局连贯）+ fidelity 校验（与原文本语义对齐）。Table 1：SimpleQA 准确率对比——原始 wiki 10 epochs=23.7；重写 1 次+10 epochs=27.3；重写 10 次+单遍=28.9。各语料最多重写 2 次。
- Math data rephrasing：按 SwallowMath 方法改写为"learning-note"风格，另将其他语言高质量数学材料译英增多样性。
作者指出合成数据作为持续扩源策略仍是 active research，挑战在于泛化到多样源域、不牺牲事实性、最小化幻觉/毒性、大规模可扩展性。

**模型架构（§2.3）**：01.04T MoE + MLA，hidden dim 7168，MoE expert hidden 2048。sparsity scaling law：固定激活参数（恒定 FLOPs）下，增总专家数（增稀疏度）一致降低 train/val loss（Fig5）。结合经济账与基建复杂度取了 48（8/384 激活）。头数权衡：DeepSeek-V3 设头数≈2×layer 数以利用内存带宽；但 128k 序列时加倍头（64→128）致推理 FLOP +83%，对 long-context agentic 应用不利；iso-token 下加倍头仅改善 val loss 0.5%~1.2%，故取 64 头。

**RL 可验证奖励 Gym（§3.2.1）**：
- Math/STEM/logic：多样覆盖 + 中等难度（用 SFT 模型 pass@k 选，过易或过难都生不出信号）。
- 复杂指令跟随：混合规则验证（code interpreter 确定性验证 + LLM-as-judge）+ hack-check 层防"声称满足但未兑现"；多源指令生成（专家条件 prompt / AutoIF agentic 增强 / 微调模型探针失败模式）。
- 忠实度：受 FACTS Grounding 启发，训 sentence-level faithfulness judge 模型，识别无证据支持的句子，作 reward model 提升整体忠实度。
- 编码/软件工程：竞赛题+judge（开源+合成），混入预训练高质量人工单测；软件工程用 GitHub PR/issue + 可执行单测，Kubernetes 沙箱支持 1 万+并发。
- 安全：人工种子 prompt（暴力/欺诈/歧视）+ 自动化 prompt evolution（Attack 模型迭代生成对抗 prompt / Target 模型响应 / Judge 模型判定是否绕过，用 task-specific rubric 给 binary 判据）。

**Self-Critique Rubric Reward（§3.2.2）**：把对齐从可验证任务扩展到开放式主观任务。K2 actor 对 general prompt 生成响应，K2 critic 用 pairwise 评价按 rubric 排——含 core rubrics（Kimi 核心价值观）、prescriptive rubrics（防 reward hacking）、人写 rubric。critic 在 SFT 阶段用开源+自有权重偏好数据初始化判据能力；RL 中用可验证信号闭环精炼 critic（on-policy rollout 蒸馏 RLVR 目标信号进评估模型）。critic 有权对 rubric 按内部先验加权，保持与自身动态行为的连贯对齐。

**RL 基础设施（§3.3）**：colocated 架构（train/infer 同 worker，交替让出 GPU）。engine switching 用分布式 checkpoint engine 广播全参数集（即使传输量数倍于理论最优，用简化设计换解耦；优于 transfer-what-you-need 的同步开销）。系统启动：训练 worker 每者选择性读部分/零参数再从对等节点广播，确保全体读 checkpoint 仅一次；复用一个 checkpoint engine 承担推论引擎启动更新，并对单点失败鲁棒。agentic rollout：重环境作独立可扩展服务 + 高并发 rollout 摊薄延迟；用 partial rollout（K1.5）暂停长尾未完成轨迹，下一轮续跑；用类 OpenAI-Gym 统一接口简化新环境接入。

**评估配置（§4.1.1）**：全部非 thinking 模式；输出 token 上限 8192（SWE-bench Verified Agentless 提至 16384）；高方差基准用 Avg@k；long-context 设 128K；SWE-bench Verified 分 agentless（single patch）与 agentic（single attempt / multiple attempts + best-of-N internal verifier）两模式；SWE-bench Multilingual 仅单次 agentic。开源基线 DeepSeek-V3-0324、Qwen3-235B-A22B（vendor 推荐 no-thinking 模式）；闭源 Claude Sonnet 4 / Claude Opus 4 / GPT-4.1 / Gemini 2.5 Flash Preview，全部统一温度/top-p。

## §5 实验结果要点

1. **Agentic & 竞争性编程**（§4.1.2, p15）：Instruct 版在真实 SWE 任务达开源 SOTA。SWE-bench Verified 65.8%（71.6% 多次尝试）、SWE-bench Multilingual 47.3%、SWE-Lancer 39.1%，显著缩小与 Claude 4 Opus/Sonnet 差距。竞争性编程 LiveCodeBench v6 53.7%、OJBench 27.1% 也在所有模型中领先。
2. **工具使用**（§4.1.2, p17）：τ-Bench 66.1、AceBench 76.5，大幅超所有基线，确立在 grounded/controlled/agent-driven 工具编排上的强项。
3. **通用能力**：SimpleQA 31.0%、MMLU 89.5%、MMLU-Redux 92.7%、IFEval 89.8%、Multi-Challenge 54.1%（领先），AIME2024 69.6%、GPQA-Diamond 75.1%、DROP 93.5%、MRCR 55.0%，长短上下文均衡。
4. **Base 模型（§4.2.2, p17-18）**：12 个英文基准中 10 个 SOTA（MMLU 87.79 / MMLU-Pro 69.17 / MMLU-Redux 90.17 / SuperGPQA 44.67 / SimpleQA 35.25）；代码 CRUXEval-I-cot 74.00 / CRUXEval-O-cot 83.50 / LiveCodeBench v6 26.29 / EvalPlus 80.33；数学 MATH 70.22 / GSM8K 92.12 / GSM8K-Platinum 94.21 / CMATH 90.26（略输 DeepSeek-V3-Base 90.53）；中文 C-Eval 92.50 / CMMLU 90.90 / CSimleQA 77.57 全 SOTA。
5. **安全（§4.3.2，Table 6，p19）**：与 DeepSeek-V3-0324、DeepSeek-R1、Qwen3-235B-A22B 用 promptfoo 对比。复杂度告警：如 Harmful–Iterative Jailbreak 通过率 Kimi 92.16（DeepSeek-V3 66.67 / R1 72.55 / Qwen3 74.51）相对偏高（作者称未针对该评估场景做定向优化）。策略趋势：Base64 策略下各模型通过率普遍趋近 100%（编码变换对基础鲁棒性影响小）；Crescendo 策略普遍拉低通过率（对抗更有效）；复杂攻击不总优于基础 prompt（多轮变换后对抗意图可能失真）。Kimi 在 Criminal–PromptInjection 75.76、Security–IterativeJailbreak 43.90 等弱项暴露。

## §6 局限

（§5, p20）作者自述：
1. 面对硬推理任务或工具定义不清晰时，模型可能生成过量 token，导致输出截断或工具调用不完整。
2. 某些任务若不必要的启用了 tool use 时，性能反而可能下降。
3. 构建完整软件项目时，单次 prompting 成功率不如把 K2 置于 agentic coding 框架下使用。

**自动红队局限（§4.3.2 end, p20）**：由于涉及人工审阅，评估结果含主观性；部分 plugin 类型涉及 API 滥用或外部工具调用，更适合评估具备 tool-calling 的 agent 模型，对 base LLM 相关性有限。附录 F 亦列 critic rubric 的局限。

**未来方向**：作者指出 synthetic data 作为持续缩放的策略仍是 active research；simulation 保真度是局限，故用真实执行沙箱互补；RL 基础设施计划扩展至更多样交互环境。
