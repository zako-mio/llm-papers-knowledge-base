## §3 核心主张与关键数字表

**核心主张**: 指令微调（instruction tuning）——在"用自然语言指令表述的数据集集合"上微调预训练语言模型——能大幅提升模型在**未见任务**上的 zero-shot 能力。用 137B 预训练模型在 60+ NLP 数据集上做指令微调得到 FLAN，显著优于未微调模型，并在 20/25 个评估数据集上超越 zero-shot 175B GPT-3。

## §4 方法细节

- **任务与模板（§2.1）**: 62 个 TensorFlow Datasets 公开数据集（含语言理解与生成任务）聚合为单一 mixture，归入 12 个 task clusters：Natural language inference (7)、Commonsense (4)、Sentiment (4)、Struct to text (4)、Closed-book QA (3)、Coreference (3)、Translation (8)、Summarization (11)、Reading comp. (5)、Paraphrase (4)、Read. comp. with commonsense (2)、Misc. (7)。每数据集手工 10 个自然语言指令模板；为增多样性，每数据集附最多 3 个"反向/换位"模板（如情感分类反向生成影评）。
- **评估流程（§2.2/2.3）**: 按任务类型把数据集分成聚类，**每个评估任务聚类用不同 checkpoint**——训练时 hold out 该聚类，只用其余聚类做指令微调，从而测"未见任务"的 zero-shot 能力。
- **训练细节（§2.4）**:
  - 架构: LaMDA-PT——dense left-to-right decoder-only Transformer，137B 参数；仅有语言模型预训练（对比 LaMDA 额外做了 dialog 微调）。
  - 预训练数据: web 文档（含代码）/dialog/Wikipedia，2.49T BPE tokens，32k 词表，SentencePiece；~10% 非英语。
  - 指令微调 pipeline: 混合所有数据集，随机采样；每数据集限制 30k 训练示例；用 examples-proportional mixing scheme（mixing rate max 3k）。
  - 优化: Adafactor，lr 3e-5，30k 步，batch 8192 tokens，输入/目标 1024/256；用 packing 把多示例拼成单序列，EOS 分隔输入与目标；TPUv3 128 核约 60 小时。
- **评估度量**: 对每个数据集报告所有模板的平均值（近似典型自然语言指令下的期望表现）；若有 dev set 可用则另取 dev 表现最佳模板的 test 值。
- **对比基线**: LaMDA-PT（用同 GPT-3 prompt 报告 zero/few-shot），GPT-3 175B（Brown et al. 2020），GLaM 64B/64E（Du et al. 2021）。

## §5 实验结果要点

1. **通用结论（Fig 5, P5）**: FLAN zero-shot 在 NLI 上以大优势优于所有基线（因 GPT-3 的 NLI 用延续式表述别扭，FLAN 用更自然的 "Does <premise> mean that <hypothesis>?"）；reading comprehension 在 MultiRC、OBQA 优于基线，BoolQ 大超 GPT-3（LaMDA-PT 本身已高）；closed-book QA 在全部 4 数据集优胜 GPT-3；翻译 6 项评估全胜 zero-shot GPT-3、多数不及 few-shot GPT-3（因英语 tokenizer 且预训练以英语为主）。
2. **指令微调有效的任务类型**: 对自然表述为指令的任务（NLI、QA、翻译、struct-to-text）非常有效；对直接是语言建模形式、指令冗余的任务（commonsense、coreference 的补全式）帮助有限甚至无效——7 个此类任务 FLAN 仅 3 个优于 LaMDA-PT（§3 负面结果）。
3. **集群数扩展（Fig 6）**: 增加指令微调聚类数总体提升 held-out 表现（49.9→63.5 平均改善），未饱和，说明更多聚类可能进一步改善；sentiment 聚类增值最小。
4. **缩放定律（Fig 7, P7）**: 模型 422M/2B/8B/68B/137B；对 ~100B 级模型指令微调大幅提升 held-out 任务，但对 8B 及以下**反而损害**通用化——推测小模型容量被 ~40 个任务完全占满；大模型分出一部分容量学指令、余下容量学迁移。
5. **指令的作用（Fig 8, P7）**: 对比"无模板"（仅输入输出）与"数据集名"（prefix 任务/数据集名）两个无指令微调设置；两者都显著差于用自然指令的 FLAN（37.3 / 46.6 / 47.0 vs 55.2 四聚类均值——无指令设置用 FLAN 指令做推理）→ 证明**训练指令对未见任务 zero-shot 至关重要**。
6. **few-shot 增强（Fig 9, P8）**: 对所有任务聚类，few-shot exemplars 提升性能；对输出空间大/复杂任务（struct to text、翻译、closed-book QA）尤其有效；few-shot FLAN 的模板间再方差更低，提示对 prompt 工程敏感度降低。
7. **促进 prompt tuning（Fig 10, P8）**: 在 SuperGLUE 各任务上，FLAN 的 soft prompt（prompt length 10，weight decay 1e-4，无 attention dropout）均优于 LaMDA-PT；低资源（32 训练示例）场景常超 10% 提升。

## §6 局限

- 指令微调**不改善许多语言建模式任务**（如补全式的 commonsense/coreference）——当任务与原预训练目标一致时指令冗余、无益（7 个中仅 3 个胜出）。
- 翻译方向不平衡：翻译**成英语强**、从英语译出较弱（英语 SentencePiece tokenizer + 多数预训练数据为英语）；多数情况下 few-shot GPT-3 在翻译上仍优于 FLAN。
- 结果为多聚类 hold-out 消融，未及确定**每个指令微调聚类对各评估聚类的具体贡献**。
- 基础模型 137B 导致**服务成本高昂**（作者在 Discussion/结论中提及）；依赖预训练数据规模与分布。
- 与 GPT-3/GLaM 的对比为论文报告值（非同设置复现），且评估模板按 dev 选择，存在一定的评估偏差。
