## §4 方法细节

### 4.1 稀疏路由的简化（§2.1, p5）
- 借鉴 Shazeer et al. (2017) 的 MoE 层。输入的 token 表示 x 被路由到 top-k 专家，从 N 个专家 {E(x)}_i=1^N 中选择。
- Router 变量 W_r 产生 logits h(x)=W_r·x，经 softmax 归一化为对所有专家的分布。
- gate value（专家i）由 softmax 概率给出，后乘到专家 FFN 输出上。

### 4.2 Switch 层：新引入的核心（§2.1–2.2, p5–6）
- **把「每 token 取 top-k」简化为「每 token 只取 1 个专家」**（top-1 routing），即 Switch 层只选单个 expert。
- 意义：路由计算的 exp（指数）运算减少、通信量骤降、单 token 只激活一个 FFN，训练更稳定（避免 Shazeer 原 MoE 的 k>1 时多专家叠加的数值/通信不稳定）。
- 「No-Token-Left-Behind」及「鼓励专家间探索」作为附录 B、C，用于防止 token 丢弃（capacity factor 不够时被丢弃）。
- Switch 层输出 = 选中的那个 FFN 的输出 × router gate 值（图2, p5）。

### 4.3 高效稀疏路由（§2.2, p6）
- 通过把建模成「稀疏激活」（每 token 激活很少的专家），在数据/模型/专家并行上做权衡，让主干（非专家）参数与 dense 基线 FLOP 对齐，专家参数随设备数增加——「权重随设备数增加，但单设备内存与计算可控」(§2, p4)。

### 4.4 改进的训练与微调技术（§2.4, p8–11）
- **selective precision / 选择性精度训练**：首次让大型稀疏模型可用 bfloat16 训练（此前稀疏模型需更高精度）。
- **初始化方案**：允许扩展到更多专家数。
- **专家正则化（expert dropout）**：微调时只在专家 FFN 层加大 dropout（0.4），非专家层用较低 dropout（0.1），显著抑制下文任务过拟合（Table4, p11）。

### 4.5 并行的设计（§5, p18–23）
- 四种并行：Data / Model / Expert / 组合。
- Expert+Data 并行（§5.4）：核心全部分给数据并行维度 n（=专家数），每 core 一个专家，做 all-to-all 通信（size [E,C,d]）。
- Expert+Model+Data（§5.5）：三路并行同时存在，需平衡 FLOPS/token 与参数量，最佳映射靠经验决定。

## §5 实验结果要点

### 5.1 预训练/缩放
- **step-basis（§3.1, p12）**：固定 FLOPS/token，专家数越多样本效率越高；Switch-Base(64专家) 在 step 60k 达到 T5-Base 在 step 450k 的性能 → 7.5x 提速。
- **time-basis（§3.2, p13）**：32 TPU v3 cores，固定 FLOPS，64专家 Switch-Base 在 1/7 时间达到 T5-Base 相同质量（7x speedup）。尽管稀疏模型有额外通信+路由开销，wall-clock 仍显著更快。
- **vs 更大 dense 模型（§3.3, p13–14）**：T5-Large 用 3.5x FLOPS/token，Switch-Base 仍更样效率更高并 2.5x 提速；新建 FLOP-matched 的 Switch-Large 能力再增。

### 5.2 下游微调（§4.1, p14–16, Table5）
- Table5 部分值（valid sets，越高越好）：
  - GLUE: T5-Base 84.3 / Switch-Base 86.7 / T5-Large 87.8 / Switch-Large 88.5
  - SQuAD: T5-Base 85.5 / Switch-Base 87.2 / T5-Large 88.1 / Switch-Large 88.6
  - SuperGLUE: T5-Base 75.1 / Switch-Base 79.5 / T5-Large 82.7 / Switch-Large 84.7
  - XSum: T5-Base 18.7 / Switch-Base 20.3 / T5-Large 20.9 / Switch-Large 22.3
  - ANLI(R3): T5-Base 51.8 / Switch-Base 54.0 / T5-Large 56.6 / Switch-Large 58.6
  - CB/OpenQA: Switch 始终高于同量级 T5。
- 结论：在推理型与知识密集型任务上均取得跨尺寸、跨任务的增益。

### 5.3 蒸馏（§4.2, p16–17, Table6）
- 用「用 teacher 非专家权重初始化 + 0.25 teacher 概率 + 0.75 ground-truth label 混合损失」，可把稀疏教师（≈3.8B Switch-Base）约 30% 的增益压缩进 1/20 参数量的 T5-Base（223M）。
- 模型被压缩 99% 时仍保留 28% 增益；压缩 82% 保留 37%。
- 微调后模型（7.4B Switch-Base 微调于 SuperGLUE）蒸馏到 T5-Base 同样保留 30% 增益。

### 5.4 多语言（§4.3, p17）
- 基于 mT5（Xue et al. 2020）mC4 101 种语言预训练；相比 mT5-Base 在全部 101 种语言上改进，91% 语言收益 4x+ 提速。

### 5.5 万亿参数模型（§5.6, p22–23）
- 设计了两模型：Switch-XXL（395B 参数，64 专家）与 Switch-C（1.57B/1.6T 参数，2048 专家）。
- Switch-C 与 T5-XXL 同 FLOP（每 seq），但以 4x 更快达到固定 perplexity，且在 250k 步后差距持续拉大。
- **关于不稳定**：Switch-C（1.6T, 2048专家）无训练不稳定；反而是 Switch-XXL（≈10x 更多 FLOP/seq）时而不稳定 → 说明不稳定风险更多与「单序列 FLOP 大」相关，而非总参数量。

## §6 局限

1. **Switch-XXL 训练不稳定**：尽管 Switch-Base/Large/C 都稳定，但 Switch-XXL（高 FLOP/seq）仍会在某些时候出现稀疏训练不稳定（§8, p26；§5.6 p23）。
2. **微调质量与 FLOP/参数数关系不明确**：出现反直觉案例——1.6T 参数的 Switch-C 在 SQuAD 上仅 87.7 精确匹配，而更小的 Switch-XXL 达 89.6；作者指出这可能源于「per-token FLOP 与参数数量之间尚未被理解的相关性」（§8, p26）。
3. **无正式 scaling 公式设计指引**：作者呼吁做「数据/模型/专家并行混合架构」的全面 scaling 研究（§8, p26）。
4. **专家同质、缺乏自适应计算**：当前始终用相同的同质专家（§8, p26）。
5. **蒸馏仅做 teacher→small dense 单向**，未探讨 large→small sparse 路径（§4.2, p16）。
6. **文献中关于稀疏模型「为何未广泛采用」的讨论**：复杂度、训练困难（不稳定）、通信成本，作者指出相较 dense 模型（与硬件协同演化）稀疏仍有短板（§7, p26）。
