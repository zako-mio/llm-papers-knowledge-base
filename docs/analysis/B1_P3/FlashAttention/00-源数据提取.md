### 3.4 IO 复杂度理论结果（§3.2）

- 标准注意力（Algorithm 0）：Θ(Nd + N²) HBM accesses
- FlashAttention（Algorithm 1）：Θ(N²d²M⁻¹) HBM accesses（M=SRAM 大小，d≤M≤Nd）
- 对典型 d（64–128）与 M（约 100KB）：d² 远小于 M，FlashAttention HBM 访问次数比标准少（最多 9× 更少）| Abstract / Fig.2
- 下界（Proposition 3）：不存在能在所有 M∈[d,Nd] 上达到 o(N²d²M⁻¹) HBM accesses 的精确注意力算法
- Block-Sparse FlashAttention（Proposition 4）：Θ(Nd + N²d²M⁻¹·s) HBM accesses，其中 s = 非零 block 比例；当 s 取 N^(-1/2) 或 N^(-1)logN 时达 Θ(N√N) 或 Θ(NlogN)
- Theorem 1：FlashAttention 以 O(N²d) FLOPs 计算 O=softmax(QK^T)V，额外内存 O(N)（线性于序列长度）

> 注：FlashAttention 虽 FLOPs 比标准多（因反向重算），但大量 HBM 访问减少，整体更快更省内存（Fig.2 左）。

## §4 方法细节

### 4.1 背景（§2）
- GPU 内存层级：A100 有 40–80GB HBM（带宽 1.5–2.0 TB/s）与 108 个 SM 上各 192KB 片上 SRAM（带宽约 19 TB/s）；SRAM 比 HBM 快一个数量级但小得多 | §2.1
- 执行模型：每个 kernel 从 HBM 装载输入到寄存器/SRAM，计算后写回 HBM | §2.1
- 算术强度（arithmetic intensity）= 每次内存访问的算术运算数；据此分 compute-bound（矩阵乘法大内维、大通道卷积）/memory-bound（elementwise、reduction 如 softmax、batch/layer norm）| §2.1
- kernel fusion 可加速 memory-bound，但训练时中间值仍需写 HBM 供反向，削弱融合效果 | §2.1

### 4.2 标准注意力实现（§2.2, Algorithm 0）
给定 Q,K,V∈R^{N×d}：
- S = QK^T ∈ R^{N×N}；P = softmax(S)；O = PV
- 标准实现把 S 和 P 物化到 HBM，需 O(N²) 内存；常用维度 N≫d（如 GPT-2 N=1024, d=64）

### 4.3 FlashAttention 算法（§3.1, Algorithm 1）
两个核心技术：
- **Tiling（分块）**：softmax 的列向耦合迫使把大 softmax 分解为带缩放的软最大值。对向量 x^(1),x^(2) 的拼接 x，维护额外统计量 (m(x), ℓ(x))，逐块增量计算。算法分块 Q/K/V，逐块计算、按归一化因子缩放后合并。
- **Recomputation（重算）**：不存 O(N²) 中间值。仅存储输出 O 与 softmax 归一化统计量 (m, ℓ)，反向时由 Q,K,V 的块在 SRAM 内轻松重算 S、P。可视为"选择性梯度检查点"；与普通检查点须以速度换内存不同，此重算因减少 HBM 访问反而加速反向。

**算法流程（Algorithm 1 骨架）**：设 SRAM 大小 M，块大小 Bc=⌊M/4d⌋、Br=min(⌊M/4d⌋,d)。将 Q 分 Br×d 块、K/V 分 Bc×d 块。外层循环加载 K_j,V_j 到 SRAM；内层循环加载 Q_i,O_i,ℓ_i,m_i，片上计算 S_ij=Q_i·K_j^T、m̃_ij=rowmax、P̃_ij=exp(S_ij−m̃_ij)、ℓ̃_ij=rowsum；更新 m_i^new=max(m_i,m̃_ij)、ℓ_i^new=e^{m_i−m_i^new}ℓ_i+e^{m̃_ij−m_i^new}ℓ̃_ij；把 O_i 按 diag(ℓ_i^new)^-1 的公式缩放写回 HBM。单 CUDA kernel，融合矩阵乘法、softmax、可选 masking/dropout、矩阵乘法。

### 4.4 Block-Sparse FlashAttention（§3.3, Algorithm 5）
- 引入块状 mask 矩阵 M∈{0,1}^{N/Br×N/Bc}，跳过零块，仅计算非零块；要求 mask 具 block form。
- IO 复杂度 Θ(Nd + N²d²M⁻¹·s)，s=非零块占比。固定使用 butterfly sparsity 模式（可近似任意稀疏）。
- 在 LRA 上 2.8× 提速且性能与标准注意力持平。

## §5 实验结果要点

- 训练更快：BERT/ GPT-2 / LRA 三组均超过基线（详 §3.1）。
- 模型更好：长上下文带来 perplexity 改善（GPT-2 0.7）、长文档分类提升（6.4 点）、以及 Path-X/Path-256 的首个"超过随机"Transformer（详 §3.2）。
- FP16/数值稳定性：FlashAttention 数值上与基线同样稳定，训练/验证曲线一致（附录 E）。
- FlashAttention 与 block-sparse 内存随序列长度线性增长；FlashAttention 内存效率比精确基线最多 20×。
- 在 seq ≤512 时 FlashAttention 比所有现有注意力方法更快且更省内存；>1K 时部分近似法（Linformer）开始反超；block-sparse 则全面领先。

## §6 局限（§5）

- **编译到 CUDA**：每种新注意力实现都须手写新 CUDA kernel，语言比 PyTorch 更低层，工程成本高；实现可能不跨 GPU 架构迁移。需支持用高层语言（PyTorch）书写再编译为 IO-aware CUDA 的方法（类似 Halide）。
- **IO-aware 深度学习**：作者认为 IO-aware 可扩展至注意力之外（每层网络都触碰 HBM），但当前仅注意力被优化。
- **Multi-GPU**：单 GPU 上该实现是常数意义最优；但多 GPU 并行化会引入 GPU 间传输的新一层 IO 分析，未来方向未解决。
- 基准（benchmarking）受 tuning 流程影响大，跨工作比较需谨慎。
