## §3 核心主张与关键数字表

> 数字与原文一致，括号注出处。

### 3.1 核心结论（Abstract / §5）

- **测试时计算可视为新的扩展轴**：允许 LLM 用更多推理时计算（搜索/投票/修正）提升输出。| Abstract
- 两种主要机制：① 对稠密 process-based verifier（PRM）做**搜索**；② **测试时自适应地修正模型**分布（revise）。| Abstract
- **困难度影响策略有效性**：不同方法在扩展 TTC 时的效果，强烈依赖 prompt 的难度。| Abstract / §2
- 提出 **compute-optimal 缩放策略**，按 prompt 难度自适应分配 TTC。| Abstract / §3
- 相比 best-of-N 基线，compute-optimal 策略可提升 TTC 缩放效率 **超过 4×**。| Abstract / §5.2
- 在 FLOPs 匹配评测中，当小模型在难题上已有**非平凡成功率**时，TTC 可让**小模型胜过 14× 更大的模型**。| Abstract / §5.3

### 3.2 在 MATH 基准上的表现（Table 1 / Fig.1，PaLM 2-S）

- best-of-N（N=1024）：小模型通过大量并行采样可将准确率从基线提升数倍（需数万次推理 token）
- PRM search（process-based verifier）：用过程监督的 RM 进行树搜索，比 best-of-N 更高效，达到相同准确率所需计算少——在 MATH 上，PRM-based 方法比最好的 best-of-N 更省算力。
- 与更大基线对比：PaLM 2-S + 高额测试时计算，可匹配甚至超过 PaLM 2-M / L。

### 3.3 Compute-optimal 缩放的核心结果（§3、§5.2）

- 将**测试时计算** 与 **预训练计算** 在统一 FLOPs 预算下做比较，得到一条"compute-optimal 曲线"——给定总 FLOPs，最优分配多少给训练、多少给推理。| §3.1
- 方法自适应：对难题多用搜索，对简单题少用搜索，从而把固定 FLOPs 花在"最能涨分处"。| §3.2
- 相对 best-of-N 提升 >4×。| §5.2
- 关键发现：**当基座模型在某个难题上已达到非零正确率时，用 TTC 就能胜过更大模型**；若基座在该题上失败率太高（几乎全错），则更多 TTC 收益有限（需要更好的基座先"能触摸到"答案点）。| §5.3

### 3.4 FLOPs 匹配的 14× 证据（Fig.4）

- 对比：PaLM 2-S（0.5B 级小模型）加上约 10^18 FLOPs 的测试时计算 vs. 约 14× 大的 PaLM 2-L 模型。
- 结论：在难题子集上（PaLM 2-S 已有非 trivial 成功率），TTC 让小模型反超大模型；在 PaLM 2-S 几乎无法开始解决的题目上则不行。

### 3.5 计算量规模参考（Table 1）

| 方法 | 计算量规模量级 | 相对准确率 |
|---|---|---|
| Single attempt | 1× | 基线 |
| Self-consistency | 与 sample 数成正比 | 温和提升 |
| Best-of-N | 与 N 成正比 | 提升但开销大 |
| PRM（process-based）搜索 | 树搜索，比 best-of-N 省 | 更高效 |
| 修正（revise） | 迭代 | 特定场景高效 |

## §4 方法细节

### 4.1 两种缩放机制（§2）

1. **Searching against verifier（搜索）**：用 **PRM（process reward model）** 作为过程验证器，在采样过程中进行搜索。
   - **Best-of-N**：对每个 prompt 采样 N 个完整响应，用 PRM（或 outcome RM）打分选最优。
   - **Self-consistency**：多次采样，多数投票（不含 PRM，纯多数）。
2. **Adaptive distribution updates（自适应分布修正）**：测试时**自适应地修正模型的响应分布**——即让模型意识到"我上一版可能错了"，从而**重新生成（revise）**。例如用指导性的"reflection"或"self-critique"提示，让模型在拿到环境反馈后修改上一版答案。| §2.3

### 4.2 Compute-Optimal 缩放（§3）

- 核心问题：给定推理阶段的总 FLOPs 预算，应把它分配到**简单的 prompt（少算）**还是**难的 prompt（多算）**？——答案是按 prompt 难度**自适应**。
- **随机启发式（random heuristic）**：作为"上界探索"的基线，先用一个非自适应的策略探索 compute-optimal 曲线的形状。
- **Adaptive scheduling**：用基座模型的不确定性/难度估计（或 PRM 分数）来判断"此题值不值得花更多 TTC"，据此分配算力。
- **Parallel & sequential 两种搜索形态**：可并行采样（一次性开 N 支，投票/选优），也可顺序搜索（一份答案被修正再修正，走"深度"而非"广度"）。| §3.3–3.4
- 关键发现（§5.2）：**并行采样（best-of-N / self-consistency）适合简单题**；**顺序搜索/修正（sequential revise）适合难题**——两者在不同难度区间各有优势。

### 4.3 实验设置（§4）

- 模型：PaLM 2-S（主力）、PaLM 2-M、PaLM 2-L（对照组）。
- 基准：MATH（数学推理）为主，GPQA（研究生级科学问答）。
- Verifier：PRM（process reward model），对解题**过程中的每一步**打分，而不是只对最终答案打分。
- TTC 方法：best-of-N、PRM 搜索、revise（修正）三种对比。
- 计算：FLOPs 匹配，将"更多推理计算"与"更大模型"放在同一总 FLOPs 预算下比较。

### 4.4 数学推理的关键直觉

- 对**过程式验证**的信号敏感：PRM 能标记"这步可能错了"，从而引导搜索在正确分支继续。
- 对**难度**敏感：简单题用并行投票（self-consistency）就够，难题用顺序修正（revise）+ PRM 搜索更好。

## §5 实验结果要点

- 给定固定推理 FLOPs，compute-optimal 策略比 best-of-N 更高效（**>4×**）。| §5.2
- **难度分层的价值**：把预算从"平均分配"改为"按难度分配"，收益显著。| §3、§5
- **小模型 + TTC 可胜大模型**：FLOPs 匹配下，小模型（PaLM 2-S 级）在它已有非零成功率的题上，用 TTC 胜过 14× 大的 PaLM 2-L。| §5.3
- **局限性提示**：TTC 提升"封顶"——当模型在某类题上几乎不会做时，靠 TTC 也救不回来，必须靠更强基座或训练。| §6
- 对预训练的含义：**推理时计算可以当作预训练算力的"一部分替代"**，但只在"基座已能触及但不稳定解决"的题类上有效。（推断）这就是后来 o1 / R1 的"推理时扩展"路线的可训练性依据。

## §6 局限（§6）

- **评测域窄**：主要在 MATH（数学）与 GPQA（科学）上验证，且依赖 PRM 这类过程奖励标注（本身也费算力与标注）。
- **PRM 依赖**：compute-optimal 调度需 PRM 提供过程奖励，而 PRM 训练需要过程标注，成本与监督信号都不可忽视。
- **基座"天花板"**：对模型不擅长的题域，TTC 的增益迅速衰减——TTC 不是万能药，模型得先"够到"答案才谈得上缩放。
- **成本结构**：TTC 把训练成本"前移/转移"到推理；对高吞吐、低时延场景（对话、实时），并行采样与顺序修正的延迟成本高。
- **未揭示"超快 vs 慢速推理"的产品权衡**：论文讨论的是学术性 FLOPs 匹配，但实际部署的时延/成本约束远比"4×"复杂。
