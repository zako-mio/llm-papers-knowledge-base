## §3 核心主张与关键数字表

### §3.1 核心主张
- 提出 BERT（Bidirectional Encoder Representations from Transformers），首个**基于 masked language model（MLM）深度双向预训练的表示模型**，突破此前单向（left-to-right）或浅层双向拼接的局限（摘要、§2）。
- 微调只需加一个输出层即可在各任务达到 SOTA，无需大量 task-specific 架构修改。
- 在 11 个 NLP 任务上刷新 SOTA（摘要、§2 贡献）。

## §4 方法细节要点

### §4.1 预训练任务
1. **Masked LM (MLM)**：随机 mask 15% 的 WordPiece token；不是全部重建，仅预测被 mask 的 token。为缓解 pre-train 与 fine-tune 的不匹配（[MASK] 在微调时不出现）：被选中的 15% token 中 —— 80% 替换为 [MASK]、10% 换成随机 token、10% 保持不变，用交叉熵预测原 token（§3.1 Task #1，Appendix C.2 有对比）。
2. **Next Sentence Prediction (NSP)**：二分类，50% B 是 A 的真实下一句（IsNext），50% B 是语料随机句（NotNext）。最终模型 NSP 准确率 97%-98%（§3.1 Task #2）。

### §4.2 Input/Output 表示（§3，Figure 2）
- 输入表示 = token embedding + segment embedding + position embedding 三者和。
- WordPiece 词表 30,000；首 token 恒为 [CLS]，其最终隐藏向量 C 作为句子级聚合表示；句子对用 [SEP] 分隔，并加学习式 segment embedding（Sentence A/B）。
- [CLS] 的 C 不是"有意义的句子向量"，仅作为聚合用于分类（§3.1 脚注）。

### §4.3 训练（§3.1 预训练数据；§4 微调）
- 预训练语料：BooksCorpus（800M 词）+ English Wikipedia（2,500M 词）；只取 Wikipedia 文本段落，忽略列表/表格/表头。强调用**文档级语料**而非打乱的句子级（如 Billion Word Benchmark），以提取长连续序列。
- 微调成本低：单块 Cloud TPU 上最多 1 小时，或 GPU 数小时，从同一预训练模型开始（§3.2）。

## §5 实验结果要点

### §5.1 GLUE（§4.1）
- batch size=32，每个 GLUE 任务 fine-tune 3 epochs；学习率从 {5e-5, 4e-5, 3e-5, 2e-5} 在 Dev 集选最优。
- BERT_LARGE 在 MNLI 获 4.6% 绝对提升（最大广报任务）。GLUE 官方 leaderboard 得 80.5%。

### §5.2 SQuAD（§4.2、§4.3）
- 只引入起始向量 S 与结束向量 E 两个参数；答案 span 分数 = S·T_i + E·T_j，取最大得分 span（j≥i）为预测；目标 = 正确起止位置 log-likelihood 之和。
- fine-tune 3 epochs，lr=5e-5，batch size=32（v1.1）；v2.0 用 2 epochs，lr=5e-5，batch size=48；非空答案阈值 τ 在 dev 上选以最大化 F1。

### §5.3 模型尺寸效应（§5.2）
- 在 MRPC（仅 3,600 标注样本）上也严格随尺寸提升——即使下游数据很小，更大更强的预训练表示仍直接受益（与 feature-based 的旧观察不同）。
- 对比文献最大 Transformer：Vaswani (L=6,H=1024,A=16) 100M；Al-Rfou (L=64,H=512,A=2) 235M——都远小于 BERT 且在无方向性上受限。

### §5.4 Pre-training vs Fine-tuning 对比（§5.1、§5.3）
- feature-based 方法固定预训练特征，仅在下游加训练层，可行且省成本；concat top-4 隐藏层最佳，只比端到端 fine-tune 低 0.3 F1。
- 纯 LTR 或 shallow 双向（如 ELMo 的 LTR+RTL 拼接）均逊于深度双向。ELMo 式需两个模型（成本 2×）、对 QA 直觉不佳（RTL 无法以问题为条件）、严格弱于深双向（后者每层都用双向上下文）——故采用深度双向（§5.1）。

## §6 局限与前提

1. **[MASK] 预训练/微调失配**：仅 15% token 参与 mask，且非全用 [MASK]（80/10/10 策略）来缓解；但仍存在预训练与下游的分布差异（§3.1、Appendix C.2）。
2. **NSP 简单二分类**：虽是纯自监督可轻松生成，但粒度粗糙，未来可换更细粒度任务（§3.1）。
3. **预训练特征/微调两难**：某些任务不易用 Transformer-encoder 表示（需 task-specific 架构）时，必须用 feature-based 或额外层（§5.3）。
4. **模型尺寸上限**：作者观察到更大模型严格更好，但未系统探索远超 340M 的方向；模型尺寸实验虽全面，仍限于特定语料与超参（§5.2、Table 6）。
5. **语料依赖**：结果依赖预训练语料（BooksCorpus + Wikipedia）与 tokenization（WordPiece 30K）；不同语料/词表下数字不可直接迁移。
6. **单向架构被排除**：为证伪单向性，LTR 对比需在微调时保持左受限（否则 pre-train/fine-tune 失配会损下游），说明方法对架构约束敏感（§5.1）。
7. **摘要与正文数字口径差异**：GLUE 平均（80.5% vs 82.1）、SQuAD v1.1 Test F1（93.2 vs 91.2）等因报告口径不同而有两种记法，引用时需注明是 leaderboard 分还是本地单模型分。
