## §4 方法细节
- 架构（Architecture，Section 2）：
  - **MLA（Multi-head Latent Attention）**：对 attention 的 keys 和 values 做 **low-rank joint compression**，把 KV cache 压缩到 latent 向量 c_t^KV（压缩维度 d_c^KV ≪ d_h·n_h）；只缓存 c_t^KV 和解耦的可加 RoPE 的 key k_t^R 即可，显著降低推理 KV cache 而保持与标准 MHA 相当的性能。对 queries 也做 low-rank compression 以减小训练激活内存。（Eq.1-11）
  - **DeepSeekMoE（with Auxiliary-Loss-Free Load Balancing）**：更细粒度 expert + 独立 shared experts。FFN 输出 = u + Σ_shared FFN(u) + Σ_routed g·FFN(u)；用 sigmoid 计算 token-to-expert affinity 并在所选 affinity 上归一化得 gating 值（Eq.12-15）。
  - **auxiliary-loss-free 负载均衡**：为每个 expert 引入 bias 项 b_i，加到 affinity 上用于 top-K 选路；bias 只用于选路，gating 值仍来自原始 affinity。训练时监测整批 expert 负载，每步末对超载 expert 减 bias、欠载加 bias，步长 γ（bias update speed）。避免常规 auxiliary loss 过大损害性能的权衡。***补充序列级平衡损失 L_Bal**（Eq.17-20，系数 α 取极小值）防单序列极端失衡。
  - **Node-Limited Routing**：每 token 最多发送到 M 个节点（按节点上 expert 最高 affinity 和选择），配合 M 约束使 MoE 训练近似全计算-通信重叠，无 token dropping（训练与推理都不 drop token）。
  - **MTP（Multi-Token Prediction）**：从 Gloeckle et al. 启发但改为**顺序预测**并保留每层（每预测深度）的完整因果链；用 D 个顺序 MTP 模块预测额外 D 个 token；每模块含共享 embedding、共享 d×2d output head、Transformer block 与投影矩阵 M。推理时直接丢弃 MTP 模块（成本与原模型一致）。
- 基础设施/训练优化（Section 3）：
  - Compute clusters：自定义集群（含 H800）；2048×H800 配置做 pre-train。
  - **DualPipe**：高效 pipeline parallelism，更少 pipeline bubble，通过 computation-communication overlap 隐藏大多数通信；保持恒定算力-通信比即可跨节点细粒度 expert 且近零 all-to-all 开销。
  - 高效 cross-node all-to-all kernel：充分利用 InfiniBand(IB) 与 NVLink 带宽。
  - 内存优化：避免使用昂贵的 tensor parallelism 即可训练 DeepSeek-V3。
  - **FP8 mixed precision training**：首次在超大规模模型验证 FP8。含混合精度框架、量化/乘法精度改进（逐块量化讨论见 Appendix B）、低精度存储与通信。
  - 推理：prefilling 用（最大化）计算-通信重叠与 expert 并行；decoding 侧重内存/吞吐优化。
- Pre-training（Section 4）：
  - 数据构建：14.8T 高质量多样 token（英文+中文为主的多语语料），通过质量过滤与数据配比优化。
  - 长上下文扩展：两阶段——第一阶段到 32K，第二阶段到 128K。
  - 评估：perplexity-based（HellaSwag、PIQA、WinoGrande、RACE-Middle/High、MMLU、MMLU-Redux、MMLU-Pro、MMMLU、ARC-Easy/Challenge、C-Eval、CMMLU、C3、CCPM）+ generation-based（TriviaQA、NQ、DROP、MATH、GSM8K、MGSM、HumanEval、MBPP、LiveCodeBench-Base、CRUXEval、BBH、AGIEval、CLUEWSC、CMRC、CMath）+ language-modeling（Pile-test 用 BPB 指标跨 tokenizer 公平比较）。
- Post-training（Section 5）：
  - SFT：在 base model 上做指令监督精调。
  - RL：Reward Model + **Group Relative Policy Optimization（GRPO）**。
  - 从 DeepSeek-R1 系列（long-CoT 模型）蒸馏推理/验证/反思能力到 DeepSeek-V3，同时控制输出风格与长度；用于 math/code/reasoning 增强。
  - Self-Rewarding / 作为 Generative Reward Model：用 LLM 作 feedback 源（含 constitutional inputs）转成 reward，主观评估显著提升对齐效果。
  - MTP 用于推理：结合 speculative decoding，第二 token 接受率 85-90%，达 1.8× TPS。

## §5 实验结果要点
- 开源 Base 对比（Table3，p.25）：DeepSeek-V3-Base 在绝大多数基准最佳，尤其 math/code；超越 DeepSeek-V2-Base（236B）与 Qwen2.5-72B-Base，多数超越 LLaMA-3.1-405B-Base（激活参数 405B，约为 V3 的 11 倍）。关键：MMLU 87.1、MATH 61.6、HumanEval 65.2、GSM8K 89.3、C-Eval 90.1、CMMLU 88.8。
- 开源 Chat 对比（Table6，p.31）：DeepSeek-V3 为最强开源 chat 模型，且与顶级闭源（GPT-4o-0513、Claude-3.5-Sonnet-1022）有竞争力。关键：MMLU 88.5、MMLU-Pro 75.9、GPQA-Diamond 59.1、DROP 91.6、MATH-500 90.2、AIME 39.2、CNMO 43.2、HumanEval-Mul 82.6、Codeforces 51.6、C-SimpleQA 64.8。
- 数学/代码优势：非 long-CoT（非 o1 类）模型中 SOTA。AIME/MATH-500/CNMO1630 上比第二名（Qwen2.5-72B）高出约 10 个百分点；Codeforces 51.6；工程类（SWE-bench Verified 42.0、Aider-Edit 79.7 等）略逊于 Claude-Sonnet-3.5 但远超其他开源。
- 长上下文：DROP F1 91.6（所有对比模型第一）、FRAMES 73.3（仅次 GPT-4o）、LongBenchv2 48.7（best-in-class）。
- 事实性：English SimpleQA 落后 GPT-4o/Claude（24.9 vs 38.2/28.4），因资源分配偏好中文知识；Chinese SimpleQA 64.8 反超（比 Qwen2.5-72B 高 16.4 点，尽管 Qwen2.5 用 18T tokens，比 V3 的 14.8T 多 20%）。
- 消融：MTP 与 aux-loss-free 策略在大/小模型上均一致带来多数基准增益；batch-wise 负载均衡可获得与 aux-free 相近效果（1B/3B MoE 验证）印证"batch-wise 更灵活、专家更 specialize"。
- 成本-性能：2.788M H800 GPU-hours ≈ $5.576M 完成含 pre-train/context extension/post-train 全流程，且训练极稳定。
- 生成速度：MTP + speculative decoding 使端到端生成速度超 DeepSeek-V2 两倍以上。

## §6 局限
- 部署单位偏大：为保证高效推理，推荐部署单元较大，可能给中小团队带来负担（p.35）。
- 推理速度仍有提升空间：虽端到端生成速度达 DeepSeek-V2 的 2 倍以上，仍有优化空间（p.35）。
- 硬件依赖：作者认为上述局限随更先进硬件发展会自然缓解（p.35）。
- 模型开放性但成本核算有限：成本仅含官方训练，不含架构/算法/数据上的先前研究与消融实验成本（p.5）。
- 事实性（SimpleQA）短板：英文事实知识落后于 GPT-4o / Claude-Sonnet，源于训练资源向中文倾斜（p.32）。
- 评估框架变化：因评估框架更新，DeepSeek-V2-Base 表现与本团队之前报告略有差异（p.24-25）；多维度评估仍在探索，防止在固定基准上过拟合（p.36）。
- 架构限制：仍受 Transformer 建模能力局限（边界未突破），追求无限上下文与突破架构限制为未来方向（p.35-36）。
- 输出 token 上限：各基准评估被限制在 8K 输出（p.31）。
