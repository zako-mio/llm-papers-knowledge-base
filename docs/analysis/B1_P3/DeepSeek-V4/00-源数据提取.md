## §4 方法细节

### 4.1 架构总览（§2）
- 保留 Transformer + Multi-Token Prediction (MTP)，引入三大升级：mHC（Manifold-Constrained Hyper-Connections）、hybrid attention（CSA + HCA）、Muon 优化器。
- **MoE**：沿用 DeepSeekMoE，但激活函数由 Sigmoid(·) 改为 Sqrt(Softplus(·))；auxiliary-loss-free 策略 + slight sequence-wise balance loss；移除 routing target node 数量约束；前几个 block 的 dense FFN 改为用 Hashrouting 的 MoE 层（根据 token ID 的 hash 函数确定目标专家）。
- **MTP**：与 DeepSeek-V3 相同，配置未改。

### 4.2 mHC（Manifold-Constrained Hyper-Connections）
- **标准 HC**：把 residual stream 宽度扩 n 倍（R^d → R^(n·d)），引入 input mapping A(1×n)、residual transformation B(n×n)、output mapping C(n×1)。但多层堆叠高频出现数值不稳定，阻碍扩展。
- **mHC 核心**：把 residual mapping 矩阵 B 约束到 doubly stochastic matrices 的流形（Birkhoff polytope）M：{M ∈ R^(n×n) | M·1=1, 1ᵀM=1, M≥0}。此举保证 ‖B‖₂ ≤ 1，residual transformation 非扩张，增强前后向数值稳定性；该集合对乘法封闭，保证深堆叠稳定。输入 A、输出 C 用 Sigmoid 约束为非负有界（C=2σ(C̃)）。
- **动态参数化**：A/B/C 由动态（input-dependent）+ 静态（input-independent）分量生成；X 先 RMSNorm，然后生成未约束 raw 参数 Ã、B̃、C̃，B̃ 用 **Sinkhorn-Knopp 算法**投影到 doubly stochastic 流形（t_max=20）。

### 4.3 Hybrid Attention（§2.3）
- **CSA（Compressed Sparse Attention）**：先把每 m 个 token 的 KV cache 压缩为 1 个 entry，然后应用 DSA（DeepSeek Sparse Attention），每个 query token 只 attend 到 k 个压缩 KV entries。含 Lightning Indexer（用低秩生成 indexer queries、index score、top-k selector）、Shared Key-Value MQA、Grouped Output Projection。图3。
- **HCA（Heavily Compressed Attention）**：更激进压缩，把每 m'（≫m）token 的 KV cache 合并为 1 个 entry，但不做 sparse attention。图4。
- **其他细节（2.3.3）**：query/KV-entry normalization（每个 head RMSNorm）、Partial RoPE（对最后 64 维）、附加 Sliding Window Attention 分支（补充局部细粒度依赖）、Attention Sink（可学习 sink logits）。
- **效率讨论（2.3.4）**：KV mixed storage（RoPE 维 BF16，其余 FP8，几乎减半 KV size）；lightning indexer 内 FP4；较小 top-k；压缩 + hybrid attention 大幅降 KV cache 与 FLOPs。

### 4.4 模型配置（§4.2.1）
- **V4-Flash**：43 层，hidden d=4096；前 2 层纯 SWA，后续层 CSA/HCA 交错。CSA: m=4, indexer heads n=64, indexer head dim c=128, top-k=512。HCA: m'=128。CSA/HCA: query heads n=64, head dim c=512, query compression dim d=1024。输出投影 groups g=8, intermediate dim d_g=1024。SWA window=128。全部层 MoE（前 3 层 Hashrouting），每层 1 shared + 256 routed experts，expert intermediate=2048，激活 6 专家。MTP depth=1。mHC: n=4, Sinkhorn-Knopp t=20。→ 284B 总 / 13B 激活。
- **V4-Pro**：61 层，hidden d=7168；前 2 层 HCA，后续 CSA/HCA 交错。CSA: m=4, indexer heads n=64, indexer dim c=128, top-k=1024。HCA: m'=128。CSA/HCA: query heads n=128, head dim c=512, query compression dim d=1536。输出投影 groups g=16, d_g=1024。SWA window=128。每层 1 shared + 384 routed experts，expert intermediate=3072，激活 6 专家。→ 1.6T 总 / 49B 激活。

### 4.5 训练设置（§4.2.2）
- **V4-Flash**：32T tokens；AdamW（embedding/head/RMSNorm）+ Muon（其余），Muon momentum 0.95, weight decay 0.1, RMS rescale 0.18；batch size 增至 75.5M；LR warm up 2000 步，峰 2.7e-4，尾声线性衰减到 2.7e-5；序列 4K→16K→64K→1M。
- **V4-Pro**：33T tokens；batch size 最大 94.4M；峰 LR 2.0e-4，终 2.0e-5；其余同 Flash。
- **Sparse attention 引入**：先 1T tokens dense warm-up，序列到 64K 再加 sparse；先 warm up CSA lightning indexer 再正式训练。bias update speed 0.001，balance loss weight 0.0001，MTP loss 0.3（decay 起始后 0.1）。

### 4.6 训练稳定性（§4.2.3，两技术）
- **Anticipatory Routing**：step t 用当前参数 θ_t 做特征计算，但 routing indices 用历史参数 θ_{t-Δ}。通过提前取数据、缓存 routing indices 使额外 wall-clock 开销约 20%；配合自动 loss spike 检测触发短回滚，将稳定开销降至可忽略。
- **SwiGLU Clamping**：把 SwiGLU 线性分量 clamp 到 [-10,10]，gate 分量上限 10；有效消除离群值并稳定训练，不损性能。

### 4.7 后训练流水线（§5.1）
- **两阶段**：先独立培育各领域专家（Specialist Training），再统一 consolidation（On-Policy Distillation, OPD）。
- **5.1.1 Specialist | 三种推理模式**（Table2）：Non-think（快直觉，日常任务，</think> summary）、Think（HL 逻辑分析，复杂问题，<think>...tokens</think> summary）、ThinkMax（推至极限，探索能力边界，特殊 system prompt + <think>）。Table3 给出 ThinkMax 的 system prompt 注入指令。
- **Generative Reward Model (GRM)**：放弃标量奖励模型，对 hard-to-verify 任务用 rubric-guided RL 数据 + GRM，并把 RL 直接应用到 GRM 本身（actor 网络原生作为 GRM），联合优化评估与生成能力。
- **Tool-call schema**：引入 "|DSML|" 特殊 token + XML 格式（Table4），缓解 escaping 失败、降低 tool-call 错误。
- **Interleaved Thinking**（Figure7）：tool-calling 场景保留全轮 reasoning（含跨用户消息边界）；一般对话场景沿用 V3.2 策略（新用户消息到来时丢弃先前 reasoning）。
- **Quick Instruction**（Table5）：把搜索触发判断、意图识别、标题生成、query 生成、authority/domain 判断等辅助任务 append 专用 special token 到输入序列，直接复用已计算 KV cache，避免冗余 prefill，可并行执行，显著降 TTFT。

### 4.8 后训练基础设施（§5.2）
- **5.2.1 FP4 QAT**：MoE expert weights + CSA indexer 的 QK path 用 FP4(MXFP4)；index scores 从 FP32 量化到 BF16（top-k 2× 加速，recall 99.7%）；FP4→FP8 dequant lossless（FP8 E4M3 有 2 个额外指数位）。backward 用 STE 直通到 FP32 master weights；推理/rollout 用原生 FP4 权重。
- **5.2.2 Full-vocab OPD teacher scheduling**：teacher weights 卸载到集中式分布式存储；只缓存最后一层 teacher hidden states，训练时经 prediction head 重建全 logits；按 teacher index 排序训练样本使每个 teacher head 每 mini-batch 仅加载一次；用 TileLang 专用 kernel 算精确 KL。
- **5.2.3 Preemptible & fault-tolerant rollout**：token-granular Write-Ahead Log (WAL)，每生成一个 token 立即 append；preemption 时暂停并保存 KV cache；恢复时用 WAL + KV cache 续解码；避免从头重生成引入 length bias。
- **5.2.4 Million-token RL 扩展**：rollout 数据格式分解为轻量 metadata + heavy per-token fields；global shuffling 只加载 metadata；heavy fields 用 shared-memory data loader 按小批量粒度释放。
- **5.2.5 Sandbox DSec**：生产级沙箱平台，三个 Rust 组件（Apiserver API 网关 / Edge host agent / Watcher 集群监控），RPC 互联，基于 3FS 分布式文件系统横向扩展；单集群管理数十万并发沙箱；四个执行 substrate（Function Call / Container / microVM(Firecracker) / fullVM(QEMU)）；layered on-demand 镜像加载（EROFS）；trajectory logging + preemption-safe resumption。

### 4.9 数据（§4.1）
- 预训练语料 >32T tokens：数学、代码、网页、长文档、多语。web 过滤掉批量自动生成与模板内容；mid-training 加 agentic data；重点长文档（科学论文、技术报告）；保留 V3 词表 128K + token-splitting + FIM；dictation 用 sample-level attention masking（区别于 V3）。

### 5.5 真实世界任务（§5.4）
- **Chinese Writing**：functional writing vs Gemini-3.1-Pro 整体 win rate 62.7% vs 34.1%（主要因 Gemini 有时用自身风格覆盖用户显式要求）；creative writing：instruction following 60.0%、writing quality 77.5%；但在最高复杂约束/多轮场景，Claude Opus 4.5 52.0% vs 45.9% 占优。
- **Search**：RAG pairwise 对比，V4-Pro 显著优于 V3.2（尤其 single-value search 与 planning & strategy）；agentic search 一致优于 RAG，且成本仅略高于标准 RAG。
- **White-Collar Task**：30 个高难度中文专业任务（13 行业），V4-Pro-Max vs Opus-4.6-Max 总体 non-loss rate 63%；优势在 Task Completion 与 Content Quality（主动预判用户潜在意图、提供补充洞见与自验步骤、长文深度叙述、规范中文层级编号），劣势在 Instruction Following（偶忽略具体格式）与 Formatting Aesthetics（视觉排版）。
- **R&D Code Agent**（Table8）：30 个内部 R&D 任务（~200 收集、50+ 工程师），PassRate(%)：Haiku4.5 13 / Sonnet4.5 47 / **DeepSeek-V4-Pro-Max 67** / Opus4.5 70 / Opus4.5-Thinking 73 / Opus4.6-Thinking 80；V4-Pro 显著超 Sonnet 4.5 并接近 Opus 4.5。
- **开发者调查（N=85）**：52% 说 DeepSeek-V4-Pro 可作默认主编码模型，39% 倾向 yes，<9% 说 no；反馈存在小错误、模糊 prompt 误读、偶发 over-thinking。

## §6 局限

- **预览版本**：明确标注 preview，架构较为复杂（"bold architectural design"），作者称保留了较多初步验证过的组件与 trick，希望未来迭代能蒸馏出更本质、更优雅的设计而无不损性能。
- **知识/教育知识仍落后闭源前沿**：DS-V4-Pro-Max 虽为开源 SOTA 并大幅缩小距 Gemini-3.1-Pro 差距，但仍落后之（SimpleQA-Verified 57.9 vs Gemini 75.6；GPQA-Diamond 90.1 vs 94.3；MMLU-Pro 87.5 vs 91.0；HLE 37.7 vs 44.4）。
- **推理略落后最前沿**：作者指出发展轨迹约落后 SOTA 闭源模型 3~6 个月（相对 GPT-5.4 与 Gemini-3.1-Pro），但已超过 GPT-5.2 与 Gemini-3.0-Pro。
- **Agent 能力仍落后闭源**：公开基准上与 Kimi-K2.6、GLM-5.1 相当，但略逊 frontier 闭源模型；内部评估优于 Claude Sonnet 4.5、接近 Opus 4.5。
- **架构复杂性与理论理解不足**：Anticipatory Routing 与 SwiGLU Clamping 虽有效，但底层原理仍未充分理解（"their underlying principles remain insufficiently understood"）。
- **符号表示/架构细节**：部分内容为保证清晰性省略了细枝末节，作者鼓励读者参考 open-source 实现；符号对齐依赖 open-source，自带一定模糊性。
- **V4-Flash 知识评估较低**：因参数规模小，知识类基准较 V4-Pro 弱。
- **部署依赖与基线限制**：部分基础模型基准（TriviaQA/CLUEWSC/CMath 等）在某些模型上未同步提升或出分差（例如 CMath V4-Pro-Base 90.9 < V3.2 92.6；BigCodeBench V4 各版本均低于 V3.2）。
- **检索能力超长退化**：MRCR 在 >128K 后出现可见退化（尽管 1M 仍强）。
- **长上下文评估覆盖有限**：未评估 GPT-5.4（API 无法大量响应）与部分 K2.6/GLM-5.1 条目缺失（API 过忙未返回）。
