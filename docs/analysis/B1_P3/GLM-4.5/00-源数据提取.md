## §4 方法细节

### 4.1 架构（2.1）
- MoE 架构：采用 loss-free balancer routing + 对 MoE 层用 sigmoid gates。
- 对比 DeepSeek-V3 / Kimi K2，**减小宽度（hidden dim 与 routed experts 数量）、增加深度（层数）**——作者发现更深模型推理能力更强。
- 自注意力用 **Grouped-Query Attention（GQA）+ partial RoPE**；注意力头数增加到 2.5×（5120 hidden 对应 96 heads）。作者指出增加头数不降低训练损失，却持续提升 MMLU、BBH 等推理 benchmark。
- 引入 **QK-Norm** 稳定 attention logits 幅度。
- 两个模型均加一个 MoE layer 作为 **MTP（Multi-Token Prediction）**层，用于推理时 speculative decoding。

**Table 1 关键架构对比**：

### 4.2 预训练数据（2.2）
- 来源：网页、社交媒体、书籍、论文、代码仓库；主要为中英文网页（受 Nemotron-CC 启发按质量分桶，最高质量桶贡献 >3.2 epochs，丢弃最低质量桶）。
- 用 **SemDedup** 移除模板生成的相似网页（MinHash 无法去除）。
- 多语言：自爬网页 + Fineweb-2，用 educational utility 质量分类器上采样。
- 代码：GitHub 等，经规则过滤 + 语言质量模型分三档，上采样高质量、排除低质量；全部代码用 **Fill-In-the-Middle**；代码相关网页用两阶段检索。细粒度 parser 保留格式。
- Math & Science：LLM 打分 + 训练小分类器预测分数，高以上题上采样。
- 预训练分两阶段：第一阶段通用文档；第二阶段上采样源代码与 coding/math/science 网页。

### 4.3 Mid-Training（2.3）
三阶段：Repo-level Code Training（序列 4K→32K，跨文件依赖、GitHub PR/issues/commits 连接、diff 格式）→ Synthetic Reasoning Data（math/science/code 竞赛合成推理）→ Long-context & Agent Training（序列 32K→128K，上采样长文档，大规模合成 agent 轨迹）。
- 最大序列长度：预训练 4096，mid-training 分别到 32768 和 131072。
- 预训练不用 best-fit packing（随机截断作数据增强）；mid-training 用 best-fit packing 避免截断推理过程/仓库级代码。

### 4.4 超参数（2.4）
- **Muon 优化器**（除 word embedding、bias、RMSNorm 权重外），Newton-Schulz 迭代 N=5，momentum 0.95，更新 RMS 0.2。
- 学习率：cosine decay（不用 WSD，因其在 SimpleQA/MMLU 上表现差），warmup 0→2.5e-4，衰减至 2.5e-5。
- Batch size warmup：16M→64M token（首个 500B token 内），其余固定。
- 正则化：weight decay 0.1，不用 dropout。
- 序列 32K 时 RoPE base 从 10,000 调至 1,000,000。
- 路由 bias 更新率前 15T token 为 0.001，其后 0.0；辅助序列级 balance loss 权重 0.0001。MTP loss 权重 λ=0.3（前 15T），后 0.1。

### 4.5 后训练（3）
两阶段：Stage 1 Expert Training（Reasoning / Agent / General chat 三个专家模型）→ Stage 2 Unified Training（self-distillation 融合成 hybrid reasoning 模型）。

**SFT（3.1）**：Cold-start SFT（少量扩展 CoT 数据）→ Overall SFT（数百万样本，涵盖 reasoning/general chat/agentic/long-context，max context 128K；从不同专家蒸馏；平衡"含完整推理"与"无显式思维过程"的数据以支持 hybrid reasoning）。
- 创新：**函数调用模板**改用 XML-like special token 包裹 key/value，大幅减少 code 段转义负担，且不损害函数调用性能（Fig 4）。
- Rejection Sampling：多阶段过滤（去重复/过短/截断/格式错误 → 客观答案正确性校验 → reward model 过滤主观题 → 工具调用协议与终态校验）。
- Prompt Selection & Response-Level Scaling：去掉 response 长度底部 50% 的 prompt 带来 math/science 提升 2%~4%（仅用一半数据）；对困难 prompt 生成 4 个 response 再提升 1%~2%。
- 自动 agentic SFT 数据构建（四步）：Agentic Framework/Tool Collection → Task Synthesis → Trajectory Generation → Quality Filtering。

**Reasoning RL（3.2）**：基于 GRPO（去 KL loss）。关键技巧（在小实验模型上验证）：
- 两阶段难度课程学习（Fig 5）：避免早期全 0 奖励/后期全 1 奖励；第二阶段只从有验证答案的池取题，持续超过性能天花板。
- **单阶段 64K RL 优于多阶段递增长度**（Fig 6）：多阶段让模型"遗忘"长上下文能力且不可逆，平均输出长度下降。
- 动态采样温度：奖励稳定视为收敛期，抬高温度增探索；用 held-out 验证集定温，阈值不超过最优解性能下降 1% 的最大温度。
- Code RL 用 **token-weighted mean loss**（优于 sequence-mean），加速收敛、缓解长度偏差、抑制过简重复"base case"（Fig 7 left）。
- Science RL 用 expert-verified 多选题，显著优于混合质量数据（Fig 7 right，GPQA-Diamond）。

**Agentic RL（3.3）**：RLHF → 聚焦 web-search / code-generation agents，动作/答案可自动校验给出稠密奖励。用 group-wise policy optimization（采样 K 条 agent trace 优化；只优化模型生成 token，忽略环境反馈 in loss）。
- Outcome Supervision + Process Action Format Penalty：web-search 用最终答案准确率；coding 用 SWE 可验证测试；格式错误则进程终止、奖励 0。
- Iterative Self-distillation：先 RL 冷启动→自蒸馏用 RL 模型输出替换冷启动数据→继续 RL 加大难度。
- 测试时计算扩展：agent 任务通过 **interaction turns** 扩展（非输出 token），BrowseComp 上精度随交互轮平滑扩展（Fig 8）。

**General RL（3.4）**：多源反馈（rule-based + RLHF + RLAIF）。
- Holistic RL：约 5000 prompts，7 primary/33 secondary/139 tertiary 分类。
- Instruction Following RL：7 major/151 minor 约束类型；确定性校验 + reward model + critique model，减轻 reward hacking（Fig 9）。
- Function Calling RL：step-wise rule-based（严格 reward：格式对且与 ground truth 完全匹配含名字/参数/字段）=1 否则 0；end-to-end multi-turn（单轮多步 + 多轮多步，用 MCP server 与 Agentgym，reward 依据 TaskCompleted，由环境规则或 LLM Judge 判定）。
- Pathology RL：针对语言混用/重复/格式错误（多 <1% 输出），专门挑高触发 prompt 训练提效。

**RL 基础设施（3.5）**：基于自研 **Slime** 框架（github.com/THUDM/slime），三大模块：Training（Megatron）、Rollout（SGLang+Router）、DataBuffer。
- 异步、分布式解耦；agent 任务用 disaggregated asynchronous（rollout 直连 agent 环境、GPU 独立调度）；reasoning 任务用 async colocated。
- Mixed-precision inference：训练 BF16、推理 FP8（每轮在线 block-wise 量化）。
- Agent-oriented：Docker 高并发 runtime、GPU 分 rollout engine + training engine、统一 HTTP endpoint + 集中 data pool（message-list 格式）。

## §5 实验结果要点

- **Base 模型（Table 2）**：GLM-4.5-Base 在英文（SimpleQA 30.0/BBH 86.2/MMLU 86.1/HellaSwag 87.1/PIQA 85.3/TriviaQA 80.0）、Code（EvalPlus 78.1、LiveCodeBench-Base 28.1）、Math（GSM8K 79.4、MATH 61.0）、中文（CLUEWSC 83.5、C-Eval 86.9、C3 83.1、Chinese-SimpleQA 70.1）上稳定，验证"单模型统一多能力"。
- **Agentic（Table 3，avg 58.1 第 2 名）**：TAU-Retail 79.7、TAU-Airline 60.4、BFCL v3 77.8、BrowseComp 26.4。TAU-bench 用优化 user simulator（Fig 11）。
- **Reasoning（Table 4，AA-Index 67.7 第 3 名）**：超 o3（AIME24 91.0 vs 89.4；SciCode 41.7 vs 41.0），均值超 Claude Opus 4。
- **Coding（Table 5，avg 50.9）**：SWE-bench Verified 64.2（超 GPT-4.1、Gemini-2.5-Pro），Terminal-Bench 37.5（超 Claude Sonnet 4）；OpenHands v0.34.0、≤100 iter、128K 截断、temp 0.6 top_p 1.0；Terminal-Bench 用 Terminus 框架标准函数调用。
- **General（Table 6）**：SimpleQA 26.4（355B 参数量≈DeepSeek V3/R1 671B 的一半）→ 参数高效；IFEval 86.1 超 DeepSeek R1；SysBench 81.0 超 GPT-4.1/DeepSeek V3/Kimi K2。
- **Safety（Table 7，SafetyBench 11,435 题 7 类）**：overall 89.99（文：89.87），与 Kimi-K2 90.48、GPT-4.1 89.71 相当；Ethics&Morality 94.3、MentalHealth 94.7、PhysicalHealth 96.7、Illegal 91.0、Privacy&Property 92.0；Unfairness&Bias 77.4 尚有提升空间。
- **人类评测（手动，0-10）**：英文 overall 8.66（超 DeepSeek-R1-0528 8.62、Kimi-K2 8.13）；中文 8.37；其他语言 8.49。660 prompts（392 英文/108 中文/160 其他）。
- **CC-Bench（52 个编程任务，对比 Claude Code）**：vs Claude Sonnet 4 胜/平/负 40.4/9.6/50.0；vs Kimi-K2 53.9/17.3/28.8；vs Qwen3-Coder 80.8/7.7/11.5。工具调用成功率 90.6% 最高。
- **新逻辑推理题（Table 11）**：Gemini 2.5 Pro 65.8 > DeepSeek-R1-0528 62.1 ≈ GLM-4.5 62.0 > GLM-4.5-Air 53.4 > Kimi-K2 51.9。
- **翻译（Table 12，0-3 盲测 100 例）**：GLM-4.5 1.71 远超专用 Qwen-MT-plus 0.38、Qwen-MT-turbo 0.55、Seed-X 0.65；例 "三花公主驾到"（三花=三花猫）、"yyds"="永远的神"、"胖"=Canon 70-300 镜头、"鱼"emoji=闲鱼。

## §6 局限

- 作者明确承认存在的不足与未竟之处（未设独立 limitations 章节，散见各处）：
  - **Unfairness & Bias 较弱**（77.4），为后续持续改进方向（§4.2.5）。
  - Reasoning 各单项仍有强对手：HLE 14.4% 明显低于 Gemini 2.5 Pro（21.1）；GPQA（79.1）低于 Gemini 2.5 Pro（84.4）与 Qwen3-235B（87.7），说明开放领域深度知识推理仍有差距（Table 4）。
  - BrowseComp（26.4）仍显著低于 OpenAI o3（49.7），Web browsing agent 能力未达最优（Table 3）。
  - Coding 相对 Claude Sonnet 4 整体仍处下风（50% 负），Terminal-Bench 外的真实软件工程任务仍难完全匹敌（Fig 12）。
  - 动态 benchmark LiveCodeBench 仅评测 2024/07/01–2025/01/01，存在时效窗口；HLE 仅评测 text-based 题且用 GPT-4o 判分；AIME/GPQA 用多采样 Avg 缓解方差，非单次精度。
  - 自动 benchmark 存在过拟合风险，作者因此额外建立手动评测框架（§4.3），但手动评测样本较小（660 prompts / 100 翻译例 / 52 编程任务 / 逻辑题量有限），统计显著性有限。
