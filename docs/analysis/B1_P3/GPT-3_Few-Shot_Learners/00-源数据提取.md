## §3 核心主张与关键数字表

### §3.1 核心主张
- 通过**仅扩大模型规模**（不微调、不做梯度更新/不动参数），极大提升 task-agnostic 的 few-shot 性能，有时达到与 prior SOTA fine-tuning 方法竞争的水平（摘要、§1）。
- 核心概念区分：**meta-learning**（训练时获得广泛技能与模式识别）与 **in-context learning**（前向传播内、在单个序列上发生的"内循环"适应）；按推理时给出演示数量分为 **zero-shot / one-shot / few-shot**（§1 脚注1）。
- GPT-3 是首个 175B 参数非稀疏语言模型，规模是此前任一非稀疏 LM 的 10×（摘要、§1）。
- 识别出若干 few-shot 仍挣扎、以及因训练于大网络语料带来的方法学问题（测试集污染）的数据集。
- 强调 few-shot 语义歧义：**不确定是"从零学新任务"还是"认出训练中见过的任务"**（§5 Limitations）。

## §4 方法细节要点

### §4.1 架构（§2.1）
- 与 GPT-2 [RWC19] 相同，含修改的初始化、pre-normalization、可逆 tokenizer；但层间用**交替的 dense 与 locally banded sparse attention**（类似 Sparse Transformer [CGRS19]），以降低大模型计算成本。
- 训练 8 个模型（125M~175B）；前馈层维度恒为 bottleneck 4 倍；上下文窗口 n_ctx=2048 tokens。
- 模型沿深度与宽度维度切分在 GPU 上，最小化节点间数据传输；用模型并行（矩阵内 + 跨层）。
- 硬指标：GPT-3 13B 几乎比 RoBERTa-Large（355M）大 10×，但两者预训练计算量约 50 petaflop/day（对比 Figure 2.2 与 [KMH20] 缩放定律——大模型训更少 token）。

### §4.2 数据清洗（§2.2、Appendix A）
- 三步提升数据质量：①按与高质量参考语料相似度过滤 CommonCrawl；②跨数据集文档级模糊去重（保护验证集完整性、防测试污染）；③加入已知高质量参考语料（WebText2、Books1、Books2、Wikipedia）提升多样性。
- 采样策略使高质量集被多次见到、CommonCrawl/Books2 不到一次，接受少量过拟合换取更高质量。

### §4.3 训练过程（§2.3、Appendix B）
- 通过测量**梯度噪声尺度**引导 batch size 选择 [MKAT18]——大模型可用更大 batch、需更小学习率（符合 [KMH20]）。
- 全部训练在 Microsoft 高带宽集群的 V100 GPU 上。

### §4.4 评估设置（§2.4）
- few-shot：从任务训练集随机抽 K 个演示作 conditioning（用 1-2 个换行分隔）；LAMBADA/StoryCloze 无监督训练集，用 dev set 抽 demo 并在 test set 评估；Winograd 单数据集抽 demo。
- 每个实例以"完成预测"方式评估；分 zero/one/few-shot。

## §5 实验结果要点

### §5.1 语言建模/Cloze（§3.1、§3.9）
- LAMBADA：zero-shot 76% / one-shot 72.5% / few-shot 86.4%，few-shot 较 SOTA 提升超 18%。few-shot 使最小模型下降近 20%，对 GPT-3 提升 10%；fill-in-blank 在 one-shot 不有效。
- HellaSwag：one-shot 78.1%、few-shot 79.3%，超 fine-tuned 1.5B [ZHR19] 的 75.4%，低于 SOTA 85.6%（ALUM 多任务 fine-tune）。
- StoryCloze：zero-shot 83.2%、few-shot 87.7%（K=70），低 fine-tuned SOTA 4.1%（BERT-based [LDL19]），较 prior zero-shot 提升约 10%。
- 算术：few-shot 表现最强，one-shot 亦强，zero-shot 仍有基本算术能力。

### §5.2 闭卷问答（§3.2）
- 无需检索系统，GPT-3 直接闭卷作答：TriviaQA few-shot 71.2% 最佳；Natural Questions 29.9%、Web Questions 41.5%，虽低于检索式 RAG 但较前代 LM（[RWC19] 仅 4% Natural Questions）大幅提升。

### §5.3 翻译/抽取类（§3.3、§3.4）
- 翻译、Winograd（Winograd Schema Challenge）等在 few-shot 下达到 competitive；CoQA few-shot 85 F1 距 human 极近。

### §5.4 记忆化与污染（§4）
- 因训练于广域网数据 + 大记忆容量，存在下游任务测试/开发集污染风险。曾试图移除与基准的 overlap，但**过滤 bug 导致若干 overlap 被忽略**，且训后无法重训模型。
- 对 LAMBADA 的污染分析显示显著少数样本在训练数据中，但 §4 分析表明对性能影响可忽略（§3.1.2）。

### §5.5 聚合趋势（Figure 1.3、3.8）
- SuperGLUE 随规模与上下文 example 数提升：K=32（8 任务 × 32 例）时 best。
- BERT-Large（SuperGLUE 125K 训练例）与 BERT++（前训 MultiNLI 392K + SWAG 113K，总 630K 例）的差距，约等于 GPT-3 从 1 example/context 到 8 examples/context 的差距（Figure 3.8）。

### §5.6 生成质量
- 可生成新闻文章，人类评审员难以区分与真人写作（摘要、§6、Appendix E）；作者讨论此的更广泛社会影响（偏见、能源）。

## §6 局限与前提

1. **文本合成弱点**：文档级语义重复、超长段落失去连贯、自我矛盾、偶含不连贯句/段（§5）。
2. **"常识物理"困难**：如 "If I put cheese into the fridge, will it melt?" 类问题处理不佳，尽管 PIQA 表现好（§5）。
3. **检测比较类任务差**：WiC、ANLI 及部分阅读理解（QuAC、RACE）在 one/few-shot 几乎只比随机好（§5、§3.7）。
4. **单一自回归架构**：未含双向架构或去噪目标（作者认为双向大模型可能对 fine-tuning 更强），这可能是填充/回看/细读类任务较弱的原因；指出"做大双向 GPT-3 量级模型"是未来方向（§5）。
5. **预训练目标上限**：当前目标对每个 token 等权，缺乏优先性；self-supervised 任务依赖"把任务塞进预测"，目标导向系统（如助手）可能更应做 goal-directed 行动；大模型未在视频/物理交互等域 grounding——纯扩展 self-supervised 预测很可能碰壁（§5）。
6. **预训练样本效率差**：虽实现 test-time 效率趋近人类（one/zero-shot），但预训练时仍比人类一生所见文本多得多（§5）。
7. **few-shot 本质不确定**：不确定是"推理时从零学新任务"还是"认出训练任务"；此光谱上位置因任务而异，合成任务（词序打乱、新词定义）可能更接近真学习（§5、§3.9）。
8. **计算成本**：V100 集群 + 数百 petaflop/day（GPT-3 13B 已约 50 petaflop/day），训练昂贵，不可重训（§2、§4）。
9. **数据偏差**：训练数据来自互联网，存在职业/性别/种族等方面偏差；作者强调需评估与缓解（§6、Appendix E 人类评估）。
10. **尚未用 fine-tuning 评估**：作者明确 GPT-3 理论上可 fine-tune 但留作未来工作，故所有结论限定在 zero/one/few-shot（in-context learning）范畴（§1、§8）。
