## §4 方法细节

### 4.1 架构（3.1，Fig 3）
- 统一端到端 VLM：encoder（DeepEncoder）+ decoder（DeepSeek3B-MoE）。
- DeepEncoder ≈380M，由 80M SAM-base（patch 16）与 300M CLIP-large 串联。
- Decoder 用 DeepSeek-MoE（DeepSeek-3B-MoE），推理激活 6/64 routed + 2 shared，≈570M 激活参数；"3B 的表达能力 + 500M 的推理效率"。
- 解码映射：f_dec: R^{n×d_latent} → R^{N×d_text}，n ≤ N（压缩维度小于文本维度）。

### 4.2 DeepEncoder 架构（3.2.1）
- 五大设计需求：高分辨率、高分辨率低激活、少 vision tokens、多分辨率、适中参数量。
- 两个组件：**window attention 主导的视觉感知组件（SAM-base）+ dense global attention 的视觉知识组件（CLIP-large）**；CLIP 移除首个 patch embedding 层（输入改为上游 token）。
- 两者之间用 Vary 风格的 2 层卷积做 **16× 下采样**：每层 kernel 3 / stride 2 / padding 1 / channel 256→1024。
- 例：输入 1024×1024 → 1024/16×1024/16 = 4096 patch tokens → 经压缩模块 → 4096/16 = 256 vision tokens，激活可控。

### 4.3 多分辨率支持（3.2.2，Table 1）
- via 位置编码的动态插值实现单模型多分辨率。

| Mode | Native Res | Vision Tokens | Process |
|---|---|---|---|
| Tiny | 512 | 64 | resize |
| Small | 640 | 100 | resize |
| Base | 1024 | 256 | padding |
| Large | 1280 | 400 | padding |
| Gundam | 640+1024 | n×100+256 | resize + padding |
| Gundam-M | 1024+1280 | n×256+400 | resize + padding |

- Tiny/Small 直接 resize（避免浪费 token）；Base/Large 等比例 padding 保持宽高比，有效 token 公式（式 1）：
  N_valid = ⌈N_actual × [1 − (max(w,h)−min(w,h))/max(w,h)]⌉
- Gundam：n 个 640×640 local tiles + 一个 1024×1024 global view（InternVL2.0 式 tiling），n∈[2,9]；若 w,h 均 <640 则 n=0，退化为 Base。vision tokens = n×100 + 256。
- Gundam-master（1024×1024 local + 1280×1280 global）在已训练模型上继续训练（主要因 load balancing，过大分辨率会拖慢整体训练），6M 采样数据。

### 4.4 数据引擎（3.4）
训练混合比：OCR 数据 70%、general vision 20%、text-only 10%。

**OCR 1.0（传统 OCR）**：
- 30M 页 PDF 数据（约 100 语言），中英 ≈25M、其他语言 5M。
- Coarse annotations（用 fitz 从全数据集提取，教学小语种 OCR 识别）+ Fine annotations（中英各 2M 页，用 PP-DocLayout、MinerU、GOT-OCR2.0 标注，layout/text 交错，坐标归一化到 1000 bins）。
- 小语种用 model flywheel：fitz 造 patch → 训 GOT-OCR2.0 → 用其标注 small patches，产 600K 样本。
- 另集 3M Word 数据（无 layout 的高质量图文对，利于公式与 HTML 表格）。
- 自然场景中英文 OCR：LAION + Wukong，PaddleOCR 标注，中英各 10M。

**OCR 2.0（图表/化学/平面几何）**：
- 图表：pyecharts + matplotlib 渲染 10M 图，**定义为 image→HTML table**（不用 OneChart 的 dictionary，省 token），覆盖 line/bar/pie/composite。
- 化学公式：PubChem SMILES + RDKit 渲染 5M 图文对。
- 平面几何：follow Slow Perception，perception-ruler=4 建模每条线段，几何平移不变数据增强，共 1M 数据；ground truth 转为 dictionary 格式（line segments/endpoint 坐标/线段类型等）。

**General vision（保持 KLCIP 通用视觉）**：follow DeepSeek-VL2，caption/detection/grounding，占总数据 20%。

**Text-only**：10% 内部纯文本预训练数据，长度 8192 tokens（也是 DeepSeek-OCR 序列长度）。

### 4.5 训练管线（3.5）
两阶段：a) 独立训练 DeepEncoder；b) 训练 DeepSeek-OCR。

**训练 DeepEncoder（3.5.1）**：follow Vary，用 compact LM（next-token prediction 框架）训练 DeepEncoder；用全部 OCR 1.0/2.0 + 100M LAION 采样数据；2 epochs，batch 1280，AdamW + cosine annealing，lr 5e-5，序列 4096。

**训练 DeepSeek-OCR（3.5.2）**：HAI-LLM 平台，pipeline parallelism 4 段（PP0 放 SAM+compressor 作为 vision tokenizer 并冻结；PP1 放 CLIP 作为 input embedding 层不冻结；PP2/PP3 各 6 层语言模型）。20 节点 × 8 A100-40G，DP 40，global batch 640，AdamW + step-based scheduler，初始 lr 3e-5。纯文本 90B tokens/天，多模态 70B tokens/天。

## §5 实验结果要点

- **压缩研究（4.1，Table 2，Fox）**：100 页英文文档（600–1300 tokens），仅测试 Tiny（64 toks）/Small（100 toks）模式。10× 内解码精度 ≈97%，10–12× 约 90%，20× 仍约 60%。实际精度比报告更高（输出格式与 Fox 无法完全对齐）。随压缩比升高性能下降的两个原因：长文档布局更复杂（可渲染单页布局缓解）；512/640 分辨率下长文本变模糊（作者视为"遗忘机制"特征）。
- **OCR 实用性能（4.2，Table 3，OmniDocBench ED）**：
  - 100 tokens（Small）0.221 超 GOT-OCR2.0（256 tokens，0.287）。
  - 400 tokens（Large，有效 285）≈0.138，与 SOTA 持平。
  - <800 tokens（Gundam 795）0.127 超 MinerU2.0（6790 tokens，0.133）。
  - Gundam-M（1853 tokens，非 800 内）0.123 最优，超 dots.ocr†200dpi（5545 tokens，0.125）。
  - 对照 pipeline 模型（Dolphin/Marker/Mathpix/MinerU-2.1.1/MonkeyOCR-1.2B/PPstructure-v3）；end-to-end 模型（Nougat 2352/SmolDocling 392/InternVL2-76B 6790/Qwen2.5-VL-7B 3949/OLMOCR/GOT-OCR2.0 256/OCRFlux-3B/GPT4o/InternVL3-78B/Qwen2.5-VL-72B/dots.ocr/Gemini2.5-Pro/MinerU2.0）。
  - 中英分项：Chinese overall 最好为 Gundam 0.181 / Gundam-M 0.157；English 均优于中文。
- **按类别（Table 4）**：幻灯片只需 64 tokens 即达标（Tiny 0.116）；books/reports 100 tokens 可良好（Small 0.085/0.079）；报纸需 Gundam/Gundam-master（文本 token 4-5,000 远超 10× 压缩，Gundam overall 0.083 由 Tiny 0.94→Gundam-M 0.077）。
- **定性（4.3，Fig 7-12）**：deep parsing 可对图内图表/几何/化学公式/自然图二次调用解析；支持近 100 语言（阿拉伯语/僧伽罗语演示）；保留通用视觉（描述/检测/grounding）但无 SFT 阶段、非 chatbot，部分能力需 completion prompt 激活；图 12 展示将进酒书法、6月香豆瓣酱标签、消防栓描述、中文 grounded OCR 等。

## §6 局限

- 作者明确承认（§3 Discussion / §6 Conclusion）：
  - **仅概念验证**：OCR 单一场景无法充分验证真正的"上下文光学压缩"，未来需 digital-optical text interleaved pretraining、needle-in-a-haystack 测试等。
  - **压缩比 20× 精度跌至 ~60%**，非无损；超过 10× 后性能明显下降，存在清晰边界。
  - **高分辨率长文本模糊**：512/640 下长文本变模糊，是难以逾越的瓶颈（作者将其正面解读为"遗忘机制"特征，但同时是精度限制）。
  - **无 SFT 阶段**：模型非 chatbot，通用对话/某些能力需特定 completion prompts 激活，复用性受限；General vision 数据仅 20%，声称"不是通用 VLM"。
  - **报纸等超长文档（4-5,000 tokens）需要高 token 的 Gundam/Gundam-master 模式**，此时"少 token"优势弱化。
  - **Gundam 训练集偏斜**：Financial Report 一列的 Gundam 分数异常（0.289，反而不如其他类别），提示分档性能不完全单调稳定。
  - **Dolphin/Mathpix 等 pipeline 与 Gemini2.5-Pro 等专有模型部分列缺失**，对比不完整；表内部分基线为专有/第三方，无法复现。
  - Token 表（Table 3）中 DeepSeek-OCR 的 valid tokens（如 182/285）依赖式 1 近似，实际与理论有差别。
  - 尚未验证 larger LLM 是否同样能自然习得压缩解码能力（作者仅"合理推测"含过拟合风险）。
  - 与人类记忆的类比（Fig 13）为初步设想，多轮对话历史光学压缩、超长上下文架构等仍是早期工作，需深入研究。
