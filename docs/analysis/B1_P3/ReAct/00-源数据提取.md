**一句话摘要**：让 LLM 交错生成「reasoning trace（推理轨迹）」与「task-specific actions（任务动作）」，使二者协同——推理轨迹帮助模型归纳/跟踪/更新动作计划并处理例外，动作则让模型从外部环境（知识库/环境）取信息。在 HotpotQA/Fever 上用简单 Wikipedia API 克服 CoT 的幻觉与误差传播；在 ALFWorld/WebShop 上仅 1–2 个 in-context 示例就比模仿/强化学习方法绝对成功率提升 34% 和 10%。

## §4 方法细节

### 4.1 核心机制（§1, §2, p1–3）
- **动机**：人类智能擅于把「任务导向的行动」与「言语推理/内心独白（inner speech）」无缝结合用于自我调节/策略化与维持工作记忆。
- **ReAct 解码**：在 CoT 的基础上增加动作。模型生成一个交错序列，步进式同步做两件事：
  1. **Thought（推理轨迹）**：用自然语言归纳/跟踪/更新行动计划、处理例外；例如「现在什么都切好了，我应该热锅」「也许我可以 search/lookup x」。
  2. **Act（动作）**：从环境/知识库取信息，如 `search[entity]`、`lookup[string]`、`finish[answer]`。
  3. **Observation（观察）**：环境对动作的文本回响，作为下一步推理的输入。
- **对比**：Act-only 缺乏推理、易迷失（无法分解目标/跟踪环境状态）；CoT/Reason-only 无法取外部信息、易幻觉；ReAct 同时使用「内部知识」与「外部信息」。
- 相比标准 CoT，ReAct 用「稀疏 thought」穿插在动作之间；相比 Act-only，ReAct 的 thought 使动作计划可解释、可恢复。任务型轨迹更贴近人类求解过程，可解释性与可信度更高。

### 4.2 知识密集任务设置（§3.1, p3）
- **HotpotQA**：多跳 QA，需推理 ≥2 个 Wikipedia 段落。
- **Fever**：事实核验，标注 SUPPORTS / REFUTES / NOTENOUGHINFO。
- 用 question-only / claim-only 设定（仅给问题/声明，不提供支持段落），模型靠内部知识或与外部交互取知识。
- **Action space（Wikipedia 风格 API）**：
  - `search[entity]`：返回该实体页面前 5 句；若不存在则建议 top-5 相似实体（来自 Wikipedia 搜索引擎）。
  - `lookup[string]`：返回页中含该字符串的下一句（模拟浏览器 Ctrl+F）。
  - `finish[answer]`：结束任务给出答案。
- 作者强调该 API 明显弱于 SOTA lexical/neural retriever——目的是模拟人类与 Wikipedia 交互的方式，「迫使」模型用显式语言推理来检索。

### 4.3 提示构造
- HotpotQA/Fever：随机从训练集挑 6 个与 3 个 case，手工构造 ReAct 格式的 few-shot 轨迹（密集 thought）。作者发现更多 exemplar 不再提升。
- 决策任务：ALFWorld 每任务类型标注 3 条轨迹，每条含稀疏 thought（分解目标→跟踪子目标完成→确定下一子目标→用常识推理物体位置/如何做）；WebShop 类似。

## §5 实验结果要点

### 5.1 知识密集任务（§3, p3–4; Table1）
- PaLM-540B prompting 结果：ReAct（27.4/60.9）在 HotpotQA 上略低于 CoT-SC（33.4/60.4）的 EM，但 F1/Acc 相当或略优；在 Fever 上与 CoT-SC 相当。
- **融合范式最强**：ReAct→CoT-SC（HotpotQA 35.1 EM）与 CoT-SC→ReAct（Fever 64.6 Acc）先后结合，比单一方法都高——提示了「自洽采样 + ReAct」可互相补足。
- 所有 prompting 方法仍远低于监督式 SOTA（HotpotQA 67.5 / Fever 89.5）。
- **误差分析**：ReAct 克服了 CoT 常见的「推理轨迹幻觉」与「误差传播」：CoT 中约 56% 的失败模式与幻觉/误差传播有关，而 ReAct 通过与 Wikipedia 交互显著缓解（§3.3）。

### 5.2 决策任务（§4, p4–5）
- **ALFWorld**（文本游戏，6 类任务，>50 位置，专家策略 >50 步）：ReAct 最优 trial 平均成功率 71%（vs Act 45%、BUTLER 37%）；最差 ReAct trial 48% 仍超两者最优。相对 Act 的 6 个受控 trial 增益 33%~90%、平均 62%。
- **WebShop**（网页浏览/商品导航）：ReAct 用稀疏推理在模型观测与动作间搭桥（如「对于‘space-saving ottoman bench for living room’，商品有选项‘39x18x18 inch’和‘blue’，看起来值得买」），绝对成功率较 prior best 提升 10%。
- ReAct 的 1–2 shot prompting 已能超越用 10^3~10^5 个任务实例训练的模仿/强化学习方法；但整体仍远低于专家人类（人类做更多商品探索与查询改写，这对 prompting 法仍难）。
- **可解释性**：ReAct 的轨迹（thought+act）比纯行动决策模型更易解释，提升用户信任。

### 5.3 与其他方法对比（§5, p5–6）
- 相关方法：CoT（Wei 2022）、least-to-most prompting、zero-shot-CoT（Kojima 2022）、self-consistency（Wang 2022）、CoT 结构研究（Madaan & Yazdanbakhsh 2022）；行动侧如记忆/工具调用、基于环境反馈的 agent；ReAct 首例把「推理 + 行动」结合并系统评估。

## §6 局限

1. **大动作空间需要更多演示**（§6, p6）：复杂任务（大 action space）要更多 demonstration 才能学好，容易超过 in-context learning 的输入长度限制——作者用微调缓解（HotpotQA 上初显成效），但「从更多高质量人类标注学习」仍是改进的关键。
2. **依赖外部环境质量**：在知识密集任务中结果受限于「弱 retriever」（作者自建简单 Wikipedia API），明显弱于 SOTA lexical/neural retriever；在决策任务中受限于环境接口与奖励稀疏。
3. **仍远慢于/不及监督与专家**：所有 prompting 法在 HotpotQA/Fever 上远低于监督 SOTA；ALFWorld/WebShop 远低于专家人类（专家人类做更多探索与查询改写）。
4. **校准/幻觉仍未根治**：ReAct 只能缓解而非彻底消除推理轨迹幻觉与误差传播；§3.3 显示部分失败仍与错误推理轨迹或无关事实有关。
5. **未与 RL 结合**：作者指出与互补范式（如强化学习）结合、多任务训练可造更强 agent，但留作 future work；人类反馈也可互补融入但同样留作 future work。
6. **可复现性依赖 PaLM**：主实验用 PaLM（非公开），作者提供全部 prompts（Appendix C）并补充 GPT-3 实验以提升可复现性。
