## §4 方法细节

### MLA（Multi-head Latent Attention）
- **痛点**：MHA 的 KV cache 是推理瓶颈；GQA/MQA 压缩 KV 但性能折损。
- **低秩 KV 联合压缩**：`c_t^KV = W_D^KV h_t`（down-projection），`k_t^C = W_U^K c_t^KV`、`v_t^C = W_U^V c_t^KV`（up-projection），c_t^KV ∈ R^dc，dc ≪ dh·nh。推理仅缓存 c_t^KV，每 token 仅 dc·l 个元素（l=层数）。
- **吸收技巧**：推理时 W_U^K 可吸收进 W_Q、W_U^V 可吸收进 W_O，无需显式算出 keys/values。
- **query 低秩压缩**：另设 c_t^Q ∈ R^dc′，降低训练激活内存（不省 KV）。
- **解耦 RoPE**：RoPE 与低秩 KV 压缩不兼容（否则 W_U^K 无法吸收进 W_Q）。故用额外多头 query q_t,i^R ∈ R^dh^R 与共享 key k_t^R ∈ R^dh^R 承载 RoPE；RoPE(·) 仅作用于解耦分支。最终 KV cache 总量为 (dc + dh^R)·l 元素。
- **参数**：nh=128 头，head 维度 dh=128，dc=512，dc′=1536，dh^R=64。

### DeepSeekMoE
- **两大思想**：①更细粒度专家划分 → 更高专家专业化与更精准知识获取；②隔离若干共享专家 → 缓解路由专家间知识冗余。
- **路由**：token 到专家亲和 s_i,t = Softmax(u_t^T e_i)；每 token 激活 K_r 个 routed expert（Topk），共享专家全部激活。
- **Device-Limited Routing**：每 token 目标专家最多分布在 M 台设备上（M≥3 时性能接近无限制 top-K）。先选 M 台亲和最高的设备，再在其中做 top-K。
- **三类平衡损失**：Expert-Level（LExpBal，防路由坍塌，α1=0.003）、Device-Level（LDevBal，跨设备均衡，α2=0.05）、Communication（LCommBal，收发均衡，α3=0.02）。
- **Token-Dropping**：每设备容量因子=1.0，按亲和度从低到高丢弃 token 至预算；约 10% 训练序列的 token 永不丢弃，保证训练/推理一致性。
- **FFN 配置**：除第一层外全换 MoE，每层 2 shared + 160 routed，每个专家中间维 1536，每 token 激活 6 个 routed。

### 超参（§3.1.2）
- 60 层 Transformer，hidden=5120；参数标准差 0.006 初始化。
- AdamW：β1=0.9, β2=0.95, weight_decay=0.1；max lr=2.4e-4，warmup 2K 步，60%/90% tokens 处各乘 0.316。
- batch size 从 2304 逐步增至 9216（前 225B tokens），此后保持 9216。
- 最大序列 4K，训练 8.1T tokens。
- 部署：pipeline（16-way zero-bubble, 8-way expert parallel, ZeRO-1）；每层 routed experts 均匀放 8 设备（D=8）。

### 基础设施（§3.1.3）
- HAI-LLM 框架；16-way zero-bubble pipeline + 8-way expert parallel + ZeRO-1；NVIDIA H800 集群（节点内 NVLink/NVSwitch，跨节点 InfiniBand）。
- MLA 基于改进版 FlashAttention-2；重叠 shared expert 计算与 all-to-all 通信。

### 对齐（§4）
- **SFT**：1.5M 实例（1.2M helpfulness + 0.3M safety），2 epochs，lr=5e-6，提升数据质量缓解幻觉。
- **RL**：GRPO（Group Relative Policy Optimization，无 critic，用组内分数估计 baseline），两阶段：先推理对齐（reward model RM_reasoning，code/math）→ 再人类偏好对齐（多奖励框架：RM_helpful + RM_safety + RM_rule，系数 c1/c2/c3）。
- **工程优化**：混合引擎、vLLM 大 batch 作推理后端、CPU offload 调度。

## §5 实验结果要点

### Table 2（基础模型对比，21B vs 67B/72B/70B）
- 架构：#Activated 21B（V2）vs 67B/72B(密集)/39B/70B。
- Pile-test (BPB)：DeepSeek 67B 0.642 / Qwen1.5 72B 0.637 / Mixtral 8x22B 0.623 / LLaMA3 70B 0.602 / DeepSeek-V2 0.606。
- MMLU 5-shot：67B 71.3 / 72B 77.2 / 8x22B 77.6 / LLaMA3 70B 78.9 / DeepSeek-V2 78.5。
- BBH 3-shot：68.7 / 59.9 / 78.9 / 81.0 / 78.9。
- DROP F1 3-shot：69.7 / 71.5 / 80.4 / 82.5 / 80.1。
- HellaSwag 10-shot：86.3 / 85.8 / 86.6 / 87.9 / 84.2（V2 略低）。
- 结论：仅 21B 激活，DeepSeek-V2 在多数英文/code/math 基准显著超 DeepSeek 67B，达开源顶级。

### 效率（§3.2.3）
- 训练：DeepSeek 67B 300.6K GPU 小时/T tokens vs DeepSeek-V2 172.8K（省 42.5%）。
- 推理：FP8 权重 + KV cache 量化 6bit；单节点 8×H800 生成吞吐 >50K tokens/s（5.76×），输入吞吐 >100K tokens/s。

### Chat 评估（Table 4/5）
- SFT 相对 base 在 GSM8K/MATH/HumanEval 大幅提升；RL 进一步提 math/code。
- 开放式对话：DeepSeek-V2 Chat (RL) 在 AlpacaEval 2.0 与 AlignBench 均超越 open-source 同类；对比 LLaMA3 70B Instruct 在 MT-Bench 相当、AlpacaEval 2.0 明显胜出。

### DeepSeek-V2-Lite（附录 B）
- 15.7B 总参 / 2.4B 激活，同样配备 MLA + DeepSeekMoE，供开源研究。

## §6 局限

1. **知识时效**：预训练后无持续知识更新。
2. **幻觉/非事实**：可能生成未经证实的建议（non-factual information）、可能产生幻觉。
3. **多语言局限**：语料主要中英文，其他语言熟练度有限，应谨慎使用（明确警示：中英文以外的场景需小心）。
4. **当前纯文本**：仅支持文本模态（未来计划支持多模态）。
5. **MoE 通信开销**：虽经优化，MoE 引入额外通信，训练仍需复杂工程调度（device-limited routing / balance losses / token-dropping）保证效率。
