## §3 核心主张与关键数字表

**核心主张**：仅用 1,000 条精心挑选的推理样本（s1K）对 Qwen2.5-32B-Instruct 做监督微调（SFT），配合一个极简的测试时缩放技巧 budget forcing（在解码时强行追加或截断思考 token），即得到 s1-32B——一个能与 OpenAI o1-preview 竞争的开放推理模型，位于样本效率帕累托前沿（sample-efficiency frontier），并首次复现了 OpenAI 的 test-time scaling 曲线。

## §4 方法细节

- **数据来源（§2.1）**：59,029 题来自 16 个来源，三类：
  - 既有数据集：Numina-MATH（30,660 数学题）、历史 AIME（1983–2021）、OlympicArena（4,250，覆盖天文/生物/化学/CS/地理/数学/物理）、OmniMath（4,238）、AGIEval（2,385，含 SAT/LSAT 等）。
  - 原创数据集新建：s1-prob（182 题，Stanford 统计系 PhD Qualifying Exams 概率部分 + 手写证明）；s1-teasers（23 道，PuzzledQuant 定量交易面试题，仅取最高难度 "Hard"）。
  - 每题用 Google Gemini Flash Thinking API 生成 reasoning trace + solution，得到 59K 三元组。
- **过滤三原则（§2.2）**：Quality（去 API 错误→54,116；去格式问题/ASCII 图/不一致编号→51,581；再保留 384 个高质量基础样本集）、Difficulty（用 Qwen2.5-7B-Instruct 与 32B-Instruct 双模型评测，Claude 3.5 Sonnet 判定对错，剔除两模型都能解对"过易"的题→24,496）、Diversity（用 Claude 3.5 Sonnet 按 AMS MSC 2020 数学分类法归入领域）。
  - 最终采样：先均匀随机选一个 domain，再按"偏爱更长 reasoning trace"的分布采样一道题（激励难度），重复至 1,000 题、跨 50 个领域。
- **s1-32B 训练（§4.1）**：对 Qwen2.5-32B-Instruct 用 s1K 做 SFT，基本超参见附录 D；26 分钟 / 16×H100，PyTorch FSDP。
- **Budget forcing（§3.1）**：解码期干预，强制最大/最小思考 token 数：
  - 上限：直接追加 end-of-thinking token 分隔符（+可选 "Final Answer:"）让模型提前结束思考→转输出答案。
  - 下限：抑制 end-of-thinking token 的生成，改为在 reasoning trace 后追加 "Wait"，诱导模型反省并继续思考（图3 示例：模型想写 "...is 2." 被抑制并追加 "Wait"，自我纠错成功）。
- **Metrics（§3.2）**：三类评测维度（§4.1 用 AIME24 / MATH500 / GPQA Diamond 三个基准）：
  - Control（可控性）= 允许强制思考token落在 [a_min,a_max] 的比例百分比，100% 为完美。
  - Scaling（缩放斜率）= 分段线性函数的平均斜率，必须为正，越大越好。
  - Performance（性能）= 方法在基准上达到的最大准确率。
- **测试时缩放方法分类**：Sequential（后序计算依赖前序，如加长 reasoning trace）vs Parallel（并行独立，如 majority voting）。本文聚焦 sequential。
- **评估**：基于 lm-evaluation-harness；除注明外 temperature=0(greedy) 即 pass@1；AIME24（30 题，字向量语言 Asymptote 输入）、MATH500（OpenAI 选定的 500 道，5-shot）、GPQA Diamond（198 道 PhD 级科学题，GPQA 恒指其 Diamond 子集）。

## §5 实验结果要点

- **主结果（表1）**：s1-32B（1K+BF）AIME24 56.7 / MATH500 93.0 / GPQA 59.6，显著优于 base（26.7/84.0/49.0），且几乎追平 Gemini 2.0 Flash Thinking（60.0 AIME24）。s1-32B 为最样本高效的开放数据推理模型。
- **Test-time scaling（图1/图4a）**：预算强制 + 更多测试时计算能提升 AIME24，但六次后趋于平缓（flatten）。抑制 end-of-thinking token 过频会陷入重复循环而非持续推理。
- **外推能力（表4，忽略 end-of-thinking 两次）**：追加不同字符串外推性能，AIME24/MATH500/GPQA Diamond 分别为：无字符串 50.0/90.2/55.1；"Alternatively" 50.0/92.2/59.6；"Hmm" 50.0/93.0/59.6；**"Wait" 53.3/93.0/59.6**（最优）。s1-32B from 50%→57% 外推即此机制。
- **并行缩放 vs 顺序（图4b/图7）**：对 base 用 majority voting（4/8/16/32/64，temp=1）追不上 s1-32B 的顺序缩放，佐证 sequential 更有效。REBASE（树搜索 + process reward）缩放效果好于 majority voting 甚至部分 sequential，但每步需额外一次 reward model forward。
- **数据消融（表2，BF 上限约30K 思考token）**：
  - 1K-random（只 quality）：AIME24 36.7 [CI -26.7%,-3.3%]
  - 1K-diverse（最大多样性）：AIME24 26.7 [CI -40.0%,-10.0%]
  - 1K-longest（最长 trace）：AIME24 33.3 [CI -36.7%,0.0%]
  - 59K-full：AIME24 53.3（但贵，394 H100-hours vs 7）
  - **s1K（三者结合）：50.0**，最优
  - 结论：三原则（quality/difficulty/diversity）联合是关键；任一单独用都明显更差（对 AIME24 约 -30%）。
- **方法消融（表3）**：TCC（token-conditional）Controllability 40%，Scaling -2（负）；SCC（step-conditional）Scaling 3、Performance 6.75；CCC（class-conditional）Scaling 50%、Performance 6.72；RS（rejection sampling）Scaling -35（负）、Performance 40.05；**BF 100% Control / Scaling 15 / Performance 56.75，最优**。
- **类条件控制研究（§5.2/§E.1）**：(1) token-conditional 单独用会失败——模型无法可靠数 token；(2) step-conditional 下模型在"少步多 token / 多步少 token"之间作弊，可控性平庸；(3) class-conditional（"think longer"）能提升但可控性一般。
- **Rejection sampling 反直觉（图6）**：按长度采样直至生成小于阈值（3500/4000/5000/8000/16000 token）出现**逆缩放**——平均需 655/97/8/3/2/1 次采样，短生成往往是"一开始就对了"，长生成常因犯错 backtracking 而更长→越长越可能错。

## §6 局限

1. **顺序缩放有上限**：预算强制最终平缓（图4），且会被底层模型 context window 约束——§6.2 提到顺序缩放提示到 512 steps 时，30 道评估题中有 12 道生成超出上下文窗口导致大幅性能跌落。
2. **并行缩放补足有限**：majority voting / REBASE 需额外 reward-model forward 开销，且 REBASE 计算成本未计入平均思考 token。
3. **数据蒸馏依赖单一教师**：s1K 全部由 Gemini 2.0 Flash Thinking 蒸馏，Gemini API 存在 "recitation error"（作者手动插入全部 30 道 AIME24 规避，但 MATH500 与 GPQA 无法规避，故表中这两行为 N.A.），数据质量与教师模型强相关。
4. **对比样本口径差异**：表 1 各模型 #ex 与训练方式不一（r1 用 RL + 800K；o1 闭源），跨表对比有限；表 1 中 Gemini 2.0 的 MATH500/GPQA 为 N.A.。
5. **关于"1000 样本为何足够"的机制未定论**：作者以 "Superficial Alignment Hypothesis"（LIMA）类比，认为推理能力已在预训练中具备，仅需激活——但这是假设而非验证（§6.1）。
6. **budget forcing 的重复循环风险**：抑制端 think token 过频会导致重复循环，需谨慎控制次数；"Wait" 恰好在特定次数下最优，泛化性尚需考证。
