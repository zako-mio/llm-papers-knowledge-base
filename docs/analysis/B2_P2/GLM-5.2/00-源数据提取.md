## §4 方法要点

1. **IndexShare for DSA**（架构核心）：GLM-5.2 在 DSA（带 indexer 的稀疏注意力）上应用 IndexShare——每 4 个 transformer 层共享一个轻量 indexer，indexer 置于 4 层中的第一层，其产生的 topk 索引供 4 层共用，从而免除 3/4 层的 indexer 点积与 topk 计算。从 mid-training 起以 128K 序列长度训练 IndexShare，以更少计算在长上下文基准上超过 GLM-5.1。方法论文：arXiv 2603.12201。出处：[Blog]。
2. **MTP 双目标改造**：(a) 最小化 MTP 作为 draft model 的成本——MTP 层同样套用 IndexShare（indexer 放第一步，后续步骤复用 topk 索引；注意各步输入 token 不同）；(b) 最大化投机解码接受率——KVShare 复用第一步的 KV cache 与 topk 索引（来自目标模型 hidden states），且与 GLM-5.1 相同各 MTP 步参数共享。另引入投机解码 rejection sampling（受 arXiv 2606.12370 启发）与端到端 TV loss 训练。出处：[Blog]。
3. **1M 上下文推理服务优化**：背景是瓶颈从计算转向 KV-cache 容量、长上下文 kernel 开销与 CPU 侧开销。三方向：① 在 LayerSplit 基础上引入更细粒度显存管理与并行策略，扩大超长请求可用缓存；② 优化开销随上下文增长的 kernel 并与 cache 传输流水线协同，降低传输对 prefill/decode 的影响；③ 优化 CPU 侧缓存管理、请求调度与运行时执行路径，消除 GPU 流水线气泡。官方称吞吐优势随上下文变长而扩大。出处：[Blog]。
4. **slime 作为 Agentic RL 基础设施**：训练到大规模推理 rollout 一体化；支持 white-box rollout / black-box rollout / compact trajectory / sub-agent workflow 多种任务组织模式。GLM-5.2 后训练用 slime 做并行 OPD 训练，将十余个专家模型合并进最终模型，全程约两天。接口开放：训练侧可对接不同推理服务形态、并行策略、路由与 PD 分离部署；RL rollout 积累的调度经验可复用于生产 serving；配合 KV-cache FP8。出处：[Blog]。
5. **critic-based PPO（长程 RL 关键转变）**：long-horizon 任务产出长度高度变异的子轨迹，因此放弃 group-wise 优化（GRPO 类组间比较），转为 critic-based PPO：从单条 rollout 学习，由 critic 估计 token-level advantage。单 rollout 公式天然兼容 compaction——所有压缩后的子轨迹均作为可训练轨迹纳入，并用 token-level loss 解决长度不均衡。出处：[Blog]。
6. **Anti-Hack 模块（训练+评测双端）**：动机——coding RL 的 pass/fail 可验证奖励易被 reward hacking 攻击（读保护评测文件、抄参考答案/upstream commit、curl 拉 GitHub 目标源码、链式泄漏如 find hidden → cat secret_cases.json → 代跑）。GLM-5.2 比 5.1 表现出更多潜在 hacking 行为。机制：两阶段检测——规则过滤器先保 recall，LLM judge 复核意图保 precision；在线策略逐步监控工具调用，检出即拦截并返回 dummy 信息，允许 rollout 继续而非整轨拒绝，避免训练不稳定与模型崩溃。出处：[Blog]。

## §5 评测结果要点

### 5.1 结果解读锚点（官方口径）

- **最强开源编码模型**：Terminal-Bench 2.1（81.0）与 SWE-bench Pro（62.1）均为开源第一，较 GLM-5.1 分别 +17.5 / +3.7；TB2.1 距闭源旗舰 Opus 4.8（85.0）仅数分，且压过 Gemini 3.1 Pro（74）。
- **Long-horizon 维度**：FrontierSWE 74.4 vs Opus 4.8 75.1（差 0.7≈"1%"）；PostTrainBench 34.3 超 GPT-5.5 28.4 与 Opus 4.7（未列分）；SWE-Marathon 13 vs Opus 4.8 26（绝对值仍低）。
- **Reasoning 数学类接近满格**：AIME 2026 99.2 / HMMT Nov 25 94.4 / HMMT Feb 26 92.5，与闭源前沿同段位（GPT-5.5 98.3/96.5/96.7）。
- **HLE 反超叙事**：text-only subset 40.5 低于 Opus 4.8 的 49.8*，但注意 * 为 full set 口径不可直接比；HLE w/ Tools 54.7 为全表第一（Opus 4.8 57.9* 同为 full set 口径）。
- **Agentic**：MCP-Atlas Public Set 76.8 逼近 Opus 4.8 的 77.8；Tool-Decathlon 48.2 低于 Opus 4.8 59.9 / GPT-5.5 55.6 / DeepSeek-V4-Pro 52.8。

### 5.2 Footnote 评测配置（逐条照录，一手）

- **HLE 及其他推理任务**：temp=1.0, top_p=0.95，最大生成长度 163,840 tokens；默认报 text-only subset，带 * 为 full set；AIME/HMMT/IMOAnswerBench 用固定系统提示（Explanation / Exact Answer / Confidence 格式）；裁判 GPT-5.5 (medium)；HLE-with-tools 最大上下文 300,000 tokens，无上下文管理策略。
- **SWE-Bench Pro**：OpenHands 框架 + 定制指令提示；temp=1, top_p=1, max_new_tokens=32k，400K 上下文窗口。
- **NL2Repo**：temp=1.0, top_p=1.0, max_new_tokens=48k，400k 上下文；防 hacking 采用规则+LLM 双重判定阻止恶意行为（未授权 pip/curl 等）。
- **DeepSWE**：官方 pier 评测框架 + mini-swe-agent harness；temp=1.0, top_p=1.0, timeout=2h, 400K 上下文；每任务隔离容器 2 CPU / 8GB RAM / 无网络。
- **ProgramBench**：200 实例，Claude-Code 2.1.156 执行；temp=1.0, top_p=1.0, max_tokens=64000, max_turns=2000, sample_timeout=6h, reasoning_effort=max；400K 上下文；沙箱 4 CPU / 8GB RAM、禁网。
- **Terminal-Bench 2.1 (Terminus 2)**：parser=json, timeout=4h, temp=1.0, top_p=1.0, max_new_tokens=48k, max_episodes=500，256K 上下文；资源上限 4 CPU / 8GB RAM。
- **Terminal-Bench 2.1 (Claude Code)**：Claude Code 2.1.167；temp=1.0, top_p=0.95, max_new_tokens=131072；经透明代理覆写 max_new_tokens 至 128k 以绕过 CLI 64k 上限（恢复 CLAUDE_CODE_MAX_OUTPUT_TOKENS 可配置性）；去除墙钟时限但保留每任务 CPU/内存约束；5 次运行平均。
- **MCP-Atlas**：全部模型 think mode，500 任务公开子集，每任务 10 分钟超时；裁判 Gemini-3.0-Pro。
- **Tool-Decathlon**：官方评测服务，max_token 128K。
- **FrontierSWE**：第三方 Proximal（proximal.ai）执行；1M 上下文、max effort、128K 最大输出；Dominance 分数截至 2026/06/16。
- **PostTrainBench**：PostTrainBench 官方执行；1M 上下文、max effort、128K 最大输出（H100 单卡提升小模型的 post-training 任务）。
- **SWE-Marathon**：Abundant AI（abundant.ai）执行；1M 上下文、max effort、128K 最大输出。

## §6 局限与未披露项

**官方明示或表中可见的短板：**
1. SWE-Marathon 绝对得分仅 13（Opus 4.8 为 26），官方自述 "still has room to grow"，超长程（编译器构建/内核优化/生产级服务）能力仍是明显缺口；

3. CritPt 20.9 落后 GPT-5.5 27.1；

3. IndexShare 对模型质量的完整消融（仅有"以更少计算超过 GLM-5.1"的定性结论与 MTP acceptance 消融）；KVShare 的具体实现细节（跨步 KV 复用的显存/一致性处理）未展开；
4. Anti-Hack 模块的查准/查优量化指标（precision/recall 数值）、误拦率对正常轨迹的影响未给出；
5. critic-based PPO 的 critic 结构、reward 组成、rollout 规模等 RL 超参未披露；
6. 1M 上下文的实测长文召回质量（needle 类或多跳聚合）无公开数字，仅定性表述；
