## §4 方法细节
### 4.1 块划分与门控路由（§2.2，p3）
- 上下文长度 N 分为 n=N/B 个块，块 i 覆盖 I_i=[(i−1)×B+1, i×B]。
- MoBA(q,K,V)=Softmax(q⊤K[I])V[I]，I=∪{I_i | g_i>0}。
- 亲和度分数 s_i=⟨q, meanpool(K[I_i])⟩（query 与块均值池化 key 的内积，无独立 router 参数）；对全块做 top-k 选择，选中者 g_i=1。

### 4.2 因果性双设计（p4）
1. **禁路由未来块**：pos(q)<i×B 的块置 s_i=−∞；
2. **强制当前块 + 因果掩码**：query 所在块 g_i 恒为 1，块内 attention 施加因果 mask——既防 meanpool 泄露未来信息，又保证局部上下文。作者将当前块类比为现代 MoE 中的 **shared expert**（静态路由）。

### 4.3 关键设计选择（p4）
- **细粒度块分割**：借鉴 MoE 细粒度专家经验沿序列维应用；
- **参数等价可替换**：与 Full Attention 参数量严格相同，可逐层随时切换（初始化时或训练中途）；
- **表达力覆盖**：SWA=恒选最近块的特例；attention sink=恒选初始块+最近块的特例——MoBA 是二者的严格超集。

### 4.4 高效实现（§2.3，p4–5，Algorithm 1）
五步：①KV 分块；②算门控分数 S=Q·K̄⊤（K̄=meanpool）并加因果 mask 后 top-k 得分配矩阵 G；③按分配重排 query；④历史块 attention 用 varlen FlashAttention（causal=False）、当前块单独用 causal=True 计算；⑤输出还原顺序并用 online softmax 合并（tiling）。

### 4.5 训练配方（§3.2–3.3，p7–9）
- Scaling law：5 模型（568M/822M/1.1B/1.5B/2.1B；token 10.8B/15.3B/20.6B/27.4B/36.9B），block=512，top-k=3，seq 8K。
- Hybrid 训练：1.5B、30B tokens、32K ctx、block 2048、top-3；前 90% token MoBA → 后 10% 切 Full Attention。
- Llama3.1 8B 长上下文续训：128K→1M 渐进（256K 起用 position interpolation），MoBA 激活 100B tokens；block=4096、top-K=12（@1M 稀疏度 95.31%）；layer-wise hybrid：**最后 3 层保留 Full Attention，其余 29 层切 MoBA**。

## §5 实验结果要点
- **Scaling law（Figure 3，p6）**：8K LM loss 曲线与 Full 几乎重合（差异 <1e-3）；trailing loss（32K last 2K）MoBA 全部 5 个尺度略高但 gap 随算力增大持续收窄。
- **细粒度消融（Figure 4，p7）**：1.5B/32K、固定稀疏度 75%（8选2/16选4/32选8/64选16/128选32），最粗粒度差约 1e-2——细粒度分割是 MoE 家族通用增益技术。
- **Hybrid 训练（Figure 5a，p8）**：位置级 loss 随位置呈幂律；MoBA-only 尾部 token loss 偏高，hybrid 配方与纯 Full 几乎重合，切换过程无 loss spike。
- **Layer-wise hybrid SFT（Figure 5b/c，p8）**：MoBA SFT 偶发欠佳，归因于 SFT loss masking（prompt 不计 loss）导致稀疏梯度难以贯穿整个上下文回传；仅将最后数层换回 Full 即显著降低 SFT loss 与 trailing loss。
- **下游评测（Table 2，p9）**：Llama-8B-1M-MoBA ≈ Full：AGIEval 0.5144/0.5146，BBH 0.6573/0.6589，CEval 0.6273/**0.6165**，GSM8K 0.7278/0.7142，HellaSWAG 0.8262/0.8279，Loogle 0.4209/0.4016，CompetitionMath 0.4254/0.4324，MBPP 0.5380/0.5320，MBPP-Sanitized 0.6926/0.6615，MMLU 0.4903/0.4904，MMLU-Pro 0.4295/0.4328，HumanEval 0.6951/0.7012，SimpleQA 0.0465/0.0492，TriviaQA 0.5673/0.5667，LongBench@32K 0.4828/0.4821，RULER@128K 0.7818/0.7849。注：**所有评测 MoBA 仅用于 prefill，生成阶段切回 Full Attention**。
- **NIAH（Figure 7，p9）**：1M 上下文内检索表现满意（热图大部分 ≥80 分带，深水区有局部低分带）。
- **效率（§3.4，p10）**：仅比较 attention 层前向时间（其余层 FLOPs 相同）。1M prefill 最高 6.5×；延长至 10M token（top-k 与块数固定、块大小等比放大以维持稀疏率；张量并行扩展至 query head 级广播 KV），10M 处注意力计算时间降 16×，短序列（32K–512K）两者相当、越长优势越大。

## §6 局限（原文可证 + 明显边界）
1. **解码未稀疏化**：全部下游评测中 MoBA 仅用于 prefill、生成阶段显式切回 Full Attention（p9"switch to full attention during generation for better performance"）——推理端到端的解码加速收益未被证明。
2. **SFT 场景需补救**：MoBA 单独 SFT 有时次优（loss masking 稀疏梯度假说，作者自称 speculation），依赖 layer-wise hybrid 缓解（p8）。
3. **尾部损失略劣**：trailing LM loss 在所有 5 个尺度上均略高于 Full（虽收敛趋势向好，p7）；RULER@128K 也略低（0.7818 vs 0.7849）。
4. **复杂推理证据不足**：作者自述未来才研究"complex reasoning tasks 的泛化"（p11 结论）；Competition Math 0.4254<Full 0.4324。
5. **超参敏感**：性能强依赖块粒度/top-k 组合（细粒度消融差 1e-2，p7）；不同规模/上下文长度需重新调配（512/3 → 2048/3 → 4096/12）。
6. **门控表示简单**：meanpool 块表示较粗糙（论文承认 Quest 的 min+max pooling 是一种更强块表示变体，p10 Related Work），检索精度上限可能受限（NIAH 深水区存在低分区域，Figure 7）。
