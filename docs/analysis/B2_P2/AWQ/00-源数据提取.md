# §4 方法细节

1. **核心观察（§3.1）**：LLM 权重并非同等重要，存在一小撮显著权重。跳过(保留为FP16)/保护这些权重可明显降低量化损失。重要的是**用激活分布而非权重分布来选择显著通道**（激活幅度大 的通道更关键）。Table1 显示：按激活幅度保留 0.1%-1% 权重，FP16 性能大幅提升（OPT-6.7B: RTN 23.54 → 保留1%激活类 11.58）；而按权重幅度或随机保留则几乎无改善。

2. **混合精度的局限**：保留 0.1%-1% 权重为 FP16 虽小，但混合精度数据类型的系统实现困难（硬件低效）。于是改用**对显著通道进行 scaling**。

3. **量化误差分析（§3.2）**：对 group/block 权重 w，y=wx；量化 Q(w)=Δ·Round(w/Δ)，Δ=w_max/(2^N−1)。将 w 乘以 s>1 并把 x 逆缩放 1/s：Q(w·s)·(x/s)。因 Δ'≈Δ < 及 s>1，显著权重的相对误差变小。经验：将 1% 显著通道乘 s>1，OPT-6.7B PPL 由 23.54(s=1) 改善至 11.92(s=2)；s 继续增大则 21.2% 通道的 Δ 改变，非显著通道误差被放大，故最优 s=2。

4. **最优 scaling 搜索**：目标 s*=argmin L(s)，L(s)=‖Q(W·diag(s))·(diag(s)·X) − W·X‖。因量化函数不可微，采用简单搜索空间：s=s_X^α，s_X 为 activation 的 per-channel 平均幅度，α∈[0,1]（0=不缩放，1=最激进）。由仿射搜索（grid 大小 20）求 α。无需反传/回归，仅测每通道平均幅度 → 最小化校准集依赖，防过拟合。

5. **TinyChat（§4）**：
   - **动机**：on-device 上 generation 阶段远慢于 context 阶段（LLaMA-7B @ 4090：生成 20 tokens 需 310ms，处理 200-token prompt 仅 10ms）。Generation 是**内存受限**的（算术强度≈1），weight access 远多于 activation。
   - **解法**：W4A16 量化把算术强度提升 4 倍 → 4 TFLOPS 峰值。通过 on-the-fly weight dequantization（融合到 GEMM kernel，避免中间 DRAM 写入）、kernelfusion（LayerNorm、QKV、attention、KV cache）、SIMD-aware weight packing（ARM 128-bit SIMD，3 指令解 32 权重）落地。

# §5 实验结果要点

- **Table4（主结果 PLLM）**：INT4-g128 AWQ 在 LLaMA/Llama-2 全尺寸上优于 RTN 与 GPTQ（含/不含 reorder）。如 Llama-2 7B INT4：FP16 5.47，RTN 5.73，GPTQ 5.69，GPTQ-R 5.63，AWQ 5.60；INT3：AWQ 6.24 vs GPTQ 6.43 vs RTN 6.66。
- **Table5（Mistral/Mixtral）**：Mistral-7B FP16 4.14 / INT4-g128 4.30 / INT3-g128 4.83；Mixtral-8x7B 5.94/6.05/6.52。AWQ 对 GQA 与 MoE 架构同样有效。
- **Figure5（Vicuna）**：GPT-4 评审下 80 样本，INT3-g128 的 AWQ 一致优于 RTN/GPTQ，表明对 instruction-tuned 模型泛化。
- **Table6（OpenFlamingo-9B COCO）**：INT4-g128，32-shot 退化：AWQ -1.17 vs RTN -4.57 vs GPTQ -6.72（FP16 基线 81.70）。首次实现 VLM 低比特量化。
- **Table7（VILA）**：INT4-g128 在 11 个多模态基准上几乎无损（如 VQA-v2 7B: 80.36→80.1）。
- **Table8（编程/数学）**：CodeLlama-7B MBPP pass@1：AWQ 40.64 vs FP16 38.53 vs GPTQ 31.97（甚至超 FP16）；Llama-2 GSM8K 7B：AWQ 13.57 vs FP16 13.87。
- **Table9（INT2 极低比特）**：OPT-6.7B AWQ+GPTQ 11.38，优于单独 GPTQ 13.25 / AWQ 11.39（正交可组合）。
- **Table10（VILA 加速）**：VILA-7B A100 81.6→155.3，4090 58.5→168.1，Orin 11.5→35.6；VILA-13B 4090 OOM→99.0。
- **Figure10（边缘平台）**：Jetson Orin 上 1.2-3.0× 优于现有系统；Raspberry Pi 4B 达 0.7 tokens/s（7B）；TinyChat 支持 StarCoder/StableCode/Mistral/Falcon，至少 2.6× 优于 AutoGPTQ。

# §6 局限

1. 论文主要聚焦 **weight-only quantization**（W4A16/W3A16），未处理 W8A8 激活量化；W4A16 需要 dequantization 融入主计算循环，实现复杂度高于 W8A8（如 SmoothQuant）。作者明确说明这是为减少硬件 barrier 与加速 token 生成等内存受限工作的主动取舍。
2. 校准集稳健性虽好，但论文承认在**校准与评估分布一致时效果最佳**；跨分布（如 PubMed↔Enron）虽有优势，仍有 0.5-0.6 PPL 损失。
3. 对 GPTQ 的融合（INT2）虽有改进，但 INT2 本身仍显著高于 FP16（OPT-6.7B AWQ+GPTQ 11.38 vs FP16 10.86），极低比特仍是挑战。
4. TinyChat 仅在特定硬件（RTX 4090/4070、Jetson Orin、Raspberry Pi）实测，需平台特定的 SIMD packing 与 kernel fusion，不同平台间可迁移性未系统性验证。
5. 主结果用 WikiText-2 困惑度作为主要指标，作者沿用文献惯例但因困惑度不能完全反映生成质量，实际部署效果仍需下游任务验证（作者通过 Vicuna/VLM/编程数学等任务部分弥补）。
