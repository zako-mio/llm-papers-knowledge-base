## §4 方法要点（后训练管线）

**① 端到端任务环境合成流水线（docs L42）**
- 研究智能体（research agent）从真实工作收集任务模式 → 转化为可运行的长程任务环境（含多步骤依赖关系、隐藏状态）。
- 评审智能体（review agent）实际尝试完成每项任务，验证任务是否确实可解。
- 验证器（verifier）在**不访问参考解法**的前提下生成。
- 系统利用求解轨迹识别并**消除奖励捷径（reward hacking / shortcut）**。
- 只有同时通过 **Oracle 检查、空操作（null-action）检查、未解决状态检查**的验证器，其生成的二值奖励信号才可靠，可直用于训练。

**② 自动奖励生成（docs L42）**
针对部分任务进一步自动生成 RL 所需奖励信号，减少人工标注。

**③ SAO + 上下文压缩的 RL（docs L43；arxiv 2607.07508；2603.12201 IndexShare）**
- SAO = Reinforcement Learning on Long-horizon tasks。
- 结合上下文压缩机制（IndexShare 用于高效长上下文处理），使增益在长程任务落地，不局限于短程。
- 配套 slime（THUDM）做大规模异步训练。

**④ 环境真实性举例（docs L40-41）**
机器学习基础设施任务中，模型获得与工程师相同环境（计算集群、存储系统、内部文档、代码库、实验结果），需定位训练技术栈性能瓶颈 → 实施优化 → 运行实验 → 保证正确性 → 端到端可量化加速。部分任务经验丰富工程师亦需数天。

**⑤ 网络安全数据纳入后训练（docs L47）**
将漏洞发现数据与环境纳入训练体系，预期提升「发现并分析推理漏洞」能力；实际随规模扩张，能力超预期，能跨漏洞利用多阶段推理，形成连贯完整 exploit chain。

**⑥ 局限披露（docs L43）**：目前流水线仍需较多人工参与，提升环境生成与验证的自主化程度是下一阶段重点。

## §5 评测结果要点

### 5.1 编程（Coding）——公开 + 内部双轨
- 内部基准 **Z.ai Code Bench**（非公开，贴近真实用户，覆盖多任务类别，复杂本地开发环境，降低测试集污染风险）。双维度评估：端到端任务完成率 + 细粒度检查项准确率（docs L44）。不同推理档位下均显著优于 GLM-5.2，且输出 Token 更少（docs L45）。Max 档 34.5% vs 23.4%，Token ~7.5万 vs ~9.6万；High 档 31.4%（~5万 Token）超 Claude Opus 4.8 的 29.5%（~12万 Token）。与 Claude Fable 5（Max 39.5%）仍有差距。
- 公开基准 SOTA：Terminal Bench 3.0 开源 SOTA、Agents' Last Exam (CLI) 开源 SOTA。

### 5.3 评测方法脚注（blog JS bundle 提取，官方口径）
- **Terminal-Bench-3**：Claude Code 2.1.207 harness，reasoning_effort=max，400K context，128K max output；avg@3（每任务 3 次 rollout）；每 rollout 独立容器（任务官方镜像），600 agent turns / 10h 超时；Tool Search 禁用；产物由任务官方独立 verifier 打分。
- **ALE**：官方协议 + Claude Code harness，reasoning_effort=max，1M context，64K max output；105 任务各跑隔离 Docker 容器；默认超时 4h（任务特定上限至 8h）；Tool Search 禁用；官方 ALE evaluators 评分。
- **DeepSWE**：mini-swe-agent harness，官方 evaluation service，Pass@1 平均 3 次独立运行。
- **ExploitGym**：Claude Code 2.1.207，max effort，t=1.0，top_p=0.95，max_new_tokens=128K，1M context；单跑 Pass@1 on 869 tasks；2h/6h 超时预算按 per-model TPS 重缩放（GLM-5.3 按 115 TPS、Kimi K3 按 40 TPS、Qwen3.8 Max 按 47 TPS，TPS 源 Artificial Analysis）+ 非 API 开销；域名白名单防作弊（仅 pypi.org / deb.debian.org）。
- **Terminal Bench 2.1 / 多通用评测**：Claude Code 2.1.207，max reasoning effort，无 web tools，t=1.0，top_p=1.0，max_new_tokens=128000，1M context；单跑 Pass@1 over 1507 tasks；Agent 置于任务容器内；移除 Git 信息 + 域名白名单防作弊。
- **NL2Repo**：t=1.0，top_p=1.0，max_new_tokens=64K，1M context；规则 + LLM 判定防恶意行为（未授权 pip/curl）。
- **自动化相关反作弊说明**：anti-cheat 原用宽泛 import 检测，误报拒绝合法实现（如经 OpenAI SDK 访问本地 vLLM endpoint），已移除改用 LLM agent 检视解决方案是否用外部 API。

### 5.4 网络安全真实场景迁移（docs L50-52）
- 三基准呈一致趋势：**利用链越深入，GLM-5.3 相对 GLM-5.2 提升越显著**；同时与闭源前沿差距也越大——「差距最大的方向恰是增长最快的方向」。
- 自 GLM-5.2 起与中国多家安全团队合作，模型对真实代码库安全测试：专家复核、筛选、去重后，在 **269 个项目中共发现 2,436 个漏洞，含 1,097 个中高危漏洞**。
- 分布：系统内核、操作系统、浏览器引擎、开源基础设施、Web 应用、网络协议等。部分漏洞潜藏数年甚至数十年，**最长达约 40 年**。
- 演化成持续漏洞披露计划：**Z.ai 安全漏洞披露台账**（Security Disclosure Ledger），公开记录披露流程进展，区分已公开/仍在协调披露，记录受影响项目、严重等级、CVE 编号、潜藏时长。

## §6 局限与未披露项

1. **无独立 arXiv 技术报告**：无论文编号；技术细节散落于博客与文档正文，缺方法模块架构及超参披露。
2. **Z.ai Code Bench 为内部非公开基准**：外部不可复现，无法独立审计量化细节。
3. **任务环境合成仍有人工参与**：官方自述「仍需较多人工参与」，环境生成/验证自主化未达标。
4. **权重未即时开放**：承诺两周后开放，发布时未提供权重、未见硬件部署/config 细节。
5. **基座/前训练细节未披露**：仅知「同 GLM-5.2 基座」，前训练数据/规模/结构未公开。
6. **安全护栏与 sota 评估**：官方用 Claude Code 2.1.207 作为 harness 评估，非自研 agent 框架；revision 拆分、覆盖得分（union）等口径需谨慎解读。
7. **收益口径差异**：文章用「较前代提升 50%」与「更省 Token」双口径，未统一可比基线（提升 % 基于分数差值，非价效比）。
8. **产品形态约束**：GLM Coding Plan 订阅用户暂仅能通过 OpenAI Chat Completion 协议调用（Anthropic/Response 协议即将迭代）；未披露服务端上下文缓存定价细节（仅知按 input/cached input/output 分开计点）。
