## §4 方法细节

- **数据收集管线（迭代式）**：
  - 种子 = OpenWebMath（13.6B token）。
  - 用 fastText 分类器（首次用 OpenWebMath 做正例 + 多样负例）召回更多网页；500,000 正例 + 1,500,000 负例；dim 256、lr 0.1、n-gram 3、min occ 3、3 epochs。
  - 对 CommonCrawl 做 URL 去重 + 近似去重 → 40B HTML 页。
  - 按 fastText 分数排序保留 top；容量经 40B/80B/120B/160B 预训练实验评估。
  - 迭代法：划分 domain（同 baseURL），>10% 收录判定为 math-related，人工标注 URL path 补充正例 → 重训分类器。
  - 第 4 次迭代 98% 数据已在第 3 次收到，停止。
- **去污染**：过滤含基准题/答的网页（英文 GSM8K/MATH；中文 CMATH/AGIEval）。10-gram 精确匹配过滤；<10 gram 但 ≥3 gram 用精确匹配。
- **1.3B 语料对比实验**：DeepSeek-LLM 1.3B 分别训练在 MathPile(8.9B)、OpenWebMath(13.6B)、Proof-Pile-2(51.9B)、DeepSeekMathCorpus(120.2B) 上 150B tokens。DeepSeekMathCorpus 在 8 个基准全面领先；1.3B 上 GSM8K 23.8%、MATH 4.8%（CMATH 41.5%）。
- **DeepSeekMath-Base 7B**：从 DeepSeek-Coder-Base-v1.5 初始化，训练 500B tokens；数据分布 56% MathCorpus + 4% AlgebraicStack + 10% arXiv + 20% GitHub code + 10% 自然语言（中英）。
- **SFT（DeepSeekMath-Instruct）**：776K 例（CoT/PoT/tool-integrated），英文（GSM8K/MATH 注释、MathInstruct 子集、Lila-OOD 训练集）+ 中文（K-12 76 子专题）。max seq 4K；500 steps；batch 256；lr 5e-5 恒定。
- **GRPO**：
  - PPO 需 4 个模型（policy/old policy/value/reward）→ 大内存。
  - GRPO 省略 critic（value）/advantage 模型，改用 group（每个 question 采样一组输出）的平均奖励为 baseline，用 group 相对优势估计优势，极大降低训练资源。
  - 交互式/迭代 RL、在线 vs 线下、outcome vs process 监督等多样性实验被纳入统一范式框架分析；RFT、DPO、PPO、GRPO 被统一为"直接或简化 RL 技术"。

## §5 实验结果要点

- **Base 7B**：CoT 下 8 个中英基准全开源基座第一；MATH 36.2% 超 Minerva540B（58.8B 级，33.6%）及 Llemma34B（25.3%）；工具（Python）下 GSM8K 66.9%/MATH 31.4%。formal 证明（miniF2F，Isabelle）valid 25.8%、test 24.6%，超 Llemma34B（21.0%/21.3%）。
- **通用能力增益**：数学预训练提升 MMLU(54.9%)、BBH(59.5%)，且保留编码（HumanEval 40.9%、MBPP 52.6%）；对比前驱 DeepSeek-Coder-v1.5。
- **Instruct 7B**：无工具时 MATH 46.8%、GSM8K 82.9%（超所有开源及多数闭源，包括 Qwen72B、WizardMath，仅输 GPT-4/Gemini-Ultra）；工具时 MATH 57.4%，逼近 60%。
- **RL (GRPO) 效果**：仅用 GSM8K+MATH 的 CoT 指令数据，DeepSeekMath-RL 在所有基准提升：GSM8K 82.9→88.2，MATH 46.8→51.7，CMATH 84.6→88.8，MGSM-zh 73.2→79.6。开源社区首次在竞赛级 MATH 超 50%。
- **GRPO 优于 PPO**：实验比较显示 GRPO 以更低资源取得强结果，PPO 需 critic 模型而 GRPO 免去；out-of-domain（CMATH/中文）也有正增益。

## §6 局限

1. **仅 7B 规模**：论文聚焦 7B；未见更大数学基座（如 ≥70B）验证 GRPO 与数据管线，scale 效应未知。
2. **依赖 decontamination 设定**：去污染依赖 10-gram/3-gram 精确匹配，可能遗漏变体/改写导致的泄漏，且去污染标准对中文基准（AGIEval）覆盖有限。
3. **训练数据分布不透明**：语料来源 CommonCrawl + 人工标注，未披露具体 web 源/许可证与原始规模（40B HTML）去留细节；arXiv 论文贡献作者承认"arXiv 训练无实质提升"，暗示部分常见数据源欠佳。
4. **GRPO 理论分析较浅**：统一范式（RFT/DPO/PPO/GRPO）以概念框架呈现，缺少严格的收敛/偏差证明；baseline 用组平均的相对优势在 token 级是否稳健仍需深入验证。
5. **工具/形式化依赖额外步骤**：工具辅助（Python/sympy）与 formal proving 依赖外部证明器（Sledgehammer），未端到端集成；正式数学证明仍是 few-shot 生成 sketch + 自动证明器补全，非完全自洽。
6. **模型版本说明**：文中部分基准用 Top1（无投票），部分对比（深灰）用 32 候选多数投票（表5 灰色格），评估协议不完全统一，跨表比较需谨慎。

## §8 训练配置速览

- **Base 7B 预训练**：从 DeepSeek-Coder-Base-v1.5 初始化；500B token；数据分布 56% MathCorpus / 4% AlgebraicStack / 10% arXiv / 20% GitHub code / 10% 中英自然语言；lr 4.2e-4；batch 10M token。

- **RL（GRPO）**：仅用 GSM8K + MATH 英文 CoT 指令数据子集；在线/线下，outcome vs process 监督，单轮 vs 迭代 RL 均在统一范式下实验。
- **corpus 对比实验**：DeepSeek-LLM 1.3B，训练 150B token；lr 5.3e-4；batch 4M token；4K 上下文。
