## §4 方法要点

### 4.1 编码自演化范式（三案例共性）
不执行固定计划，而以反馈循环自我改进：
1. **Harness 自举**（oh-my-cli）：需求归一化为 GitHub Issues → 状态机认领流转（ready→leased→active）→ 实现 → E2E/CI 门控合并；watchdog/monitor/dispatcher 组成恢复机制；社区经验与用户反馈转化为可执行的 capability 迭代（/goal、/resume、Dynamic Workflow、Session Replay、Desktop 等）。全程公开于 github.com/qwen-code-dev-bot/oh-my-cli。
2. **科研复现→超越**：先零起点重建论文 pipeline（数据处理/训练/评测全部自写），验证六项主结论后进入"假设→编码→GPU 实验→分析→再试"循环；四轮 18 个想法中"按难度分层选择""熵-分数差加权""选择宽度调参"均有效，最优者为统计候选解中的硬决策点（nhighgate）计数。
3. **竞赛冲刺**：多模型微调集成 + 跨模态融合 + 以提交反馈驱动逐轮再加权，体现资源约束下（24h、固定提交数）的搜索策略。

### 4.2 Real-World RL 扩展方法论
- 环境、奖励、数据三线并进：环境沿 Task（单任务→多任务→多日）/ Workspace（多文件→层级目录→异构复杂目录）/ Harness（类别、版本、skills）三轴解耦扩展，使增长组合式放大而非逐一定制；
- Universal Reward System 把异构验证统一进单一系统：执行校验 + rubric 条件裁判（文本与渲染视觉输出）+ agentic inspection，rubric 自动规模化，消除 task-specific verifier 的不一致；
- 在线数据均衡器控制每批的任务/难度/workspace/harness 分布，抑制批间梯度方差，支撑 RL 算力持续稳定扩展。
- Dynamic Workflows：把编排逻辑固化为可复现程序，驱动大规模子代理编排（量化案例中 330 子代理、6000 回测、中途自适应换框架/剪枝/多种子联合验证）。

### 4.3 长程任务机制
- 芯片设计：edit-simulate-synthesize-layout 闭环；无 golden reference 下靠 cocotb 功能测试严格验证每轮迭代、OpenROAD 保证物理可行性；展示数百 turn 后仍能做算法级重构（非早期低垂收益后平台期）。
- 电商运营：全年周期内前瞻性资本配置（早期重投建立地位→年末变现库存兑现现金）；对同一供应商同商品多轮试探性议价实现渐进降价，并把议价经验泛化到同类商品；识别 152 家欺诈商户的风控表现。

### 4.4 多模态 Agent 架构
视觉贯穿 plan→execute→verify→iterate 全环：生成时观察、行动时复查；Hybrid Agent 将"写码实现逻辑"与"GUI 操作真实界面"双通道互补，GUI 反馈真实运行态结果延伸视觉反馈环；RecreationBench 仅凭黑盒交互（无源码、无网络）复刻应用；Qwen-MM-Plugins 作为 harness 扩展库使任意既有 agent 框架多模态原生化。
