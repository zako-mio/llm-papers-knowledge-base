# 00-源数据提取：Seed-OSS-36B（ByteDance Seed Team，2025-08）

> 节点定位：中量级开源稠密模型在"长上下文原生训练 + 可控思考预算 + 合成指令数据进预训练"三个方向上的代表性节点；Apache-2.0 全开放（含预训练权重双版本）是其区别于同期主流开源模型的显著特征。
> 说明：本节点无 arXiv 技术报告 PDF（README 明示 "Tech Report Coming Soon"），一手资料为 GitHub 官方仓库 README + ByteDance Seed 官方博客。注：raw.githubusercontent.com 直连不可达，实际经代理抓取；默认分支为 master（非 main）。

## §4 方法要点

1. **合成指令数据进预训练（Research-Friendly 设计）**：将合成 instruction 数据混入预训练语料，实测多数基准提升（如 MATH 从 woSyn 的 61.3 提升至 81.7）；但官方承认该做法会影响后训练研究者的实验纯净度，故同时发布不含合成数据的 `Seed-OSS-36B-Base-woSyn`——把"数据配方选择权"交还研究社区，这在同规模开源模型中少见。（出处：README Evaluation Results 节）
2. **Thinking Budget 机制（可控推理长度）**：通过 chat template 的 `thinking_budget` 参数注入控制信号；模型在 CoT 中周期性自检消耗量并输出 `<seed:cot_budget_reflect>` 反思标签；预算耗尽强制收敛到最终回答。默认 -1 为无限思考。工程建议按 512 整数倍设定（训练分布对齐）。该机制直接回应了推理模型"思考不可控、推理成本不可预算"的落地痛点。（出处：README Thinking Budget 节）
3. **原生长上下文训练**：以最高 512K 上下文直接训练（RoPE base frequency 设为 1e7 支撑超长位置编码），而非"短训+外推"。128K RULER 达 94.6 说明长程能力在中距离区间已稳定。（出处：README Model Summary / Evaluation 表）
4. **架构选型保守稳健**：标准 dense causal LM 组合（RoPE+GQA+RMSNorm+SwiGLU），80 query heads 对 8 KV heads 的 GQA 配比压缩 KV cache 以服务 512K 上下文的显存可行性；无 MoE，走"中等规模稠密 + 数据效率"路线。（出处：README Model Summary）
5. **Agentic 能力专项优化**：工具调用与 issue 解决列为四大能力之一；vLLM 侧提供专用 `seed_oss` tool-call parser 与配套 chat template，TAU-bench Retail/Airline、SWE-Bench Verified 双框架（OpenHands / AgentLess）、Multi-SWE-Bench 均入评测矩阵。（出处：README Key Features / Inference / Evaluation 节）
6. **低成本数据策略叙事**：官方反复强调"only 12T tokens"——相对同期前沿模型 20T–40T 级数据量，主打单位 token 效率与低训练成本下的性价比。（出处：README Introduction；博客核心句）

## §6 局限与未披露项

**官方明示或可从材料推出的局限：**
1. Tech report 缺位：截至发布材料，仅有 README + 博客，无系统技术报告（徽章明示 Coming Soon），训练细节不可核查。
2. 合成指令数据进预训练的双刃性：官方自己指出可能影响后训练研究（否则无需发 woSyn 版）；两个 Base 版成绩差异也证明其对部分基准有负迁移风险（如 GPQA-D 上 woSyn 35.2 > w/syn 31.7，SimpleQA 上 woSyn 7.4 > w/syn 5.8）。
3. i18n 取向明确，中文场景未做专门声明（对国内使用者需自行评估中文能力）。
4. thinking budget < 512 不被支持（官方建议设 0 直接作答）；预算控制依赖训练分布（512 整数倍），任意值的可靠性未保证。
5. 评测自报为主：对照模型成绩部分为复现、部分为转引，跨框架 agentic 评测（OpenHands vs AgentLess 差异巨大：SWE-Bench Verified 56 vs 47）敏感性高。

**未披露项：**
1. 训练算力规模（GPU 型号/数量/时长）、训练成本、能耗与碳排——完全未提及（对比 Llama 4 Model Card 有完整披露）。
2. 数据配比细节：12T token 中文本/代码/多语言/合成指令的具体比例、清洗去重流程、512K 长上下文数据的阶段安排（是否有 mid-training 式分段）均未披露。
3. 后训练配方：Instruct 版的 SFT/RL/DPO 流水线、RL 算法与奖励设计、安全对齐方法均无描述（仅 AIR-Bench 单一安全分数 75.6）。
4. Thinking Budget 的训练方法：如何在训练中构造预算条件、reflect 标签如何监督，未说明。
5. 512K 原生上下文的评测证据缺口：RULER 仅测到 128K；256K–512K 区间无任何基准数字（MTOB 类长文档任务未提供）。
6. vision/多模态：纯文本模型，无图像输入能力（同期 Llama 4 已原生多模态）。
