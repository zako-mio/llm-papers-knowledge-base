## §4 方法要点

1. **Gated DeltaNet 线性注意力**（源自论文 "Gated Delta Networks: Improving Mamba2 with Delta Rule", arXiv:2412.06464）：以门控衰减 + delta rule 更新固定尺寸循环状态替代逐 token 注意力矩阵，序列复杂度近线性；输出门控（output gating）消除 attention sink 与 massive activations，保障大规模训练稳定性。3:1 混合排布保留周期性全局混合层，规避纯线性注意力的记忆瓶颈。
2. **高稀疏 MoE**：512 选 10+1 的路由粒度将每 token 激活参数压到 17B，配合 MTP（multi-step 多步预测训练头）提升解码吞吐——是 19× 吞吐数字的架构基础。
3. **早期文本-视觉融合（early fusion）原生多模态**：不做 VL 适配器后挂，而是预训练即混入视觉 token，换取"跨代持平 + 超 Qwen3-VL 同级"的双目标。
4. **RL 环境规模化（Scalable RL at Agent Scale）**：在百万级 agent 环境上做难度与任务分布递进扩展的 RL，强调泛化性优先于刷榜；配套全异步 train-inference 分离框架（FP8 端到端、rollout router replay、投机解码、多轮 rollout locking、梯度陈旧性约束）。
5. **自适应思考模式**：auto/thinking/fast 三模式，auto 模式下模型自适应决定是否思考及调用 search/code interpreter。
6. **评测脚注披露的工程细节**：Search Agent 采用 context-folding（256k 阈值裁剪工具响应）或 discard-all 策略（BrowseComp 69.0 vs 78.6 差异来源），坦承 agentic 分数依赖 scaffolding。

## §5 评测结果要点

- **效率叙事为核心卖点**：256k 长上下文下 19.0× 于 Qwen3-Max 的解码吞吐 + 性能相当，构成"线性注意力工程化落地"的最强公开证据；同数字亦被 AMD MI355X/SGLang、PyTorch TokenSpeed 等第三方推理优化报告引用复现。
- **Agent 能力对标第一梯队**：TAU2-Bench 86.7 接近 Claude 4.5 Opus 91.6；MCP-Mark 46.1 显著超 K2.5-1T-A32B（29.5）但低于 GPT5.2（57.5）；BrowseComp 双策略最高 78.6 与 K2.5 持平、略超 Claude 4.5 Opus（67.8）。
- **编码非最强项**：SWE-bench Verified 76.4 落后 Claude 4.5 Opus（80.9）与 GPT5.2（80.0），与其"多模态通用 agent"定位一致。
- **视觉多模态多项反超**：MathVision 88.6、ZEROBench 12、BabyVision 52.3（CI on）、OCRBench 93.1 等 VLM 指标在同表领先，支撑 native multimodal 主张。
- **多语言广度第一梯队**：NOVA-63 59.1、MAXIFE 88.2、INCLUDE 85.6 均为表中最高或次高。
- **基座对照全面领先同代开源**：MMLU-Pro 76.01 较 DeepSeek-V3.2（62.82）高出约 13 分，SWE-agentless 43.26 vs 34.67。

## §6 局限与未披露项

1. **无独立技术报告**：发布时仅有博客 + 模型卡，官方称"更全面的 scaling 结果将在后续技术报告详述"，训练数据配比、RL 环境具体构造、奖励设计均未披露。
2. **吞吐数字的口径依赖**：8.6×/19.0× 以自家 Qwen3-Max 为参照且绑定 32k/256k 特定上下文档位，未给跨厂商同硬件对照；第三方 SemiAnalysis 指出此类比值对 TP 配置与 interactivity 假设敏感。
3. **首日仅一个尺寸**："more sizes are coming"——小尺寸衍生型号是否沿用 DeltaNet 混合架构当时未定（后续 Qwen3.6 系列才补齐）。
4. **评测自评 + 脚注口径差异**：BrowseComp 等分数强依赖 context-folding/discard-all 策略选择；MathVision 对自家模型用固定 boxed{} prompt、对他家取两次运行最高值等脚注做法存在有利于己的口径空间。
5. **未披露项清单**：总训练 token 数（仅提"数十万亿"量级的 FP8 稳定扩展）、GPU 型号与算力成本、视觉编码器规格（HF 卡仅列 LM 部分）、蒸馏/合成数据占比、安全评测（未附 system card 或安全评估章节，与 Anthropic 式发布形成对照）。
6. **GDN 状态管理的外部依赖**：混合架构要求推理框架做 KV Cache + Mamba State 双资源池管理与 PD 分离状态迁移，部署复杂度高于标准 Transformer（PyTorch TokenSpeed 博客可见一斑），官方博客未讨论该迁移成本。
7. **201 语言的质量分布未验证**：仅报广度覆盖数，低资源语言质量无逐语种评测证据（第三方评论亦有指出）。
