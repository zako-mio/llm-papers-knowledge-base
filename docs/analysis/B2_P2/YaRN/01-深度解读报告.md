## 摘要

本文解读 Nous Research 联合 EleutherAI、University of Geneva 提出的《YaRN: Efficient Context Window Extension of Large Language Models》（arXiv 2309.00071v3，初版 2023-09，共 20 页）。论文针对的核心矛盾是：以 RoPE 为位置编码的大语言模型无法泛化到超出预训练长度的序列——LLaMA 预训练上下文仅 2k token、Llama2 也只有 4k，而长文档与长对话的需求远超此限。既有修复路线各有代价：Position Interpolation（PI）对所有维度等比压缩角度，NTK-aware 插值则是缺乏统一理论框架的经验方案。YaRN 给出一条"分维度治理 + 注意力修正"的完整公式：NTK-by-parts 按波长比 r(d)=L/λ 将旋转维度划为"不插值/只插值/混合"三档，用 ramp 函数（α=1, β=32）平滑衔接；再将注意力 logits 除以温度常数 t，其中 1/√t = 0.1·ln(s)+1 经 LLaMA 7b/13b/33b/65b 与 Llama2 7b/13b/70b 全系无微调拟合验证，展现出跨模型尺度的普适性。实现上借助 length scaling 技巧将缩放折入旋转位置编码本身，零推理/训练开销且与 FlashAttention2 直接兼容。效果上：相比前法用 10× 更少 token、2.5× 更少训练步数，微调 <0.1% 原始预训练数据即达 SOTA 上下文扩展——将 Llama2 7B/13B 扩展到 128k 上下文仅需 s=16 微调 400 步再加 s=32 续训 200 步，且 64k 训练长度可外推至 128k 评测长度；结合 Dynamic Scaling 的"Dynamic-YaRN"更可无需微调扩展 >2× 上下文。本报告按"问题—概念—方法—证据—批判—启示"六层结构逐层拆解。

## 一、问题定位：RoPE 的外推失效与既有路线的代价

### 1.1 论文要解决的问题

大语言模型的上下文窗口在预训练时即被固定：LLaMA 为 2k token，Llama2 也仅为 4k（脚注 §，出处 §4.1 p7）。一旦推理序列超出该长度，模型性能会急剧劣化甚至完全崩溃。问题的根源出在位置编码上：RoPE（Rotary Position Embedding）是当前主流的相对位置编码，但其设计只保证了训练长度内的相对位置关系得到良好表达，**无法泛化到超过训练长度的序列**。这不是某个应用的边缘缺陷，而是所有基于 RoPE 的开源模型共同面对的结构性天花板——长文档问答、长程代码库理解、多轮长对话，全部卡在这一限制之前。

论文要回答的问题因此非常聚焦：能否用极小的微调代价（最好是无微调），把一个既有的 RoPE 模型可靠地扩展到数倍乃至数十倍的上下文长度，同时不破坏其在原始任务上的能力？

### 1.2 方法演化谱系中的定位

论文 Figure 1（p2）刻画了方法的演化关系，这条谱系是理解 YaRN 设计动机的地图：

- **直接外推**：不做任何修改直接喂长序列。RoPE 在未见过的旋转角度区域行为失稳，性能崩溃，此路不通。
- **Position Interpolation（PI，Chen et al. 2023）**：将位置角度整体除以扩展倍数 s，把 [0, sL] 的位置区间"压缩"回训练过的 [0, L] 区间内。这避免了外推，但代价是**所有频率维度一视同仁地被压缩**（推断）——高频维度原本承担的细粒度位置区分能力被稀释，需要微调来弥补。
- **NTK-aware 插值（bloc97 等社区工作）**：意识到不同维度的波长差异，对高低频维度采取区别对待，无需微调即可获得一定扩展能力。但它本质上是**经验性的启发式**，缺乏统一的数学框架来说明"为什么这样处理各个维度"。
- **YaRN**：本文方案。它吸收了 NTK-aware"区别对待"的直觉并将其形式化为 NTK-by-parts，再补上前人缺失的一块——注意力分布本身因位置拉伸而产生的熵变，用温度缩放修正。两个组件合成为一个有定义、有推导、有拟合验证的完整方法。

> **一句话小结**：YaRN 的切入点不是发明新的位置编码，而是承认 RoPE 已成事实标准的前提下，回答"如何用最小的改动和最小的训练代价榨出最大的上下文扩展"——答案是把插值做成"分维度的"、再把注意力做成"被修正过的"。

## 二、概念内核：六个核心概念逐一定义

### 2.1 RoPE 与波长

**定义**：Rotary Position Embedding，主流相对位置编码；每个注意力头维度 d 对应一个特征波长 λ，衡量该维度旋转一个完整周期的 token 距离。

**拆解**：理解 YaRN 的钥匙是**波长视角**：RoPE 的不同维度像一组不同频率的钟摆，有的维度转得快（波长短，负责区分相邻 token 的细粒度位置），有的维度转得慢（波长长，负责区分远距离的粗粒度位置）。论文用比例 r(d)=L/λ 把"维度"与"上下文长度 L"联系起来——它问的是：在长度为 L 的序列里，这个维度大约转了多少圈？这个比值决定了该维度在上下文扩展时应被如何对待。

### 2.2 Position Interpolation（PI）

**定义**：将 RoPE 的位置角度整体除以扩展倍数 s，使新位置区间落入已训练的角度范围内。

**拆解**：PI 的功绩是证明了"插值优于外推"这一方向，但它是一刀切的：所有维度的角度都被同一比例压缩。从波长视角看，（推断）这意味着短波维度的相邻位置区分度被人为降低——两个相距 1 的 token 在高频维上的角度差缩小为原来的 1/s，模型对局部顺序的感知随之模糊，这就是 PI 需要微调恢复的原因。

### 2.3 NTK-aware 插值

**定义**：源自 bloc97 等社区实践的一类改进插值方案，对不同波长维度施加不同程度的处理，无需微调即可获得一定扩展能力。

**拆解**：它的直觉正确——高频维度少插值或不插值、低频维度多插值——但表述形态多样且缺乏统一框架：为什么是这个程度而不是那个程度？各维度之间的过渡应该是怎样的函数？这些都没有答案。（推断）正是这种"有效但说不清"的状态，构成了 YaRN 将其理论化的空间。

### 2.4 NTK-by-parts（Definition 1）

**定义**：按波长比例 r(d)=L/λ 与 ramp 函数 γ(r) 构造的分维度插值：h(θ_d)=γ·θ/s + (1−γ)·θ。ramp 函数满足 r<α 时 γ=0、r>β 时 γ=1、α 与 β 之间线性过渡。LLaMA 族实验取 α=1、β=32（§3.2 p5）。

**拆解**：这是全文第一个正式贡献，把"区别对待"翻译成精确的三档策略：

| 维度类型 | 判据 | 处理方式 | 理由 |
|---|---|---|---|
| 高频（短波） | λ 远小于 L，r 很大 | 不插值（γ→1 时保留原角度） | 波长远小于上下文的维度，其角度范围早已被充分训练，插值只会白白损失分辨率 |
| 低频（长波） | λ 大于等于 L | 只插值（γ→0 时角度除以 s） | 这些维度的角度从未在训练中转满一圈，属于"没见过的区域"，必须压回已知范围避免外推 |
| 中间维度 | α ≤ r ≤ β | 部分插值（线性 ramp 过渡） | 兼具两种性质，平滑衔接避免突变 |

注意 ramp 方向：r(d)=L/λ 越大意味着波长越短（转得越快），γ 越接近 1 则越少插值——与上表一致。α=1/β=32 这组数值是 LLaMA 族上的实验值，而非理论推导值。

### 2.5 注意力温度 t 与 pre-softmax 缩放（Eq.14/15）

**定义**：YaRN（Definition 2）= NTK-by-parts + 注意力缩放。将注意力 logits 除以温度常数 t：softmax(qᵀk / (√|D| · t))（Eq.14）；缩放系数取 1/√t = 0.1·ln(s)+1，s 为扩展倍数（Eq.15，§3.3 p6）。

**拆解**：这是前人完全没有处理、而 YaRN 补上的最后一块拼图。逻辑链条是：位置插值改变了 q 与 k 点积的统计分布——（推断）当大量位置被压缩进有限角度范围后，注意力 logits 的分布整体偏移，softmax 的熵随之变化，注意力模式变得过锐或过钝。引入温度 t 相当于对注意力分布做一次"重新校焦"。关键发现在于拟合结果的简洁与普适：对 LLaMA 7b/13b/33b/65b 以及 Llama2 7b/13b/70b 无微调拟合，最低 perplexity 都落在同一条曲线上——1/√t = 0.1·ln(s)+1。例如 s=8 时 1/√t = 0.1·ln(8)+1 ≈ 1.208（A.3 Eq.23, p14）。论文据此称温度常数 t 具有"普适性"，可跨模型规模与训练数据泛化（§3.3 p6）。

### 2.6 Dynamic Scaling（"Dynamic NTK"）

**定义**：推理期按当前序列实际长度 l 动态更新缩放因子 s=max(1, l/L')（L' 为目标训练长度），而非全程固定 s（§3.4, p6）。

**拆解**：固定 s 有两个尴尬：序列还没到 L' 时就已经承受了插值的分辨率损失（白亏）；到达临界点时又面临一次骤变（跳水）。动态缩放让 s 随长度增长平滑爬升，序列短于 L' 时 s=1 即完全原样运行，超过后再逐步启用插值。结合此前无微调即可扩展的主张，论文给出"Dynamic-YaRN"：**无需任何微调即可扩展 >2× 上下文**（§2 p2）。工程上有一个人命关天的细节：与 kv-caching 结合时，必须在施加 RoPE **之前**缓存 kv-embeddings——因为 s 一旦变化，每个 token 的 RoPE 都会改变，若先旋转再缓存，旧缓存就全部作废了。

> **一句话小结**：六个概念构成递进链条——RoPE/波长提供观察框架，PI 与 NTK-aware 提供正反教材，NTK-by-parts 把"区别对待"公理化，温度缩放补上注意力分布的修正，Dynamic Scaling 把静态方法改造成随长度自适应的在线策略。

## 三、方法拆解：一条"分档插值 + 温度校正 + 零开销实现"的技术闭环

### 3.1 分维度治理的数学构造

NTK-by-parts 的全部构造只用三个零件：

1. **比值函数** r(d)=L/λ：给每个维度算出"在上下文 L 里转几圈"；
2. **ramp 函数** γ(r)：r<α 时输出 0（全插值），r>β 时输出 1（不插值），中间线性；
3. **混合公式** h(θ_d)=γ·θ/s + (1−γ)·θ：γ 作为开关在"压缩后的角度"与"原始角度"之间做凸组合。

整个设计的自由参数只有 α 和 β 两个，LLaMA 族取 α=1、β=32。相比 PI 的零参数与 NTK-aware 的隐式规则，这是一个**参数极少、语义明确、每一段行为都可单独解释**的中间态设计——（推断）这正是它后来能被广泛复现与改造的内在原因。

### 3.2 YaRN 的完整定义与 length scaling 实现技巧

YaRN（Definition 2）= NTK-by-parts 插值 + pre-softmax 温度缩放。真正体现工程智慧的是实现方式：论文没有去改注意力内核里的 softmax，而是利用 RoPE 的复数表示，把 q 与 k **同时乘以 1/√t**——这在数学上等价于对旋转位置编码整体缩放（"length scaling"技巧），注意力代码一行都不用动。

由此带来三个实打实的性质：

- **零额外推理/训练开销**：位置编码预生成后复用，前向计算路径不变；
- **与 FlashAttention2 直接兼容**：不碰注意力内核是兼容的前提；
- **实现侵入性最小**：改动被完全封装在位置编码层。

（推断）这种"把修正折叠进位置编码"的做法是论文工程品味的集中体现，也是它区别于同类学术方案的落地优势——后者往往需要动 kernel 或维护自定义算子。

### 3.3 训练配方：数百步微调的极限压缩

源数据记录的训练配置（§4.1 p7）值得逐项列出，因为它定义了"上下文扩展要花多少钱"的新基准：

- **对象**：Llama2 7B / 13B，从原始 4k 上下文扩展至 **128k**（s=16 阶段）再到 s=32；
- **第一阶段**：s=16，微调 **400 步**，global batch 64，数据取 PG19 切成 64k 段，lr 2e-5，AdamW（β=0.9/0.95），FSDP + FlashAttention2；
- **第二阶段**：s=32，从 s=16 检查点**续训 200 步**（受计算资源限制）；
- **消融实验**：用 LLaMA 7B（预训练上下文 2k），数据切 32k 段。

换算成直观感受：（推断）400 步 × batch 64 × 64k token 量级的训练，相对于动辄万亿 token 的预训练，正是摘要所称"微调 <0.1% 原始预训练数据"的具体含义——上下文扩展从"重新预训练级别"的开销，被压缩成了"轻量适配级别"的任务。

### 3.4 工程要点：Dynamic-YaRN 与 kv-cache 的正确组合

Dynamic Scaling 与 kv-caching 组合时有一条铁律：**必须在施加 RoPE 之前缓存 kv-embeddings**。原因在 2.6 已述：s 是全局变量，s 变则全体 token 的旋转矩阵都变。正确的流程是缓存"未旋转"的 k/v，每次前向时用当前 s 临时旋转。这一约束是使用 Dynamic-YaRN 时最容易踩的实现陷阱（源数据局限第 6 条明确点名"实现易错"）。

> **一句话小结**：方法体系是"三层叠加"——NTK-by-parts 决定"哪些维度压多少"，温度缩放决定"注意力怎么重新校焦"，length scaling 决定"这一切如何在不动注意力代码的前提下落地"；训练侧再用 400+200 步的极端轻量微调证明该体系不是纸上谈兵。

## 四、证据链：Table 1 逐行解读与四路验证

### 4.1 主证据：Table 1 长序列困惑度（Llama2，Proof-pile 测试集，滑窗 S=256，10 条 ≥128k 样本）

评测设置：GovReport / Proof-pile 测试集，滑动窗口 perplexity，S=256；Table 1 基于 10 条长度 ≥128k 的 Proof-pile 样本（§4.2 p8）。逐格转录如下：

| 配置 | 8k | 16k | 32k | 64k | 128k |
|---|---|---|---|---|---|
| 7B, s=16 (400步) | 3.51 | 2.99 | 2.65 | 2.42 | **>10** |
| 7B, s=32 (400+200步) | 3.56 | 3.04 | 2.70 | 2.45 | **2.37** |
| 13B, s=16 (400步) | 3.25 | 2.79 | 2.50 | 2.29 | **>10** |
| 13B, s=32 (400+200步) | 3.29 | 2.83 | 2.53 | 2.31 | **2.24** |

**逐层解读**：

1. **核心结论藏在最后一列**：s=16 只训 400 步时，128k 处困惑度 **大于 10**（实质崩溃）；而从 s=16 检查点续训 200 步达到 s=32 后，128k 困惑度骤降到 7B=2.37、13B=2.24。论文对此的定性是**转移学习式的外推**——训练只见过 64k 长度的数据段，却在两倍距离的 128k 上正常工作（extrapolation beyond 64k training context）。
2. **短程的微小代价清晰可见**：从 s=16 到 s=32，短距离困惑度小幅上升（7B 8k 处 3.51→3.56、13B 3.25→3.29）。这是对表格数字的直接读取：更大的扩展倍数以短程性能的轻微折损换取远程能力的质变，trade-off 量级约在 0.04–0.05 ppl。
3. **规模一致性**：7B 与 13B 曲线形态几乎平行，说明方法对模型规模不敏感——这与温度公式跨 7 个模型尺度拟合成功的内部证据互相印证。

### 4.2 效率证据：与前一方法的成本对比

摘要级主张：YaRN 相比前法用 **10× 更少 token、2.5× 更少训练步数** 达到相当性能（Abstract p1）；附录 B.2 给出直接对照——YaRN 比 PI 收敛更快、loss 更低（Figure 2）。加上"<0.1% 预训练数据"的数据效率主张，三条证据共同支撑"高效"这一定语。

### 4.3 检索能力证据：Passkey retrieval

设置：五位数 passkey 埋入长文本，passkey 位置在 prompt 内均匀随机放置，prompt 长度覆盖 2k–32k，50 次迭代取平均，模型为 LLaMA 7B 扩展至 32k（§4.3 p8）。结果：同等训练预算下 YaRN 得分高于对照方法（Figure 3 右）。（推断）该实验的价值在于补足 perplexity 的盲区——滑窗困惑度衡量的是"局部语言建模质量"，而 passkey 衡量的是"穿过数千 token 精确取出一个针"的检索保真度，二者结合才构成对长上下文能力的较完整刻画。

### 4.4 安全网证据：标准化基准的退化检查

OpenLLM Leaderboard 四项：25-shot ARC-Challenge、10-shot HellaSwag、5-shot MMLU、0-shot TruthfulQA（§4.4 p8）。目的不是刷榜，而是回答一个必要问题：**扩展上下文有没有伤害原有短上下文能力**。（推断）这类"回归测试"在上下文扩展文献中常被忽略，却是部署决策的关键输入——一个 128k 但 MMLU 掉点的模型在很多场景是不可接受的。

### 4.5 机理性证据：附录 A.3 的温度消融

在 896 个 16k token 的 RedPajama 文档上验证 pre-softmax 缩放的影响：s=8 时推荐值 1/√t = 0.1·ln(8)+1 ≈ 1.208 确实对应最低困惑度；Figure 5 展示 t=1（不加缩放）时各位置困惑度的变化百分比，为"注意力熵漂移确实存在且可被温度修正"提供了位置级别的细粒度证据。

> **一句话小结**：证据体系呈"一路主证 + 三路侧翼"结构——Table 1 用 128k 外推给出决定性主证，效率对比、passkey 检索、标准基准回归与温度消融分别封住"成本""检索""退化""机理"四个可能的质疑口。

## 五、批判性分析：局限的深层含义与独立疑点

### 5.1 作者自述七项局限的深层含义

1. **α/β 需 case-by-case 调参**（LLaMA 取 1/32，其他模型需重调）：这条与温度的"普适性"形成耐人寻味的对照——**t 普适而 α/β 不普适**。方法实际上有两个超参面：一个是可跨模型复用的对数公式，一个是必须逐模型手调的 ramp 边界。"普适"主张只覆盖了一半的超参面。
2. **微调仍是必要成本，无微调路径上限仅 >2×**：Dynamic-YaRN 的"免费午餐"只在小倍数区间成立；要 128k 级别的扩展，200–400 步（数十亿 token）的训练账单躲不掉。两条路径的适用域必须分开表述。
3. **s=32 因算力受限仅续训 200 步，推测存在未达的性能上限**：这是一条罕见的"自曝式"局限——论文的最优数字（128k=2.24）很可能不是方法的上限而是预算的上限。
4. **滑窗 S=256 的评测盲区**：滑动窗口把长文本切成局部片段计困惑度，间隔小于 256 token 的长程依赖被结构性掩盖。（推断）Table 1 的漂亮数字主要证明"局部语言建模在长位置索引下不崩"，而非"模型能利用 100k 距离外的信息"。
5. **t 的普适性仅在 LLaMA/Llama2 族实测**：七个模型全是同族近亲，跨架构（如 PaLM/GPT-NeoX 类）泛化未被充分验证。0.1·ln(s)+1 的对数形式目前是经验规律而非定理。
6. **与 kv-caching 组合需特殊处理，实现易错**：必须在 RoPE 前缓存的约束把复杂度转嫁给了每一个集成方，工程错误面客观存在。
7. **限定英语数据与 rotary 类编码**：非 RoPE 架构（ALiBi/T5 bias 等）的适配完全未覆盖，方法的势力范围被划定为"RoPE 世界的英语模型"。

### 5.2 独立观察到的四个疑点

**① 主表的统计基数很小**：Table 1 的 128k 结论建立在 **10 条** ≥128k 的 Proof-pile 样本之上（源数据明确记载）。单条长文档的困惑度方差可观，10 条样本给出的均值置信区间较宽——结论方向可信，具体数值（如 2.24 vs 2.37 的排序）不宜过度解读。

**② "10× 更少 token、2.5× 更少步数"的比较基线未在源数据中指明**："前法"指 PI 还是 NTK-aware 微调路线，提取文件未记录。效率主张的归因对象因此存在模糊——（推断）考虑到附录 B.2 的对照实验对象是 PI，大概率指 PI，但这属于推断而非源数据明示。

**③ 温度公式的因果解释缺位**：论文展示了 0.1·ln(s)+1 拟合得很好，但对"为什么恰是对数形式"没有给出机理性推导。（推断）合理的猜想方向是注意力熵随位置密度变化的增长形态，但在论文框架内它是拟合公式，其在新架构上的可靠性只能靠实测兜底——这与局限⑤构成同一个硬币的两面。

**④ Dynamic NTK 与增量解码的内在张力**：动态缩放意味着每当前缀越过阈值，全体历史 token 的有效位置编码都在变。虽然"RoPE 前缓存"解决了正确性，但（推断）每次 s 更新都潜在要求对注意力统计做全局重新校准，流式场景下的稳定性与延迟特性论文未讨论——这是从局限⑥延伸出的工程深水区。

> **一句话小结**：这篇论文最硬的数字（128k 外推、10× 效率）都真实且可复核，但其证据的"精度半径"有限——小样本主表、未言明的对比基线、经验性温度公式与同族验证范围，共同提醒读者：YaRN 是一场漂亮的工程胜利，其理论部分仍是"有效的经验定律"而非"封闭的第一性原理"。

## 六、启示与影响：可迁移的经验与历史坐标

### 6.1 五条可迁移启示

1. **"分维度治理"是处理异质系统的通用模式**：NTK-by-parts 的精髓是不对系统做一刀切，而是找到分类轴（这里是波长比 r=L/λ），对每类成员施加恰当强度的干预，并用 ramp 函数消除类别间的悬崖。（推断）同一模板可直接映射到学习率分层、混合精度分组、量化敏感度分级等一切"不同组件耐受度不同"的场景。
2. **修正项应尽量做成正交叠加而非侵入重构**：温度缩放不改动插值本体、实现上又折叠进位置编码而不碰注意力内核，两个组件各自独立成立、组合增益。这种模块化让后续工作可以只取其一，也是方法得以快速扩散的结构性原因。
3. **上下文扩展的成本基准被永久改写**："<0.1% 预训练数据 + 数百步微调 + 64k 训练外推 128k"重新定义了这个问题应有的开销水位。此后任何上下文扩展方案都必须先回答"比 YaRN 便宜还是贵"。
4. **回归测试应成为位置编码改造的标配**：OpenLLM Leaderboard 四项退化检查 + passkey 检索 + 滑窗困惑度的三件套组合，为后续所有"动位置编码"的工作提供了评测模板——尤其是"改长处必查短处"的纪律。
5. **小团队+开放社区的问题选择能力**：Nous Research 与 EleutherAI 的合作、20 页篇幅、GitHub 开放实现，展示了一条"社区洞察（bloc97）→ 学术形式化（NTK-by-parts）→ 工程收束（length scaling）"的高效管线；（推断）这也是开源社区反向输出学术议程的早期标志性案例之一。

### 6.2 走向判断（推断）

- **与原生长训练的竞争长期共存**：YaRN 类后验扩展胜在便宜灵活，原生长上下文预训练胜在无折损，二者分别占据"存量模型激活"与"新一代基座"的生态位；
- **超参面的自动化**：α/β 的 case-by-case 调参是最明显的自动化靶点，按波长谱自动搜索 ramp 边界是自然的下一步；
- **向非 RoPE 架构与非英语数据的移植**：论文自己划出的空白区（局限⑦），以及温度公式跨架构有效性（局限⑤），都是留给后续工作的显式接口；
- **与 KV 压缩/稀疏注意力的组合**：上下文变长后 KV cache 成为新瓶颈，YaRN 解决"进得去"、KV 压缩解决"存得起"，两者的组合是长上下文栈的完整拼图。

## 总结

《YaRN》是一次教科书级的问题收束：它面对的不是"发明新位置编码"的宏大命题，而是"如何让已成事实标准的 RoPE 以最小代价突破长度天花板"的精确工程问题。其方法体系三层叠加——NTK-by-parts 用 r(d)=L/λ 与 ramp（α=1, β=32）把"区别对待不同频率"公理化，pre-softmax 温度缩放用 1/√t = 0.1·ln(s)+1 这条跨七个模型尺度成立的拟合曲线完成注意力再校焦，length scaling 技巧则把全部改动折叠进位置编码层达成零开销与 FlashAttention2 兼容。证据端，Llama2 7B/13B 以 400+200 步微调抵达 128k 上下文（13B 困惑度 2.24），64k 训练外推 128k 评测，配合 10× token / 2.5× 步数的效率优势与 <0.1% 数据占比，构成完整的"高效"论证；passkey、标准基准回归与 A.3 温度消融补齐检索、退化、机理三翼。批判端须记住四个限定：主表仅 10 条样本、效率基线归属未明示、温度公式是经验定律且只在 LLaMA 族验证、α/β 仍需逐模型手调。总体而言，YaRN 把上下文扩展从"重训级"工程降维成"适配级"任务，其"分维度治理 + 正交修正 + 零开销落地"的三段式设计哲学，是本文超越单一技巧、可供广泛迁移的真正遗产。
