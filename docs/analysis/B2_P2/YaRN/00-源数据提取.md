## §4 方法细节

- **背景**：RoPE 是主流相对位置编码，但无法泛化超训练长度。Position Interpolation (PI, Chen et al. 2023) 与 NTK-aware/bloc97 等提供改进但仍有不足。
- **NTK-by-parts（Definition 1）**：按波长 λ 与上下文 L 的关系划分维度——λ 远小于 L 不插值；λ 大于等于 L 只插值避免外推；中间维度二者兼有。用比例 r(d)=L/λ 和 ramp 函数 γ(r)（r<α→0, r>β→1, 其余线性）构造 h(θ_d)=γ·θ/s+(1−γ)·θ。α=1, β=32（LLaMA 族）。
- **YaRN（Definition 2）**：NTK-by-parts + 注意力缩放。将 logits 除 t：softmax(qᵀk / (√|D| · t))（Eq.14）。实现上用"length scaling"技巧：把 q 与 k 同乘 1/√t，等价缩放复数旋转位置编码，不改注意力代码。零推理/训练开销（位置编码预生成复用）。与 FlashAttention2 直接兼容。
- **1/√t 拟合**：对 LLaMA 7b/13b/33b/65b 无微调，在最低 perplexity 处拟合 1/√t = 0.1ln(s)+1。
- **Dynamic Scaling（"Dynamic NTK"）**：推理期按当前序列长 l 动态更新 scale factor s=max(1, l/L')；相比固定 s，避免在短于 L' 时性能折损及到达 L' 时骤降。与 kv-caching 结合时，须在施加 RoPE 前缓存 kv-embeddings（因 s 变化时每个 token 的 RoPE 都变）。

## §5 实验结果要点

- **§4.1 训练**：将 Llama2 7B/13B 扩展到 128k 上下文；s=16 微调 400 步（global batch 64，PG19 分 64k 段，lr 2e-5，AdamW β=0.9/0.95，FSDP + FlashAttention2）；s=32 从 s=16 检查点续训 200 步（计算受限）。消融用 LLaMA 7B（32k 数据段）。注意 LLaMA 预训练上下文 2k、Llama2 4k。
- **§4.2 长序列 LM**：GovReport / Proof-pile 测试集，滑窗 perplexity S=256。表1（Llama2，10 条 ≥128k Proof-pile 样本）：
  - 7B, s=16 (400步): 8k=3.51, 16k=2.99, 32k=2.65, 64k=2.42, 128k=>10
  - 7B, s=32 (400+200步): 8k=3.56, 16k=3.04, 32k=2.70, 64k=2.45, 128k=2.37
  - 13B, s=16 (400步): 8k=3.25, 16k=2.79, 32k=2.50, 64k=2.29, 128k=>10
  - 13B, s=32 (400+200步): 8k=3.29, 16k=2.83, 32k=2.53, 64k=2.31, 128k=2.24
  - 结论：s=32 仅用 64k 数据训练 200 步即可外推到 128k（转移学习，extrapolation beyond 64k training context）。
- **§4.3 Passkey retrieval**（五位数 passkey，LLaMA 7B 32k，50 次迭代，passkey 均匀随机放置，prompt 2k–32k）：YaRN 在同训练预算下得分更高（Figure 3 右）。
- **§4.4 标准化基准**（OpenLLM Leaderboard：25-shot ARC-Challenge / 10-shot HellaSwag / 5-shot MMLU / 0-shot TruthfulQA）：评估上下文扩展对短上下文性能的退化，与既有分数对比。
- **α/β 与训练效率**：YaRN 比 PI 训练效率更高（附录 B.2），收敛更快、loss 更低（Figure 2）。
- **附录 A.3**：pre-softmax scaling 1/√t 的影响。s=8 时推荐 1/√t=0.1ln(8)+1≈1.208；在 896 个 16k token RedPajama 文档上验证。t=1 时各位置 perplexity 变化百分比见 Figure 5。

## §6 局限

1. α/β 需 case-by-case 调参（LLaMA 取 1/32，其他模型需重调）。
2. 需微调时，200–400 步（数十亿 token）仍属训练开销；无微调仅靠 Dynamic Scaling 时扩展倍数有限（>2×）。
3. s=32 因算力限制仅续训 200 步，推测存在未达到的性能上限。
4. perplexity 滑窗 S=256 掩盖了超长依赖（<256 token 间隔）的细粒度评测。
5. 温度 t 的"普适性"仅基于 LLaMA/Llama2 族实测，跨架构（如 PaLM/GPT-NeoX）泛化未充分验证。
6. 与 kv-caching 结合需特殊处理（须在 RoPE 前缓存），实现易错。
7. 主要针对英语数据与 rotary 类编码；对非 RoPE 架构（如 ALiBi/T5 bias）的适配未覆盖。
