## §4 方法要点

### 4.1 数据引擎：Self-Instruct 的 5 项改造（低成本的关键）
1. **换更强教师**：text-davinci-003 取代 self-instruct 原用的 davinci；
2. **新写 prompt.txt**：显式给出指令生成要求（README 自述该 prompt 含一处小错，修复见 PR #24）；
3. **激进批量解码**：一次生成 20 条指令（self-instruct 逐条生成），显著降低单位数据成本；
4. **简化管线**：丢弃分类/非分类任务的区分逻辑；
5. **单实例化**：每条指令只生成 1 个输出实例（self-instruct 为 2–3 个）。
→ 结果：52K 样本成本 <$500，且初步分析显示比 self-instruct 官方发布数据更多样（root verb × direct object 分布图）。

### 4.2 训练配方：极简全参微调
- 标准 Hugging Face 训练栈 + **FSDP full_shard auto_wrap**（包裹 LlamaDecoderLayer）+ bf16/tf32 混合精度；
- cosine 调度 + warmup_ratio 0.03；全局 batch 128（多卡时调低 gradient_accumulation_steps 保持）；
- 同一脚本兼容 OPT 系列（换 wrap 类为 OPTDecoderLayer 即可）；
- 显存不够的三档降级：FSDP + CPU offload → DeepSpeed stage-3 双 offload → LoRA（28GB 级，可上消费级卡）。

### 4.3 发布工程：weight diff 规避许可风险
Meta 的 LLaMA 权重不可再分发 → Alpaca 只发布与 LLaMA-7B 的**差值**（`weight_diff.py recover`），用户须自行将 Meta 原始权重转 HF 格式后恢复完整权重。这一设计使"可复现"与"遵守 LLaMA 许可"并存，成为后续开源微调模型发布的通行范式。

### 4.4 推理模板
有 input 时用三段式模板（Instruction/Input/Response），无 input 时两段式；demo 推理统一用空 input 版模板。

## §5 效果证据

| 证据 | 内容 | 强度评估 |
|---|---|---|
| 盲配对人评 | self-instruct 评测集上 Alpaca 90 : text-davinci-003 89（5 作者执行） | 正向，但样本量小、评委即作者、无统计显著性检验 |
| 交互式定性观察 | "often behaves similarly to text-davinci-003 on a diverse set of inputs"；回答风格偏短（继承教师模型的短输出风格） | 正向，非量化 |
| 多样性对比 | 52K 数据 root verb/direct object 分布较 self-instruct seed 更丰富 | 正向，定性图示 |
| 反例（诚实披露） | 幻觉案例：答坦桑尼亚首都为 Dar es Salaam（实为 Dodoma，1974 年前才是 Dar es Salaam）；且幻觉频率高于 text-davinci-003 | 负向证据，团队主动披露 |
| 复现可信度 | 团队声明用公开命令可复现出与 demo 同等质量模型（Python 3.10 实测） | 正向 |

**行业意义（源内表述）**：证明"强基座 + 便宜的自生成指令数据 + 3 小时学术级算力"即可逼近闭源 SOTA 的指令跟随表现，把指令微调从大厂专利变为学术可复现操作。

## §6 局限与未披露项

### 源内明确声明的局限
1. **未做安全对齐**："we have not yet fine-tuned the Alpaca model to be safe and harmless"（README 原文）；
2. **幻觉为主要失败模式**，甚至多于其教师 text-davinci-003；另有毒性与刻板印象问题；
3. **评测薄弱**：作者自认 "evaluation may be limited in scale and diversity"，故另开 demo 众包反馈；
4. **禁止商用的三重原因**：① LLaMA 非商业许可传染；② text-davinci-003 服务条款禁止训练与其竞争的模型；③ 缺乏安全措施不宜部署；
5. **demo 已下线**（后续 Update）：托管成本 + 内容过滤器不足。

### 未披露 / 源中缺失项
- **无 arXiv 论文、无同行评审**：全部技术细节止步于 README + 博客，评测协议（题目清单、评判标准、置信区间）未公开；
- 52K 数据的领域/难度分布仅有可视化图，无统计表；
- 13B 版本的评测结果从未单独公布（超参给了，效果没给）；
- 大尺寸 LLaMA（13B 以上）微调版权重始终未获 Meta 明确许可放出；
- prompt.txt 的已知错误（PR #24）对数据的实际影响幅度未量化；
- ⚠️ 任务侧勘误：外部流传的 "Alpaca 复刻了 175B LLaMA"说法在本两处一手源中**不存在**——Alpaca 仅微调 LLaMA **7B**（及给出 13B 超参）；"175" 实为 self-instruct 种子指令条目数（见 §3 表 #5）。
