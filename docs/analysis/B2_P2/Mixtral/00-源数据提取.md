## §4 方法细节

- **架构**：decoder-only Transformer，与 Mistral 7B 相同，唯一区别是每层的 FFN 被替换为 MoE layer（8 个专家）。专家为标准 SwiGLU FFN。gating 用 `Softmax(TopK(x·W_g))`，TopK 对低于第 K 大的 logit 置 -∞。K=2。
- **输出公式**：`y = Σ_{i=0}^{n-1} Softmax(Top2(x·W_g))_i · SwiGLU_i(x)`
- **与 GShard 区别**：(1) Mixtral 用 MoE 替换**所有** FFN 子块，GShard 只替换隔一个；(2) GShard 对第二个专家用更精细的 gating 策略。
- **训练与推理**：预训练 32K 上下文；训练用多语言数据上采样。稀疏 MoE 推理随 `n_experts` 增参、随 K 近常数计算，区分"sparse parameter count"（随 n 增长）与"active parameter count"（随 K×n 增长）。
- **高效实现**：Megablocks（CUDA kernel）把 FFN 运算转成稀疏矩阵乘法，处理专家收到的可变 token 数；支持 Model Parallelism 和 Expert Parallelism（EP，有 load balancing 挑战）。
- **Instruct 训练**：SFT + DPO（Direct Preference Optimization）在 paired feedback 数据集上。未披露 SFT/DPO 细节参数。

## §5 实验结果要点

- **综合性能**：Mixtral 8x7B 在几乎所有流行基准上与 Llama2-70B 持平或超越，仅用 5x 更少激活参数。
- **代码/数学显著领先**：HumanEval 40.2%（Llama2-70B 29.3%）、MBPP 60.7%、MATH 28.4%、GSM-8K 58.4%。
- **多语言**：上采样多语言数据后，Mixtral 在法/德/西/意四语 MMLU 全面超 Llama2-70B。
- **长上下文**：Passkey retrieval 100% 命中，不论序列长度或位置；proof-pile 子集 perplexity 随上下文单调下降。
- **偏差（Bias）**：BBQ accuracy 56.0% vs 51.5%；BOLD 各群体 sentiment 更正面，std 相近。
- **Instruct**：MT-Bench 8.30，为 2023-12-03 时开源最优；Arena Elo 1121 超过 Claude-2.1(1117)、GPT-3.5-Turbo(1117)、Gemini Pro(1111)、Llama-2-70b-chat(1077)。
- **路由分析**：专家选择**与语法而非主题对齐**。各领域（ArXiv/生物/哲学）在层0/15/31 分配近乎一致，仅 DM Mathematics 略有差异。连续 token 倾向分配到相同专家，高层（15/31）临时局部性显著（表5），对 Expert Parallelism 的影响是过度订阅风险，可被缓存利用。

## §3.1 基准评测设置（全文摘录）

作者用自有 evaluation pipeline 重跑所有基准以确保公平比较，按任务分类如下：

- **Commonsense Reasoning (0-shot)**：Hellaswag、Winogrande、PIQA、SIQA、OpenbookQA、ARC-Easy、ARC-Challenge、CommonsenseQA
- **World Knowledge (5-shot)**：NaturalQuestions、TriviaQA
- **Reading Comprehension (0-shot)**：BoolQ、QuAC
- **Math**：GSM8K（8-shot，maj@8）与 MATH（4-shot，maj@4）
- **Code**：Humaneval（0-shot）与 MBPP（3-shot）
- **Popular aggregated**：MMLU（5-shot）、BBH（3-shot）、AGIEval（3-5-shot，仅英文多选题）

**评估协议与 Llama2 官方差异**（§3 明确）：(1) MBPP 用手验证子集；(2) TriviaQA 不提供维基上下文。

## §6 局限

1. **内存与硬件利用未建模**：§3 明确成本分析只基于 active parameter count（正比于推理计算成本），未考虑 memory cost 与 hardware utilization；SMoE 层因 routing 与多专家/设备带来额外 overhead，更适合 batch 工作负载。
2. **路由无主题化**：专家未按数学/生物学等主题分工，难以获得直观的专家语义分工。路由更多表现"语法/位置局部性"而非语义专门化，用户难以利用专家分工进行剪枝或蒸馏。
3. **MoE 结论**：仅限 13B 激活参数对比（相对 LLaMA2-70B/33B/13B/7B 与 Mistral 7B），未在更大 scale 上验证 SMoE 的 scaling 规律。
4. **评估协议差异**：部分基准（MBPP 用手验证子集、TriviaQA 不提供维基上下文）与 Llama2 官方不同；Mixtral-8x7B 的数学基准 maj@4/maj@8 采用多数投票（非单采样），跨表对比需谨慎。
5. **缺乏训练细节披露**：预训练数据配比、学习率、训练时长并未完整披露（仅给出架构与最终性能），可复现性受限；Instruct 的 SFT/DPO 超参未给出。
