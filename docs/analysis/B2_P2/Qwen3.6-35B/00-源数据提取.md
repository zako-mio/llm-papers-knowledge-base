## §4 方法要点

1. **高效稀疏 MoE 架构（继承 Qwen3.Next 路线）**：40 层按 10 组循环堆叠，每组 3 层 Gated DeltaNet（线性注意力）+ 1 层 Gated Attention（全注意力 GQA）。线性注意力主导的长上下文低 KV 成本路径 + 少量全注意力层保证精确检索。出处：[HF] Model Overview。
2. **极窄激活宽度**：256 选 8 routed + 1 shared，专家中间维仅 512，hidden 2048 —— 以极小激活计算预算（3B）撬动 35B 总容量。这是「35B-A3B」命名含义。出处：[HF]。
3. **多步 MTP（Multi-Token Prediction）**：预训练即带 multi-steps MTP 头，官方部署示例直接给出 vLLM `qwen3_next_mtp` 与 SGLang NEXTN 投机解码配置（num_speculative_tokens=2 / steps 3）。出处：[HF] Quickstart。
4. **Thinking Preservation**：新会话选项，保留历史消息中的思考上下文用于迭代开发，降低重复推理开销。属后训练/API 行为层特性，非架构改动。出处：[Blog][GH] Highlights。
5. **双模式输出**：thinking 模式默认开启（`<think>...</think>` 包裹）；可通过参数切换 non-thinking 直接回答。官方推荐采样参数分三档：通用 thinking（temp=1.0, top_p=0.95, top_k=20, presence_penalty=1.5）、精确编码/WebDev thinking（temp=0.6, top_p=0.95, presence_penalty=0.0）、non-thinking（temp=0.7, top_p=0.80）。出处：[HF]。
6. **原生多模态**：单模型带 Vision Encoder（image-text-to-text），文本-only 部署可用 `--language-model-only` 跳过视觉编码器省显存换 KV cache。出处：[HF]。

## §5 评测结果要点

### 5.1 官方口径核心结论（[Blog]）

- 仅 3B 激活参数，在多项关键编码基准上超过 dense 27B 的 Qwen3.5-27B，并大幅超越直系前代 Qwen3.5-35B-A3B（尤其 agentic coding 与推理）。
- Terminal-Bench 2.0 得 51.5，为对比五模型中最高（超 Gemma4-31B 42.9 达 8.6 分）。
- QwenWebBench 1397 Elo，领先所有对比模型（次优 Gemma4-31B 1197）。
- 多数 VL 基准持平 Claude Sonnet 4.5，空间智能（RefCOCO 92.0 / ODInW13 50.8，后者较上代 +8.2）显著反超。
- MCPMark 37.0，为对比中最强（约为 Gemma4-31B 18.1 的两倍），体现工具集成能力。

### 5.2 评测协议脚注（逐条照录，[Blog]＝[HF]）

- **SWE-Bench 系列**：内部 agent scaffold（bash + file-edit 工具）；temp=1.0, top_p=0.95, 200K 上下文；官方修正了 SWE-bench Pro 公开集中部分问题任务，所有基线在修订版上重评。
- **Terminal-Bench 2.0**：Harbor/Terminus-2 harness；3h 超时，32 CPU/48GB RAM；temp=1.0, top_p=0.95, top_k=20, max_tokens=80K, 256K ctx；5 次运行平均。
- **SkillsBench**：经 OpenCode 评测，78 个自包含任务（剔除依赖 API 的任务）；5 次平均。
- **NL2Repo**：其余模型经 Claude Code 评测（temp=1.0, top_p=0.95, max_turns=900）。
- **QwenClawBench**：内部真实用户分布 Claw agent 基准（即将开源）；temp=0.6, 256K ctx。
- **QwenWebBench**：内部前端代码生成基准；中英双语、7 类别（Web Design/Web Apps/Games/SVG/Data Visualization/Animation/3D）；自动渲染 + 多模态裁判（代码/视觉正确性）；BT/Elo 计分。
- **TAU3-Bench**：官方用户模型（gpt-5.2, low reasoning effort）+ 默认 BM25 检索。
- **VITA-Bench**：子域平均分；裁判改用 claude-4-sonnet（原裁判 claude-3.7-sonnet 已不可用）。
- **MCPMark**：GitHub MCP v0.30.3；Playwright 响应截断于 32K tokens。
- **MCP-Atlas**：公开集得分；gemini-2.5-pro 裁判。
- **AIME26**：使用完整 AIME 2026 (I & II)，分数可能与 Qwen3.5 笔记口径不同。

## §6 局限与未披露项

**官方成绩中的相对短板（同表可见）：**
1. SWE-bench Verified 73.4 仍低于自家上代 dense 旗舰 Qwen3.5-27B 的 75.0；
2. HLE 21.4 显著低于 Qwen3.5-27B 24.3（对比列中 Gemma4-26BA4B 低至 8.7，分化极大）；
3. TAU3-Bench 67.2 / VITA-Bench 35.6 / Tool Decathlon 26.9 均非对比列第一（分别落后 Qwen3.5-35BA3B 68.9、Gemma4-31B 43.0、Qwen3.5-27B 31.5）——General Agent 组整体不敌部分更大模型；
4. MMLU-Pro 85.2 / C-Eval 90.0 微幅低于 Qwen3.5-27B（86.1/90.5），知识面基本持平而非超越。

**未披露项：**
1. 训练数据构成、token 量、训练算力与成本完全未披露；
2. 后训练配方（RL 算法、奖励设计、数据规模）未披露——博客仅呈现能力结果；
3. Vision Encoder 的参数量、结构、训练策略未在任何一手文档中给出（Model Overview 仅覆盖语言模型部分）；
4. 1,010,000 tokens 扩展上下文的实现方式（是否 YaRN 类外推）未说明；
5. Thinking Preservation 的具体机制（上下文裁剪/压缩策略）未公开；
6. `qwen3.6-flash` API 定价与限速在博客发布时未公布（coming soon）；
7. 内部基准 QwenClawBench / QwenWebBench / Claw-Eval 无第三方复现，QwenClawBench 标注 "open-sourcing soon" 截至提取日未见放出；
8. 对比基线不含任何 2026 年闭源旗舰（如 Claude/GPT 系列），"rivaling much larger dense models" 的说法限定于开源同级池。
