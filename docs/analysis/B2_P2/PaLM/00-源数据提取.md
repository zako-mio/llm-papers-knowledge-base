## §4 方法细节

### 4.1 架构（§2.2, p5–6）
- decoder-only、稠密激活、标准 Transformer（Vaswani et al. 2017）。
- 关键修改：MLP 中间激活采用 **SwiGLU**（Swish(xW)·xV），作者称优于常规 activations。
- 标准 causal attention 与相对位置编码等细节沿用惯例。
- Feed-forward 尺寸恒为 4×d，attention head size 恒为 256。

### 4.2 三种规模（§2.1, p6; Table1）
- 8B：32 层，d=4096，16 head（8.63B 参数）。
- 62B：64 层，d=8192，32 head（62.5B 参数）。
- 540B：118 层，d=18432，48 head（540.35B 参数）。
- FLOPs/token ≈ 参数量；三者（除 batch size 外）用相同数据、词表、训练配置。batch size 8B/62B 从 256→512，540B 从 512→1024→2048。

### 4.3 训练数据（§3, p6）
- 高质 780B token 语料：过滤的网页（按质量分类器分数采样）、书籍、Wikipedia、新闻、源代码、社交对话。
- 选用 LaMDA 与 GLaM 所用的数据集。三个模型在完全相同的一遍数据上训练（统一 shuffle），混合比例避免任何子组件重复。
- 源代码来自 GitHub 开源仓库；按许可证过滤（排除 copy-left）、按文件扩展名限制到 24 种语言（Java、HTML、JavaScript、Python、PHP、C#、XML、C++、C 等），得 196GB 源码；用 Levenshtein 距离去重。

### 4.4 训练系统（§4, p7）
- 基于 JAX + T5X codebase，全部在 TPU v4 Pods 上训练。
- PaLM-540B 横跨两个 TPU v4 Pod，经数据中心网络（DCN），结合模型并行（model parallelism）与数据并行（data parallelism）。
- 每 Pod 3072 chip / 768 host——迄今最大已报道 TPU 配置，把训练扩展到 6144 chip 而无需 pipeline parallelism。
- 对比：LaMDA/GLaM 单 TPU 系统无 pipeline/DCN；Megatron-Turing 530B 用 2240 A100 + 模型/数据/pipeline 并行；Gopher 用 4 个 DCN 互联 TPU v3 Pod（每 1024 chip）+ pod 间 pipeline。
- **pipeline 的缺点**：step time 的 bubble 开销（填/排空流水线时大量设备空闲）；微批内需从内存重载权重、要求更高内存带宽。
- 作者提出用并行效率与 token/sec 吞吐衡量（而非硬件 FLOPs 利用率 HFU），指出 HFU 会因重计算（rematerialization）等design选择而失真。

### 4.5 训练设置（§5, p10）
- 权重初始化：fan-in variance scaling W~N(0,1/n)；输入 embedding E~N(0,1)（因为 embedding 不做 layernorm）；共享输入/输出 embedding，pre-softmax logits 缩放 1/√n（n=embedding size）。
- 优化器：Adafactor（无 factorization），等价 Adam + parameter scaling。
- 超参：Adafactor learning rate 等，进一步细节见论文 §5。

### 4.6 训练稳定性（§5.1, p11）
- 论文报告训练过程中的不稳定性处理经验（具体数值/措施见正文 §5.1），作为大规模训练稳定性的实证讨论。

## §5 实验结果要点

### 5.1 English NLP（§6.1, p11–12; Table4/5）
- 在 Du et al. (2021) 与 Brown et al. (2020) 的 29 个 English 基准上评估（含 5 类：TriviaQA/NQ/WebQuestions 闭卷 QA、LAMBADA/HellaSwag/StoryCloze cloze 与补全、Winograd/WinoGrande、PIQA/ARC/OpenBookQA 常识、DROP/CoQA/QuAC/SQuADv2/RACE 阅读理解、SuperGLUE、ANLI）。
- 只考虑预训练单 checkpoint（排除 fine-tune/多任务适应）。PaLM-540B 在 1-shot 超越 prior SOTA 24/29，few-shot 28/29；在一些阅读理解与 NLI 任务上 few-shot 比 prior SOTA 高 >10 分。
- Table5 平均：NLG/NLU，PaLM-540B 63.9/74.7，两类均较 prior 提升 >5 分；PaLM-62B（57.7/67.3）在两类均超 GPT-3-175B（52.9/65.4）。

### 5.2 BIG-bench（§6.2, p14–16; Figure3/4）
- BIG-bench 150+ 任务（仅文本任务），含 human performance（众包，允许用外部工具）。「best」为单例最高，「average」为全部人力答案平均。
- 3 个 PaLM 模型在 58 个共同任务上评估。5-shot PaLM-540B 得分高于「average human」；超前 SOTA 44/58 任务。
- 对 150 任务集整体（Figure3 右图）亦近似。表现随规模呈 log-linear；大量任务出现「不连续跃升」（emergent abilities）。
- PDF 中为插图，含特定任务（如 arithmetic、logical reasoning）的示例输出，见正文 §6.2 与附录。

### 5.3 推理（§6.3, p20; Table10; Figure9/10）
- 用 8-shot chain-of-thought prompting + 后置外部计算器（作者称计算器改善 <5%）。仅用模型规模 + CoT 即可达 SOTA（无需 domain 架构 / task 微调 / verifier）。
- GSM8K：PaLM-540B +CoT+calculator 58%，超 Cobbe(2021) 55%（verifier）；PaLM-540B +CoT 54%；无 CoT 17%；PaLM-62B +CoT 33%。
- 7 任务中 SOTA 4 个（GSM8K, MAWPS, SVAMP, StrategyQA），其余 3 个（ASDiv, AQuA, CommonsenseQA）接近 SOTA。
- 误差分析（Figure9）：150 个 GSM8K 示例，62B 犯错 45 个（20 语义理解错——540B 修复 6 个；18 一步缺失——540B 修复 12 个；7 其他——540B 修复 4 个）。缩放对三类错误均显著修复。

### 5.4 Code Tasks（§6.4, p22）
- 在代码生成/完成基准评估，PaLM 在代码任务上表现强（具体数值见正文）。

### 5.5 翻译与多语言（§6.5, §6.6, §6.7, p28–33）
- 翻译（WMT 语言对）与多语言 NLG/QA：PaLM 未显式训练于平行语料仍具跨语言能力；在高资源/低资源平移方向细节见正文。WMT 等基准细节在正文章节中。

### 5.6 记忆化与数据污染（§7, §8, p35–36）
- PaLM 单遍 780B token，但容量极大且 web 语料含近重复。方法：随机取 100 个训练 token 片段，喂前 50 个 token，贪心解码看复现 50-token 续写的频率（沿用 Carlini 等方法）。细节见正文。

### 5.7 偏见与毒性（§10, p40–43）
- **Distributional bias in social groups**（10.1）：用代词/身份词触发工具分析模型对社会群体的分布偏差。
- **Toxicity in open-ended generation**（10.2）：开放生成中测量毒性。详细评估与缓解见正文。
- 作者强调需谨慎使用 LMs 输出（见 §6 局限 / §11 伦理考量）。

## §6 局限

1. **有关「平均人类」等对比需谨慎解读**：BIG-bench「平均人类」允许用外部工具且用平均/最优指标，PaLM 超平均人类不等于具备通用人类智能（§6.2 说明）。
2. **偏置与毒性未根治**（§10, p40–45）：代表偏差与开放生成毒性仍存在，作者提供分析并讨论缓解策略，但不声称彻底解决（§10.3 Limitations）。
3. **记忆化与隐私**（§7, p35）：大容量 + 近重复文可能记取训练数据，存在隐私/泄露风险。
4. **数据污染**（§8, p36）：基准可能混入训练数据，需评估。
5. **伦理与部署风险**（§11, p45）：大规模 LMs 有滥用、偏见、有害内容等风险，作者给出缓解建议但强调未完。
6. **开放性问题的缩放**（§13, p48）：即使 PaLM-540B，bigger LMs 的涌现能力、安全性、可解释性、硬件/能效上限等仍是开放问题（附录 B 讨论计算使用量与环境影响）。
7. **模型开发成本极高**：6144 TPU v4 训练，算力/能源消耗大（附录 B），可复现门槛高（PaLM 本身非公开可访问）。
