## §3 核心主张与关键数字表

## §4 方法细节

- **Generic MoE 公式 (Eq.3–5)**：`h_t^l = Σ_i g_{i,t} FFN_i(u_t^l) + u_t^l`，gate `g_{i,t}` 由 Softmax(u_t^l·e_i^l) 取后对非 TopK 置 0；`e_i` 为第 i 专家质心。
- **细粒度专家切分**：把每个 FFN 专家沿中间 hidden 维度切成 m 个更小专家（每个维度 1/m），同时把激活专家数从 K 提升到 mK，保持总参与计算恒定。组合学上极大增加激活组合的灵活度（120 → 4.4 billion 例）。
- **共享专家隔离**：额外隔离 K_s 个共享专家，每个 token **确定性**分配到它们（不经过 router），以捕捉公共知识、缓解 routed 专家冗余。为保持计算恒定，routed 激活数相应减 K_s。完整公式 Eq.9–11。
- **负载均衡**：两类 loss——Expert-Level Balance Loss (Eq.12–14) 用 factor α1 缓解 routing collapse；Device-Level Balance Loss (Eq.15–17) 用 factor α2 平衡跨设备计算。实践中 α1 设很小、α2 设较大。2B 规模单 GPU，未用 device-level loss；DeepSeekMoE2B 用 expert-level balance factor 0.01；16B 用 0.001。
- **验证实验配置**：9 层 Transformer，hidden 1280，10 头×128；所有可学习参标准差 0.006；全部 FFN 换 MoE，专家总参=标准 FFN×16，激活（共享+activated routed）=标准 FFN×2；~2B 总参、~0.3B 激活。AdamW β=(0.9,0.95) wd=0.1；warmup 2K steps，80%/90% 处 ×0.316 衰减；max lr 1.08e-3；batch 2K×2K=4M token；25,000 steps=100B tokens。
- **16B 配置**：28 层，hidden 2048，16 头×128；除首层外全部换 MoE（首层 load balance 收敛慢）；2 shared + 64 routed，每专家 0.25×FFN，每 token 路由到 2 shared + 6/64 routed；16.4B 总参、2.8B 激活。max lr 4.2e-4，batch 4.5K×4K=18M token，106,449 steps=2T tokens。BPE vocab 100K。
- **评估基准**：语言建模（Pile；16B 用 BPB）、HellaSwag/PIQA/ARC、RACE、DROP、GSM8K/MATH、HumanEval/MBPP、TriviaQA/NQ、MMLU、WinoGrande、中文（CLUEWSC/CEval/CMMLU/CHID）、OpenLLM Leaderboard。
- **SFT**：1.4M 例，batch 1024、8 epochs、max seq 4K、lr 恒定 1e-5（无调度）。

## §5 实验结果要点

- **2B 验证**：DeepSeekMoE 在相同总参/激活下全面碾压 GShard（Pile 1.808 vs 1.867；HellaSwag 54.8 vs 50.5；TriviaQA 16.6 vs 10.2）；逼近 Dense×16（1.808 vs 1.806）→ 接近 MoE 理论上限。
- **消融**：①共享专家隔离（GShard 基础上隔离 1 个）在多数基准提升性能；②细粒度切分到 32/64 专家持续提升（图3）；③1/2/4 个共享专家 Pile loss 1.808/1.806/1.811，选 1:3（shared:activated routed）比例。
- **专家专门化证据**：关闭 top routed 专家时 DeepSeekMoE 比 GShard×1.5 更敏感 → 冗余更低、每个 routed 专家更不可替代；共享专家不可被 routed 替代（关闭后 Pile 1.808→2.414）；4 routed 激活即达到 GShard 全量效果；仅一半激活参时仍超 GShard。
- **16B vs DeepSeek7B**：40.5% 计算取得可比性能；在语言建模与知识密集型（Pile/HellaSwag/TriviaQA/NQ）强，多项选择受限（仅 0.5B attention 参 vs 2.5B）。
- **16B vs LLaMA2-7B**：39.6% 计算，多数基准超越 Mamba；数学/代码显著强（HumanEval 26.8 vs 14.6，MATH 4.3 vs 2.6）；中文基准大幅领先；英文理解基准可比或更优。
- **Chat 模型**：DeepSeekMoE-Chat16B（对 LLaMA2-SFT7B、DeepSeek-Chat7B 同 SFT 数据）以 40% 计算，多数基准可比或更优。
- **可部署性**：16B 单 GPU 40GB，无量化，优化后约 7B 稠密模型 2.5× 推理速度。

## §6 局限

1. **145B 仅初步**：摘要与 §1 提到 scaled 到 145B（对比 DeepSeek67B 用 28.5%/18.2% 计算），但正文未给出完整基准表，属初步探索，证据强度弱于 16B。
2. **多项选择任务局限**：16B 注意力参数仅 ~0.5B，导致 MMLU 等多项选择任务弱于 DeepSeek7B（48.2 vs 45.0）甚至 LLaMA2-7B（45.8）。
3. **中文评估风险**：正文 §6.1 剔除 CHID 因"结果不稳定"，反映中文基准测评的不确定性；作者自述语料以英中为主。
4. **无并行 scaling law**：未系统给出 MoE 专家数、激活数、细粒度 m 随规模的最优曲线（">16B 更细粒度仍可行"是推测）。
5. **专家设备级负载均衡仅在部分配置启用**：16B 用 pipeline parallelism 时每层专家放在同一设备，因此未用 device-level loss，跨设备均衡未在最大规模验证。
