**方法核心**：将每个请求的 KV cache 划分为固定大小 block，物理上无需连续存储；通过 block table 记录 logical→physical 映射；PagedAttention kernel 可访问非连续物理 block；支持 block 级共享（同一请求内不同序列、跨请求共享，如 parallel sampling 的 prompt 部分）。

## §4 方法细节

- **背景问题**：KV cache 随生成动态增长、生命周期与长度未知 → 现有连续空间预分配低效。作者将 LLM 生成分为 prompt phase（可并行矩阵运算）与 autoregressive generation phase（逐 token、内存受限），后者使 GPU 算力利用率不足。
- **PagedAttention 定义**：以固定 KV block 为单位管理 KV cache；block 大小 B 为 token 数；key/value block 分开管理。每个 token 在各层具备多组 key/value 向量；可选择"同一层全部 head/layer 合并进单 block"或"不同 head/layer 各单独 block 并各自 block table"。两设计性能无差，作者选后者以简化实现。
- **block table 翻译**：分离 logical / physical blocks；每 entry 记录 physical block 地址与已填充位置数。物理 block 尾部未填位置为未来 token 预留。
- **PagedAttention kernel**：对 query token 与某个 KV block（如 block 0 的 "Four score and seven" 的 key）计算注意力分数，再结合 value 向量得到输出 o。kernel 分别识别并抓取非连续 block。
- **解码流程**：左到右填充 block，旧 block 满后才分配新 block，因此内存浪费限制在单块内。例子：文本"Four score and seven years ago our fathers brought forth..." 的 key/value 散布在三个非连续物理 block（Block 1/2/3），block 0 在远处。
- **与迭代级调度（iteration-level scheduling，Orca 引）协同**：CPU 侧同样分块用于 swap；物理 KV block 池预分配隔离干扰；preemption 请求调度与 PagedAttention co-design。
- **分布式**：支持模型超过单 GPU 内存，跨 worker 的 KV block 管理；block 大小可变（block size >1 允许多 token/block，kernel 一次处理多 token）。
- **内存浪费分析（Figure 2）**：现系统 KV cache 内存使用率仅 20.4%–38.2%，分类为 external frag. / token states / reservation / internal frag. & others。Reservation（提前预留最大长度）为最大浪费项。

## §6 局限

1. 依赖 GPU 显存分配；CPU swap 场景（§4.5）需额外管理开销。
2. block size 选择需权衡碎片 vs 利用率（§7.2 明确研究，block size 恒定时 trade-off 存在）。
3. 因 Orca 未公开，部分对照由 Oracle 估计；对比公平性受限（§6.2 提及）。
4. 论文口径为"near-zero waste"，实际仍有单 block 尾部碎片（最后 block 未填满位置被保留）。
5. 评估主在解码吞吐，prompt 长序列（chunked prefill）仅部分覆盖。
6. 文章写作侧重工程系统，理论分析较少（OS paging 类比为主）。
