## §4 方法细节
### 4.1 三阶段训练管线（§2，p4）
1. **Continual Pre-Training**：在 MiniMax-Text-01 上续训 7.5T tokens；强化 Web/PDF 解析与清洗、优先抽取自然 QA 对（网页/论坛/教材）、严格不用合成 QA、语义去重；STEM+代码+书籍+推理数据提至 70%。降低 MoE auxiliary loss 系数并调大 microbatch。
   - 长上下文扩展教训：lightning attention 混合架构收敛复杂度高，激进扩长会突遭梯度爆炸（归因于前后层衰减率不同、早层偏局部信息更新跟不上）→ 采用 **32K 起步四阶段平滑扩至 1M**。
2. **冷启动 SFT**：注入反思式长 CoT 模式；覆盖数学/代码/STEM/写作/QA/多轮对话，数学+代码约占 60%。
3. **大规模 RL**（核心阶段）。

### 4.2 CISPO 算法（§3.1，p5–7）
- 动机（token clipping 缺陷）：GRPO/PPO 的 trust-region clip 会把低概率高 IS 权重的 token（典型为反思词 "**However, Recheck, Wait, Aha**"——推理路径分叉点）在首次 on-policy 更新后剔除，使其无法参与后续 off-policy 梯度；该问题在 hybrid 架构上尤为突出（16 轮 off-policy 更新场景下 DAPO 的 upper-bound 放宽也无效）。
- 方案：保留 REINFORCE 型目标，改为 **clip 重要性采样权重本身**：r̃=clip(r_IS, 1−ε_low, 1+ε_high)（实验中 ε_low 取大值即不设下界，仅调 ε_high）；所有 token 始终贡献梯度，熵自然维持在合理区间；采用 GRPO 组相对优势 + token-level loss；**无 KL penalty**；辅以 DAPO 的动态采样与长度惩罚。
- 统一形式（式 6–7）：引入 token-wise mask M 后可在同一框架下表达 PPO/GRPO/DAPO 等不同裁剪策略。

### 4.3 Hybrid 架构 RL 工程配方（§3.2，p7–8）
- **精度不匹配**：training-kernel 与 inference-kernel 概率不一致导致 reward 不增长（小规模稠密 softmax 模型无此问题）；逐层排查锁定输出层 LM head 高幅值激活 → **LM head 提精度至 FP32**。
- **优化器超参**：VeRL 默认 β=(0.9,0.999)、eps=1e-8 会致不收敛；实测 M1 梯度跨 1e-18~1e-5 且相邻迭代相关性弱 → 定为 β₁=0.9、β₂=0.95、eps=1e-15。
- **重复早停**：基于概率飙升特征（重复循环时每 token 概率飙升）而非字符串匹配。

### 4.4 RL 数据与奖励（§4，p9–11）
- 可验证任务：数学 50K（pass@10 ∈ (0, 0.9) 过滤、n-gram+嵌入去污染、与 SFT 严格分离）；逻辑 53K（SynLogic 自动生成+规则验证器、上下难度双边界控制、随训练进度加难）；竞赛编程 30K（LLM 生成测试用例补全）；SE 沙盒（GitHub issue/PR 衍生 bug 定位/修复/测试合成，容器化执行 pass/fail 为奖励）。
- 通用域 25K：有标准答案用 GenRM 五档评分；无标准答案用成对比较（−1/0/1）+ Swiss Round 选参考答案。
- GenRM **长度偏置**治理：离线手段（数据多样化/对抗样本/架构改进）不足以阻止 RL 中的 length hacking → 核心=RL 期间在线监控 length-seeking 行为并即时重校准 GenRM，辅以 reward shaping/value clipping/normalization。
- 课程：先纯规则奖励推理任务，再逐步混入通用任务。

### 4.5 思考长度扩展（§5，p11–12）
40K 模型过滤数据（去易解样本、降合成推理数据配比——其重复同质输出会破坏长上下文 RL 稳定性）→ 阶梯扩长 40K→48K→56K→64K→72K→80K（以生成序列困惑度收敛 + 输出长度 99 分位逼近窗口为切换指标）。
**Pattern collapse 根因分析**：扩长后期负样本长度增长远快于正样本、更早触顶窗口，GRPO 优势归一化 + token-level loss 导致序列尾部负梯度堆积 → 三项对策：①重复早停；②sample-level 与 token-level 归一化组合；③调低 IS 梯度裁剪阈值 ε_high。

## §5 实验结果要点
- **评测设置**（§6.1，p12–13）：全部 temperature 1.0、top-p 0.95；AIME/GPQA-Diamond 采样 32 次平均，LiveCodeBench/FullStackBench 16 次平均；SWE-bench Verified 用 Agentless 式两阶段定位 scaffold；HLE 无工具。
- **核心基准（Table 2，p13，M1-40k/M1-80k）**：AIME2024 83.3/86.0；AIME2025 74.6/76.9；MATH-500 96.0/96.8；LiveCodeBench(24/08~25/05) 62.3/65.0；FullStackBench 67.6/68.3；GPQA-Diamond 69.2/70.0；HLE(no tools) 7.2/8.4；ZebraLogic 80.1/86.8；MMLU-Pro 80.6/81.1；SWE-bench Verified 55.6/56.0；OpenAI-MRCR 128k 76.1/73.4、1M 58.6/56.2；LongBench-v2 61.0/61.5；TAU-bench airline 60.0/62.0、retail 67.8/63.5；SimpleQA 17.9/18.5；MultiChallenge 44.7/44.7。
- **思考预算缩放效应**：M1-80k 在复杂数学/编程上优于 M1-40k（AIME24 86.0 vs 83.3），验证 test-time compute 扩展收益；但并非全面（retail TAU-bench、MRCR 128k 反而略降）。
- **横向定位**（Table 2 + p3 正文）：开放权重阵营中整体超原版 DeepSeek-R1 与 Qwen3-235B，尤其 SE/工具使用/长上下文；MRCR(128k) 73.4 显著高于对比表中多数模型；但数学/编码竞赛弱于 DeepSeek-R1-0528（AIME25 76.9 vs 87.5 档位）、SimpleQA 事实性明显偏低（18.5）。
- **效率主张**（Figure 1 Right，p1/p3）：理论推理 FLOPs 随生成长度近线性增长；这是 RL 仅需 $0.53M 的根本原因（rollout 延迟是 RL 主要瓶颈，hybrid attention 直接削减该成本，p7 §3.2）。

## §6 局限（原文可证 + 明显边界）
1. **硬核竞赛弱于最强开源对手**：自认"MiniMax-M1 lags in mathematical and coding competitions"对比 DeepSeek-R1-0528（p3）；HLE(no tools) 仅 8.4，远低于闭源头部（o3 20.3、Gemini2.5 Pro 21.6）。
2. **事实性短板**：SimpleQA 18.5，虽高于原版 R1（12.9）但显著低于闭源模型（Gemini2.5 Pro 54.0）——幻觉抑制未随 RL 提升（Table 2）。
3. **思考预算非普惠**：80K 预算在部分任务回退（TAU-retail 63.5 vs 40k 版 67.8；MRCR 128k 73.4 vs 76.1），长思考存在过思/漂移代价。
4. **工程脆弱性自曝较多**：hybrid 架构 RL 需多项定制补丁（FP32 LM head、专用优化器超参、重复早停、pattern collapse 三重对策），作者明言这些问题在小规模 dense softmax 模型中不存在（p7–8），方法向其他架构迁移的鲁棒性存疑。
5. **GenRM 长度偏置只能在线缓解**：离线防御"经常失败"（p11 原文 frequently failed），依赖运行期监控触发重校准，属于持续运维成本而非一次性解决。
6. **CISPO 梯度轻微有偏**：作者承认权重裁剪使梯度 slightly biased（p7），理论上以偏差换稳定性，缺乏无偏性保证。
7. **合成推理数据副作用**：合成逻辑推理数据会使长上下文 RL 失稳（输出重复同质），被迫在 80K 阶段降采样（p12）——数据配方与长思考目标存在张力。
