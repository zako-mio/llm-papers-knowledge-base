## §3 核心主张与关键数字表

**核心主张**：MiniMax-01 系列（MiniMax-Text-01 + MiniMax-VL-01）通过在 Transformer 块中大量采用闪电线性注意力（lightning attention，I/O-aware 高效线性注意力）而非传统 softmax 注意力，配合稀疏 MoE，实现极长上下文。训练上下文 1M token，推理可外推到 4M token，性能与 GPT-4o / Claude-3.5-Sonnet 相当，上下文窗口却长 20–32 倍。

## §4 方法细节

### 架构
- **MoE**（§2.1）：每层 32 专家，top-2 routing；采用 token-drop 策略（每个专家设容量上限，超限 token 丢弃）提升训练效率。引入 global router（受 GShard 启发的负载均衡策略）：aux loss `L_aux = α_aux·(1/E)Σ f_i·m_i`（f_i = 分配到第 i 专家的 token 比例，m_i 平均路由概率），并为保持可微性、路由不塌缩而设计（路由塌缩 = token 分配过度集中问题）。
- **Linear attention**（§2.2）：用 "right product kernel trick" 把二次复杂度变线性。TransNormer 的 NormAttention `O = Norm((QKᵀ)V)` 转 `O = Norm(Q(KᵀV))`，训练复杂度 O(nd²)，推理恒定 O(d²)。因因果语言建模需 cumsum，阻碍高效并行——解释为何 LLaMA3/Qwen2.5/DeepSeekV3/Mistral 均未采用。容量对比：softmax attention 容量 O(d)；lightning attention 容量 O(d²/h)（d>h 故更大）→ 更强检索/外推（§2.2.4 讨论）。
- **Lightning attention**（§2.2.1）：I/O-aware 实现，tiling 技术把注意力分成 intra-block（left product）与 inter-block（right product），规避 cumsum，保持线性复杂度。前向递归公式 `kv0=0; kv_t=kv_{t-1}+k_t v_tᵀ; o_tᵀ=q_tᵀ kv_t`。算法1 给出 forward pass（块大小 B，HBM→SRAM 加载，片内算 intra/inter，KV 累加）。
- **Hybrid**：8 层一循环，最后为 softmax（hybrid-lightning）；对比 hybrid-cosformer2、hybrid-hgrn2、hybrid-window（滑动窗口，256–1024）——hybrid-lightning 最优。
- **归一化**：PostNorm + DeepNorm 优于 PreNorm（两者在 9.3B 激活参数/60B 总量/48 层/500B token 上对比，PostNorm 全面胜出）。
- **最终模型**（§2.4）：单设备推理约束 P_all < 500B；通过小规模对比确定最优 softmax:linear 混合比、depth:width、linear 内存:隐藏尺寸、激活 FFN:attention、RoPE 维度比例等。优化问题 `min L(P_all,P_act,T) s.t. C_compute<C, P_all<500B`。用 scaling laws + 自定义公式 `L(P_act,T|E)=d+aP^α_act+bT^β+c(P_act·T)^γ` 外推到 45.9B 激活/456B 总量最优。

### 计算优化（§3）
- MoE（§3.1）：token-grouping 重叠方案；引入 ETP（专家张量并行）+ EDP（专家数据并行）组，`world_size = PP×DP×CP×TP = PP×EDP×ETP×EP`，可完全解耦 MoE 与非 MoE 并行策略 + ZeRO。EP-ETP 重叠策略降低纯通信开销 **50%**。
- 长上下文（§3.2）：data-packing（样本尾部相接）；Varlen Ring Attention（避免传统 ring attention 对齐 padding 浪费）；LASP+（改进线性注意力序列并行，把串行依赖转并行，速度可达原 LASP 的 1/N_pcn）；varlen 块大小 256。
- 推理（§3.3）：Batched Kernel Fusion（prefix 阶段 Q/K/V 融合 + decoding 阶段 KV 与 prefix cache 更新融合，端到端解码延时降低 **10%**）；Separated Prefill/Decoding（长度 1 与 >1 用双 CUDA stream，负载 20 中 1–2 个长输入场景延时 100ms→50ms）；Multi-level Padding（块 32/64/128/256 动态选最小开销）；StridedBatchedMatmul 扩展 + TMA/WGMMA。H20 上端到端 MFU>75%；1024K 序列时 softmax attention 占 attention 延时 **95%**，lightning attention 占 <12%。

### 预训练（§4）
- 数据（§4.1）：规则清洗 + 去重 + reward-based 质量提升（用前代 5B 激活/60B 模型做 reward labeler，聚焦知识深度/实用帮助性/类别分布三维，其余为辅）；格式优化（嵌套文档格式，避免过度 markdown 约束）；byte-level BPE，vocab 200K，多语言上采样。
- 数据实验（§4.1.3）：统计假设检验框架，用 byte-normalized log 概率 `logacc_norm2`；采用 1B 激活/8B 总量的 MoE + 40B token（20B web + 20B 假设数据）做实验步；重复感知框架（对比文献"高质量文档重复训练至 50 次"观点，指出其实验不足以评估重复影响）。
- 训练策略（§4.2）：Xavier 初始化；DeepNorm α=(2N)^0.25, β=(8N)^-0.25；AdamW (β1=0.9,β2=0.95,wd=0.1)；初始序列长 8192；batch 16M→32M(69B token)→64M(790B)→128M(4.7T)；LR warm-up 500 步→峰值 2×10⁻⁴ 至 7.2T token，后调低 1.3×10⁻⁴ 至 3.2T token，快衰减阶段 1T token→3×10⁻⁵；MoE aux loss 系数 0.01。
- 长上下文扩展（§4.2/表6）：三阶段（128K/500B token，RoPE base 5M，Short30% Medium70% Long0%；512K/32B token，RoPE 10M，35/35/30；1M/26B token，RoPE 10M，30/30/40）→ 外推至 4M NIAH（图14）。

### 后训练（§5）
- 多阶段：Prompt collection（百万级，tag 系统按任务/领域/难度）→ Reward Model（正确性/真实性/有帮助性/无害性 4 维）→ SFT（领域专家模型 + rejection sampling，按 reward 选最优示范）→ 离线 RL（DPO）→ 在线 RL（改进版 GRPO：importance sampling weight clipping + KL 梯度方差重公式 `D_KL=E_t[SG(π_θ−π_ref)log π_θ]` + balanced advantage estimation）。
- 安全对齐：安全类别专属 prompt + 真实用户数据 + prompt 增强（red team 攻击 prompts）；harmless reward model 融合有帮助性以防过度拒答。
- 长上下文适配（§5.6/表7）：5 阶段（Stage I SFT 8192；Stage II 1,032,192，50% 长上下文；Stage III DPO 8192；Stage IV 全上下文类 Stage III；Stage V Online RL 8192）。RoPE base 恒定 10M。

### VLM（§6）
- ViT-L/14：224×224 预训练 37B image-caption pairs，336×336 微调 1.2B pairs；caption 截断 76 token；CoCa 对比学习；zero-shot ImageNet-1K @336 达 80.55%。
- 4 阶段训练：Stage I 模态对齐（80B token，描述数据）；Stage II 视觉理解增强（420B 多模态 token，与文本 post-train 数据 20:1）；Stage III 用户体验增强（真实应用图像 + DPO/early stopping 防过拟合）；Stage IV 留白/收尾。

## §6 局限

1. **softmax 注意力仍保留**：模型保留 1/8 组件为 vanilla softmax attention；未来要消除 softmax 实现无限上下文（§7 局限2）。
2. **长上下文评估场景偏人工/简化**：现有长上下文检索评测多为人工或简化场景，长文本文档分析等实际推理评估不足；M-LongDoc（32.5）相对 GPT-4o（41.4）仍有差距（§7 局限1 + 表13）。
3. **复杂编程任务偏弱**：预训练代码数据集有限，advanced programming 表现待提升（§7 局限3）。
4. **NIAH 难以监测训练进度**：NIAH 在早期（~128K 步）即达峰值，作者改用以更复杂任务mid-checkpoint，反映其严谨但说明单一长上下文指标失真。
5. **用户体验与学术基准差距**：leading 商用/开源模型在自研 in-house benchmark 上可大幅落后（如 Llama-3.1-405B Instruction Following 50.3），提示学术基准代表性有限；作者承认 multi-level instruction following 因训练数据不足仍是弱点。
6. **搜索工具不可比**：因不确定其他助手是否含类似搜索工具，作者避免与无搜索助手做不公平比较——故 71.5% 的搜索增益无法跨模型对标。
7. **对比口径差异**：表13 中部分模型（Qwen2-VL-72B、InternVL2.5-78B）用各自报告值，VLM 基准横表对比存在口径差别。
