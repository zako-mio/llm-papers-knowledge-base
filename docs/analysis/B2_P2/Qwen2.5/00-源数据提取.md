## §4 方法细节

### 架构（§2）
- 开源为 dense Transformer decoder（同 Qwen2）：GQA（grouped query attention）、SwiGLU、RoPE、QKV bias、RMSNorm 预归一化。
- 闭源 MoE：替换 FFN 为 MoE 层（每层多 FFN experts + top-K 路由）；采用细粒度专家分割与共享专家路由（Dai et al. 2024）。
- Table 1 配置：
  - 0.5B：24 层，14/2 头，tie embedding，32K/8K，Apache 2.0
  - 1.5B：28 层，12/2 头，tie，32K/8K，Apache 2.0
  - 3B：36 层，16/2 头，tie，32K/8K，Qwen Research
  - 7B：28 层，28/4，无 tie，128K/8K，Apache 2.0
  - 14B：48 层，40/8，128K/8K，Apache 2.0
  - 32B：64 层，40/8，128K/8K，Apache 2.0
  - 72B：80 层，64/8，128K/8K，Qwen
- tokenizer：BBPE，151,643 常规 tokens；控制 token 3→22（新增 2 个工具 token），统一词表。

### 预训练（§3）
- (1) **数据过滤**：用 Qwen2-Instruct 作质量过滤器做多维度评分。
- (2) **更好的数学/代码数据**：纳入 Qwen2.5-Math 与 Qwen2.5-Coder 训练数据。
- (3) **更好的合成数据**：用 Qwen2-72B-Instruct 与 Qwen2-Math-72B-Instruct 合成数学/代码/知识数据；经 general reward model + Qwen2-Math-RM-72B 过滤。
- (4) **更好的数据混合**：用 Qwen2-Instruct 分类均衡；下采样过表示域（电商/社媒/娱乐），上采样高价值域（科技/科学/学术）。
- 总规模 7T→18T tokens。
- **Scaling law（§3.2）**：确定 batch size B 与 lr μ；覆盖 dense 44M~14B、MoE 44M~1B activated，训练数据 0.8B~600B tokens；指导 MoE 与 dense 性能对齐。
- **长上下文（§3.3）**：两阶段（先 4,096 上下文，后扩展）；非 Turbo 扩展至 32,768 + ABF（RoPE base 1,000,000）；Turbo 四阶段 32,768→65,536→131,072→262,144（RoPE base 10,000,000），每阶段 40% 最长序列 + 60% 短序列；推理用 YARN + DCA，Turbo 达 1M、其他 131,072。

### 后训练（§4）
- **SFT（§4.1）** 扩展覆盖：长序列生成（8,192 输出，back-translation 生成长文本 queries）、数学（Qwen2.5-Math CoT + rejection sampling）、代码（Qwen2.5-Coder + 多语言 agent + sandbox 单测）、指令遵循（code-based validation + execution feedback 拒绝采样）、结构化数据理解（表格 QA/事实校验/纠错 + 推理链）、逻辑推理（70,000 queries：多选/对错/开放 + 演绎/归纳/类比/因果/统计推理）、跨语言迁移（translation model 转译低资源语言 + 语义对齐校验）、鲁棒系统指令（数百 general system prompts）、响应过滤（critic model + 多 agent 评分，全通过才保留）。
- 最终 >1M SFT 样本；2 epochs，seq 32,768，lr 7e-6→7e-7，weight decay 0.1，grad clip 1.0。
- **Offline RL（§4.2）**：聚焦 reward model 难评的领域（数学/代码/指令遵循/逻辑推理）；用 SFT 模型重采样 → 通过为 positive、否则 negative → DPO；数据 ~150,000 pairs，1 epoch，Online Merging Optimizer，lr 7e-7。
- **Online RL（§4.3）**：reward model 标注准则 = Truthfulness / Helpfulness / Conciseness / Relevance / Harmlessness / Debiasing；query 来自公开开源数据 + 专有高复杂度 query；preference pairs 人标 + 自动标；用 GRPO，query 处理顺序按 response score 方差排序；每 query 8 responses，global batch 2048。
- **长上下文微调（§4.4）**：Turbo 两阶段 SFT（先仅短指令 ≤32,768，后混长短 ≤262,144）；RL 阶段仅短指令（长文 RL 昂贵 + 缺乏长文 reward model）。

## §5 实验结果要点

### 72B+ / Plus（Table 6）
- Qwen2.5-72B-Instruct：MMLU-Pro 71.1、MMLU-redux 86.8、LiveBench 52.3、MATH 83.1、GSM8K 95.8、HumanEval 86.6。
- 对比 Llama-3.1-405B-Instruct：MMLU-Pro 73.3 / MMLU-redux 86.2 / MATH 73.8 / GSM8K 96.8 / HumanEval 89.0。
- 结论：Qwen2.5-72B-Instruct 在 MMLU-redux、MATH、MBPP、MultiPL-E、LiveCodeBench、Arena-Hard、MTBench 等超越 Llama-3.1-405B-Instruct；Qwen2.5-Plus 在 13 个基准中 9 个超 72B-Instruct。

### 14B/32B/Turbo（Table 7）
- Qwen2.5-32B-Instruct 多任务优于同级；Qwen2.5-14B-Instruct 竞争 GPT-4o-mini；Qwen2.5-Turbo 在 10 基准中 8 个超 14B-Instruct（更低成本）。

### 7B+（Table 8）
- Qwen2.5-7B：MMLU-Pro 56.3、MATH 75.5、GSM8K 91.6、HumanEval 84.8、MBPP 79.2、LiveCodeBench 28.7 —— 明显超 Gemma2-9B / Llama3.1-8B / Qwen2-7B。

### 小模型 0.5B/1.5B（Table 10）
- Qwen2.5-1.5B：MMLU-Pro 32.4 vs Qwen2-1.5B 22.9；MATH 55.2 vs 25.3 —— 显著提升。

## §6 局限

1. **数据泄漏防护**：依赖 n-gram（LCS 判据）去污染，但未覆盖 paraphrase 型泄漏。
2. **RL 长文受限**：长上下文 RL 因计算昂贵 + 缺少长文 reward model，RL 阶段仅用短指令。
3. **闭源 vs 开源**：MoE（Turbo/Plus）仅经 API 提供；开源仅 dense（MoE 未完全开放权重）。
4. **授权差异**：3B 与 72B 用自定义 license（Qwen Research / Qwen），非全部 Apache 2.0。
5. **推理能力上限**：提升推理依赖推理期计算扩展（o1 风格），尚未完全转向多模态/统一框架（未来工作）。
6. **评估偏自动**：评估套件以自动为主、最小人工介入，可能遗漏需要主观判断的方面。
