## §3 核心主张与关键数字表（注出处）

**动机**：GPT-3 等 100B 级模型不可见、不可训练，需开源一个质量至少齐平 GPT-3 (davinci) 的 100B 级双边模型。难点不在某点，而在预训练效率、稳定性、收敛性上的多重意外挑战（与 OPT-175B / BLOOM-176B 同期遭遇类似）。

**主要结果数字**：
- GPU 集群：96 台 DGX-A100 (8×40G)，60 天访问权；训练 400B tokens（中英各约 200B），序列长 2048/样本。
- 硬件 FLOPs 利用率 HFU=43.3%，模型 FLOPs 利用率 MFU=32.5%（含 re-materialization）。
- 模型规模：130B 参数，hidden state 12,288，70 层 transformer（9×8−2，为平衡 pipeline 分区移除 2 层），单 DGX-A100 (40G) 节点在 FP16 下可整跑。
- LAMBADA zero-shot 精度 **80.2%**（图2，双向注意力，刷新纪录；超过 GPT-3 与 PaLM 540B）。
- Pile 18 子集平均 BPB：Jurassic-1 0.650 / GPT-3 0.742 / **GLM-130B 0.634**（最优）。
- MMLU 5-shot：GLM-130B 在约 300B tokens 时逼近 GPT-3 (43.9)，最终 400B tokens 达 **44.8**（图6）。
- BIG-bench-lite (24 tasks)：GLM-130B 0/1/3-shot = **13.31 / 14.91 / 15.12**，zero-shot 超 GPT-3 175B 及 4× 更大的 PaLM 540B (0-shot 8.05)；对比 GPT-3 175B 13.18 (3-shot)。
- INT4 量化（表2左）：MMLU 44.75(FP16)→44.80(INT4)，LAMBADA 80.21→79.47，Pile BPB 0.634→0.641，几乎无损；GPT-3 FP16 MMLU 43.9 / LAMBADA 76.2 / Pile 0.74。
- INT4 推理速度（表2右，FasterTransformer）：4×RTX 3090 (24G) 编/解 0.37s/8.16s (128) 、1.30s/32.3s (512)；8×RTX 2080 Ti (11G) 0.39s/6.77s、1.04s/27.3s；8×A100(40G) 0.15s/4.29s、0.18s/17.7s；8×V100(32G) 0.31s/6.97s、0.67s/28.1s。对比 Huggingface/BLOOM-176B：解码推理快 7–8.4×。
- CLUE/FewCLUE 12 中文任务 zero-shot 全面优于 ERNIE Titan 3.0 260B（图8）；两个 abstractive MRC（DRCD、CMRC2018）上至少提升 **260%**。
- 三组评估基准：GLM-130B 最终在 **112 项任务**上达到高质量语言性能，并在 bias/toxicity 伦理基准上表现良好。

**INT4 量化缩放律**（图5右）：LLM 权重分布宽度影响量化质量；宽分布的 attn-dense 与 w2 导致 GPT 风格 BLOOM INT4 失败；GLM 权重分布显著更窄，且 INT4 与 FP16 差距随 GLM 规模增大而进一步缩小（附录图15）。GLM-130B 激活中约 **30%** outlier（对比 OPT/BLOOM 约 0.1%），故不做激活量化，只做权重 INT4、激活保持 FP16，运行时动态转 FP16。

## §4 方法细节

**4.1 骨架：双向 GLM（General Language Model）而非 decoder-only**
- 采用 autoregressive blank infilling 目标：对序列 x=[x1..xn]，采样文本片段 {s1..sm} 替换为 mask token 形成 x_corrupt，模型自回归恢复；片段间可见性由随机排列决定。
- 双向注意力（unmasked context）区别于 GPT 风格单向注意力。
- 两个 mask token：
  - [MASK]：句中短空白，长度相加占输入一定比例 → 行为类似 BERT / T5。
  - [gMASK]：句尾随机长度长空白，带 prefix context → 行为类似 PrefixLM。
- LAMBADA 80.2% 归因于双向注意力的更强上下文理解；把注意力改为单向则性能对齐 GPT-3 / OPT-175B。

**4.2 Layer Normalization: DeepNorm-based Post-LN**
- 实测 Pre-LN / Post-LN / Sandwich-LN 均无法稳定 100B 训练（图3a，失败 30+ 次初步试验）。
- 最终选 DeepNorm 初始化 + Post-LN：`DeepNorm(x) = LayerNorm(α·x + Network(x))`，α=(2N)^{1/2}；对 ffn、v_proj、out_proj 用 (2N)^{-1/2} 的 Xavier normal 初始化，bias 全零。
- 图3b：DeepNorm 梯度范数小且早期不尖峰，为最稳选择。

**4.3 位置编码与 FFN**
- PE 选 RoPE（Rotary Positional Encoding）而非 ALiBi。
- FFN 用 GeLU 激活的 GLU（GLU with GeLU）替代原 Transformer FFN。

**4.4 预训练目标（两段混合）**
- 自监督 blank infilling：**95% tokens**。30% 序列用 [MASK]（片段长度服从 Poisson λ=3，总和占输入 15%，上下文窗口 512，拼接 4 样本凑 2048）；70% 序列用 [gMASK]（prefix 保留、掩码长度 Uniform，上下文窗口 2048）。
- 多任务指令预训练 MIP（Multi-task Instruction Pre-training）：**5% tokens**，含 74 个 prompt 数据集（选自 Sanh et al. 2022 / Wang et al. 2022a，附录C、表12），覆盖语言理解、生成、信息抽取。MIP 置于预训练阶段（非微调），防污染模型其他通用能力（如无条件自由生成）。作者据此划定 zero/few-shot 收录标准（避免在 MIP 覆盖任务上评测）。

**4.5 数据组成**
- 1.2T Pile (train split, 英文) + 1.0T 中文 Wudao-Corpora (Yuan et al.) + 250G 自爬中文（论坛、百科、QA）→ 中英平衡混合。
- 分词：icetk，SentencePiece unigram 模式。

**4.6 并行与配置（platform-aware 3D 并行）**
- 数据并行 + 张量并行 + 流水线并行（PipeDream-Flush / DeepSpeed）。
- 采用 4-way tensor parallel + 8-way pipeline parallel（附录B.4 数值+实验验证），global batch size 4,224。
- 训练 400B tokens（中英各约 200B），固定 seq_len 2048；batch size 前 2.5% 样本从 192 warmup 到 4224；AdamW β1=0.9 β2=0.95 权重衰减 0.1；LR 前 0.5% 样本 1e-7 升至 8e-5，再按 10× cosine 衰减；dropout 0.1；梯度裁剪值 1.0（完整配置表11）。

**4.7 稳定性工程：混合精度 + EGS**
- 混合精度 Apex O2：FP16 前反向，FP32 optimizer states 与 master weights。
- 三个规模化后问题：①Pre-LN 深层主体支路 value scale 极大 → DeepNorm-based Post-LN 使 value scale 有界；②注意力分数超出 FP16 范围（CogView PB-Relax、BLOOM BF16、embedding norm 等各有代价）；③embedding 层异常梯度范数（常比其他层大数个量级，早期剧烈波动）。
- **Embedding Layer Gradient Shrink (EGS)**：`word_embedding = word_embedding*α + word_embedding.detach()*(1-α)`，α=0.1（图4），几乎清掉预训练期尖峰，延迟可忽略。最终仅经历 3 次后期 loss divergence。

## §5 实验要点

**5.1 语言建模**
- LAMBADA：zero-shot 80.2（双向注意力，破纪录，图2）。
- Pile 18 子集平均权重 BPB 0.634，优于 GPT-3 (0.742) 与 Jurassic-1 (0.650)（表3）。

**5.2 MMLU (57 tasks, 5-shot)**
- 300B tokens 时逼近 GPT-3 (43.9)，400B 结束训练时达 44.8（图6）。BLOOM-176B 用与 GLM-130B 相同 prompt 复测。结论呼应 Hoffmann 等：多数 LLM 仍欠训练。

**5.3 BIG-bench-lite (24 tasks)**
- 0/1/3-shot = 13.31/14.91/15.12；zero-shot 超 GPT-3 175B 与 PaLM 540B（4× 大）。归因于双向注意力 + MIP。
- 局限讨论：few-shot 增长（13.31→15.12）远小于 GPT-3（4.35→13.18）。作者推测：①双向注意力零样本已近上限；②现有 MIP 范式只含 zero-shot 预测，偏向 zero-shot、弱 few-shot；建议用多变体 shot 的 in-context 样本；③PaLM 增长快源于更强数据（私有高质量语料）。

**5.4 中文 CLUE/FewCLUE**
- 12 任务 zero-shot 全面超 ERNIE Titan 3.0 260B（最大中文单语模型，图8）；DRCD 与 CMRC2018 两个抽象式 MRC 提升 ≥260%，因预训练目标天然契合 abstractive MRC 形式。中文任务未纳入 MIP（跨语种即为 zero-shot 迁移）。

**5.5 推理落地（附录B.5/B.6 支撑）**
- FasterTransformer (C++ 实现) 替代 PyTorch；同单 A100 node 上比 BLOOM-176B/Huggingface 解码快 7–8.4×。
- INT4 权重量化（激活 FP16），运行时转回 FP16；相比 INT8 再省一半显存至 70GB，可在 4×RTX 3090 Ti (24G) 或 8×RTX 2080 Ti (11G) 推理。
- 附录：另配合 BMInf 在单 V100/3090 上异步流水式换页推理。

## §6 局限

1. **few-shot 提升弱**：few-shot 增长远不及 GPT-3，MIP 偏向 zero-shot 造成 in-context few-shot 相对偏弱（作者自述）。
2. **评测范围受限**：因纳入 MIP，作者自设 zero/few-shot 选集标准（固定标签任务不强评、需明显 domain transfer），并过滤潜在污染数据集（LAMBADA/CLUE 13-gram 最小重叠；Pile/MMLU/BIG-bench held-out 或晚于语料抓取）——即部分基准未全量收录，报告有选择性。
3. **训练成本极高**：96 台 DGX-A100 仅 60 天访问权、400B tokens，复现昂贵，作者承认现阶段难以复现预训练。
4. **GPT-3 175B 数据为转引**：Pile/TABLE 部分结果直接取自已发表文献（Jurassic-1 等），非本组复测；OPT-175B 结果因申请数月未获批而缺席（正文脚注），可比对象不完整（如 PaLM 540B 3-shot 结果缺失，附录表）。
5. **稳定性仍非零**：最终训练仍出现 3 次后期 loss divergence，仅靠 EGS 进一步收缩缓解，依赖人工介入与经验，并非完全自动稳定。
6. **激活异常值**：GLM-130B 激活含 ~30% outlier（远高于 OPT/BLOOM 约 0.1%），未做激活量化，INT4 仅限权重，性能与通用性之间存在未完全解决的权衡。
7. **只含单一规模（130B）与单一架构变体**：作者承认限于算力无法系统性探索多种架构设计（LLM 架构价格高昂）；RoPE 的 C++ CUDA 算子曾遭精度问题被弃，部分工程细节未完全公开。
8. **伦理/安全性仍存隐忧**：尽管开放权重被认为促进安全性研究，作者在 Ethics 部分明确承认模型可被用于垃圾短信欺诈、政治宣传等；若缺乏对齐（alignment）与安全审查，开放 100B 级模型也带来滥用风险（本报告就"开源爆发"节点语境下的风险定性补充，非原文明示结论）。

### 附：训练问题时间线要点（图21，附录B.10，2021.12–2022.7 精要）
- 2021.12 提出 100B 开源 dense GLM愿景；调查 GPT-3/Gopher 公开训练资料有限。
- 2022.2 训练速度慢 → kernel/fused operator 优化；icetk SentencePiece unigram。
- 2022.3 checkpoint 恢复失败（分布式 dataloader 状态种子问题）；batch 过大 (≤12000) 伤收敛；突破 6000 节点（调 Linux TCP 参数）。
- 2022.4 输入 embedding 梯度范数大 (170+) → embedding norm 与 gradient shrink 近似等效；RoPE vs ALiBi 取舍（ALiBi 慢）；定 130B 规模（适配 40G 节点单卡推理）。
- 2022.5-6 注意力 softmax 用 FP32 → 成功；PB-Relax 变多余；后期尖峰用缩减梯度 shrink 因子到 0.1、降 LR、跳噪声 batch 缓解。
- 2022.6-7 调整 pipeline parallel 为普通 parallel 用于单 A100 推理；实现 P-Tuning/P-Tuning v2；配合 BMInf 单 V100/3090；fine-tune 用 32-way model parallel。
