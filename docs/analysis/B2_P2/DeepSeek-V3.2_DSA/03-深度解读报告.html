DeepSeek-V3.2 深度解读：DSA 稀疏注意力与规模化 Agentic RL 的工程化合流

Pushing the Frontier of Open Large Language Models —— 唯一架构改动换来 O(L²)→O(Lk)，四项 RL 稳定技术与四类 Agent 管线支撑开源旗舰的又一次跃迁

arXiv:2512.02556v12025-12-02 · 23 页DeepSeek-AI · 200+ 作者数据依据：00-源数据提取.md

◆ 摘要

DeepSeek-V3.2 相对上一版 V3.1-Terminus 的唯一架构改动是通过继续训练引入 DeepSeek Sparse Attention（DSA），将核心注意力复杂度从 O(L²) 降至 O(Lk)（实验取 k=2048），经「dense warm-up（2.1B tokens）→ sparse training（943.7B tokens）」两阶段完成适配，达成性能 parity（ChatbotArena Elo 接近、标准基准相当），并大幅压缩长上下文推理成本。后训练侧，以六域专家蒸馏 + GRPO 单阶段混合 RL 合并推理、agentic 与人类对齐三目标，提出无偏 KL 估计、Off-Policy 序列掩码、KeepRouting、KeepSamplingMask 四项稳定技术，支撑 1,800+ 环境、85,000+ 复杂 prompt 的四类 agent 数据管线，使 thinking 内嵌工具调用成为原生能力。V3.2-Thinking 在 AIME2025 得 93.1、SWE-Verified 73.1、BrowseComp 51.4（context management 后 67.6*）；Speciale 变体 AIME25 达 96.0、IMO2025 取 35/42 金牌，但 token 效率仍显著逊于 Gemini-3.0-Pro；128K 上下文偏紧与冗余自我验证构成主要边界。

一问题定位

三大缺陷诊断：差距为何重新拉开

论文 Introduction（p1–2）将开源与闭源差距拉大的根源归结为三点：架构效率——dense attention 复杂度 O(L²)，长上下文下成为推理经济瓶颈；post-training 算力——其投入已超过预训练成本的 10% 且性能随 RL 预算持续提升，能力增长重心正从预训练向 RL 迁移；agent 泛化——真实工具使用需要「环境规模 × 任务质量 × RL 稳定性」的系统工程。

（推断）三者并非并列：架构效率决定单位 token 服务成本下限，post-training 决定能力上限增速，agent 泛化决定能力能否兑换为价值——V3.2 的三组设计恰好一一回应。

为什么把注意力稀疏化作为突破口

（推断）Agent 时代负载结构根本改变：搜索结果、代码仓库、工具 JSON 都以超长上下文涌入模型。若注意力成本不降，agent 任务永远进不了经济区间。因此架构改动的验收标准不是提升质量，而是在不损质量的前提下压扁成本曲线——这解释了论文为何把 DSA 目标设为 parity 而非增益。

问题定义的克制性

DSA 的定位是「无损近似」：长上下文收益主要体现为效率而非质量；独立评测 AA-LCR 高 4 分、Fiction.liveBench 多指标胜出属外部佐证且幅度有限。这种克制反映了成熟的工程价值观：渐进改造的红利可以直接兑现，而激进换血的风险由全社区承担。

二概念内核

Lightning Indexer + 细粒度 token 选择

DSA 的思想是「先用便宜的打分器找出值得注意的 token，再只在选中集合上做完整注意力」。索引分数定义为：

I(t,s) = Σ(j=1→H_I) w_I(t,j) · ReLU( q_I(t,j) · k_I(s) )
  • ReLU 纯为吞吐考虑；head 数少且可全程 FP8 实现——indexer 虽形式上仍为 O(L²) 全序列扫描，但计算量远小于 MLA 主注意力；
  • 按 top-k 索引分逐条选取 KV 条目，是 token 级精确选择（区别于 NSA 的块级选择，引 Yuan et al. 2025）。

MLA(MQA 模式) 实例化

MLA 的 KV 条目即 latent 向量，每个 latent 向量被该 query token 的所有 query head 共享，满足内核级 KV 复用要求。（推断）稀疏化只发生在「读取多少」维度而不动「存什么」维度，这正是 DSA 能以续训而非从头训练落地的结构性原因。

复杂度账本与短序列兜底

主注意力 O(L²)→O(Lk)；indexer 保持 O(L²) 但常数极小。短序列 prefill 用 masked MHA 模式模拟 DSA 以获得更高效率。（推断）L 不大时稀疏调度开销可能超过收益，「长短双模式」切换对用户透明，具体阈值未披露——这是生产级系统的标志。

Thinking in Tool-Use 与 Speciale

V3.2 提出在推理过程内部嵌入多次工具调用：思维链中途发起工具请求，拿到结果后继续推理。Context Management 规则：仅在新 user 消息进入时丢弃历史推理内容；仅追加 tool 输出则完整保留推理链。Speciale 则是竞赛特化变体（仅推理数据 + 降低长度惩罚 + DeepSeekMath-V2 数据/奖励），与正式版构成同一基座上的「效率-精度前沿」两端——正式版追求更少 token 下够用的精度（如 AIME25 16k vs 24k token 对比 K2-Thinking），Speciale 反向以 77k token @ Codeforces 换更高峰值精度。

三方法拆解

两阶段稀疏化续训

起点为已扩至 128K 上下文的 V3.1-Terminus checkpoint，续训数据分布与其长上下文扩展数据完全一致：

阶段机制规模学习率
Dense Warm-up冻结除 indexer 外全部参数；主注意力跨头求和 + L1 归一化作目标分布，KL 散度对齐（式 3）1000 步 × 16 × 128K = 2.1B tokens1e-3
Sparse Training启用 top-k=2048，全参适配；indexer 只在选中集合 S_t 上 KL 对齐（式 4）；indexer 输入从计算图 detach——indexer 仅由 KL 损失训练、主模型仅由 LM loss 训练；post-training 全程稀疏15000 步 × 480 × 128K = 943.7B tokens7.3e-6
（推断）Detach 的意义：若允许主任务梯度流入 indexer，可能学出「配合主模型偷懒」的退化打分；切断梯度后 indexer 始终锚定 dense 分布这一外部真值——职责清晰、故障域隔离，且 warm-up 阶段可随时中断、服务指标零回退。

Scaling GRPO 四项稳定技术

  • Unbiased KL Estimate：原 K3 estimator 在 π_θ≪π_ref 时给低概率 token 无界放大的提升权重→噪声梯度累积致不稳；经当前/old 策略重要性比校正后 KL 梯度无偏。实践上数学等域弱 KL 或免 KL 更优。
  • Off-Policy Sequence Masking：rollout 大批拆多 mini-batch 更新 + 训推框架差异双重 off-policy 源；对 A<0 且平均 log-ratio>δ 的负序列整体 mask；π_old 直取推理框架返回概率。直觉：「模型最应从自己的错误中学习」，高度 off-policy 的负样本有害。
  • KeepRouting：MoE 训推路由不一致引发激活子空间突变；训练期强制复用采样期路由路径（自 DeepSeek-V3-0324 起 pipeline 标配）。
  • KeepSamplingMask：采样期 top-p/top-k 截断 mask 保留到训练期，修复重要性采样前提破坏；与 top-p 组合可维持 RL 中语言一致性。
（推断）四项分别封堵梯度噪声、off-policy 方差、MoE 不一致性、动作空间漂移四类崩塌模式；共同特征是「工程修补而非算法发明」，可复制性强，是对开源 RL 社区最有公共价值的部分之一。

冷启动、思考管理与专家蒸馏

冷启动用 system prompt 指示模型在推理过程中内嵌多次工具调用，偶尔产出目标轨迹作为 RL 种子。六个专家域（数学/编程/通用逻辑推理/通用 agentic/agentic coding/agentic search，均双模式）各自从同一 base checkpoint 大规模 RL，专家产出蒸馏数据训练最终 checkpoint（略低于专家，RL 后差距消除）；偏好对齐采用 GRPO 单阶段合并 reasoning+agent+human alignment，规避多阶段灾难性遗忘。（推断）「专家探索→蒸馏回收→单阶段合并」是用并行专家换探索多样性、再收敛回单一模型的拓扑，与 Speciale 另起炉灶冲峰值形成完整策略光谱。

五批判性分析

① Parity 的隐藏成本由长尾用户承担。约 20%+ 的 BrowseComp 测试样例超出 128K，需 context management 补救才有 67.6*（裸分 51.4）。「无损」只在窗口内成立，窗口外用户须自建补救层。
② 冗余自我验证未被根治。频繁生成过长验证轨迹，MCP-Mark GitHub/Playwright 类任务常撑爆限窗拖累得分（作者列为 future work）。与 Speciale 靠堆 token 冲精度互为镜像：「多想」在受限窗口是负债、在开放预算是资产。
③ Token 效率存在代差。Speciale 精度虽超 Gemini-3.0-Pro 但 token 效率仍显著劣于；服务边际成本主要由输出 token 决定，劣势会在定价上被放大。
④ 框架兼容性是隐性生态税。context management 与 Terminus 不兼容：TerminalBench 46.4 须 ClaudeCode 框架，Terminus non-thinking 仅 39.3——近 7 分差距本质是「协议红利」而非「模型红利」，RooCode 类框架同样无法受益。
⑤ DSA 是止损不是增益。绩效主张建立在「不变得更差」之上；短上下文场景收益近零（甚至要走 MHA 模拟路径）。（推断）价值高度集中于 32K–128K 区间，具体边界论文未给出。
⑥ Indexer 单点依赖。（推断）top-k 质量完全系于 indexer 打分精度，KL 对齐只保证分布意义上接近 dense，错误排除强相关 token 的风险由 LM loss 隐式吸收；论文未提供选择命中率/关键 token 召回率的微观度量。
⑦ k=2048 普适性未经检验。（推断）检索型任务（少量 needle）与聚合型任务的最优 k 理应不同，固定 k 可能在两类任务间留下未榨取的余量。
⑧ 评测敏感性信号。HLE 官方模板 23.9 vs 自报模板 25.1，2.1 分之差提示旗舰分数带上评测协议足以改变排名叙事。
⑨ 合成环境的模拟鸿沟。General 环境全合成（沙盒数据库+自造工具），search/code prompt 亦非来自真实用户交互（p10 自述）；实验室泛化与野外泛化的距离需真实流量回归测量——目前缺席。

六启示与影响

① 「唯一架构改动」的渐进演进范式。把激进改动封装在可续训、可验证 parity 的最小增量里（仅动注意力一处，943.7B tokens 完成切换），让权重、推理栈、微调脚本等生态以最低成本跟进。
② Detach 式模块解耦是稀疏化训练的通用钥匙。（推断）「辅助模块只吃 KL/蒸馏监督、主干只吃任务损失」可推广到一切预测器+消费者结构（推测器/路由器/检索器），以牺牲端到端联合优化换取稳定性与故障可归因性。
③ RL 稳定技术四件套进入公共领域。无偏 KL、负样本 off-policy 掩码、KeepRouting、KeepSamplingMask 都是「一行描述就能懂」的工程修补，任何试图把 GRPO 推到千卡规模的团队都应视作 checklist 级默认配置。
④ 「难解易验」是合成环境四字心法。solution function 锁死工具接口、verification function 保证可判定、逐步加难度、pass@100>0 过滤——可直接移植到数学、代码、规则类可验证领域（推断：主观评价类任务适用性有限，verifier 难以形式化）。
⑤ 思考链管理将成为框架层标准议题。「新 user 消息才丢推理、tool 追加则保留」实质是把 KV 显存变成可编程资源；谁控制消息流协议谁就控制 thinking 模型的实际发挥——Terminus 与 ClaudeCode 近 7 分差距即是明证。（推断）推理框架消息协议标准化将被加速。
⑥ 效率-精度双产品线是新形态。正式版压 token、Speciale 放开冲峰值的二元布局，暗示旗舰发布将标配「经济档+峰值档」，同一基座覆盖全谱系需求。
⑦ 开源竞争的主战场迁移。当 SWE-Verified 73.1 等硬基准逼近闭源第一梯队，竞争焦点从「能力有无」转向「每 token 能力的单价」——DSA 的 O(L²)→O(Lk) 曲线与 H800 实测账单，正是这场成本战争的第一次公开报价。
