## §4 方法细节

**问题设定**（§3）：逐层（layer-wise）后训练量化。对线性层 Wℓ 用 m 条校准数据的输入 Xℓ，求解 argmin_Ŵ ‖WX−ŴX‖²₂（Eq.1），量化网格预先固定、单个权重可自由移动。

**基础：OBQ 回顾**（§3）：逐行独立贪心量化——每步选当前量化误差最小的权重 w_q（Eq.2，基于 Hessian 逆 [H_F⁻¹]_qq，其中 H_F=2X_F X_Fᵀ），量化后按 δ_F 补偿性更新剩余全部未量化权重，经一步高斯消元维护 H⁻¹（Eq.3）。缺点：复杂度 O(drow·dcol³)，ResNet-50（25M 参数）需 ≈1 小时，无法扩展到十亿级。

**GPTQ 三步改造**（§4）：
1. **任意顺序洞察（Step 1）**：发现 OBQ 的贪心选序相比任意固定顺序的收益很小（大层上尤甚——误差大的权重留到最后时可用于补偿的其他权重已所剩不多）。据此改为**所有行按同一列顺序量化**：F 集合与 H_F⁻¹ 对所有行统一（H 只依赖输入 X 不依赖权重），每列只做一次 H⁻¹ 更新而非每权重一次。
2. **懒批量更新（Step 2）**：直接实现算术强度低、被内存带宽瓶颈卡死。观察到第 i 列的最终舍入决策只受施加于该列自身的更新影响 → 以 B=128 列为块"懒"积攒块内更新，块完成后才用多权重版 Eq.4/Eq.5 做全局更新。不减少理论计算量但大幅提高 GPU 利用率，实际再获一个数量级加速。
3. **Cholesky 重构（Step 3）**：大规模下数值误差累积可致 H⁻₁ indefinite，引发错误方向的激进更新甚至任意坏的层量化（数十亿参数模型几乎必然在若干层出现）。注意到每次所需仅为 H⁻¹ 的对应行（自对角起），其行消除过程本质即 Cholesky 分解 → 用数值稳定的 Cholesky kernel **一次性预计算全部所需信息**，配合 mild dampening（λ=对角均值的 1%），稳健且额外提速。

**完整算法**（Algorithm 1, p.5）：输入 H⁻¹=(2XXᵀ+λI)⁻¹ 与块大小 B；先对 H⁻¹ 做 Cholesky 分解转置存储；外层按块推进，内层逐列量化 Q:,j 并把误差 E 按 [H⁻¹]_jj 缩放回写更新块内后续列，块结束时一次性更新所有剩余权重。

**工程实现**（§Setup, p.6）：PyTorch + HuggingFace；均匀 per-row 非对称 min-max 量化网格（同 LLM.int8() 的 RTN 基线网格）；一次只加载 1 个 Transformer block（6 层）进显存累积 layer-Hessian 再量化，且下一块的输入取自**已部分量化模型**的实际激活（精度略升、成本可忽略）。专用 CUDA kernel 做 quantized-matrix × full-precision-vector 乘法（推理时动态反量化），无需激活量化。

## §5 实验结果要点

- **小模型对标 SOTA PTQ**（Table 1）：ResNet18/50 上 4-bit 与 AdaRound/BRECQ/OBQ 持平（如 RN50 4bit 75.71 vs OBQ 75.72），3-bit 略逊（74.87 vs BRECQ 75.32），显著快于它们；BERT-base/OPT-125M 上 3-bit 反超完整贪心 OBQ（53.85 vs 69.32 PPL，Appendix Table 8）。耗时 <1 分钟 vs OBQ ≈1 小时。
- **大规模语言生成**（Fig.1, Tables 3/4）：整个 OPT 家族（125M–175B）与 BLOOM 家族（560M–176B）压至 3/4 bit。规律：模型越大越易量化（例外 OPT-66B，footnote 2 归因于早期层大量 dead units）；RTN 在 3-bit 全面崩溃而 GPTQ 保持合理 PPL。
- **175B 级详评**（Table 5）：4-bit 各任务 PPL 劣化 ≤0.25；3-bit 仅损 0.3–0.6（>5× 压缩）；LAMBADA 上量化后甚至高于 FP16。
- **实用加速**（Table 6, A.2.2）：生成式 batch-1 场景受内存带宽约束，反量化 kernel 减少内存访问带来 3.24×/4.53× 端到端加速；FP16 基线与量化模型的通信开销 <5%，加速几乎全部来自 kernel；大 batch 场景可先解压缩再算矩阵乘（A100 上 <1.5ms，相对 FC2 层 76ms 开销极小）。
- **零样本任务**（Fig.3, Appendix A.4）：LAMBADA/PIQA/ARC-easy/ARC-challenge/StoryCloze 全谱系验证同一结论——4-bit 下连 RTN 都尚可，3-bit 下 RTN 崩溃而 GPTQ 接近 FP16。
- **极端量化**（Table 7）：分组是 2-bit 可用的关键——g128（≈2.2 bit）PPL 增幅 <1.5，g32（≈2.6 bit）仅 0.6–0.7；group-size 8 时可做 ternary (-1,0,+1)，OPT-175B 达 9.20 PPL，适合 FPGA 类定制硬件。

## §6 局限（§6 Summary and Limitations, p.9 + Ethics）

1. **只有内存搬运加速，无计算量削减**：加速来自减少内存移动；因主流硬件不支持混合精度操作数（FP16×INT4），实际乘法本身不提速。
2. **不含激活量化**：目标场景中激活非瓶颈；需与正交技术（如 ZeroQuant）结合。
3. **kernel 适用面窄**：针对低 batch 生成式推理（memory-bound 的矩阵-向量积）设计；非生成或大 batch 应用只能走"解压后计算"路线。
4. **C4 任务非严格 zero-shot**：校准数据采样自 C4 训练集，故 C4 困惑度评测存在轻微数据泄漏（论文在 Table 11/12 标题诚实标注）。
5. **精度-位宽-模型规模的非平凡权衡**：压缩并非自然免费，中等规模模型 4-bit 退化明显（Fig.4 显示 grouping 可缓解）；OPT-66B 因 dead units 成为异常难点。
6. **伦理关注点**：压缩让超大模型更易部署（双刃剑）；现有困惑度指标未覆盖偏差等次级影响，作者呼吁后续研究。
