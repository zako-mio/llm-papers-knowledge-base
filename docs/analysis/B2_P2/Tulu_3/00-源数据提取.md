## §4 方法细节

### 数据（§3）
- **公开数据来源**：广泛搜罗 permissively licensed 公开数据，严格核查 provenance 与 license。明示排除 ShareGPT（法律来源存疑），用 WildChat 替代；剔除 UltraFeedback 相关子集；不用 Helpsteer2（其 prompt 含 ShareGPT）。
- **合成数据**：persona-driven（Chan et al. 2024），用 Persona Hub ~250K personas + 数据合成 prompt（如"create a coding problem"）引导 LLM 按 persona 视角生成；用 GPT-4o-2024-08-06 生成。
  - 精准指令遵循：手写 1-2 示例/约束（共 33 个 verifiable 指令种子），GPT-4o 生成，共 29,980 对。
  - 数学/代码：zero-shot GPT-4o 生成问题，math 多步解用 GPT-4o、Python 用 claude-3-5-sonnet。数学 ~220K、编码 35K。
  - 安全/拒绝（noncompliance）：基于 contextual noncompliance taxonomy（Brahman et al. 2024），含 incomplete/unsupported/indeterminate/humanizing/unsafe。
- **去污（decontamination）**：n-gram 匹配最有效（embedding 难区分分布相似与真改述）；用 8-gram，判据：>50% test token 与同一训练实例共享 8-gram；训练集任实例与 >2% 的评估实例重叠即判污染，从 unseen 套件中删；保留注：去污后可逆（附 example 处理）。

### SFT（§4）
- 从 prompt 到 SFT 数据：为 prompt 生成高质量完成。
- SFT Mix 含公开（UltraFeedback 41,635、OpenAssistant 88,838、No Robots 9,500、WildChat GPT-4 100,000、FLAN 89,982 等）+ persona 合成（Persona MATH 149,960、Persona GSM 49,980、Persona Algebra 20,000、OpenMathInstruct 2, NuminaMath-TIR 64,312、Persona Python 34,999、Evol CodeAlpaca 等）。
- Batch aggregation、关键实验优化 mix。

### Preference Finetuning（§5）
- 用 DPO；preference 数据来自 on-policy 对比（Tülu 3 SFT 完成 vs 其他 LM 输出）。
- Preference mix 按模型 8B/70B/405B 分别发布。

### RLVR（§6）—— 核心创新
- 定义：把 RLHF 的 reward model 换成 deterministic 验证函数 v(x,y)：答案正确给 α、否则 0。
- 目标：max_πθ E[R_RLVR] = v(x,y) − β·KL[πθ‖π_ref]，PPO 优化，α=10。
- 领域：数学（GSM8K/MATH）+ 精准指令遵循（IFEval）。
- **工程细节**：① value model 从 general RM 初始化；② RM/RL 训练 dropout=0；③ 每轮间 shuffle（~13 epoch）；④ 无 EOS 给 -10 penalty；⑤ advantage whitening。
- 探索：single-task（GSM/MATH/IFEval 分别）、value model init 消融、RM 分数+verifiable 组合、从 weaker model 起步。

### 405B 规模（§8.1）
- 32 节点 256 GPU；NCCL timeout/同步问题、硬件故障重启。
- RLVR：vLLM 16-way TP 推理 + 240 GPU 训练，每轮 weights 用 NCCL broadcast 同步；inference ~550s / 权重转移 ~25s / 训练 ~1500s；用 8B value model 省算力。
- 因 GSM8K 在 SFT+DPO 已饱和、IFEval 收益小，405B RLVR 只用 MATH train 集。

## §6 局限

1. **长上下文与多轮不足**：数据较短（平均 2.4 turns，多数样本 <2,048 tokens），未覆盖长上下文/多轮。
2. **多语言局限**：聚焦英语数据与评估（仅纳入多语 Aya 数据集），忽视其他语言。
3. **工具/Agents**：未训练/评估工具使用与 agent 框架集成。
4. **计算约束**：405B RLVR 仅 75 步（compute 限制），MATH 未观察到饱和，可能进一步提升；value model 用 8B（未来可探索更大 value model 或 GRPO 等免价值模型算法）。
5. **RLVR 目标有限**：仅涉及解析式可验证领域（数学/指令遵循），复杂 verifier（如代码执行反馈）留待未来。
6. **负结果**：多种方法未进入最终配方（Online DPO、Rejection Sampling）——on-policy 受限提效甚微；公开判官模型对选最佳响应较弱。
