## §4 方法细节

**MoE 设计（§2.2.1）**：细粒度专家提高路由组合多样性、降低设备利用率方差；sigmoid gating 去除 softmax 零和约束允许多专家高置信同激活；可学习 expert bias 隐式调负载，大幅削减辅助均衡损失。

**Attention 抉择（§2.2.2）**：回归 full attention。三理由——评测困难（hybrid 在标准基准看似持平但大规模下多跳推理赤字显现，proxy 指标相关性脆弱）；基础设施差距（线性注意力内存受限训练、低精度敏感、缺 prefix cache 与投机解码集成）；数百亿~万亿 token 的 hybrid SWA 对照在检索/多跳/ICL 全面劣化。作者仍认为亚二次注意力长期值得投入。

**MTP（§2.3）**：预训练单模块 K=1（loss 权重 0.3→0.1）；decay 相权重复制扩至 K=3 支持多步投机解码（复制初始化收敛快且不扰动主模型；先冻结主模型训 MTP 再联合训练，纯 MTP-only 训练终态更差）。推理时草稿由主模型单次前向验证。

**Post-training 数据（§4）**：
- SWE-scaling 六阶段 GitHub PR 流水线：采集过滤→agent 合成多语言 Docker 环境（编译语言构建编排/异构测试接口/仓库结构变异三难点）→PR 打标路由→任务抽取验证→模型校验补全→变换扩充（bug 注入、commit 合并、SWE-Test 反演写失败测试、代码评审近似可验证任务）；奖励按类型定制（bug fix 用 F2P/P2P，性能优化用显著差异验证）；跨 10+ 语言。
- AppDev 专家在环：专家元查询模板注入生产级技术模式 + MinHash 去重 + LLM-as-judge 三维质检（TechStack 合理性/Feature 可行性/需求清晰度）；prompt distillation 使最佳实践内化为默认行为；Agent-as-a-Verifier 三层验收（Execution 硬门禁→Playwright Interaction→Visual Aesthetics），带证据二值判定。
- Terminal-Gym：StackOverflow 全库按标签与属性筛选→查询改写分级（仅留 top2 档）→三阶段合成（环境+测试生成自愈迭代 / query evolution 抹去提示+统一测试防过拟合 / 参考求解器通过率难度校准）；正演进为零人工 Anything2Docker 并扩展 CVE-Factory。
- Cowork 四域共享范式（真实可运行工作区 + 扰动脚手架蒸馏教师轨迹 + 工件对齐验收信号）：deep search 的 guide-and-rewrite 强制证据落地；knowledge worker 以 GDPval 为锚层次合成 + 多轴 rubric + 类型化清洗（清除伪造数据/引用）；金融 evidence-driven 反推 + workbook-walk 轨迹逆序出题、外部引擎重算公式做确定性数值判分；幻灯片双流生成/编辑 + 视觉打分器 + 混入备选渲染库防工具过拟合。
- Reasoning 三轴 scaling（query/response/training-side 配比动态分配至弱项）+ 全链路质检。
- Role-play 形式化 {Worlds}×{Stories} 条件生成，Role-Play Bench 离线指标强相关在线参与度；dispersion sampling 四轴 + Best-of-N + 分段 LLM 重写；RLHF 信号因果推断去噪 + 分层偏差移除 + 熵监控防 reward hacking。

**SFT（§5）**：interleaved thinking 轨迹（思考-行动-观察交织于同一 trajectory，非整块 CoT），大规模拒绝采样 + 多级清洗，四域 chat/reasoning/code/cowork。

**RL 算法（§6.1）**：MDP M=(S,A,T,R,γ)，环境边界画在生成接口（工具/harness/CM/子 agent 皆环境）；(s_t,a_t) 为原子策略梯度样本，credit assignment 在 episode 级经 reward-to-go + trajectory baseline 完成。CISPO：IS ratio 非对称裁剪至 [0, 1+ε_high]（上限抑制过大更新、零下限允许激进降权），stop-gradient 保证重要性权重只调制梯度幅值的一阶稳定更新。复合奖励 r_t = α·r_process + β·r_speed + r_perf，完成时间相对奖励显式激励并行工具调用/子 agent。Mixed-domain RL：每步四域混采，跨阶段调节域配比（前期基础后期 agent）、上下文长度（per-domain curriculum）、难度分布，同时规避灾难性遗忘与负迁移。

**Forge 基础设施（§6.2）**："不可能三角"=吞吐×稳定×agent 灵活性，目标函数 Effective Agent Training Yield=Throughput×SampleEfficiency s.t. 梯度方差与偏差约束。三解耦模块：Agent Side（纯轨迹生产者）/ Middleware（Gateway Server + DataPool 异步存储）/ Training+Inference Side（Rollout Engine + Train Engine 权重同步）。白盒 agent 注册 CM 操作供训练期精确重建状态分布；黑盒 agent 仅凭外部 (s,a,o) 流训练，已验证数百种 scaffold、数千种工具格式。Windowed FIFO W=0.3N：窗口内贪婪消解 HoL 阻塞、窗口间严格 FIFO 保分布一致性。Prefix tree merging 共享前缀一次前向 + 元数据拆树逐样本计损，无损 40× 加速并解锁更长序列更大 batch。推理加速三项：MTP 草稿与 RL 策略以 top-K KL 协同训练保持接受率、异构 prefill-decode 分离调度、DFS 支撑的全局 L3 KV cache pool（成本感知路由平衡排队延迟与缓存迁移）。

**Agentic 机制（§7）**：Interleaved thinking 作为一等公民——τ=(r₁,a₁,o₁,...,r_T,a_T,o_T)，reasoning state persistence 将完整思考块保留进历史（H⊕[assistant(r,a)]⊕[tool(o)]），消融显示深搜索/SWE 类长程任务收益最大；Plan-Act-Reflect 循环赋予自校正/样本效率/可调试性。Self-evolution：Model Iteration System 秉持 "humans steer while models build"，Agent Harness 本身由 M2.7 生成零人写代码；双环工作流中人类评审触发大迭代、agent 自主续跑有界分析；递归 scaffold 升级案例中 100 轮自主迭代引入 loop detection 等机制获内部评测 +30%。

## §5 实验结果要点

- **评测协议（§8.1）**：闭源基线取各自最强推理配置（Opus/Sonnet 4.6 extended thinking、GPT5.4 与 Gemini 3.1 Pro high effort）；M2.7/M2.5 开 thinking + interleaved 协议；temperature 1.0 / top-p 0.95；SWE 类统一 Claude Code 脚手架（GPT5.4 用原生 CodeX），4 trials 取均值；Terminal-Bench 2.0 用 Terminus-2 XML + verified 数据集；MLEBenchLite 每任务单 A30 跑 24h ×3 独立试验取奖牌率均值；AIME2026/GPQA 等走 ArtificialAnalysis Index v4.0 无工具 pass@1。
- **编码 agent**：SWE-bench Pro 56.2 与旗舰带内（Sonnet 57.3/Gemini 57.7）；Multi-SWE-bench 52.7 参比最高；NL2Repo 较 M2.5 +13 分体现全栈仓库数据增益。
- **应用开发**：VIBE-Pro 55.6 与最强闭源持平；HyperTask 67.6（+8 vs M2.5）——作者视 AppDev 为"~10B 激活 + 数据/AaaV 奖励逼近十倍激活旗舰"论点最干净的验证域。
- **Cowork**：BrowseComp 77.8 / WideSearch 75.2 / RISE 64.3（系列内 +14）；Excel 域增益最大（MEWCv2 +13.5、FinanceModelingPro +23.2）但绝对值仍落后 Gemini/GPT（63.3 vs 76.5/77.2）。
- **推理知识**：AIME2026 94.2、GPQA-D 89.8 处前沿带；HLE 28.0 明显低于 Gemini 41.6；MMLU-Pro 81.8 为参比最低。
- **自进化案例（§8.3）**：22 项竞赛 × 24h 自主迭代，最佳 run 9 金 5 银 1 铜，三 trial 平均 66.6% 追平 Gemini 3.1 Pro；定性观察为模型主动调试自身训练脚手架、改配置文件、数百轮迭代。

## §6 局限

1. **绝对性能仍有差距**：Terminal-Bench 2.0（57.0 vs Gemini 75.1）、HLE（28.0 vs 41.6）、MMLU-Pro（81.8 为六模型最低）、BrowseComp（77.8 vs GPT 84.0）等多数单项并非第一，"接近最强闭源"是带内水平而非超越。
2. **评测依赖内部基准**：NL2Repo/VIBE-Pro/HyperTask/MMClaw/MEWCv2/FinanceModelingPro/RISE 均为内部构建，外部不可复核；部分基线分数引自官方报告而非同脚手架复测。
3. **第 1 页图表页文本层损坏**（本 PDF 提取乱码），Figure 1 的 headline 数字无法从文本核验，只能依赖正文复述。
4. **Self-evolution 的边界未量化**：30%-50% 负载吸收与 +30% 内部增益均为内部口径；人类评审触发点、失败模式与安全护栏仅定性描述。
5. 训练成本/GPU 规模、推理价格等部署经济性数据未披露；MTP 扩展与 Forge 加速的实际端到端收益未给出统一口径的对比表。
