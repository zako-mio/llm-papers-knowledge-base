## §4 方法要点

### 4.1 统一 RL 环（白盒/黑盒一致的 Middleware 架构）
- **三层解耦**：Agent Side（业务逻辑：Context Management、推理链，对底层训练/推理机制无感知）→ Middleware Abstraction Layer（**Gateway Server** 以标准协议隔离模型实现细节；**Data Pool** 异步收集轨迹、解耦生成与训练、允许灵活数据处理与批策略）→ Training/Inference Side（Rollout Engine 高吞吐生成 + Train Engine 消费 token 序列更新策略并与 Rollout 引擎同步）。
- **白盒路径（CM-as-Action）**：将 Context Management 显式建模为驱动状态转移的动作，St→St+1 的转移隐式封装上下文切换逻辑，使推理期 CM 与 RL 训练分布对齐，解决 inference-training mismatch 与 Context Rot；模型由此内化"状态关键 token"优先的推理模式。
- **黑盒路径（非侵入泛化）**：agent 仅需把请求路由到 Gateway，框架自动完成数据采集与训练；兼容任意上下文操作（memory compression、history rewriting）与复杂内部 loop（Deep Think、Multi-Agent）；跨异构 scaffold 保持稳定提升。

### 4.2 工程优化三板斧
1. **Windowed FIFO 混合调度**：在全局严格顺序与纯贪心之间取中——滑动可见窗口 [Ti, Ti+W−1] 内即时取任何已完成轨迹（缓解 HoL blocking），窗口边界外即使完成也禁止取用（强制等待慢任务、防止训练分布向"快而简单"样本漂移）；窗口随队头消费而前移。
2. **Prefix Tree Merging**：针对多轮对话样本高共享前缀（含 CM 造成的非常规公共前缀），在样本级将多个 completion 合并为单棵前缀树；借注意力原语（Magi Attention）保证与标准 forward 数学一致；forward 后按元数据拆树正常计算 loss。宣称 **40x 训练加速**且 loss/metrics 零影响。
3. **极限推理加速**：MTP 头投机解码（持续 Top-K KL 对齐 RL 后策略，维持高接受率）；异构 PD 分离（消除混合 MoE 调度中的 PD 干扰，各自独立并行度，兼顾全局吞吐与长尾延迟）；DFS 支撑的全局 L3 KV Cache 池（cost-aware 调度最大化 group-level rollout 的前缀缓存命中率）。

### 4.3 算法层
- **CISPO** 作为核心策略优化算法（本文未展开公式文字，公式以图片给出），面向 long-horizon 场景适配。
- **统一混合域训练**替代多阶段串行 RL：Reasoning + General QA + Agent 同池混训，避免域间干扰与性能退化。
- **复合奖励**：过程奖励（中间行为密集反馈）+ 相对完成时间奖励（把 wall-clock 写进优化目标，激励工具并行与子代理并发）+ Reward-to-go 方差缩减，共同应对 200k 窗口下的 credit assignment 与稀疏奖励问题。
