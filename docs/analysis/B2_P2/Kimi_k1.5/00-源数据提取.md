## §3 核心主张与关键数字表

**核心主张**：Kimi k1.5 是通过强化学习（RL）训练的多模态 LLM。关键配方是**长上下文缩放**（把 RL 上下文窗口扩到 128k）+ **改进策略优化**（无价值函数/无 MCTS/无 process reward model 的极简框架，用 online mirror descent 变体）。用长-CoT 训练出的推理能力可通过 long2short 转移给短-CoT 模型，在少 token 下也达到 SOTA。系统在 AIME 2024、MATH-500、Codeforces、MathVista 上达到或匹配 OpenAI o1。

## §4 方法细节

- **RL Prompt Set 策展（§2.1）**：三原则——多样覆盖（STEM/编码/通用推理）、难度均衡（易/中/难分布）、可评估性（verifier 可客观判断）。用模型自身能力自适配难度评估：对每个 prompt，SFT 模型用高温度生成 10 次，pass rate 越高代表越易；以此预过滤平凡样例、规避 reward hacking（保证推理过程与最终答案都可验证）。
- **Long-CoT SFT（§2.2）**：报告聚焦 RL，Long-CoT SFT 为 RL 前一步。
- **RL 问题设定（§2.3.1）**：训练 policy π_θ 解 x→y，CoT z=(z1..zm) 桥接。指出 planning 算法（MCTS 等用 critic value 构建搜索树）可视为把搜索树展平到 full context 的映射——由此提出**不显式构建搜索树，直接训练模型近似该过程**，思路即长上下文缩放（thought 数即搜索步数）。
- **策略优化（§2.3.2）**：online mirror descent 变体（相对熵正则）：`max_θ E[(y,z)~π_θ [r]−τ KL(π_θ||π_θi)]`。闭式解 + 用 surrogate loss，τ logZ 用 (y1,z1)..(yk,zk) 采样近似；梯度里用 sampled rewards 均值 r̄ 作 baseline，并加 ℓ2 正则。**显式 exclude 价值网络**——作者假设经典 RL 的 credit assignment（用 value function）不适合此语境：探索一个当前会出错的分支（z't+1）对训练极有价值，若按 value 应 penalize 反而错误。
- **长度惩罚（§2.3.3）**：`len_reward(i)= { λ if r=1;  min(0,λ) if r=0 }`，其中 `λ=0.5− (len(i)−min_len)/(max_len−min_len)`。对答案正确者奖励短、惩罚长；对答案错者显式惩罚长。初始训练会变慢，故逐步 warm up（先是标准无长度惩罚，后加常数惩罚）。
- **采样策略（§2.3.4）**：
  - Curriculum sampling：先易后难（初始 RL 性能弱，硬题浪费计算）。
  - Prioritized sampling：追踪每题成功率 s_i，按 `1−s_i` 比例采样，集中火力于弱项。
- **训练配方细节（§2.3.5）**：代码题自动生成测试用例（用 CYaRon，聚焦无需 special judge、有 ground truth solutions 的题）。CoT-RM：约 800k CoT-labeled 样本微调 Kimi，输出 JSON 判定 + 逐步推理；手动抽查 Classic RM 84.4 vs CoT-RM **98.5**，RL 采用 CoT-RM。Vision RL 数据三类：real-world（科学图题/位置猜测/图表分析）、synthetic visual reasoning（程序化生成图像、几何/空间/物体交互）、text-rendered（把文本/代码转图像，增强跨模态一致性）。
- **Long2short（§2.4）**：用长-CoT 技术改进短-CoT 模型（知识迁移）：
  - 长-CoT 蒸馏：用长-CoT 教师的响应蒸馏到短模型；
  - 最短拒绝采样（shortest rejection sampling）：从长-CoT 教师的多个采样中选最短正确候选；
  - DPO 训练；
  - 模型合并（merge）；
  - Long2short RL：标准 RL 后选性能与 token 效率最佳平衡的模型做 base，加长度惩罚并大幅降低 rollout 最大长度。
- **其他训练细节（§2.5）**：
  - 预训练三阶段：vision-language pretraining（先建语言基础再逐步并入多模态）→ cooldown（curated+synthetic）→ long-context activation（131,072 token）。语言数据覆盖英/中/代码/数学推理/知识五域。
  - 时序：32k 序列 1 epoch（LR 2e-5→2e-6），再 128k 序列 1 epoch（rewarm to 1e-5→1e-6），packing。
- **RL 基础设施（§2.6）**：
  - 迭代同步 RL 框架：rollout worker（由 master 协调）+ 训练工人 + 奖赏模型 + replay buffer + code execution service。
  - **Partial Rollouts**：固定输出 token 预算截断每条轨迹——长/短轨迹都高效，复用先前轨迹大块，避免从零重生成（长上下文 RL 的关键）。
  - **Hybrid Deployment**（图4）：Megatron（训练）与 vLLM（推理）Kubernetes Sidecar 共处一 pod 共享 GPU；checkpoint-engine 生命周期管理；Mooncake + RDMA 在 peer node 间传 checkpoint；**训练→推理 <1 分钟，推理→训练 ~10 秒**。
  - **Code Sandbox**：Kubernetes 服务，用 Crun（替代 Docker）、cgroup 复用、overlayfs+tmpfs 上界。容器启动 0.12s→**0.04s**；16-core 每容器吞吐 **27→120 containers/sec**。

- **长上下文缩放（§3.3）**：中小型模型上随训练迭代，response length 与 accuracy 同时上升；越难基准（AIME2024/GPQA AI 等）response length 增速越陡（图5）。图6 显示 model performance 与 response length 强相关（各基准斜率 ~1e-5 至 4e-5）。最终 k1.5 扩到 **128k 上下文**，在硬推理基准上持续改善。
- **Long2short（§3.4/图7）**：对比 DPO/最短拒绝采样/模型合并，k1.5-long（长-CoT 教师）与各式长2短产物在 MATH500、AIME2024 上均表现出比 Claude-3.5、deepseek-v3、gpt-4-0513 更好的 token 效率；k1.5-shortest 系最省 token 版本。
- **消融（§3.5）**：
  - 模型尺寸 vs 上下文长度（图8）：较小模型用更长 CoT 可追平大模型，但大模型 token 效率更好；若追求最强性能，大模型+更长上下文上限更高更 token 高效；若测试时计算受限，小模型+大上下文可行。
  - 负梯度（图10）：对比 ReST（只拟合当前模型最优响应，无负梯度），本文方法（含负梯度）在 OMNI-MATH500/MATH500/AIME2024/GPQA 等上样本复杂度明显更优——负梯度显著提升长 CoT 生成效率。
  - 采样策略（图9）：curriculum sampling（先 warm-up 全量，再专注硬题）显著优于 uniform baseline。

## §6 局限

1. **long-CoT 的 token 成本**：长-CoT 模型消耗远多于短-CoT 的测试时 token，本文靠 long2short 缓解但仍存在（§2.4 引言）。
2. **overthinking 问题**：作者承认需要研究"减少 overthinking 而不损害探索能力"的 credit assignment 改进（§4 结论）。
3. **reward hacking 风险**：依赖 prompt 可验证性 + Difficulty pass-rate + 双奖励模型来规避，但仍是 RL 固有风险（§2.1）。
4. **部分基准短板**：
   - LiveCodeBench 长-CoT **62.5** < o1 **67.2**（表2）；
   - MMMU-Val 长-CoT **70.0** < o1 **77.3**（表2）；
   - MMMU-Val 短-CoT **68.0** < GPT-4o **69.1**（表3）；MathVision-Full **31.0** < Claude **35.6**（表3）。
5. **VLM 基准来源**：短-CoT 表3 的 VLM 性能取自 OpenCompass 平台（https://opencompass.org.cn/），并标注为平台所得，横表对比存在口径依赖（§3.1 说明）。
6. **代码 reward 特殊约束**：自动测试用例生成仅针对"无需 special judge + 有 ground truth solution"的题目，覆盖面受限（§2.3.5）。
7. **RL 框架的样本复杂性**：尽管优于 ReST，但仍需较大规模 RL prompt 集与多阶段训练（pretrain→vanilla SFT→long-CoT SFT→RL→long2short RL），复现成本高。
