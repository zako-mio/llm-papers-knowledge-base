## §4 方法细节
### 4.1 总体框架（§3.2，p6）
对每个 query q_t，将原始 (k,v) 重映射为紧凑表示后做注意力，再按三种策略加权聚合：
`o*_t = Σ_{c∈C} g_t^c · Attn(q_t, K̃_t^c, Ṽ_t^c)`，C={cmp, slc, win}。
门控 g∈[0,1] 由输入特征经 MLP+sigmoid 产生；保持重映射后的键值总数 N_t ≪ t 以维持高稀疏率。

### 4.2 三分支算法（§3.3，p6–8）
- **Token Compression（压缩）**：以块长 l、步长 d 聚合连续 key 块，φ 为带块内位置编码的可学习 MLP，将块内 keys 映射为单个压缩 key；取 d < l 缓解信息碎片化。提供粗粒度全局语义扫描。
- **Token Selection（选择）**：
  - 块级选择（blockwise）：依据①GPU 对连续块访问吞吐远高于随机索引读取、Tensor Core 利用率（FlashAttention 式分块）；②注意力分数空间连续性（相邻 key 重要性相近）。
  - 重要性分数零开销复用：直接用压缩分支产生的中间注意力分数 p̃^cmp 诱导选择块重要性（式 8–9），块划分不一致时按空间关系聚合。
  - GQA/MQA 兼容：组内所有 query head 的重要性分数求和共享（式 10），保证组内一致块选择，最小化解码期 KV 加载。
  - Top-n 块选择：保留重要性排名 ≤n 的块内 token（式 11–12）；实验中 n=16，含固定激活的 1 个初始块 + 2 个局部块。
- **Sliding Window（滑窗）**：窗口 w=512 显式承接局部上下文。三分支使用**相互独立的 K/V 投影**并分别隔离计算，经学习门控聚合——防止局部模式"走捷径"主导学习、避免梯度互相干扰。

### 4.3 内核设计（§3.4，p8–9）
基于 Triton 实现，面向 GQA/MQA 共享 KV 架构；压缩与滑窗分支可直接复用 FlashAttention-2 内核，专为其余稀疏选择设计三特征内核：
1. Group-Centric Data Loading：内循环加载 GQA 组内全部 query head（共享同一稀疏 KV 块索引）进 SRAM；
2. Shared KV Fetching：按索引顺序加载连续 KV 块，B_k | l′；
3. Outer Loop on Grid：query/output 循环放入 Triton grid 调度器（内循环长度≈选中块数 n，各 query 块几乎一致）。
达成近最优算术强度：消除冗余 KV 传输 + 均衡 SM 负载。

### 4.4 关键超参（p10 §4.1）
l_cmp=32，stride d=16，选择块 l′=64，n=16，w=512。

## §5 实验结果要点
- **预训练设置**：27B 总参 / 3B 激活的 GQA+MoE 骨干（DeepSeekMoE：72 routed + 2 shared experts，top-6）；30 层，hidden 2560，GQA 4 组 64 heads，d_q=d_k=192，d_v=128；首层 MoE 换 SwiGLU MLP 保稳。**270B tokens、8k 长度**预训练至完全收敛，再用 YaRN 于 32k 长度续训/微调（p9–10）。
- **通用基准（Table 1，p10）**：FullAttn→NSA：MMLU 0.567→0.565，MMLU-PRO 0.279→0.286，CMMLU 0.576→0.587，BBH 0.497→0.521，GSM8K 0.486→0.520，MATH 0.263→0.264，DROP 0.503→0.545，MBPP 0.482→0.466，HumanEval 0.335→0.348；平均 0.443→0.456。推理类增益显著：DROP +0.042、GSM8K +0.034。
- **长上下文**：NIAH 64k 完美检索（Figure 5）。LongBench（Table 2，p11）：NSA 0.469 > FullAttn 0.437 > Exact-Top 0.423 > Quest 0.392 > InfLLM 0.383 > H2O 0.303；多跳 QA（HPQ 0.437 vs 0.350）、代码理解 LCC 0.341 vs 0.294、PassR-en 0.232 vs 0.163 提升最大——作者归因原生端到端稀疏预训练 + 分层机制兼顾全局/局部。
- **CoT 推理（Table 3，p13）**：因小模型 RL 效果有限，改用 DeepSeek-R1 蒸馏，SFT 10B tokens 的 32k 数学推理轨迹；AIME24（temperature 0.7、top-p 0.95、每题 16 采样取平均）：NSA-R 0.121（8k 上限）/ 0.146（16k）vs FullAttention-R 0.046 / 0.092。
- **效率（§5，p13–14）**：8-GPU A100，与同后端 Triton 版 FlashAttention-2 比较。前向最高 9.0×、反向 6.0×（64k；随长度单调增强，8k 时仅 ~1.1×/2.1×）。解码内存访问量（Table 4）：上下文 8k/16k/32k/64k 时 NSA 需加载 2048/2560/3584/5632 等效 token vs Full Attention 的全长，期望加速 4×/6.4×/9.1×/11.6×——解码 memory-bound，加速比近似线性于内存访问缩减。
- **讨论（§6，p14）**：曾尝试 ClusterKV 类聚类方案训练，受制于动态聚类开销、MoE 专家并行负载不均放大失衡、强制周期性重聚类与分块顺序训练协议三重瓶颈而放弃；可视化证实注意力分数空间连续性是块选择的分布依据。

## §6 局限（原文可证 + 明显边界）
1. **短序列收益有限**：通用评测多为短文本，作者自认"NSA may not fully leverage its efficiency advantages on shorter sequences"（p11），8k 前向/反向加速仅约 1.1×/2.1×（Figure 6）。
2. **架构适配范围**：明确不支持 MHA 解码（memory-intensive），仅面向 GQA/MQA（p8 §3.4）；Quest 类方法在 GQA 下的 KV 访问 union 问题由组内一致选择缓解，但依赖该假设。
3. **规模验证有限**：全部训练实验在 27B/3B-ACTIVE、270B tokens 完成；CoT 用蒸馏 SFT 而非 RL（作者称小模型 RL 效果有限，p12），更大规模与 RL 场景未验证。
4. **评测取舍**：LongBench 因低分剔除了部分子集（p12）；基线稀疏度按"激活 token 数对齐"而非 FLOPs 严格对齐。
5. **超参手工性**：块长/步长/选择数/窗宽（32/16/64/16/512）为人工设定，论文未给出自适应选择机制或敏感性系统消融（附录外未展示完整扫参）。
6. **硬件覆盖**：内核对比限于 A100 GPU + Triton 后端，未覆盖其他加速器/后端。
