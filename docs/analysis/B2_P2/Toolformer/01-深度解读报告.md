## 摘要

本文解读 Meta AI 于 2023 年 2 月发布的《Toolformer》。论文的核心论断是：语言模型无需大规模人工标注，即可通过**自监督方式**学会使用外部工具——只需让模型自己生成海量候选 API 调用、真实执行、再以"加入调用后语言建模损失是否显著下降"这一单一准则过滤，就能把计算器、问答系统、Wikipedia 搜索、机器翻译、日历五种 API 织入普通文本语料，随后用标准语言建模目标微调一个 6.7B 的 GPT-J。结果是一个会"边写边调工具"的模型（Toolformer）：零样本设置下 LAMA 知识探测较同尺寸最佳基线提升 11.7/5.2/18.6 点（SQuAD/Google-RE/T-REx），数学基准上远超 OPT(66B) 与 GPT-3(175B)，同时**困惑度完全不劣化**（禁用工具时 WikiText 10.3 / CCNet 10.5）；工具使用能力在约 **775M 参数**处涌现。方法论上，本文把"何时调用哪个工具"彻底转化为下一个词预测问题，把"工具调用是否有用"转化为损失差度量——这两步转化是全文真正的胜负手，也是其后三年 function calling、RAG 与 agent 数据工程的共同源头。本报告按"问题—概念—方法—证据—批判—启示"六层结构逐层拆解。

## 一、问题定位：能力锁死在参数里，而世界在语料之外

### 1.1 论文要解决的问题

大语言模型的知识与技能全部压缩在参数里，这带来一组结构性短板：算术不可靠、知识随训练截止而过期、多语言覆盖不均、对当前日期一无所知。补齐这些短板有两条传统路径——要么把更大规模的语料塞进更大的模型，代价高昂且收益递减；要么人工编写大量"问题→工具调用→答案"格式的训练样本做监督微调，成本同样惊人。论文选择第三条路：**能否让 LM 以完全自监督的方式，从普通文本中学会使用外部工具？**

作者为此提出三项设计要求（desiderata），构成全文的评价坐标系：

1. **自监督**：以无监督方式学会使用工具，不依赖海量人工标注；
2. **无损性**：习得工具能力不应以牺牲核心语言建模能力为代价；
3. **自主性**：由模型自行决定何时、调用哪个工具，而非依赖外部流水线或特定提示词工程。

这三条要求分别对应后文方法的三个支柱：自监督数据生成（第三章管线）、困惑度审计（第四章 §4.3）、以及解码期的自主触发机制（`<API>` token 概率驱动）。

### 1.2 谱系定位：夹在两条路线之间的第三条路

（推断）从相关工作脉络看，彼时"LM+工具"存在两个极端：一端是需要昂贵监督的工具增强模型（每类任务都要人工写调用示例），另一端是依赖超大规模模型上下文学习能力的提示式工具使用（如 GPT-3 级别才玩得动）。Toolformer 的独特定位在于同时攻击两端——用自监督砍掉标注成本，用 6.7B 参数砍掉规模门槛。它证明的不是"小模型能用工具"，而是"**用工具这件事本身可以被降维成文本预测，从而任何够大的 LM 都能自学**"。这个降维视角是论文超越具体技巧的真正贡献。

### 1.3 核心洞察：两个转化

全文方法论可以浓缩为两个关键转化：

- **转化一（动作→文本）**：API 调用被线性化为普通文本序列，插入语料后与正文无缝交错。调用工具不再是结构化的"函数执行事件"，而是"生成某个特殊 token 序列"。于是"会用工具"就是"会在合适的位置生成合适的调用"，完全落入标准语言建模范式的射程之内。
- **转化二（有用→低损失）**：一条插入的 API 调用是否值得保留，判据是它是否让后续文本的预测损失显著下降。计算器结果让后续算式答案变得可预测、日历返回值让时间表述变得确定——凡是"真有用"的调用必然在下一词分布上留下可测量的痕迹。

这两个转化一旦成立，剩下的全部工作只是工程化：怎么生成候选（采样）、怎么验证（执行）、怎么筛选（过滤）、怎么训练（微调）。

> **一句话小结**：本文解决的是"工具能力的获取成本"问题——通过"调用即文本、有用即降损"两个转化，把需要人工监督的工具使用教学，变成模型自己就能完成的数据标注流程。

## 二、概念内核：五个核心概念逐一定义

### 2.1 API 调用的线性化表示（e(c) 与 e(c,r)）

**定义**：调用 c 的文本形式为 e(c) = `<API> ac(ic) </API>`，带响应的形式为 e(c, r) = `<API> ac(ic) →r </API>`，其中 ac 为 API 名、ic 为输入、r 为响应，`<API>`/`</API>`/`→` 为特殊 token。

**拆解**：实践中作者用 `[`、`]`、`->` 三个现成字符串替代特殊 token，避免改动现有 LM 词表——这是一个极易被忽视但极具工程智慧的细节：**新能力的注入不需要动架构和词表**。（推断）这一"最小侵入"取向贯穿全文，与 desiderata 第 2 条（无损性）一脉相承：既然目标是证明"加能力不伤本体"，那么连词表都不动，就把混淆变量压到了最低。

### 2.2 自监督工具标注（Self-supervised Annotation）

**定义**：不依赖人工标签，由基座模型自身在普通语料上生成、验证并筛选 API 调用注释，产出增强语料 C* 的三步骤流程。

**拆解**：C* 与原始语料 C 包含**完全相同的文本内容**，唯一区别是穿插了 API 调用——这意味着训练数据的语义分布没有被改变，改变的只是"正文中偶尔出现一段可执行的请求—响应记录"。这是"无损性"能在数据层面成立的根基。（推断）这个思路与后来 self-instruct 一类"用模型造数据教模型"的方法共享同一哲学：基座模型已有的浅层能力（模仿格式、提出候选）+ 外部执行环境的硬反馈（真实响应）+ 目标函数的可测量性（损失差），三者组合足以替代人类教师。

### 2.3 损失下降过滤准则（Filtering Criterion）

**定义**：对位置 i 的候选调用，定义加权交叉熵 L_i(z) = −Σ_{j=i}^{n} w_{j-i} · log p_M(x_j | z, x_{1:j-1})；比较 L⁺_i = L_i(e(c_i, r_i))（插入调用及真实响应）与 L⁻_i = min(L_i(ε), L_i(e(c_i, ε)))（什么都不插或只插调用不带响应），仅保留 L⁻_i − L⁺_i ≥ τ_f 的调用。

**拆解**：这是全文最精巧的单点设计，有三层含义值得展开：

1. **权重函数编码"就近有效"**：w~t = max(0, 1 − 0.2·t)（归一化后）意味着响应必须在其后约 5 个 token 的窗口内发挥预测作用才算数——它强制筛选出"答案立刻被用到"的调用，排除那些"看似相关实则冗余"的插入。
2. **对照组设计的严谨性**：L⁻ 取"不插"与"只插调用不带响应"两种情形的最小值，等于给候选设置了双重否定检验——如果光秃秃地插入调用文本本身就降低了损失（比如让格式更顺），这种调用不算有用，必须是**看到响应内容**才带来增益。（推断）这一设计堵住了"模型学会插入装饰性调用刷分"的漏洞。
3. **阈值 τ_f 的经济学含义**：τ_f 越高，留下的调用越少越精。实验用了 0.5/1.0/2.0 三档，各工具单独选取——本质上是在"工具使用频率"与"每次使用的确定性收益"之间做预算分配。

### 2.4 工具使用的涌现性（Emergent Tool Use）

**定义**：工具使用能力并非随参数量线性增长，而是在约 **775M 参数**处涌现——更小的模型用与不用工具结果相似，更大的模型则收益持续扩大。

**拆解**：（推断）这一发现的深层含义是双重的。积极面：它说明"利用工具响应修正后续生成"是一种需要最小认知底座的通用能力，不是靠记忆模板实现的；消极面：它给"用工具拯救小模型"的幻想划了红线——低于阈值的模型即使喂再多增强数据也无济于事，工具红利只在已有一定推理底座的模型上兑现。

### 2.5 无损性保证（Capability Preservation）

**定义**：在增强语料 C* 上微调后的模型，禁用 API 时与仅在原语料 C 上微调的对照模型困惑度完全一致（WikiText 10.3 / CCNet 10.5，见 Table 8）。

**拆解**：这是 desiderata 第 2 条的直接实证，也是 Toolformer 区别于"为任务性能牺牲通用能力"式微调的关键卖点。（推断）其机制在于数据设计：C* 的正文与 C 逐字相同，模型学到的额外东西只有"`<API>` 出现在哪些上下文"以及"调用后如何衔接响应"，这些知识不会干扰原有语言建模行为——除非真的生成了触发 token。

> **一句话小结**：五个概念构成一条完整链条——线性化表示打通"动作即文本"、自监督标注解决"谁来做标注"、损失差准则回答"什么调用值得留"、涌现阈值揭示"多大模型学得会"、无损性证明"学会了不伤本"。

## 三、方法拆解：三步自监督管线与五工具体系

### 3.1 管线总览

整体流程四段式：**采样候选调用 → 真实执行 → 损失差过滤 → 标准微调**；部署期增加一个"解码中断—执行—续写"的运行时机制。全程唯一的监督信号是基座模型的下一词预测损失，没有任何人工参与。

### 3.2 Step 1：采样 API 调用

为每个工具手工写一个小样本提示 P(x)（如 Figure 3 的 QA prompt），然后对语料中每个位置 i 计算该位置出现 `<API>` 的概率 p_i = p_M(`<API>` | P(x), x_{1:i-1})：

- 仅保留 p_i > τ_s 的位置；若超过 k 个则取概率最高的前 k 个；
- 对每个入选位置，采样至多 m 个不同调用 c^i。

（推断）这一步的本质是"让模型自己提名可能的调用位点"——few-shot 提示给了模型调用格式的先验，而位置概率筛选取代了人工规则。省算力的启发式也在这一层介入：例如计算器工具只处理含至少 3 个数字的文本子集，避免对无关文本全量扫描。

### 3.3 Step 2：执行 API 调用

将采到的每个调用真实发给对应 API，获得单文本序列形式的响应 r。五个工具的具体实现决定了整个系统的能力边界：

| 工具 | 后端实现 | 关键细节 |
|---|---|---|
| 问答（QA） | Atlas 检索增强模型 | 微调于 Natural Questions |
| 计算器（Calculator） | 仅四则基本运算 | 结果四舍五入至两位小数 |
| Wikipedia 搜索（WikiSearch） | BM25 检索 | 索引 KILT 的 Wikipedia dump |
| 机器翻译（MT） | NLLB 600M | 支持 200 语言；fastText 检测源语言；目标语固定为英语 |
| 日历（Calendar） | 返回当前日期 | 无输入参数 |

注意这套工具箱刻意保持简陋：没有链式调用、没有多结果浏览、计算器连乘方开方都没有。（推断）这种"低保真工具"策略是有意为之——论文要比拼的是学习机制而非工具质量，简单工具反而让"模型学会了什么"更可归因。

### 3.4 Step 3：损失差过滤

对每个（位置，调用，响应）三元组，按第二章 2.3 的准则计算 L⁺_i 与 L⁻_i，保留 L⁻_i − L⁺_i ≥ τ_f 的调用。最终产出的增强语料 C* 的规模差异极大（τ_f=0.5 时，Table 2）：

| 工具 | C* 中调用数 |
|---|---|
| WikiSearch | 207,241 |
| QA | 51,987 |
| Calendar | 61,811 |
| Calculator | 3,680 |
| MT | 3,156 |

**这张表本身就是一条重要证据**：计算器调用要从百万级文档里才能淘出三千多个合格样本（作者自述局限），而搜索类调用几乎俯拾皆是。（推断）工具的"可自监督学习性"与其使用场景在自然文本中的密度强相关——越是"答案紧跟调用"的场景（搜索补充事实、日历锚定日期），越容易自动挖出训练信号；越是"需要模型自己构造中间计算"的场景（计算器），单位语料的产出就越稀薄。

### 3.5 Step 4：微调与推理机制

- **微调**：把保留的调用与原文交错成 x* = x_{1:i-1}, e(c_i, r_i), x_{i:n}，用标准语言建模目标训练。超参：batch size 128，学习率 1e-5，前 10% 步线性 warmup。无任何强化学习、无偏好优化——纯粹的自回归下一词预测。
- **推理**：正常解码，直到生成 `→` token 时中断，解析当前调用并发往对应 API，将响应插入上下文后继续解码。两个关键细节：① 不要求 `<API>` 是 argmax token，只要进入 top-k（k=10）即触发——大幅提高召回；② 每次输入至多一次 API 调用，防止循环调用失控。

（推断）"top-k 触发 + 单次上限"这对组合拳很有意思：前者承认模型对"要不要调用"的置信度是软性的，后者用硬约束兜底安全——这是在没有 RL 训练调用策略的条件下能做的最朴素也最有效的工程折衷。

> **一句话小结**：方法体系是"一个判据贯穿始终"——采样时用模型自己的概率提名位点，过滤时用模型自己的损失裁决去留，推理时用模型自己的置信度触发调用；人是这套系统的旁观者。

## 四、证据链：六大任务域逐一体检

### 4.1 LAMA 知识探测：最大的提升，最"借力"的胜利

LAMA 三分子集（SQuAD / Google-RE / T-REx）上 Toolformer 得分 33.8 / 11.5 / 53.5，较同尺寸最佳基线分别提升 **11.7 / 5.2 / 18.6 点**，且同时优于 OPT(66B) 与 GPT-3(175B)。工具使用画像高度集中：98.1% 的例子调用了 QA 工具，其余工具仅占 0.7%，另有 1.2% 完全不用工具。

（推断）解读需冷静：LAMA 本是"探测参数内知识"的基准，而这个成绩本质上是把探测外包给了另一个内置 LM（Atlas）——模型学会的是"遇到知识缺口就去问"，而不是"把知识装进了参数"。提升幅度之大恰恰反衬出参数内知识的贫瘠，以及"外挂知识源"杠杆之高。这也为第五章批判埋下伏笔。

### 4.2 数学基准：工具红利 + 意外的副产品

ASDiv / SVAMP / MAWPS 上得分 40.4 / 29.4 / 44.0，97.9% 的例子使用计算器，远超 OPT(66B) 与 GPT-3(175B)。最有意思的发现是：**即使解码时禁用 API，数学成绩仍高于未微调基线**——微调过程顺带提升了模型的内生数学能力。（推断）机制可能是：增强数据中"题目→调用→正确答案"的模式反复出现，使模型即便拿不到计算器结果，也对常见运算模式形成了统计记忆。

### 4.3 开放域 QA：赢在同尺寸，输给 175B

WebQS / NQ / TriviaQA 上得分 26.3 / 17.7 / 48.8，99.3% 依赖 Wikipedia 搜索，大幅领先同尺寸基线，但仍落后 GPT-3(175B)。作者将其归因于搜索器的简单性——BM25 单轮检索无法交互式改进查询或浏览多条结果。

### 4.4 MLQA 多语问答：唯一未拿下战场的诚实记录

翻译工具使用率在多数语言上达 63.8%–94.9%，但印地语例外（仅 7.3%）；总体上 Toolformer 未稳定优于 GPT-J——部分语言上 CCNet 语料微调反而造成劣化（分布偏移所致）。附带发现：OPT/GPT-3 因不理解任务要求而不给英语作答，表现极弱。（推断）这一失败案例的价值在于它揭示了方法的适用边界：当增强语料的领域分布与目标任务的分布错位时，"无害"的数据也可能变成负资产——而论文的安全审计（困惑度）测不出这类细粒度退化。

### 4.5 时间数据集：一次干净的工具归因

TEMPLAMA 上 16.3 分，日历工具仅被使用 0.2%，提升主要来自搜索/问答工具；DATESET 上 27.3 分，日历使用率 54.8%，提升全部归功于日历。两个数据集构成了教科书级的归因对照：工具使用比例与性能来源一一对应，说明模型确实在"按需选工具"，而非机械触发。

### 4.6 语言建模审计：无损性的量化证明

Table 8（WikiText / CCNet 困惑度）：GPT-J 原版 9.9 / 10.6；GPT-J+CC（仅在 C 上微调）10.3 / 10.5；Toolformer(disabled) 10.3 / 10.5。两组微调模型完全打平——API 注释对语言建模能力的影响严格为零。值得注意的是 CC 微调本身让 WikiText 困惑度从 9.9 升到 10.3，这是语料切换的正常代价，与工具无关。

### 4.7 缩放律与涌现：约 775M 的分水岭

§4.4 显示：工具使用能力在约 **775M 参数**处涌现；小于该规模的模型用不用工具差别不大；更大的模型从工具中获益越来越多，且用/不用 API 的差距随规模拉大。（推断）这与 2.4 的概念分析互证：整合外部信息进生成流，需要对"调用—响应—续写"三元结构的足够建模容量。

### 4.8 解码策略与校准：模型知道自己的无知

§5 的两项分析颇具前瞻性：

- **k 值效应**：k=1（仅 argmax 触发）时 T-REx 使用率仅 40.3%、WebQS 仅 8.5%；放开到 k=10 后飙升至 98.1% 与 100%。说明大量有效调用场景下 `<API>` 只是"次优但靠前"的候选——argmax 触发会漏掉绝大多数机会。
- **隐式校准**：k=1 时模型表现出天然的自我校准——它选择调用 API 的那部分例子，成绩（44.3 / 19.9）高于全体平均（34.9 / 18.9），即**模型倾向在自己不会的题上调用工具**。这一"知道自己不知道"的行为未经任何显式校准训练就自发出现了。
- **数据质量的鲁棒性**：高 L⁻_i − L⁺_i 的调用确实对应更有用的调用；而且少量噪声调用混入反而防止模型盲从每一次工具结果——过滤器天然带有抗过拟合的正则效应。

> **一句话小结**：证据体系呈"五胜一平"格局——LAMA/数学/QA/时间/缩放律全面验证方法有效，MLQA 诚实暴露边界；而困惑度审计与隐式校准两条暗线，分别守住了底线（无损）与打开了想象（元认知萌芽）。

## 五、批判审视：局限的深层含义与独立疑点

### 5.1 作者自述五项局限的深层含义

1. **无法链式使用工具**：一个工具的输出不能成为另一个工具的输入，因各调用独立生成、训练数据中没有链式示例。（推断）深层原因在过滤准则本身：L⁻_i − L⁺_i 度量的是单点插入的即时收益，链式调用的价值要在整条链完成后才兑现，单点损失差天然筛不掉"当下无用、后续有大用"的第一环。这不是没想到，而是判据的结构性盲区。
2. **无法交互式使用工具**：对搜索结果不能浏览多条或改写查询（对比 Nakano 2021）。单响应协议决定了模型永远只见搜索的第一眼。
3. **对输入措辞敏感**：是否调用 API 易受 prompt 措辞影响——自主触发机制的稳定性存疑。
4. **样本效率低**：处理超百万文档才得到数千个有用的计算器调用；作者建议迭代应用缓解。
5. **不考虑调用成本**：模型不知道各工具的计算代价差异，无法做性价比决策。

### 5.2 独立观察到的六个疑点

**① QA 工具与 NQ 评测集的训练重叠嫌疑**：源数据明确记载 QA 工具（Atlas）微调于 Natural Questions，而 Table 5 的评测集恰包含 NQ。（推断）尽管论文大概率只用了 NQ 训练划分、且 Atlas 是独立组件而非 Toolformer 本体，但"NQ 上 17.7 分"这一数字背后站着的是一个见过 NQ 训练分布的检索器——跨模型比较时，这一分数不能完全记在"工具学习能力"账上。同理，LAMA 的暴涨（+18.6 点 T-REx）主要反映 Atlas 内置知识的释放，把它读作"参数内知识增强"会是误读。

**② 过滤准则的循环性：模型只能学会它几乎已经会的东西**：判据是"响应降低基座模型的损失"，这意味着只有当模型**有能力消化响应**（理解它、并在续写中使用它）时，该调用才会存活。模型自身能力构成天花板：它能学会"查询并填空"，但很难自发学会需要全新推理模式的用法。（推断）这是自监督范式的固有代价——教师即学生，学生的视野就是课程的边界。

**③ 基线的不对称比较**：OPT(66B)、GPT-3(175B) 作为对照时均无工具权限，且为零样本设定。"6.7B 用工具胜过 175B 不用工具"证明的是工具的价值，而非 Toolformer 架构/训练法的优越——严格说，任何给 GPT-3 外接同一套 API 的方案都可能有类似增益，Toolformer 的独特性在于**获取这种能力的过程是自监督的**，这一点在对比表中并不直接可见。

**④ 涌现阈值的证据强度**："~775M 涌现"来自一族模型的缩放实验，源数据显示为单点观察（Figure 4）。（推断）涌现类结论对评测集、提示格式、温度等实验细节敏感，在缺乏多次运行方差与跨模型族复验的情况下，应视为描述性现象而非精确常数。

**⑤ MLQA 劣化暴露安全审计的盲区**：CCNet 微调导致部分语言劣化、印地语翻译工具使用率骤降至 7.3%，而困惑度指标对此无感（MLQA 不是建模任务）。"无损性"的实证仅覆盖了语言建模这一个维度，下游细粒度能力的退化需要逐任务体检才能发现——这提示**单一困惑度审计不足以作为能力安全的充分条件**。

**⑥ 单次调用上限人为封顶了组合性**：每次输入至多一次调用的防死循环约束，与局限①（无链式）叠加，意味着系统在架构层面就不可能展现多步工具推理。后续所有"Toolformer 学不会复杂任务"的结论都应先扣除这一硬约束的影响。

> **一句话小结**：论文最响亮的战绩（LAMA +18.6、6.7B 胜 175B）都需要贴着"工具有多强"而非"模型有多强"来读；而过滤准则的循环性与单次调用上限这两处结构性设计，预先注定了它无法通向链式与交互式工具智能——后者正是下一代工作要接棒的空位。

## 六、启示提炼：可迁移的经验与历史走向

### 6.1 五条可迁移启示

1. **"用自己的目标函数给自己造课程"是技能注入的通用范式**：损失差过滤的本质是让模型的目标函数充当数据质检员。凡属"插入某段信息后下游预测变容易"的场景（检索文档、代码文档注释、思维链步骤），都可以套用这套自监督标注逻辑，替代昂贵的人工筛选。
2. **动作空间文本化是最小成本的具身化**：把 API 调用线性化为普通 token 流，不动架构、不动词表（甚至直接复用 `[` `]` `->` 三个现成字符串），就让生成模型获得了行动能力。（推断）后来的 function calling 协议无论多么结构化，其底层依然是"生成特定 token 序列即触发执行"这一 Toolformer 式安排。
3. **能力安全要有专门的回归测试**：困惑度审计（10.3/10.5 打平）是"加能力不伤本"主张得以成立的证据形态。任何向基座模型注入新能力的微调，都应预注册一套"禁用新能力后的基线体检"，而非只报峰值性能。
4. **涌现阈值决定投入时机**：775M 分水岭提示——在阈值以下的模型上堆工具训练数据是浪费算力；工具增强应作为规模化路线上的一个阶段性投资，而非普适药方。
5. **数据产出的悬殊比例是工具可学习性的天然标尺**：207,241（搜索）vs 3,680（计算器）vs 3,156（翻译）的产出比，提前告诉实践者哪些工具适合自监督挖掘、哪些需要外部课程设计——单位语料的合格调用产出率，本身就是值得监控的元指标。

### 6.2 局限走向：五条局限 = 未来三年的研究路线图

（推断）回望 2023 年之后的 agent 研究史，本文的五项局限几乎逐条变成了热门方向：链式缺失 → 思维链中的工具编排与 ReAct 类交替范式；交互缺失 → 多轮检索、浏览器操作代理；措辞敏感 → 调用决策的鲁棒化与显式训练；样本效率 → 迭代自举与合成数据飞轮；成本盲视 → 模型路由与预算感知规划。一篇好论文的局限清单，往往比它的结果表更能预言领域的下一步。

## 总结

《Toolformer》的贡献不在于某个具体分数，而在于完成了两个降维转化：**把工具调用变成文本生成**，**把调用价值变成损失差**。前者让任何自回归 LM 都能表达行动，后者让模型自己就能筛选出值得学的行动——两者相乘，工具使用第一次成为可以纯自监督习得的能力。证据链上，6.7B 的 GPT-J 在 LAMA 上凭 98.1% 的 QA 工具使用率碾压同尺寸基线 18.6 点、在数学上越过 175B 的 GPT-3，同时困惑度一分不涨、775M 涌现阈值清晰可见，构成一个罕见地"效果、安全、机理"三线齐备的实证包；而 MLQA 的失守与五项自述局限，则诚实地圈定了这套机制的边界。批判视角下的两点保留——QA 工具与 NQ 的训练重叠嫌疑、过滤准则"只能教已经几乎会的"这一循环性——提醒我们把它最亮眼的数字读作"工具杠杆的胜利"；但恰恰是这些边界，而非那些分数，定义了此后三年工具增强与 agent 研究的议程。作为"LM 自学用工具"的开山之作，Toolformer 值得任何研究 LLM 能力注入机制的人精读原文。
