## §3 核心主张与关键数字表

**核心主张**：投机采样的关键在于降低 draft 阶段时间开销并提升 draft 的接受率。作者给出两个关键观察：(1) 在 feature（second-to-top-layer，LM head 前）层面做自回归比 token 层面更简单可行；(2) feature 层面自回归固有的不确定性（不同采样结果→不同 feature 分支）限制了性能。EAGLE 通过把 token 序列前移一位作为输入，解决不确定性，实现 2.7x–3.5x（LLaMA2-Chat70B 上 2.7x–3.5x）延迟加速。

## §4 方法细节

- **符号**：target LLM 为待加速模型；draft model 生成草稿。feature f = second-to-top-layer 隐藏状态（LM head 前）。流程 `T→E→f→p→t`。
- **Drafting phase（图5/6）**：
  - Speculative sampling/Lookahead 基于 token 预测；Medusa 用 MLP 基于当前 f 独立预测多个位置的 token。
  - EAGLE 输入 feature 序列 `(f₂,f₃)` 与 token 序列 `(t₂,t₃)`（前移一位），输出下一 feature `f₄`。EAGLE 的 draft model 含三个模块：Embedding layer（复用 target LLM 参数）+ LMHead（复用）+ Autoregression Head（FC + decoder layer，唯一可训练部分）。
  - fuse 序列 shape `(bs, seqlen, 2×hidden_dim)`，FC 降回 hidden_dim，decoder 预测下一 feature。
- **Tree-structured draft（tree attention）**：用 m 个 forward pass 生成深度 m 的树，节点数 > m。如 10-token 树仅 3 forward（图6）。树注意使 target LLM 单次 forward 计算整棵树各 token 概率。
- **Training**：
  - 回归 `L_reg = SmoothL1(f_{i+2}, DraftModel(T_{1:i}, F_{1:i}))`。
  - 分类 `L_cls = CrossEntropy(p_{i+2}, p̂_{i+2})`，`p = Softmax(LMHead(f))`。
  - 联合 `L = L_reg + w·L_cls`，w=0.1（分类 loss 数值上大一个数量级）。
  - 数据增强：对 target feature 加 `U(−0.1, 0.1)` 噪声（缓解 feature 误差累积）。
- **Verification phase**：树注意下 target LLM 单次 forward 计算整树概率，每节点递归应用 speculative sampling 算法（与 SpecInfer 一致，保证输出分布对齐）。
- **Lossless 保证**：EAGLE 不改 target LLM、采用标准接受/拒绝规则，理论上保证 greedy 与非 greedy 都无损分布（对比 Lookahead 仅 greedy、Medusa 非 greedy 不保证）。

## §5 实验结果要点

- **加速**：MT-bench greedy（T=0）下 Vicuna/LLaMA2-Chat 系列达 2.7x–3.5x；T=1（非 greedy）1.8x–2.4x。对比 Lookahead/Medusa 分别快 1.70x–2.08x / 1.47x–1.60x。
- **HumanEval 最佳**：因代码模板固定、易生成草稿，LC13B 达 3.76x。
- **接受长度/接受率**：0-α（全对 feature）明显 > 1-α 及以上，表明 feature 误差影响；但 1-α 到 4-α 仅 0.6–0.8 小幅波动，显示对 feature 误差鲁棒。
- **MoE 模型受限**：Mixtral8x7B-Instruct 仅 1.5x（平均接受长度更短，MoE 加速复杂度：验证阶段多 token 可能需访问 >2 专家权重）。
- **组合加速**：EAGLE + gpt-fast（量化+编译）在 RTX3090 上让 LLaMA2-Chat7B 达 160.4 tokens/s。
- **树注意消融**：树状草案+验证使平均接受长度增约 0.6–0.8、加速比增 0.3–0.5；即使无树注意，EAGLE 也有显著加速（超过 4.5 tokens/forward vs vanilla 1 token/forward）。
- **训练数据敏感度低**：§4.3.3 消融显示对训练数据不敏感，可使用固定数据集而非 target LLM 自回归生成文本。

## §6 局限

1. **MoE 加速有限**：Mixtral8x7B-Instruct 仅 1.5x。验证阶段对多个 token 需读取 >2 专家权重，MoE 的投机采样增益被削弱，作者未完全解决。
2. **接收率未达理想**：接受率 0-α 最高约 0.79（T=0），仍有提升空间；feature 级误差在自回归中会累积，仅用噪声增强部分缓解。
3. **只针对独立 draft model 对比**：作者明确只比较"无需微调 backbone"的投机采样方法；对需要微调 backbone 的方法未评估，确保分布一致性的假设限制了适用面。
4. **未见 7B target 的 draft 模型**：文中指出 7B 模型缺合适 draft model（用 7B 做 13B 的 draft 开销大，用 TinyLLaMA 指令模板不一致），即对小模型缺乏可用草稿，是场景受限。
5. **训练开销仍未完全消除**：虽远低于 TinyLLaMA（2–4B vs 3000B tokens），但每次新 query/新模型仍需一次训练会话，作者以"随 query 数摊销趋于 0"为其辩护。

## §7 关键方法对比（加速点）

| 方法 | 草稿预测对象 | 是否需微调 backbone | 无损保证 | 代表性加速 |
|------|------|:--:|:--:|:--:|
| Speculative sampling | token（目标 LLM 次采样）| 否 | 是（标准接受/拒绝）| 基线 |
| Lookahead | token（n-gram + Jacobi）| 否 | 仅 greedy | <EAGLE |
| Medusa | token（MLP 独立预测多位置）| 否（detached head 训练）| 非 greedy 不保证 | 1.47–1.60x 慢于 EAGLE |
| DistillSpec | token（蒸馏 draft）| 否（蒸馏）| 是 | > vanilla，但受限 |
| **EAGLE** | **feature(second-to-top) + shifted-token** | 否（仅轻量 decoder 层）| **greedy+非 greedy 均保证** | 2.7–3.5x |

> EAGLE 的独特之处：预测对象是 feature（而非 token），并把 token 序列前移一位作为输入以消除 feature 级不确定性；这既降低草稿误差，又把分布保持的理论保证扩展到非 greedy 设置。

## §8 训练/推理关键配置速览

- **数据**：ShareGPT 对话；68,000 次迭代。
- **优化器**：AdamW，β=(0.9, 0.95)；lr 3e-5；梯度裁剪 0.5。
- **可训练参数**：7B=0.24B；13B=0.37B；33B=0.56B；70B=0.99B；Mixtral8x7B=0.28B。
- **Loss 组合**：`L=L_reg+w·L_cls`，w=0.1（回归 SmoothL1 + 分类 CrossEntropy）。
- **Data augmentation**：对 target feature 加 U(−0.1,0.1) 噪声。
- **树状草稿**：depth m，用 m 个 forward pass；tree attention 使目标 LLM 单次 forward 计算整树概率。
- **可用环境**：70B 在 A100(40G)×4，1–2 天；7B/13B/33B 可 RTX3090 单卡。
