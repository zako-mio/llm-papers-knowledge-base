# 《EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty》深度解读报告

> 数据依据：pdf-worker 源数据提取文件（00-源数据提取.md，出自 arXiv:2401.15077v3，ICML 2024，13页），全部数字与原文一致；文中标注"（推断）"处为分析者推理补充。

## 摘要

本文解读北大、微软研究院、滑铁卢大学联合提出的《EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty》。论文的核心论断是：投机采样（speculative sampling）的性能瓶颈不在"草稿模型多大"，而在两个被忽视的结构性问题——**自回归应该在 feature 层面而非 token 层面进行**（feature 层面的自回归更简单、更平滑），以及 **feature 层面自回归固有的不确定性**（同一 token 序列在不同采样路径下对应不同的 feature 分支）必须被显式消解。EAGLE 的解法极为轻巧：把输入 token 序列前移一位（shifted token），与 second-to-top-layer 特征拼接后送入一个仅含 FC + 单个 decoder layer 的轻量自回归头（Embedding 与 LMHead 直接复用目标 LLM 参数），配合树状草稿与 tree attention 验证。结果是：MT-bench greedy 设定下对 Vicuna/LLaMA2-Chat 系列 2.7x–3.5x 无损加速（非 greedy 下 1.8x–2.4x），比 Lookahead 快 1.70x–2.08x、比 Medusa 快 1.47x–1.60x，单次 forward 平均生成 3.2–4.5 个 token；训练只需 ≤70k 对话、可训练参数最高不到 1B（70B 目标模型对应 0.99B），A100×4 上 1–2 天完成。本报告按"问题—概念—方法—证据—批判—启示"六层结构逐层拆解。

## 一、问题定位：LLM 推理瓶颈与投机采样的两难

### 1.1 论文要解决的问题

大语言模型自回归解码每步只产出 1 个 token，却要完整执行一次 forward pass——访存受限使得 GPU 的并行算力大量空转。投机采样是该问题的主流解法：用一个廉价 draft model 快速起草多个 token，再由 target LLM 一次性并行验证，接受/拒绝规则保证输出分布与 target 完全一致。但论文观察到，既有投机采样方法卡在一个尴尬的天花板上：

1. **草稿阶段开销压不下来**：draft 越强越准，但越强越贵；标准 speculative sampling 用独立小模型（如 TinyLLaMA 为 LLaMA2 打草稿），为了对齐分布甚至需要蒸馏训练（DistillSpec 用了 3000B token 量级的训练），开销与收益难以平衡；
2. **接受率上不去**：Lookahead 用 n-gram + Jacobi 迭代零训练打草稿，但仅在 greedy 下有无损保证；Medusa 用 MLP 头基于当前 feature 独立预测多个未来位置的 token，非 greedy 下不保证无损。二者的共同点是都在 **token 空间**里做文章。

作者由此提出全文的两个关键观察：(1) **在 feature 层面做自回归比 token 层面更简单可行**——feature 是 LM head 之前的隐藏状态（second-to-top-layer），它承载了比离散 token 更丰富的语义信息，预测下一个 feature 是一个连续空间里的回归问题，天然比离散空间的生成问题更平滑；(2) **feature 自回归存在固有的不确定性**：同一个 token 序列，经不同采样路径到达时对应的 feature 序列并不唯一（采样温度不为零时每个位置的 token 都有多个可能取值，导致 feature 分支爆炸），若不处理，draft model 学到的映射是多值的，精度必然受损。（推断）这两个观察合起来的潜台词是：此前所有方法的失败，根源是把"预测什么"（token vs feature）和"以什么条件预测"（是否消除多值性）这两件事想当然了。

### 1.2 在投机采样谱系中的定位

论文在对比方法时明确划定了范围：只比较"无需微调 target backbone"的方法，保证输出分布一致性的假设不可破。

| 方法 | 草稿预测对象 | 是否需微调 backbone | 无损保证 | 代表性表现 |
|------|------|:--:|:--:|------|
| Speculative sampling | token（小模型自回归） | 否 | 是（标准接受/拒绝） | 基线 |
| Lookahead | token（n-gram + Jacobi） | 否 | 仅 greedy | 慢于 EAGLE |
| Medusa | token（MLP 独立预测多位置） | 否 | 非 greedy 不保证 | 慢于 EAGLE 1.47–1.60x |
| DistillSpec | token（蒸馏 draft） | 否（蒸馏） | 是 | 受限于训练开销 |
| **EAGLE** | **feature(second-to-top) + shifted-token 输入** | 否（仅轻量 decoder 层） | **greedy + 非 greedy 均保证** | **2.7x–3.5x** |

这张表的深层信息是：EAGLE 是唯一同时做到"预测对象换到 feature 层""训练极轻""greedy与非greedy双无损"三个属性的方法。（推断）它的真正对手不是某篇具体论文，而是"投机采样必须重训一个大 draft model"的行业惯性认知——标题里的 "Requires Rethinking" 正是对这一惯性的宣战。

> **一句话小结**：本文的问题定位不是"如何造更好的 draft model"，而是"投机采样的草稿应该在哪个表示空间、以什么条件生成"——把战场从 token 空间挪到 feature 空间，并消解 feature 空间固有的多值不确定性。

## 二、概念内核：四个核心概念逐一定义

### 2.1 Feature Autoregression（特征层自回归）

**术语定义**：draft model 的自回归对象不是 token，而是 target LLM 的 second-to-top-layer feature f（LM head 前最后一层之前的隐藏状态）。

**拆解**：target LLM 每一步的内部流程是 `T→E→f→p→t`（token → embedding → feature → 概率 → 下一个 token）。传统方法在链条末端 t 上做文章，EAGLE 把自回归搬到中间环节 f 上。这样做的理由有两层：其一，feature 是稠密连续向量，携带的信息远多于 one-hot 化的 token，从 feature 预测下一个 feature 本质上是连续回归，梯度信号更丰富、学习更平滑；其二，feature 已经"消化"了全部上下文的历史语义，等于站在 target LLM 的肩膀上打草稿——draft model 不必从零理解语言，只需学会"在 target 的思维状态里往前走一步"。（推断）这解释了为何 0.24B 的可训练参数就能达到高接受率：绝大部分"语言理解能力"是免费复用的，可训练部分只学增量动态。

### 2.2 Feature Uncertainty 与 shifted-token 解法

**术语定义**：feature 层自回归固有的不确定性——不同采样结果会产生不同的 feature 分支，使"token 前缀 → 下一 feature"的映射成为多值函数；EAGLE 通过把输入 token 序列前移一位来消解。

**拆解**：这是标题中 "Feature Uncertainty" 的正主。设想 draft model 要根据 `(f₁,f₂,f₃)` 预测 `f₄`：如果训练数据里 token 序列 `(t₂,t₃)` 在温度采样下出现过多种取值组合，那么同样的 feature 条件下 `f₄` 的真值就不唯一，模型只能学到模糊平均。EAGLE 的解法是改变输入构造：draft model 的输入是 **feature 序列 `(f₂,f₃)` 与前移一位的 token 序列 `(t₂,t₃)` 的融合**——即预测 `f₄` 时显式告知"`f₄` 所对应的那个已采样 token `t₄` 是什么"。这样一来，`f₄` 由确定的上下文 `(t₄, f₂, f₃)` 唯一决定，多值坍缩为单值。（推断）这个设计的精妙在于成本为零：shifted token 本来就在手上（draft 时刚被采样出来），只是从未有人想到把它喂进去。一个输入排列的改变，解决了一个理论层面的病。

### 2.3 Tree-Structured Drafting 与 Tree Attention（树状草稿与树注意力）

**术语定义**：草稿不再是一条线性序列而是一棵树——深度 m 的树用 m 个 forward pass 生成，节点数可超过 m（如 10-token 树仅用 3 次 forward）；验证侧用 tree attention 让 target LLM 单次 forward 计算整棵树所有节点的概率。

**拆解**：线性草稿只有一条赌注链，树状草稿则是同时在多条分支上下注，哪条被接受都赚。生成端，m 个 forward 各扩展一层，树的宽度由每个节点保留的 top-k 分支决定；验证端，tree attention 通过自定义注意力掩码让树中每个节点只看见自己的祖先链，从而在一次 forward 内并行算出整棵树每个位置的概率。两项增益的量化：树状草案+验证使平均接受长度增约 0.6–0.8 个 token、加速比增 0.3–0.5。（推断）树结构之所以有效，是因为 feature 空间的预测虽然总体准确，但具体到某个分叉点总有多种合理走向——与其押一条最可能的路，不如把 top 几种可能性都铺开让 target 一次裁决。

### 2.4 Lossless Guarantee（无损保证）

**术语定义**：EAGLE 不修改 target LLM、验证阶段逐节点递归应用标准 speculative sampling 接受/拒绝规则，理论上保证 greedy 与非 greedy 设定下输出分布均与 target LLM 对齐。

**拆解**：无损性是投机采样区别于其他加速手段（量化、剪枝、早退）的生命线——加速可以打折，输出不能变味。对比之下，Lookahead 仅 greedy 无损，Medusa 非 greedy 不保证，而 EAGLE 因为验证完全继承标准接受/拒绝规则（与 SpecIner 一致的递归应用），两种设定下都有理论保证。（推断）这一点对 EAGLE 的商业价值至关重要：它意味着可以无脑插到任何生产管线上而不需要重新评估输出质量，这是"1.8x–2.4x 但绝对无损"优于"更快但有偏"的根本原因。

> **一句话小结**：四个概念构成一条因果链——feature 自回归选对战场（2.1）、shifted-token 消除多值病根（2.2）、树状草稿放大单次收益（2.3）、标准验证规则守住无损底线（2.4）。

## 三、方法拆解：Draft-Train-Verify 全流程还原

### 3.1 Drafting Phase：三模块轻量架构

EAGLE 的 draft model 只含三个模块，其中两个直接复用 target LLM 参数：

1. **Embedding layer**：复用 target LLM 的 embedding，把 shifted token 序列编码；
2. **LMHead**：复用 target LLM 的 LM head（用于训练时的分类 loss 及草稿输出）；
3. **Autoregression Head**：**唯一的可训练部分**——一层 FC 加一个 decoder layer。输入 fuse 序列 shape 为 `(bs, seqlen, 2×hidden_dim)`（feature 与 embedding 沿通道维拼接），FC 将其降回 hidden_dim，decoder layer 预测下一时刻的 feature。

具体地，以上下文 `(t₁,t₂,t₃)` 已产生 feature `(f₁,f₂,f₃)` 为例：draft model 输入 feature `(f₂,f₃)` 与前移一位的 token `(t₂,t₃)`，输出下一 feature `f₄`，经复用的 LMHead 得到 `p₄`，采样出 `t₄`；随后 `(f₃,f₄)+(t₃,t₄)` 继续滚动。整个过程与普通自回归无异，只是状态从 token 换成了 feature、输入多了一份 shift 过的 token。（推断）复用 Embedding 和 LMHead 还有一层好处：draft model 与 target 共享词表与输出空间，无需任何对齐训练，可训练参数全部花在刀刃上。

### 3.2 训练目标：回归 + 分类 + 噪声增强

训练损失是双重目标的加权组合：

$$L = L_{reg} + w \cdot L_{cls}, \quad w = 0.1$$

- **回归损失**：`L_reg = SmoothL1(f_{i+2}, DraftModel(T_{1:i}, F_{1:i}))`——让预测的下一 feature 对齐真实 feature；
- **分类损失**：`L_cls = CrossEntropy(p_{i+2}, p̂_{i+2})`，其中 `p = Softmax(LMHead(f))`——让 feature 经 LMHead 映射后的 token 分布也对齐；
- 权重 w=0.1 的原因是分类 loss 数值上比回归 loss 大一个数量级，等权会淹没回归信号。

另一个关键技巧是**数据增强**：训练时对 target feature 加 `U(−0.1, 0.1)` 均匀噪声。动机是 feature 级误差会在自回归滚动中累积（draft 自己生成的 feature 与 target 真实 feature 存在偏差），加噪声模拟这种偏差，让模型在训练时就见过"带误差的 feature"，缓解推理时的误差雪崩。

**训练配置速览**：ShareGPT 对话数据，68,000 次迭代；AdamW，β=(0.9, 0.95)；lr 3e-5；梯度裁剪 0.5。可训练参数量：7B→0.24B，13B→0.37B，33B→0.56B，70B→0.99B，Mixtral8x7B→0.28B。

**训练成本**：70B 目标模型在 A100(40G)×4 上 1–2 天，使用 ≤70k 对话；7B/13B/33B 单张 RTX3090 即可在 1–2 天完成。作为对照，TinyLLaMA 式独立 draft model 的对齐训练需要约 3000B token，EAGLE 只需 2–4B token——**相差约三个数量级**。

### 3.3 Verification Phase：一次 forward 验证整棵树

验证阶段，target LLM 以 tree attention 方式单次 forward 计算整棵草稿树所有节点的 logits，然后在树上**逐节点递归应用 speculative sampling 的接受/拒绝算法**（与 SpecInfer 一致）：每个节点以其父路径为条件独立执行接受判定，保证最终输出分布严格等于 target LLM 的分布。greedy 设定是概率判定的确定性特例，同样被覆盖。

### 3.4 端到端流水线的收益账

把三段拼起来看单次循环的经济性：draft 侧 m 次 forward 生成含 >m 个节点的树（10-token 树只要 3 次 forward），verify 侧 1 次 target forward 同时裁决全树，典型吞吐为每次 target forward 产出 3.2–4.5 个 token（vanilla 自回归是 1 个）。（推断）这就是 2.7x–3.5x 加速的微观来源——draft model 的轻量 forward 替换了大部分昂贵的 target forward，而替换比例的上限恰由接受率决定，这正是第四章要检验的。

> **一句话小结**：方法体系是"一轻一移一树"——架构轻（仅 Autoregression Head 可训练，Embedding/LMHead 白嫖 target）、战场移（feature 空间 + shifted token 消不确定性）、下注树状化（m 次 forward 铺开 >m 个赌注，1 次 forward 全收）。

## 四、证据链：主实验、对比与消融的逐层检验

### 4.1 主结果：2.7x–3.5x 的成色

MT-bench（greedy, T=0）设定下，EAGLE 在 Vicuna/LLaMA2-Chat 全系列上取得 **2.7x–3.5x** 端到端加速；切换到 temp=1 的非 greedy 采样，加速比为 **1.8x–2.4x**（图2 区间）。单项峰值出现在 HumanEval：代码任务模板固定、草稿极易命中，LLaMA2-Chat-13B 达 **3.76x**——这也是全文最大加速数字。（推断）greedy 高于采样的原因直观：T=0 时 target 的输出高度确定，草稿命中率更高；温度越高、随机性越大，长链草稿被中途拒绝的概率越大。

### 4.2 同类方法对比与组合加速

- **vs Lookahead**：EAGLE 快 **1.70x–2.08x**；
- **vs Medusa**：EAGLE 快 **1.47x–1.60x**；
- **接受率**：0-α 接受率（全对 feature 口径，T=0）达 **0.74–0.79**（Vicuna7B/13B 部分）；
- **吞吐口径**：典型每 target forward 生成 **3.2–4.5 tokens**；
- **工程组合**：EAGLE + gpt-fast（量化+编译叠加）在 RTX3090 上将 LLaMA2-Chat-7B 推到 **160.4 tokens/s**（对照：vanilla HF 24.5、gpt-fast alone 55.1）——相对 vanilla 约 6.5x，说明投机采样与系统级优化**乘性叠加**而非互斥。

### 4.3 接受率曲线透露的鲁棒性

表2 的 0-α 至 4-α 接受率序列藏着一个重要事实：0-α（draft feature 全部精确对齐）明显偏高（0.74–0.79），但从 1-α 到 4-α 仅小幅波动（0.6–0.8 区间内变化）。这说明两件事：其一，feature 误差确实存在并影响首个条件的精度；其二，**误差累积的杀伤力有限**——即便 draft feature 带着误差继续滚动，接受率并未断崖下跌。（推断）这间接验证了噪声增强（U(−0.1,0.1)）的有效性：模型学到的映射对 feature 扰动是鲁棒的，这正是 feature 自回归能够实际工作的隐含前提。

### 4.4 消融：树注意的贡献与 MoE 的天花板

- **Tree attention 消融（§4.3.1）**：去掉树状草案+验证后，平均接受长度降约 0.6–0.8、加速比降 0.3–0.5。但值得强调的是，即使无树注意，EAGLE 仍超过 **4.5 tokens/forward**（vanilla 为 1）——即树注意是增益项而非命脉，核心增益来自 feature 自回归本身。
- **MoE 模型（§4.2）**：Mixtral8x7B-Instruct 仅获 **1.5x** 加速，平均接受长度也更短。作者的归因是 MoE 验证复杂度：对多 token 并行验证时可能需要访问 >2 个专家的权重，抵消了投机采样的部分收益。这是全文唯一显著失速的架构族。
- **训练数据敏感度（§4.3.3）**：对训练数据不敏感，可用固定数据集而非 target LLM 自生成文本——这意味着部署门槛进一步降低，新模型上线不需要先跑一遍自举数据生成。

> **一句话小结**：证据链呈"金字塔"形态——塔尖是 2.7x–3.5x 主结果与 3.76x 峰值，中层是稳定压制 Lookahead/Medusa 的同场对比，塔基是接受率鲁棒性与消融（树注意锦上添花、数据不敏感、MoE 除外）对机制的交叉印证。

## 五、批判性分析：局限的深层含义与独立疑点

### 5.1 作者自述局限的深层含义

1. **MoE 加速有限（Mixtral8x7B 仅 1.5x）**：验证阶段读多个专家权重的设计使投机采样在 MoE 上收益折半。深层含义是：EAGLE 的加速公式隐含假设"target forward 成本对所有 token 一致"，MoE 破坏了这个假设。（推断）随着 MoE 成为开源模型主流形态（DeepSeek/Qwen-MoE 等），这一局限的时效重要性反而上升。
2. **接受率未达理想（0-α 最高约 0.79）**：仍有提升空间，且 feature 误差自回归累积仅靠噪声增强部分缓解。深层含义是：EAGLE 只是"rethinking"的第一步而非终点，feature 不确定性还有进一步压缩的空间（后续工作如 EAGLE-2/3 正是沿此推进——此为背景知识补充）。
3. **只对比免微调 backbone 的方法**：对需微调 target 的方法未评估。这是实验范围的自我设限，目的是守住"分布一致性"的可控比较，但也意味着 EAGLE 在更大设计空间中的相对位置未被检验。
4. **7B 级 target 缺乏现成 draft model 的困境反证了自身价值**：文中指出 7B 模型没有合适的独立 draft model 可用——这恰恰是"独立大 draft model 路线"的死穴，也是 EAGLE 轻量头路线的存在意义。（推断）这条"局限"实为对竞品的隐性批判。
5. **训练开销只是摊薄而非消除**：每个新模型仍需一次 1–2 天的训练会话，作者以"随 query 数摊销趋于零"辩护。该辩护在生产环境成立（大模型日均 query 量巨大），但对频繁切换模型的场景（研究/评测）仍是摩擦。

### 5.2 独立观察到的疑点

**① "2.7x–3.5x"的边界条件应被牢记**：该区间限定于 MT-bench 类对话分布 + greedy 设定。temp=1 时降至 1.8x–2.4x，HumanEval 这类模板化任务可冲到 3.76x。（推断）引用者在转述时应绑定"什么任务、什么采样参数"，否则数字会被滥用——这不是论文的错，而是 headline 数字的传播规律使然。

**② 接受率口径（0-α/1-α/…/k-α）的定义依赖 feature 全对的理想化条件**：0-α 的 0.74–0.79 是"draft feature 无误差"下的上限口径，真实推理中 draft feature 必然带误差，故实际生效的是 1-α 及以下的曲线段。论文同时报告两者是诚实的，但读者容易拿 0-α 数字当作期望命中率。（推断）真实的等效接受率应介于 1-α 与 0-α 之间，且随深度衰减——3.2–4.5 tokens/forward 的实测吞吐才是综合了两者的地面真相。

**③ 与 Medusa 的对比公平性有一个隐藏维度**：Medusa 的多头独立预测放弃了位置间依赖，其树结构是"顶层组合搜索"；EAGLE 的树是"自回归展开"。二者树规模相近时算力消耗不同，（推断）加速比差距（1.47x–1.60x）中有多大比例来自"shifted token 消不确定性"、多大比例单纯来自"更强的自回归头结构"，论文未做完全的单变量归因消融——§4.3 的消融覆盖了树注意，但没有覆盖"去掉 shifted token 输入"这一关键设计的直接消融。这是证据链上最值得补的一块。

**④ 训练数据为 ShareGPT 对话域**：虽然 §4.3.3 显示对训练数据不敏感，但不敏感性的检验范围仍在对话/代码等英文指令域内。（推断）对极端低资源语种或特殊格式任务，feature 回归头的泛化性未经直接证明——不过考虑到可训练参数极少、且 feature 空间由冻结的 target 决定，风险可控。

**⑤ batch size > 1 场景未在主表呈现**：论文的加速数字均为单序列（batch=1）延迟口径——这正是投机采样的主场（访存受限、算力空闲）。服务端批量并发时 GPU 算力已被填满，投机采样的边际收益会收缩。文中未讨论 batch>1 下的行为，这是生产部署者必须自行评估的盲区。

> **一句话小结**：EAGLE 的证据在"免微调、无损、dense 模型、batch=1"的划定范围内近乎无懈可击；批判的火力集中在范围之外——MoE 失速、关键设计缺少单变量消融、headline 数字的传播失真风险，这些都不推翻结论，但框定了结论的适用半径。

## 六、启示与影响：可迁移的经验与历史坐标

### 6.1 五条可迁移启示

1. **"换个表示空间"是方法论级别的杠杆**：token→feature 的一步之遥带来 2.7x–3.5x，说明当某个空间里的问题久攻不下时，先问"是否在正确的抽象层级上作业"。可迁移到一切"在离散输出上学辅助模块"的场景：推荐系统的 next-item 预测、语音的 acoustic unit 建模、代码补全的 AST 层预测——**连续内部表示往往比离散表层更适合做预测载体**。
2. **消除条件多值性先于增大模型容量**：shifted token 的案例证明，一个输入构造的修正（零参数成本）胜过堆参数。任何条件建模任务都值得先画一遍"给定条件下目标是否唯一"的因果图，再谈模型规模。
3. **白嫖冻结组件是轻量化的极限形态**：复用 target 的 Embedding/LMHead，可训练参数压缩到 0.24B–0.99B 且训练数据降到 2–4B token（对手 3000B）。凡是"围绕大模型造小模块"的工程，都应最大化复用主干已学好的表征，只训练增量变换。
4. **无损加速的商业护城河是"零迁移成本"**：不改 target、不改输出分布、单卡 RTX3090 即可训好——EAGLE 的采纳门槛几乎为零，加上与 gpt-fast 叠加到 160.4 tokens/s 的示范，说明**兼容性设计（plug-and-play + 理论保证）比极致数字更能决定技术扩散速度**。
5. **树状下注是高方差预测的通用收敛器**：与其押单一最优草稿，不如铺开 top-k 分支一次裁决。该模式适用于一切"单次验证昂贵、多次尝试廉价"的不对称成本结构（如形式化验证中的猜想生成、数据库查询计划枚举）。

### 6.2 历史坐标与后续走向

在投机采样的谱系里，EAGLE 是"feature 系"路线的奠基节点：它证明了草稿质量的主战场在表示层而非模型层，此后该家族沿三个方向延伸——树结构自动化（EAGLE-2 动态树）、接受率逼近理论极限（EAGLE-3 训练与推理策略再优化）、以及向 MoE/批量服务等薄弱场景进军。（推断）与此同时，"draft-free"路线（提示复用/prompt lookup 等零训练方案）与 EAGLE 形成互补光谱：前者零成本但低上限，后者轻训练但高上限。EAGLE 论文留下的开放问题——MoE 验证效率、batch>1 收益、feature 误差累积的根治——至今仍是投机采样社区的活跃前线。

## 总结

《EAGLE》是一次教科书级的"重新定义问题"式创新：它把投机采样的研究焦点从"造更大的 draft model"拉回到"在哪个表示空间、以什么条件做自回归"这两个更本质的问题上。答案极其克制——second-to-top-layer feature 作为自回归对象、前移一位的 token 作为消歧条件、复用 target 的 Embedding/LMHead、仅训一个 FC+decoder layer 的自回归头——却在 MT-bench greedy 下实现 2.7x–3.5x 无损加速（峰值 3.76x），以 0.74–0.79 的 0-α 接受率和 3.2–4.5 tokens/forward 的吞吐全面压制 Lookahead（快 1.70x–2.08x）与 Medusa（快 1.47x–1.60x），并与 gpt-fast 叠出 160.4 tokens/s 的工程纪录。其证据在 dense 模型、免微调、无损约束的划定圈内扎实可靠；圈外——MoE 的 1.5x 天花板、batch>1 的未知行为、shifted token 缺少直接消融——则标注了适用半径。"换个表示空间 + 消除条件多值性 + 白嫖冻结组件"三条经验，早已溢出投机采样领域，成为高效微调与推理系统设计的通用心智模型。
