## §4 方法细节

- **联合预训练策略**：以固定视觉-文本 token 总预算消融注入时机与比例，推翻"晚期高比例视觉注入"惯例——低视觉比例早融合最优，全训练过程恒定比例混合。
- **Zero-vision SFT**：所有图像操作经 IPython 编程操作代理（传统视觉工具使用的泛化），支持像素级操作（二值化估尺寸/计数）、定位、OCR 等；因联合预训练已建立强对齐，人工设计视觉轨迹反而损害泛化。
- **Joint Multimodal RL**：RL 域不按输入模态而按能力组织（知识/推理/编码/agentic），域专家同时学习纯文本与多模态查询；GRM 同样跨模态无壁垒优化，实现双向迁移。
- **PARL（Parallel-Agent RL）**：可训练 orchestrator + 冻结子代理（取自固定中间策略 checkpoint）；子代理输出视为环境观察而非可微决策点，解耦 credit assignment 歧义与训练不稳。奖励 r_PARL = λ1·r_parallel（抗 serial collapse）+ λ2·r_finish（防 spurious parallelism 奖励黑客）+ r_perf（任务结果）；λ1/λ2 训练中退火至 0。先小模型训 orchestrator 再换大模型。
- **Critical Steps**：按计算图关键路径定义 CriticalSteps = Σ_t [S_main(t) + max_i S_sub,i(t)]，以关键步数而非总步数作资源约束，激励真正缩短端到端时延的均衡分解。
- **并行诱导 Prompt**：合成 wide search/deep search/长文档分析/大规模下载类任务，靠任务分布自然偏好并行分解，不显式指示并行。
- **架构**：MoonViT-3D（SigLIP-SO-400M 初始化 + NaViT patch packing 扩展至时间维，图/视频共享全部参数与嵌入空间）→ MLP projector → K2 MoE LLM。
- **预训练三阶段**（Table 3）：ViT Training（1T tokens，仅 caption 交叉熵、无对比损失，两段式对齐 Moonlight-16B-A3B 与 MLP projector）→ Joint Pre-training（15T tokens，4K 序列，加码编码数据）→ Joint Long-context Mid-training（500B→200B 高质量数据，YaRN 依次扩至 32k→262144）。
- **RL 策略优化**：K1.5 算法改进版——token 级 log-ratio 区间裁剪（[α,β] 外梯度置零的梯度掩码，不论 advantage 符号），抑制训练/推理框架差异放大的 off-policy 发散；MuonClip 优化器。
- **奖励体系**：可验证任务用规则结果奖励 + 预算控制奖励；通用任务用 GRM 细粒度评估（多套 rubric 防奖励黑客）；视觉任务专用奖励（IoU 软匹配 grounding、高斯加权点匹配、多边形栅格化 IoU、归一化编辑距离 OCR、绝对差计数、K2 做 LLM verifier 的视觉谜题）。
- **Toggle**：每 m 迭代交替 Phase0（预算受限：均值精度 > λ 才施加 budget(x)=正确回答 token 数 ρ 分位）与 Phase1（标准 scaling 相位），双目标交替优化，兼顾推理能力与 token 效率。
- **DEP**：利用视觉编码器位于前向起点/反向终点的拓扑位置——全 GPU 复制小 ViT、按负载均衡执行视觉前向并丢弃中间激活 → 主干正常 PP 训练 → 重计算视觉前向再做视觉反向。

## §5 实验结果要点

- 对比对象：Claude Opus 4.5（extended thinking）、GPT-5.2（xhigh）、Gemini 3 Pro（high reasoning）；开源对比 DeepSeek-V3.2（thinking）/Qwen3-VL-235B-A22B-Thinking。评测配置 temperature=1.0、top-p=0.95、256k 上下文。
- 推理与通用：AIME 96.1/HMMT 95.4/GPQA-Diamond 87.6/MMLU-Pro 87.1/SimpleQA Verified 36.9/AdvancedIF 75.6/LongBench v2 61.0；SimpleQA Verified 显著低于 Gemini 3 Pro（72.1）。
- 编码短板可见：Terminal Bench 2.0 50.8 vs Opus 59.3；CyberGym 41.3 vs Opus 50.6；SciCode 48.7 vs Gemini 56.1；SWE-Bench Pro 50.7 vs GPT-5.2 55.6。
- 图像感知：OCRBench 92.3、InfoVQA 92.6、OmniDocBench 88.8、CharXiv(RQ) 77.5；BabyVision 36.5 仍远低于 Gemini 49.7。
- token 效率横向（Table 5）：K2.5 在 AIME 2025 用 25k token 达 96.1（K2 Thinking 30k/94.5），多数基准比 K2 Thinking 更省且更高；但仍高于 Gemini 3 Pro 的 token 用量。
- Agent Swarm = 主动式上下文管理：子代理各自维护独立工作记忆、只回传任务相关输出（context sharding），效果与效率均优于 Discard-all 反应式截断。

## §6 局限

- SimpleQA Verified（36.9）等参数化知识基准明显落后 Gemini 3 Pro（72.1）；部分编码/安全基准（Terminal Bench、CyberGym、SciCode、SWE-Bench Pro）仍逊于 Claude Opus 4.5 或 GPT-5.2。
- Agent Swarm 收益集中于可分解的 wide/deep search 类任务；In-house Swarm Bench 为内部基准，第三方不可复核。
- PARL 子代理冻结于中间 checkpoint，编排上限受制于子代理能力，未做端到端共优化（作者承认是为绕开 credit assignment 与稳定性问题的取舍）。
- zero-vision SFT 的有效性依赖联合预训练已建立的图文对齐，难以迁移到非联合预训练的模型。
- 报告未披露后训练数据规模、RL FLOPs 总量与推理成本细节；部分基线分数来自内部复评（标 *）。
