- **核心主张**：针对 LLM 流式部署（多轮对话长交互）的两大痛点——decoding 阶段缓存历史 token 的 KV 状态带来巨量内存、以及模型无法泛化到大于训练序列长度的文本——提出 **StreamingLLM**：无需微调即可让「有限长度注意力窗口训练的 LLM」泛化到无限序列长度。观察并命名了 **attention sink（注意力汇聚点）** 现象：即使初始 token 语义上不重要，模型仍对其分配强注意力得分；仅保留「初始 sink token + 滚动窗口」即可稳定流式生成。**推理可达 400 万 token（4M+）**，流式场景下比「滑窗重算」基线最高快 **22.2x**。

## §3 关键数字
- **模型覆盖**：Llama-2、MPT、Falcon、Pythia 等主流开源 LLM；LoRA / 微调版（dense 与 MPT 等）
- **序列长度**：稳定流式语言建模达 **4,000,000 token（4M+）**，远超训练长度
- **速度提升**：流式场景比滑窗重算（sliding window recomputation）基线最高 **22.2x 加速**
- **attention sink**：初始 token（如序列起始的 few tokens）获得异常高的注意力权重，即使语义无关也扮演「注意力汇聚点」；滑窗注意力在文本长度超过缓存大小时崩溃，随后才发现「保留初始 KV」能几乎完全恢复性能
- **StreamingLLM 策略**：丢弃中间 token 的 KV，仅保留「attending sink（可为初始 token 或专门占位 token）+ 滚动窗口的最近 token」
- **预训练优化**：加一个**专门的占位（placeholder）token 作为 attention sink** 可进一步改善流式部署性能
- **实验设置**：用 PG19 语料 / 长文本基准评测困惑度与吞吐；对比 full attention、滑动窗口 recomputation、H2O 等
- **代码与数据**：开源（`github.com/mit-han-lab/streaming-llm`），支持 Llama-2 等 4 个家族、多倍长度外推验证
