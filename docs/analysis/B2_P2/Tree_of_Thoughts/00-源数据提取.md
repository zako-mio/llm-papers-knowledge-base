# §0 摘要速览

本文针对 LLM 在推理时只能做"token 级、从左到右"决策这一局限，提出 **Tree of Thoughts (ToT)** 框架：把链式思维 (Chain-of-Thought) 泛化为在"thought"这一更高语义单元上做探索、前视与回溯（System 2 式的深思熟虑）。ToT 从人类问题求解（Newell/Shaw/Simon 的树搜索）出发，用语言模型本身生成与评估 thought，并用 BFS/DFS 在思维树中系统搜索。在三个连 GPT-4 用标准 IO/CoT 都表现很弱的新任务上，ToT 显著提升：Game of 24 从 CoT 的 4% 提升到 74%；Creative Writing 在人类盲评中 41/100 偏好 ToT＞CoT 的 21/100；Mini Crosswords 词级成功率 60%（CoT 仅 16%）。论文强调无需额外训练，仅需预训练模型。

# §4 方法细节（ToT 四要素）

1. **Thought decomposition（thought 分解）**：按问题性质设计中间 thought 粒度。可为几个词（Crosswords）、一行方程（Game of 24）、或整段写作计划（Creative Writing）。thought 应"足够小而可多样生成"，又"足够大而可评估其前景"。

2. **Thought generator G(p_θ, s, k)**：给定状态 s=[x, z_{1..i}]，生成 k 个下一 thought 候选。两种策略：
   - (a) 用 CoT prompt 采样 i.i.d. thought（Creative Writing，thought 空间丰富时利于多样性）；
   - (b) 用 "propose prompt" 顺序提议多个 thought（Game of 24、Crosswords，thought 空间受限时避免重复）。

3. **State evaluator V(p_θ, S)**：评估前端状态对解题的进展，作为搜索启发式。两种策略：
   - (a) 独立给每个状态标值（1-10 或 sure/likely/impossible），基于少量 lookahead 模拟 + 常识；
   - (b) 跨状态投票（"good state" s* ~ p(s|S)），当成功难直接标值（如 passage coherency）时比较并投票。两者都可多次采样聚合以更稳健。

4. **Search algorithm**：可插拔。本文用两个简单算法：
   - **BFS**（Algorithm 1）：每步保留 b 个最有希望状态。用于 Game of 24（T≤3，b≤5）和 Creative Writing。
   - **DFS**（Algorithm 2）：优先探索最有希望状态，直到最终输出（t>T）或评估器认为从当前状态不可能解（V(s)≤v_thr）则剪枝，并回溯到父状态继续。用于 Mini Crosswords。

**概念性优点**：(1) Generality——IO/CoT/CoT-SC/self-refine 是 ToT 特例（有限深度与宽度树）；(2) Modularity——各组件可独立变化；(3) Adaptability——适应不同问题/模型能力/资源约束；(4) Convenience——无需额外训练，仅需预训练模型。

**与 baseline 的关系**：IO、CoT、CoT-SC、Self-Refine 都可看作 ToT 的特例——即"有限深度和宽度的思维树"。图1 示意 IO（单路径无中间 thought）、CoT（单路径含中间 thought）、CoT-SC（多条路径取多数）、ToT（有条理地分叉、评估、回溯）。

# §5 实验结果要点

- **Game of 24**：ToT(b=5) 74%，远超 CoT 4% 与 CoT-SC 9%。随节点访问数增长，ToT 改善优于 CoT-best-of-k（最优 CoT best100 仅 49%）。错误分析显示约 60% CoT 样例在第 1 步（前 3 个词）即失败，暴露直接 left-to-right decoding 的问题。
- **Creative Writing**：ToT 得分 7.56 > CoT 6.93 > IO 6.19，且 GPT-4 的 5 次评分标准差约 0.56（较一致）。人类盲评中 41/100 偏好 ToT、21/100 偏好 CoT、38 相似。叠加 iterative-refine 后 IO→7.67、ToT→7.91。
- **Mini Crosswords**：词级成功率 ToT 60% vs CoT 40.6% vs IO 38.7%；完整解 4/20 游戏。Oracle best state 达 7/20。消融：-prune 更差（但可解 3 个 pruning 解不了的游戏）；-backtrack（贪心 BFS b=1）仅 20%。
- **扩展实验**：零样本 ToT 在 GSM8K（GPT-4 90% vs CoT 86%）与 StrategyQA（83% vs 82%）小幅提升；GPT-3.5 上 ToT>CoT>IO 趋势成立，但 Game of 24 GPT-3.5+ToT 仅 19%（远逊 GPT-4 的 74%）。瓶颈在 thought 生成而非评估。

# §6 局限

1. 许多 GPT-4 已擅长的现有任务不需要 deliberate search（见 Appendix B.1），本文只探索了 3 个相对简单但能挑战 GPT-4 的任务。
2. ToT 所需资源（如 GPT-4 API 成本）显著高于普通采样，单任务成本可达 CoT 的 5-100 倍生成 token。
3. 仅使用 off-the-shelf 预训练 LM；用 ToT 风格的高层反事实决策（deliberating over 下一段选择，而非预测下一 token）微调 LM 是潜在方向，但未实现。
4. 状态评估作为剪枝启发式并非完美——5×5 填字游戏设计上含一些 GPT-4 无法识别的罕见/废弃词，导致评估器误判"impossible"而剪枝。
5. 未探索更高级的搜索算法（A*、MCTS），仅用 BFS/DFS；成本与效率高度依赖 prompt 与搜索算法设置。
